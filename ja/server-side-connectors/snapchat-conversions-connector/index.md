## 仕組み

Snapchat Conversions コネクタは、Snap Conversions API を使用します。Snap Conversions API は、Server-to-Server（S2S）統合を通じて、Web、アプリ、オフラインのイベントを Snap に直接送信できる、構造化されたプライバシー重視のインターフェイスです。この API は、Snap Pixel が提供するトラッキングと同様のイベントトラッキングをサポートし、コンバージョンが発生したデバイスの種類を使用します。この機能により、モバイルコンバージョンには Snap App ID を、Web およびオフラインのコンバージョンイベントには Pixel ID を使用できます。

Snap Conversions API は、単独でデプロイすることも、クライアント側の Snap Pixel と組み合わせてデプロイすることもできます。

Snap の Conversions API の詳細については、[Snap：Conversion API](https://businesshelp.snapchat.com/s/article/conversions-api?language=en_US)を参照してください。

## API 情報

このコネクタでは、次のベンダー API を使用します。

* API 名：Snapchat Marketing API - Conversion API
* API バージョン：v3
* API エンドポイント：`https://tr.snapchat.com/v3/conversion`

## 考慮事項

* キャンペーンの最適化を有効にするため、イベントの発生後、できれば 1 時間以内にイベントを送信することを推奨します。
* データをリアルタイムで送信することを強く推奨します。これにより、キャンペーンによる成果をより迅速に確認でき、現在の市場需要に対して入札の競争力を維持できます。
* Conversions API リクエストは、サーバーイベントを Snapchat 広告アカウントに関連付ける一意の識別子に紐付けられます。Web およびオフラインイベントには[Pixel ID](https://businesshelp.snapchat.com/s/article/pixel-website-install?language=en_US)を、アプリイベントには[Snapchat App ID](https://businesshelp.snapchat.com/s/article/snap-app-id?language=en_US)を使用します。

## バッチ処理の上限

このコネクタでは、ベンダーへの大量データ転送をサポートするために、リクエストをバッチ処理します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまで、リクエストはキューに格納されます。

* リクエストの最大数：2000
* 最も古いリクエストからの最大経過時間：10 分
* リクエストの最大サイズ：2 MB

## 重複排除

Snap Conversions API は、単独の API として使用することも、他の Snapchat ソリューションと併用することもできます。シグナルの損失を最小限に抑え、より効率的な結果を得るため、Snap Pixel で構成したものと同じイベントを Snap Conversion API 経由でも送信することを推奨します。

Snap Conversions API でイベントの重複排除が表示されるのは、次の条件を満たす場合のみです。

* Snap App ID、Pixel ID、またはその両方に複数のソース（API、SDK など）がある
* イベントが同じコンバージョンタイプ（Web、アプリ、またはオフライン）である
* 選択したイベントが 2 つ以上のソースに追加されている

Tealium では、統合構成に基づいて次の重複排除方法を推奨しています。

* **単一ソースの冗長性** - 同じ統合で送信されるイベントの重複。  
同じ統合ソースを通じてコンバージョンを複数回送信する場合は、一貫した情報を送信することを強く推奨します。
* **複数ソース間の冗長性** - 複数の統合から送信されるイベントの重複。  
複数の統合からデータを送信する場合は、最適化、ターゲティング、測定機能を最大限に活用できるよう、冗長なデータを送信することを推奨します。

重複排除のユースケースに応じて、次のパラメータを使用します。

* **イベント ID** - Web およびオフラインチャネルの一意のイベントを重複排除します。48 時間の重複排除期間を構成できます。
* **トランザクション ID** - すべてのチャネル（Web、モバイル、オフライン）の購入イベントを重複排除できます。30 日間の重複排除期間を構成できます。
* **モバイル広告 ID** - 一意のイベントの重複排除には、AAID やハッシュ化された IDFV などの共有デバイス識別子を使用します。

詳細については、[Snap：ベストプラクティス - 重複排除](https://developers.snap.com/api/marketing-api/Conversions-API/BestPractices#deduplication)を参照してください。

#### 自動重複排除


<blockquote>
バージョン 3 では、コネクタは重複排除に **Client Dedup ID** ではなく **Event ID** を使用します。
</blockquote>


**自動重複排除**の値に Tag Management タグの UID が入力されている場合、コネクタは対応するイベント属性を検索します。このセクションに値が入力されており、Tag Management を使用している場合は、**イベント ID** を追加する必要はありません。ただし、Tag Management を使用せずに Event Streaming を使用する場合は、次の方法が引き続き必要になることがあります。

コネクタの処理順序は次のとおりです。

* **自動重複排除**に値が入力され、その値がデータレイヤーで検出された場合（例：`6V5xX1T0n9pC42luElKD`）、その値が **イベント ID** にマッピングされた値よりも優先されます。
* **自動重複排除**に値が入力されているものの、タグ ID バージョンが見つからず、従来のバージョン（ID がエンリッチメントされていないもの）が見つかった場合は、その値が使用されます（例：`6V5xX1T0n9pC42luElKD`）。
* **自動重複排除**に値が入力されているものの、その値が見つからない場合は、**イベント ID** にマッピングされた値が入力されていれば、その値が使用されます。

タグの UID は、Tag Management の **タグ**テーブルまたはタグの詳細画面で確認できます。

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加したら、次の構成を行います。

* **長期有効トークン**：この認証方式では、3-legged OAuth フローは不要で、有効期限もありません。詳細については、[Snap：Static Long Lived Tokens](https://marketingapi.snapchat.com/docs/conversion.html#static-long-lived-tokens)を参照してください。
