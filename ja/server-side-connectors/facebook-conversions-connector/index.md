## 前提条件

WebイベントにFacebook Conversionsコネクタを使用する場合は、クライアント側の[Facebook Pixelタグ](https://docs.tealium.com/facebook-pixel-tag/)がWebブラウザで実行されている必要があります。詳細については、[Facebookヘルプセンター](https://www.facebook.com/business/help/2041148702652965)を参照してください。

Facebook広告アカウントの構成でTealiumパートナー連携を有効にするには、次の手順を実行します。

1. Facebook広告マネージャアカウントにログインし、メニューから**イベントマネージャ**を選択します。
1. メニューで**データソース**を選択し、Pixelを選択して**構成**タブをクリックします。
1. **サーバーサイドAPI**セクションまで下にスクロールします。
1. **パートナー連携**セクションで、**パートナーを選択**をクリックします。
1. **Tealium接続を承認**を選択し、**続行**をクリックして**Tealium**を有効にします。

パートナー連携を切り替えるオプションが表示されない場合は、Tealiumアカウントマネージャにお問い合わせください。


<blockquote>
Facebook Pixelタグは、ユーザーデータを自動的にハッシュ化します。Facebook Pixelタグの値や、事前にハッシュ化されたその他の値を変換する場合は、二重にハッシュ化されないように、それらのパラメータの`Already SHA256 Hashed`バリアントにマッピングしてください。
</blockquote>


## API情報

このコネクタでは、次のベンダーAPIを使用します。

* API名：Facebook Graph API - Facebook Pixel
* APIバージョン：v25.0
* APIエンドポイント：`https://graph.facebook.com`

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。コネクタを追加する一般的な手順については、[コネクタについて](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加したら、次の構成を構成します。

* **Pixel / Dataset ID**
  * Facebook Pixel ID。
  * Facebook Pixelが正しく動作するように、[前提条件]()に記載されている手順に従い、Facebook Pixelのパートナー連携を有効にしてください。
  * 詳細については、[Meta Pixelの構成とインストール方法](https://www.facebook.com/business/m/pixel-set-up-step-1#step-1)を参照してください。

### 接続のテスト

Facebookへの接続をテストするには、次の手順を実行します。

* Pixelが許可リストに追加され、Tealiumで有効になっている場合、**TealiumTestConnector**イベントがPixelでトラッキングされます。**接続をテスト**をクリックして、**TealiumConnectorTest**という名前のテストイベントを送信します。
* FacebookイベントマネージャのPixel概要を確認し、イベントが受信されたことを確認します。
* テストに失敗した場合は、構成構成を再確認してください。

## Webイベントの重複排除

このコネクタで[Facebook Pixelタグ](https://docs.tealium.com/facebook-pixel-tag/)からのイベントを重複排除するように構成するには、次の命名規則に従ってイベント属性として送信されるイベントIDを使用します。

```nohl
fb_event_id_{FACEBOOK_EVENT}_{TAG_UID}
```

タグのUIDは、Tealium iQの**タグ**テーブルまたはタグの詳細画面で確認できます。

![](https://docs.tealium.com/images/server-side-connectors/facebook-pixel-tag-uid.png)

たとえば、UIDが`168`のタグから送信される購入イベントには、次の属性値が含まれます。

```json
{
  "fb_event_id_Purchase_168": "028b2ade7478..."
}
```

同じタグから送信されるページビューイベントには、次の属性値が含まれます。

```json
{
  "fb_event_id_PageView_168": "084b1cda7461..."
}
```

イベントの種類ごとに個別のアクションを使用します。イベント固有のイベントID属性を`Event ID`にマッピングし、対応するイベント名を`Event Name`にマッピングします。例：

| Tealium属性 | Facebookパラメータ |
|:-------------------------|:-------------------|
| `fb_event_id_Purchase_168`（属性） | Event ID |
| `"Purchase"`（カスタムテキスト） | Event Name |


<blockquote>
タグUIDのない`fb_event_id_{FACEBOOK_EVENT}`という命名形式のイベントID属性のみを受信している場合は、タグを更新することをお勧めします。詳細については、を参照してください。
</blockquote>


### 自動重複排除

**自動重複排除**の値が入力されている場合、コネクタは対応するイベントID属性を検索します。このセクションに値が入力されており、Tealium iQを使用している場合は、`Event ID`を追加する必要はありません。ただし、Tealium iQを使用せずにEventStreamを使用する場合は、引き続き次の方法が必要になることがあります。

コネクタは、次の処理順序に従います。

* **自動重複排除**に値が入力されており、その値がデータレイヤー内で見つかった場合、この値が`Event ID`にマッピングされた値より優先されます。例：`fb_event_id_ViewContent_30`。
* **自動重複排除**に値が入力されており、タグIDを含むバージョンが見つからないものの、従来のバージョン（IDが付いていないもの）が見つかった場合は、その値が使用されます。例：`fb_event_id_ViewContent`。
* **自動重複排除**に値が入力されているものの、その値が見つからない場合は、`Event ID`に値がマッピングされていれば、その値が使用されます。

### オフラインコンバージョン

Facebook Conversionsコネクタを使用してオフラインイベントと店舗イベントを処理するには、必要なパラメータを含めるようにコネクタを構成します。

#### 前提条件

* Facebook Conversions APIを介して送信されるオフラインイベントは、Facebookイベントマネージャ内のデータセットに関連付ける必要があります。
* すべてのオフラインイベントと店舗イベントで、広告主はイベント内の`action_source`パラメータを`physical_store`に構成する必要があります。
* オフラインイベントには、必須のイベントパラメータをすべて含める必要があります。詳細については、[Meta：サーバーイベントパラメータ](https://developers.facebook.com/docs/marketing-api/conversions-api/parameters/server-event)を参照してください。

#### 構成手順

オフラインイベントと店舗イベントを送信するようにFacebook Conversionsコネクタを構成するには、次の手順を実行します。

1. Facebookイベントマネージャで、オフラインデータソースを新規作成するか、既存のものを選択します。構成手順については、[Meta：Conversions APIを使用したオフラインイベントの送信](https://developers.facebook.com/docs/marketing-api/conversions-api/offline-events/)を参照してください。
1. コネクタの構成で、オフラインデータソースに関連付けられている**Dataset ID**を入力します。このIDは、適切なMetaデータセットにイベントを送信するために使用されます。
1. **アクション**タブで、**イベントを送信**などの新しいアクションを追加します。
1. **Action Source**パラメータを`physical_store`にマッピングします。
1. 必須パラメータをマッピングし、イベントの種類に応じて必要なオプションパラメータを含めます。
1. イベントを送信し、Facebookイベントマネージャで確認します。

詳細については、[Meta：Conversions APIを使用したオフラインイベントの送信](https://developers.facebook.com/docs/marketing-api/conversions-api/offline-events/)を参照してください。

## 自動マッピング

デフォルトでは、コネクタによってeコマース拡張機能から次のパラメータが自動的にマッピングされます。

| Tealium属性 | Facebookパラメータ | 説明 |
| --- | --- | --- |
| `_csubtotal` | `value` | イベントの小計値。 |
| `_ccurrency` | `currency` | イベントの通貨。 |
| `_cprod` | `contents[].id` | イベントに関連付けられた製品ID。 |
| `_csku` | `contents[].content_ids` | 製品のSKU。 |
| `_cquan` | `contents[].quantity` | 製品の数量。 |
| `_corder` | `order_id` | イベントに関連付けられた注文ID。 |
| `_ccat` | `contents[].category` | 製品のカテゴリ。 |
| `_cprodname` | `contents[].content_name` | 製品名。 |
| `_cprice` | `contents[].item_price` | 製品の価格。 |
| Browser ID | `fbp` | Facebookの`_fbp` Cookieに保存されているブラウザID。 |
| Click ID | `fbc` | Facebookの`_fbc` Cookieに保存されているFacebookクリックID値。 |

コネクタがこれらのパラメータをベンダーに自動送信しないようにするには、**自動マッピングを無効化**を`true`に構成して有効にします。
## ユーザーデータのハッシュ化

ハッシュ化可能な各識別子フィールドには、次の2つのマッピング先があります。

* **SHA256ハッシュを適用**：値がプレーンテキストの場合に使用します。コネクタは、Metaに送信する前に値を正規化し、SHA-256を使用してハッシュ化します。
* **SHA256でハッシュ化済み**：MetaのParamBuilder SDKや独自のハッシュ化パイプラインなどにより、値がアップストリームですでに正規化およびハッシュ化されている場合に使用します。コネクタは値を変更せずに転送します。

同じフィールドに両方のバリアントをマッピングしないでください。何らかの理由で両方が存在する場合（たとえば、古いプロファイルバージョンを復元した場合）、**SHA256でハッシュ化済み**の値が優先されます。

<blockquote>

</blockquote>

### CRM（CAPI）イベントの送信



#### バッチ制限

このアクションでは、ベンダーへの大量のデータ転送をサポートするため、バッチリクエストを使用します。並列処理により、イベントが順不同でベンダーに到達する場合があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまでキューに保持されます。

* リクエストの最大数：1000
* 最も古いリクエストからの最大経過時間：10分
* リクエストの最大サイズ：1 MB

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| リード ID | （必須）ダウンロードしたリードに含まれる、Facebook が生成した15桁または16桁の `leadgen_id`。この番号は、リード生成 Webhook の `leadgen_id` フィールドから取得され、`user_data` パラメータに含まれます。 |
| イベント名 | （必須）CRM で使用するリードステージを取得します。`event_name` パラメータは、CRM のセールスファネル内をリードが進行していることを示します。未加工のリードを含め、更新時にすべてのステージを送信してください。 |
| イベント時刻 | CRM によってリードステージの更新イベントが更新された時刻を示す、秒単位の Unix タイムスタンプ。タイムスタンプはリード生成時刻より後である必要があります。そうでない場合、イベントが破棄される可能性があります。このフィールドがマッピングされていない場合は、現在のタイムスタンプで初期化されます。 |
| テストイベントコード | **イベントマネージャー**の**テストイベント**機能を使用して、サーバーイベントが Facebook に正しく受信されていることを確認します。このツールを見つけるには、**イベントマネージャー > データソース > ピクセル > テストイベント**に移動します。 |
| リードイベントソース | イベントの送信元となる CRM の名前。 |

## イベントの確認

イベントを送信した後、概要ビューと内訳ビューで Facebook がイベントを受信したことを確認します。

1. **ビジネスマネージャー** &gt; **ピクセル**に移動します。
1. `POST` リクエストの `PIXEL_ID` に対応するピクセルをクリックします。

![](https://docs.tealium.com/images/server-side-connectors/datasources.png)
### ［概要］タブ

［**概要**］タブで、表示を［**すべて**］から［**サーバー**］に変更すると、正常に送信されたイベント数を確認できます。

![](https://docs.tealium.com/images/server-side-connectors/overview.png)

### ［内訳］タブ

［**内訳**］タブには、正常に送信されたイベントの内訳が表示されます。破棄されたイベントは、`Server Events Received`列には表示されません。

![](https://docs.tealium.com/images/server-side-connectors/breakdown.png)


<blockquote>
サーバーから送信したイベントは、送信後20分以内に確認できます。
</blockquote>


### 検証

イベント構造を検証するには、データパラメータのフィールドを指定して、Facebookの［Payload Helper](https://developers.facebook.com/docs/marketing-api/server-side-api/payload-helper)を使用します。このツールでは、サーバーからFacebookへ送信する際のイベントの構造を確認できます。問題のトラブルシューティングについて詳しくは、Facebookの［サポート](https://developers.facebook.com/docs/marketing-api/server-side-api/support)ページを参照してください。

Conversions APIについて詳しくは、Facebookの［Conversions APIの使用](https://developers.facebook.com/docs/marketing-api/conversions-api/using-the-api)を参照してください。
