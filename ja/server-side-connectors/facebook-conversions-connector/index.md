## 前提条件

Web イベントに Facebook Conversions コネクタを使用する場合は、クライアント側の [Facebook Pixel タグ](https://docs.tealium.com/facebook-pixel-tag/)が Web ブラウザで実行されている必要があります。詳細については、[Facebook ヘルプセンター](https://www.facebook.com/business/help/2041148702652965)を参照してください。

Facebook 広告アカウントの構成で Tealium パートナー連携を有効にするには、次の手順を実行します。

1. Facebook 広告マネージャアカウントにログインし、メニューから **イベントマネージャ**を選択します。
1. メニューで**データソース**を選択し、Pixel を選択してから**構成**タブをクリックします。
1. **サーバー側 API** セクションまで下にスクロールします。
1. **パートナー連携**セクションで、**パートナーを選択**をクリックします。
1. **Tealium 接続を承認**を選択し、**続行**をクリックして **Tealium** を有効にします。

パートナー連携を切り替えるオプションが表示されない場合は、Tealium アカウントマネージャにお問い合わせください。


<blockquote>
Facebook Pixel タグはユーザーデータを自動的にハッシュ化します。Facebook Pixel タグの値や、すでにハッシュ化されたその他の値を変換する場合は、二重にハッシュ化されないよう、それらのパラメータの `Already SHA256 Hashed` バリアントにマッピングしてください。
</blockquote>


## API 情報

このコネクタは、次のベンダー API を使用します。

* API 名：Facebook Graph API - Facebook Pixel
* API バージョン：v25.0
* API エンドポイント：`https://graph.facebook.com`

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **Pixel / Dataset ID**
  * Facebook Pixel ID。
  * Facebook Pixel が正しく動作するように、[前提条件]()に記載されている手順に従って、Facebook Pixel のパートナー連携を有効にしてください。
  * 詳細については、[Meta Pixel の構成とインストール方法](https://www.facebook.com/business/m/pixel-set-up-step-1#step-1)を参照してください。

コネクタを構成したら、**完了**をクリックします。

### 接続のテスト

Facebook への接続をテストするには、次の手順を実行します。

* Pixel が許可リストに追加され、Tealium に対して有効になっている場合、**TealiumTestConnector** イベントが Pixel でトラッキングされます。**接続をテスト**をクリックして、**TealiumConnectorTest** という名前のテストイベントを送信します。
* Facebook イベントマネージャの Pixel の概要を確認し、イベントが受信されたことを確認します。
* テストに失敗した場合は、構成構成を再確認してください。

## Web イベントの重複排除

このコネクタを構成し、[Facebook Pixel タグ](https://docs.tealium.com/facebook-pixel-tag/)からのイベントの重複を排除するには、次の命名規則に従ってイベント属性として送信されるイベント ID を使用します。

```nohl
fb_event_id_{FACEBOOK_EVENT}_{TAG_UID}
```

タグの UID は、タグ管理の**タグ**テーブルまたはタグの詳細画面で確認できます。

![](https://docs.tealium.com/images/server-side-connectors/facebook-pixel-tag-uid.png)

たとえば、UID が `168` のタグから購入イベントが送信される場合、次の属性値が送信されます。

```json
{
  "fb_event_id_Purchase_168": "028b2ade7478..."
}
```

同じタグからページビューイベントが送信される場合、次の属性値が送信されます。

```json
{
  "fb_event_id_PageView_168": "084b1cda7461..."
}
```

イベントの種類ごとに個別のアクションを使用します。イベント固有のイベント ID 属性を `Event ID` にマッピングし、対応するイベント名を `Event Name` にマッピングします。例：

| Tealium 属性 | Facebook パラメータ |
|:-------------------------|:-------------------|
| `fb_event_id_Purchase_168`（属性） | Event ID |
| `"Purchase"`（カスタムテキスト） | Event Name |


<blockquote>
タグ UID を含まない `fb_event_id_{FACEBOOK_EVENT}` 形式のイベント ID 属性のみを受信している場合は、タグを更新することをお勧めします。詳細については、を参照してください。
</blockquote>


### 自動重複排除

**自動重複排除**の値が入力されている場合、コネクタは対応するイベント ID 属性を検索します。このセクションに値が入力され、タグ管理を使用している場合は、`Event ID` を追加する必要はありません。ただし、タグ管理を使用せずにイベントストリーミングを使用する場合は、引き続き次の方法が必要になることがあります。

コネクタは、次の優先順位で処理します。

* **自動重複排除**に値が入力され、その値がデータレイヤーに存在する場合、この値が `Event ID` にマッピングされた値より優先されます。例：`fb_event_id_ViewContent_30`。
* **自動重複排除**に値が入力されているものの、タグ ID を含むバージョンが見つからず、レガシーバージョン（ID がエンリッチメントされていないもの）が見つかった場合は、その値が使用されます。例：`fb_event_id_ViewContent`。
* **自動重複排除**に値が入力されているものの、その値が見つからない場合は、マッピングされた `Event ID` に値が入力されていれば、その値が使用されます。

### オフラインコンバージョン

Facebook Conversions コネクタを介してオフラインイベントと店舗イベントを処理するには、必須パラメータが含まれるようにコネクタを構成します。

#### 前提条件

* Facebook Conversions API を介して送信されるオフラインイベントは、Facebook イベントマネージャ内のデータセットに関連付けられている必要があります。
* すべてのオフラインイベントと店舗イベントで、広告主はイベント内の `action_source` パラメータを `physical_store` に構成する必要があります。
* オフラインイベントには、すべての必須イベントパラメータを含める必要があります。詳細については、[Meta：サーバーイベントパラメータ](https://developers.facebook.com/docs/marketing-api/conversions-api/parameters/server-event)を参照してください。

#### 構成手順

Facebook Conversions コネクタを構成してオフラインイベントと店舗イベントを送信するには、次の手順を実行します。

1. Facebook イベントマネージャで、新しいオフラインデータソースを作成するか、既存のものを選択します。構成手順については、[Meta：Conversions API を使用したオフラインイベントの送信](https://developers.facebook.com/docs/marketing-api/conversions-api/offline-events/)を参照してください。
1. コネクタの構成で、オフラインデータソースに関連付けられている **Dataset ID** を入力します。この ID は、イベントを正しい Meta データセットに送信するために使用されます。
1. **アクション**タブで、**イベントを送信**などの新しいアクションを追加します。
1. **Action Source** パラメータを `physical_store` にマッピングします。
1. 必須パラメータをマッピングし、イベントの種類に応じて必要な任意パラメータを含めます。
1. イベントを送信し、Facebook イベントマネージャで確認します。

詳細については、[Meta：Conversions API を使用したオフラインイベントの送信](https://developers.facebook.com/docs/marketing-api/conversions-api/offline-events/)を参照してください。

## 自動マッピング

デフォルトでは、コネクタは e コマース拡張機能から次のパラメータを自動的にマッピングします。

| Tealium 属性 | Facebook パラメータ | 説明 |
| --- | --- | --- |
| `_csubtotal` | `value` | イベントの小計値。 |
| `_ccurrency` | `currency` | イベントの通貨。 |
| `_cprod` | `contents[].id` | イベントに関連付けられた製品 ID。 |
| `_csku` | `contents[].content_ids` | 製品の SKU。 |
| `_cquan` | `contents[].quantity` | 製品の数量。 |
| `_corder` | `order_id` | イベントに関連付けられた注文 ID。 |
| `_ccat` | `contents[].category` | 製品のカテゴリ。 |
| `_cprodname` | `contents[].content_name` | 製品名。 |
| `_cprice` | `contents[].item_price` | 製品の価格。 |
| Browser ID | `fbp` | Facebook の `_fbp` Cookie に保存されているブラウザ ID。 |
| Click ID | `fbc` | Facebook の `_fbc` Cookie に保存されている Facebook クリック ID の値。 |

コネクタからベンダーへこれらのパラメータが自動送信されないようにするには、**自動マッピングを無効化**を `true` に構成して有効にします。
## ユーザーデータのハッシュ化

ハッシュ化可能な各識別子フィールドには、次の2つのマッピング先があります。

* **SHA256ハッシュを適用**：値がプレーンテキストの場合に使用します。コネクタは、Metaに送信する前に値を正規化し、SHA-256でハッシュ化します。
* **SHA256でハッシュ化済み**：MetaのParamBuilder SDKや独自のハッシュ化パイプラインなどにより、上流ですでに値が正規化およびハッシュ化されている場合に使用します。コネクタは値を変更せずに転送します。

同じフィールドに両方の形式をマッピングしないでください。何らかの理由で両方が存在する場合（古いプロファイルバージョンを復元した場合など）は、**SHA256でハッシュ化済み**の値が優先されます。

**ユーザーデータ**パラメータについて、次の表に一部のパラメータの重要度を示します。重要度は、イベントのマッチ品質に対するパラメータの影響を表します。たとえば、**メールアドレス（em）**の重要度は**最高**で、**電話番号（ph）**の重要度は**高**です。


<blockquote>

</blockquote>

カスタムデータをプレーンテキスト値として、またはテンプレート名を `{{template_name}}` 形式で参照する JSON テンプレートを使用してマッピングします。

| 予測顧客生涯価値 | コンバージョンイベントの予測顧客生涯価値。例：`432.12`。 |
| 純収益 | コンバージョンイベントの利益額。このフィールドとともに**通貨**をマッピングしてください。例：`20`。 |
| 商品数 | `InitiateCheckout` イベントでのみ使用します。ユーザーがチェックアウト時に購入しようとしている商品の数。例：`4`。 |
| 検索文字列 | Search イベントでのみ使用します。ユーザーが入力した検索クエリ。例：`lettuce`。 |
| ステータス | `CompleteRegistration` イベントでのみ使用します。登録イベントのステータス。例：`registered`。|

### CRM（CAPI）イベントの送信



#### バッチ制限

このアクションでは、ベンダーへの大量データ転送に対応するため、バッチリクエストを使用します。並列処理により、イベントが順不同でベンダーに到達する場合があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまで、リクエストはキューに保持されます。

* リクエストの最大数：1000
* 最も古いリクエストからの最大経過時間：10分
* リクエストの最大サイズ：1 MB

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| リード ID | （必須）ダウンロードしたリードに含まれる、Facebook が生成した15桁または16桁の `leadgen_id`。この番号は、リード生成 Webhook の `leadgen_id` フィールドから取得され、`user_data` パラメータに含められます。 |
| イベント名 | （必須）CRM で使用しているリードステージを記録します。`event_name` パラメータは、CRM のセールスファネルをリードが進行していることを示します。未処理のリードを含め、更新されたすべてのステージを必ず送信してください。 |
| イベント時刻 | CRM によってリードステージの更新イベントが更新された時刻を示す、秒単位の Unix タイムスタンプ。タイムスタンプはリード生成時刻より後である必要があります。それ以前の場合、イベントが破棄される可能性があります。このフィールドがマッピングされていない場合は、現在のタイムスタンプで初期化されます。 |
| テストイベントコード | **イベントマネージャ**の**テストイベント**機能を使用して、サーバーイベントが Facebook に正しく受信されていることを確認します。このツールを開くには、**イベントマネージャ > データソース > ピクセル > テストイベント**に移動します。 |
| リードイベントソース | イベントの送信元となる CRM の名前。 |

## イベントの検証

イベントを送信した後、概要ビューおよび内訳ビューで Facebook がイベントを受信したことを確認します。

1. **ビジネスマネージャ** &gt; **ピクセル**に移動します。
1. `POST` リクエストの `PIXEL_ID` に対応するピクセルをクリックします。

![](https://docs.tealium.com/images/server-side-connectors/datasources.png)
### 概要タブ

**概要**タブで、ビューを**すべて**から**サーバー**に変更すると、正常に送信されたイベントの数を確認できます。

![](https://docs.tealium.com/images/server-side-connectors/overview.png)

### 内訳タブ

**内訳**タブには、正常に送信されたイベントの内訳が表示されます。ドロップされたイベントは、`Server Events Received`列には表示されません。

![](https://docs.tealium.com/images/server-side-connectors/breakdown.png)

サーバーからイベントを送信してから20分以内に、そのイベントを確認できます。

### 検証

イベント構造を検証するには、データパラメータのフィールドを指定して、Facebookの[ペイロードヘルパー](https://developers.facebook.com/docs/marketing-api/server-side-api/payload-helper)を使用します。このツールでは、サーバーからFacebookにイベントを送信する際のイベント構造を確認できます。問題のトラブルシューティングについて詳しくは、Facebookの[サポート](https://developers.facebook.com/docs/marketing-api/server-side-api/support)ページを参照してください。

コンバージョンAPIについて詳しくは、Facebookの[コンバージョンAPIの使用](https://developers.facebook.com/docs/marketing-api/conversions-api/using-the-api)を参照してください。
