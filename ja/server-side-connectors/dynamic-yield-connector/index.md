## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加したら、以下の項目を構成します。

* **ホスト**
    * （必須）Dynamic Yieldプロジェクトに関連付けられているホストを選択します。
    * EUベースのAPIエンドポイントを指定するには、**https://dy-api.eu**を使用します。米国ベースのAPIエンドポイントを指定するには、**https://dy-api.com**を使用します。
* **APIキー**  
    * （必須）Dynamic YieldのAPIキー。

コネクタを構成したら、**完了**をクリックします。

### ページビューを記録

#### パラメーター

| **パラメーター** | **説明** |
| --- | --- |
| ユーザーID | 一意のユーザーID。有効な値は`dyid`または`dyid_server`です。 |
| Dynamic Yieldによって生成されたセッション識別子 | `_dyjsession` Cookieが存在する場合は、その値を渡します。存在しない場合は、Dynamic Yieldによって新しいセッション識別子が作成され、レスポンスで返されます。 |
| ページタイプ | （必須）ページのタイプ。有効なフィールドは、`HOMEPAGE`、`CATEGORY`、`PRODUCT`、`CART`、`OTHER`です。 |
| ページの場所 | デバイスまたはアプリケーションのタイプ。アプリまたはサイト内の現在の場所に基づいて、エクスペリエンスやキャンペーンのターゲティングを行うために使用します。有効なフィールドは、ページURL（Webの場合）、場所（SPAの場合）、または画面名（モバイルアプリの場合）です。 |
| ページリファラー | ページリファラーのドメイン。サイトまたはアプリ内の直前の場所に基づいてエクスペリエンスをターゲティングするために使用します。 |
| ページロケール | `en_US`などのページロケールコード。 |
| ページデータ | PRODUCTタイプのページにおける商品SKUなど、ページタイプに関連する追加データ。カテゴリページと商品ページの場合にのみ必須です。ホームページやその他のタイプでは使用しないでください。 |
| デバイスIP | IPフィルタリングに使用するクライアントIPアドレス。この値を渡さない場合は、呼び出し元のIPアドレスが使用されます。 |
| チャネル | 監視するチャネル。有効なフィールドは、Web、アプリ、キオスクです。 |
| アクティブな同意の承諾 | ユーザーの同意に関する決定。有効なフィールドは`true`または`false`です。このパラメーターを送信しない場合、APIのデフォルト値は`false`です。 |

### イベントを送信
#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザー ID | 一意のユーザー ID。有効な値は `dyid` または `dyid_server` です。 |
| Dynamic Yield によって生成されたセッション識別子 | `_dyjsession` Cookie が存在する場合は、その値を渡します。存在しない場合、Dynamic Yield によって新しいセッション識別子が作成され、レスポンスで返されます。 |
| 名前 | （必須）イベントを説明する、人が判読可能な名前。標準イベントを識別するために使用され、通常はスキーマ名に対応します。 |
| DY タイプ | 標準イベント識別子。 |
| 値 | 支払い通貨で表したイベントの合計金額。たとえば、購入されたカートの合計金額です。有効なフィールドは、`add-to-cart-v1`、`purchase-v1`、`remove-from-cart-v1`、`sync-cart-v1` です。 |
| 通貨 | 支払い通貨。有効なフィールドは、`add-to-cart-v1`、`purchase-v1`、`remove-from-cart-v1`、`sync-cart-v1` です。 |
| 製品 ID | 製品フィードに表示されているものと完全に一致する SKU。有効なフィールドは、`add-to-cart-v1`、`add-to-wishlist-v1`、`remove-from-cart-v1` です。 |
| 数量 | カートに追加されたアイテムの合計数。有効なフィールドは、`add-to-cart-v1`、`remove-from-cart-v1` です。 |
| 一意のトランザクション ID | 重複したイベントが報告された場合でも、トランザクション ID に対して購入が一度だけ記録されるようにします。有効なフィールドは、`purchase-v1` です。 |
| CUID | ユーザー識別子の値。有効なフィールドは、`identify-v1`、`login-v1`、`signup-v1`、`newsletter-subscription-v1` です。 |
| CUID タイプ | ユーザー識別子の値のタイプ。デバイスをまたいでユーザーを識別するには、この値を使用します。<ul><li>例：`customer_id`、`account_id`、`email`。</li><li>注：この値には個人を特定できる情報を含めないでください。</li><li>有効なフィールドは、`identify-v1`、`login-v1`、`signup-v1`、`newsletter-subscription-v1`、`message-optin-v1`、`message-optout-v1` です。</li></ul> |
| ハッシュ化されたメールアドレス | 小文字に変換したメールアドレスの SHA-256 エンコード値。`cuid` および `cuidType` の代わりに、この識別子タイプを使用できます。有効なフィールドは、`identify-v1`、`login-v1`、`signup-v1`、`newsletter-subscription-v1`、`message-optout-v1` です。 |
| 電話番号 | Reconnect キャンペーンの SMS チャネルでユーザーを識別するには、この識別子タイプを使用します。有効なフィールドは、`login-v1` です。 |
| プレーンテキストのメールアドレス | 有効なプレーンテキスト形式のメールアドレス。`plainTextEmail` または `externalId` のいずれかを使用します。有効なフィールドは、`message-optin-v1` です。 |
| 外部 ID | ユーザーの識別に使用する外部 ID。ESP は、この ID を認識してメールアドレスにマッピングできる必要があります。`plainTextEmail` または `externalId` のいずれか一方を使用し、両方は使用しないでください。**注：** 外部 ID タイプは、カスタム ESP および Emarsys インテグレーションでのみサポートされます。有効なフィールドは、`message-optin-v1`、`message-optout-v1` です。 |
| サイズ | 製品のサイズ。有効なフィールドは、`add-to-wishlist-v1` です。 |
| フィルタータイプ | フィルター名。たとえば、色、サイズ、ブランド、フィット、著者、キーワードなどです。製品フィード内の製品プロパティに対応している必要があります。有効なフィールドは、`filter-items-v1` です。 |
| フィルターの数値 | セグメンテーション条件の動作を決定する値。このプロパティまたは `filterStringValue` のいずれかに値を指定します。有効なフィールドは、`filter-items-v1` です。 |
| フィルターの文字列値 | セグメンテーション条件の動作を決定する値。このプロパティまたは `filterNumericValue` のいずれかに値を指定します。有効なフィールドは、`filter-items-v1` です。 |
| 属性タイプ | 属性のタイプ。たとえば、色、サイズ、フィット、ブランド、著者などです。有効なフィールドは、`change-attr-v1` です。 |
| 属性値 | 新しい属性値。たとえば、新しい色がグレーである場合などです。有効なフィールドは、`change-attr-v1` です。 |
| 並べ替え基準 | 価格、経過時間、人気度、評価など、許可する任意の並べ替えパラメータ。有効なフィールドは、`sort-items-v1` です。 |
| 並べ替え順序 | ASC または DESC。有効なフィールドは、`sort-items-v1` です。 |
| コード | プロモーションコード。有効なフィールドは、`enter-promo-code-v1` です。 |
| キーワード | 検索文字列。有効なフィールドは、`keyword-search-v1` です。 |
| アイテム ID | コンテンツフィード内のアイテム ID と一致する ID。有効なフィールドは、`video-watch-v1` です。 |
| カテゴリー | 動画カテゴリーの配列。有効なフィールドは、`video-watch-v1` です。 |
| 自動再生 | 動画が自動的に再生されたか（`true`）、ユーザー操作によって再生されたか（`false`）を示します。デフォルトは `false` です。有効なフィールドは、`video-watch-v1` です。 |
| 進捗 | 動画の再生状況を示します。指定可能な値：<ul><li>`VIDEO_STARTED`：動画の再生が開始されました。動画が最後まで再生されたか、または特定の時点まで再生されたかは示しません。</li><li>`PREROLL_FINISHED`：プリロールの再生が完了しました。</li><li>`VIDEO_FINISHED`：プリロールの有無にかかわらず、動画の再生が完了しました。</li><li>`VIDEO_PROGRESS`：クライアントが動画内の詳細な進捗をパーセント単位で定期的に報告できる場合は、この値を `progressPercent` プロパティとともに使用します。</li><li>デフォルトは `VIDEO_STARTED` です。</li><li>有効なフィールドは、`video-watch-v1` です。</li></ul> |
| 進捗率 | 動画がどの程度視聴されたかをパーセントで示します。有効なフィールドは、`video-watch-v1` です。 |
| 製品 ID | 製品識別子の配列。 |
| 数量 | 製品数量の配列。 |
| アイテム価格 | Dollars.cents 形式のアイテム価格の配列。 |
| アクティブな同意の受諾 | ユーザーの同意に関する決定。有効な値は、`true` または `false` です。このパラメータを送信しない場合、API のデフォルト値は `false` です。 |
| 店舗 ID | 一意の店舗識別子。たとえば、レストランのレコメンデーションに使用します。 |
| 店舗の時間帯 | 時間帯に基づいてキャンペーンを区別するために使用します。 |
| デバイス IP | IP フィルタリングに使用するクライアントの IP アドレス。渡されなかった場合は、呼び出し元の IP が使用されます。 |
| デバイスのユーザーエージェント | Web ベースのクライアントの場合は、User-Agent 文字列。渡されなかった場合、API Gateway は HTTPS リクエスト内の該当ヘッダーを確認します。 |
| カスタムイベントプロパティ | 共有するカスタムイベントプロパティ。たとえば、`product_category` や `coupon_code` です。イベントプロパティの `value` と `currency` は予約済みプロパティであるため、ここにはマッピングできません。 |

### イベントの送信（バッチ）

#### バッチ制限

このアクションでは、ベンダーへの大量データ転送をサポートするためにバッチリクエストを使用します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルが公開されるまで、リクエストはキューに格納されます。

* リクエストの最大数：10
* 最も古いリクエストからの最大経過時間：5 分
* リクエストの最大サイズ：1 MB

| デシジョン ID | 選択したエンドポイントから返される一意のデシジョン ID。CLICK または IMP のレポートに必要です。デシジョン ID は base64 形式の配列である必要があります。 |
| バリエーション | ユーザーが閲覧した複数のバリエーション ID の配列。各デシジョンで複数のバリエーションを返すカスタムキャンペーンについて、インプレッションを明示的にレポートする場合にのみ必要です。たとえば、スライダーなどです。 |
| スロット ID | 選択したエンドポイントから返される、クリックされた特定商品のスロット ID。カスタム API キャンペーンでは使用されません。API レコメンデーションキャンペーンでのクリックをレポートする場合に必要です。 |
| アクティブな同意の承認 | ユーザーによる同意の判断。有効な値は `true` または `false` です。このパラメーターを送信しない場合、API のデフォルト値は `false` です。 |

### エンゲージメントのレポート（バッチ）

#### バッチの制限

このアクションでは、ベンダーへの大量のデータ転送をサポートするために、リクエストをバッチ処理します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルが公開されるまで、リクエストはキューに格納されます。

* リクエストの最大数：10
* 最も古いリクエストからの最大経過時間：1 分
* リクエストの最大サイズ：1 MB
#### パラメーター

| **パラメーター** | **説明** |
| --- | --- |
| ユーザーID | 一意のユーザーID。有効な値は `dyid` または `dyid_server` です。 |
| Dynamic Yieldによって生成されたセッション識別子 | `_dyjsession` Cookieが存在する場合は、その値を渡します。存在しない場合は、Dynamic Yieldによって新しいセッション識別子が作成され、レスポンスで返されます。 |
| デバイスIP | IPフィルタリングに使用するクライアントのIPアドレス。渡されなかった場合は、呼び出し元のIPアドレスが使用されます。 |
| タイプ | （必須）エンゲージメントタイプ。<ul><li>APIカスタムコードキャンペーンには、CLICKまたはIMP（インプレッション）を使用します。</li><li>APIレコメンデーションキャンペーンには、`SLOT_CLICK`を使用します。</li><li>QSRレコメンデーションキャンペーンには、`SLOT_IMP`を使用します。</li></ul> |
| デシジョンID | 選択したエンドポイントから返される一意のデシジョンID。CLICKまたはIMPのレポートには必須です。デシジョンIDはbase64形式の配列である必要があります。 |
| バリエーション | ユーザーが閲覧した複数のバリエーションIDの配列。スライダーなど、デシジョンごとに複数のバリエーションを返すカスタムキャンペーンについて、インプレッションを明示的にレポートする場合にのみ必須です。 |
| スロットID | 選択したエンドポイントから返される、クリックされた特定の商品に対応するスロットID。カスタムAPIキャンペーンでは使用されません。APIレコメンデーションキャンペーンのクリックをレポートする場合は必須です。 |
| アクティブな同意の承諾 | ユーザーの同意に関する決定。有効なフィールドは`true`または`false`です。このパラメーターを送信しない場合、APIのデフォルト値は`false`になります。 |
