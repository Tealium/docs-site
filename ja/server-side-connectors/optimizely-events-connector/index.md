## コネクタアクション

| **アクション名** | **訪問プロファイル** | **イベントデータ** |
|:-----------------------------|:-------------------|:----------------|
| イベントを追跡（ユーザーをアクティブ化） | ✓  | ✓ |

## 構成の構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **アカウントID**  
イベントの帰属先となるOptimizelyアカウント。
* **アクセストークン**  
アクセストークンは、**[Optimizelyプロファイル &gt; APIアクセス](https://app.optimizely.com/v2/profile/api)**に移動して取得できます。

## アクション構成 - パラメーターとオプション

**続行**をクリックして、コネクタアクションを構成します。アクションの名前を入力し、リストからアクションタイプを選択します。

### アクション - イベントを追跡（ユーザーをアクティブ化）

#### パラメーター

| **パラメーター** | **説明**  |
|:--------------|:-----------------|
| 訪問ID  | <ul><li>（必須）訪問の一意の識別子。</li></ul>  |
| セッションID  | <ul><li>これらのイベントにセッションコンテキストがある場合、そのコンテキストを識別する一意の識別子。</li><li>省略した場合、Optimizelyバックエンドはセッションを推測し、特定の`visitor_id`からイベントを初めて受信したときにセッションを開始し、その訪問からイベントを受信しない状態が30分間続くとセッションを終了することで、セッションベースの結果を計算します。</li><li>セッションの最大時間は24時間です。</li></ul> |
| プロジェクトID  | <ul><li>（オプション）プロジェクトIDを渡す必要があるのは、Recommendations製品を使用している場合のみです。</li></ul>   |
| IPの匿名化  | <ul><li>Optimizelyは通常、各リクエストのクライアントIPアドレスを保存します。</li><li>値は`true`または`false`です。<ul><li>このフラグを`true`に構成すると、IPアドレスの最後のオクテットが保存前に切り捨てられます。</li><li>`false`に構成すると、IPアドレス全体が保存されます。</li></ul> </li><li>Webブラウザーまたはモバイルクライアントのコンテキストに実装され、エンドユーザーを特定できる情報の保存を制限するポリシーや規制の対象となる、このAPIの利用者に特に関連します。</li><li>このフラグは、アカウントおよびプロジェクト構成のIP匿名化構成とは独立しています。そちらの構成は、Optimizelyクライアントがこのフラグを構成する方法のみを制御します。</li><li>このフラグを構成する場合、IPフィルタリング機能の使用時には注意が必要です。完全修飾された明示的なIPアドレスはフィルターとして機能しません（イベントがIPでフィルタリングされる前に匿名化が行われます）。</li></ul> |
| 判定の拡充  | <ul><li>値は`true`または`false`です。</li><li>Optimizely Easy Event Tracking機能を有効にするには、`true`に構成する必要があります。</li><li>このフィールドの詳細については、[Event APIリファレンス](https://developers.optimizely.com/x/events/api/#api_reference)を参照してください。</li><li>[Optimizelyによるコンバージョンのカウント方法](https://help.optimizely.com/Analyze_Results/How_Optimizely_counts_conversions)も参照してください。</li></ul>  |
| クライアント名 | <ul><li>デバッグ目的での使用を推奨します。</li><li>このイベントを生成したシステムの一意の識別子。</li><li>慣例として、次の例のような形式にします：`organization_name/system_name`</li><li>Event APIの詳細な説明については、[Event APIリファレンス](https://developers.optimizely.com/x/events/api/#api_reference)を参照してください。</li></ul> |
| クライアントバージョン  | <ul><li>デバッグ目的での使用を推奨します。</li><li>このイベントを生成したシステムのバージョン識別子。</li></ul>   |
| タイムスタンプ | <ul><li>（必須）イベントが生成された時刻を、Unixエポックからの経過ミリ秒で表したタイムスタンプ。</li><li>マッピングされていない場合は、コネクタの実行時刻が使用されます。</li></ul> |
| UUID  | <ul><li>（必須）このイベントの一意の識別子。</li><li>`{{uuid}}`を使用して自動的に作成されます。</li><li>誤って、または不正に再送されたリクエストをOptimizelyバックエンドで重複排除するために使用されます。</li><li>Optimizelyは、`entity_id`、`uuid`、`timestamp`が同一のイベントを検出し、そのうち1つだけを保存します。</li><li>送信前に、各イベントで一意の`uuid`または`timestamp`が使用されていることを確認してください。</li></ul>  |
| エンティティID | <ul><li>（オプション）この属性に対応するエンティティのID。</li><li>カスタム属性（`type="custom"`）の場合にのみ必要です。</li><li>その他の属性タイプでは無効です。</li></ul> |
| キー | <ul><li>キー</li></ul>  |
| 数量  | <ul><li>数量</li></ul>   |
| 収益 | <ul><li>収益</li></ul>  |
| タイプ  | <ul><li>イベントのタイプ。</li><li>たとえば、`decision_point`を示すには、タイプを`campaign_activated`にする必要があります。</li></ul> |
| イベントタグ  | <ul><li>（オプション）追加のイベントプロパティ。</li><li>タグに関連するキーと値の属性。</li><li>使用する場合、キーのうち2つとして`type`と`value`を含める必要があります。</li></ul>  |
| イベントプロパティ  | イベントのプロパティまたは特性を定義するキーと値のペア。  |
| キャンペーンID | <ul><li>（必須）この実験を含むキャンペーンのID。</li></ul>  |
| 実験ID | <ul><li>（必須）訪問が接触した実験のID。</li><li>パーソナライゼーションキャンペーンでは、キャンペーンのリーチを正確に計算するため、実験に割り当てられていない訪問の実験IDとして明示的に`null`を送信します。</li></ul>  |
| バリエーションID  | <ul><li>（必須）訪問が接触したバリエーションのID。</li><li>パーソナライゼーションキャンペーンでは、キャンペーンのリーチを正確に計算するため、実験に割り当てられていない訪問のバリエーションIDとして明示的に`null`を送信します。</li></ul> |
| キャンペーンホールドバック | <ul><li>値は`true`または`false`です。</li><li>`true`の場合、選択されたエクスペリエンスはキャンペーンレベルで保留されました。</li><li>パーソナライゼーションでは必須です。それ以外の場合は省略してください。</li></ul>  |
| タイプ  | <ul><li>（必須）`custom`を指定できます。</li></ul>   |
| 値 | <ul><li>必須</li></ul>   |
| エンティティID | <ul><li>カスタム属性タイプでは必須です。</li></ul>  |
