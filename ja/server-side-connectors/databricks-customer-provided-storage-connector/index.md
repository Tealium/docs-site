## 要件

**Databricks OAuth** 認証タイプを使用する場合は、コネクタを構成する前に、サービスプリンシパルに以下の権限を付与してください。これらの権限がない場合、接続テスト、ノートブックの作成、またはジョブの実行に失敗します。

* `MANAGE` 権限を持つユーザーによって付与されるUnity Catalog権限：
    * カタログに対する `USE CATALOG`。
    * スキーマに対する `USE SCHEMA`。
    * ボリュームに対する `READ VOLUME` および `WRITE VOLUME`。
    * スキーマに対する `CREATE TABLE`、`MODIFY`、および `SELECT`。
* ワークスペースのエンタイトルメント：
    * サービスプリンシパルがワークスペースに表示されるようにするためのワークスペースアクセス権。
    * サービスプリンシパルがジョブを作成および管理できるようにするための、Jobsリソースに対する `CAN MANAGE`。
    * サービスプリンシパルとしてジョブを実行するために必要な **Service principal: User** ロール。
* **JDBC HTTP path** フィールドで参照されるSQLウェアハウスに対する `CAN USE`。この権限がない場合、接続テストに失敗します。
* ノートブックを格納するワークスペースフォルダーに対する `CAN MANAGE` または `CAN EDIT`。これらのいずれかの権限がない場合、ノートブックの作成に失敗します。
* 生成されたジョブ用のコンピューティングリソース。デフォルトはサーバーレスコンピューティングです。サービスプリンシパルがサーバーレスコンピューティングにアクセスできる場合、クラスターの構成は不要です。ワークスペースでサーバーレスコンピューティングが制限されているか、有効になっていない場合、サービスプリンシパルにはクラスターを作成する権限も必要です。

## 仕組み

Databricksコネクタは、次の2つの接続アーキテクチャをサポートしています。

* **Databricks Unity Catalog Volume**：TealiumはファイルをUnity Catalog Volumeに直接書き込みます。Databricksから保存への個別の接続は必要ありません。
* **外部クラウド保存（AWS S3、Azure Blob Storage、Google Cloud Storage）**：Tealiumは外部保存バケットにファイルを書き込み、Databricksは保存資格情報と外部ロケーションを使用して同じバケットからファイルを読み取ります。

### 出力ファイル形式

**Send Entire** アクションでは、コネクタは各イベントまたは訪問レコードを、次の2つのトップレベルフィールドを持つ1行のJSONファイルとしてクラウド保存の場所に書き込みます。

* `event_payload`：すべてのイベント属性または訪問属性を含むJSON文字列。このフィールドはシリアル化された文字列であり、ネストされたJSONオブジェクトではありません。
* `event_timestamp`：ISO 8601形式のイベント時刻。Tealiumがこのフィールドを自動的に追加します。

次の例は、1つのファイルの内容を示しています。

```json
{"event_payload":"{\"tealium_event\":\"purchase\",\"order_total\":\"129.99\"}","event_timestamp":"2026-09-14T10:32:11Z"}
```

コネクタは、クラウド保存にファイルを書き込むだけです。アクションでDatabricksテーブルを選択しても、そのテーブルにデータは読み込まれません。Tealiumが作成するノートブックとジョブ、またはお客様自身が作成したノートブックとジョブを使用して、ファイルを読み取り、データを読み込む必要があります。詳細については、[ノートブックの作成](#create-a-notebook)および[ジョブの作成](#create-a-job)を参照してください。


<blockquote>
**Send Entire** アクションは、APIキーや測定シークレットなど、他のベンダーの認証情報を保持する属性を含め、イベントまたは訪問プロファイルのすべての属性を `event_payload` に書き込みます。コネクタを有効にする前にデータレイヤーを監査し、属性フィルタリングを使用して機密属性を除外してください。
</blockquote>


### Tealiumからクラウド保存への接続

Tealiumがバケットを一覧表示し、イベントデータとオーディエンスデータをクラウド保存のオブジェクトおよびファイルにアップロードするには、Databricks Unity Catalog Volume、AWS S3、Azure Blob Storage、またはGoogle Cloud Storageインスタンスへの接続が必要です。Databricksコネクタでは、次の認証オプションを使用できます。

* [Databricks Unity Catalog](#databricks-unity-catalog-settings)
    * クライアントIDとクライアントシークレット（OAuth）を指定します。
* [AWS S3](#aws-s3-settings)
    * アクセスキーとアクセスシークレットを指定します。
    * STS（Security Token Service）資格情報を指定します。
* [Azure Blob Storage](#azure-blob-storage-settings)
    * クライアント資格情報。
    * 認可コードフロー（SSO）。
    * Shared Access Signature（SAS）。
* [Google Cloud Storage](#google-cloud-storage-settings)
    * Googleでログイン（SSO）。

#### Databricks Unity Catalogの構成

##### クライアントIDとシークレット資格情報

Databricksアカウントの新しいOAuth資格情報を生成するには、次の手順を実行します。

1. Databricksインスタンスにログインします。
1. ワークスペースに移動します。
1. 画面右上で、**Settings > Identity and access > Service principals** に移動します。
1. 新しいサービスプリンシパルを作成するか、既存のサービスプリンシパルをクリックします。
1. **Secrets** タブをクリックし、**Generate secret** をクリックします。
1. **Permissions** タブをクリックし、サービスプリンシパルに **Service principal: User** ロールが割り当てられていることを確認します。

#### AWS S3の構成

##### アクセスキーとシークレット資格情報

AWSアクセスキーとシークレットを確認するには、次の手順を実行します。

1. AWS Management Consoleにログインし、IAM（Identity and Access Management）サービスに移動します。
1. **Users**、**Add user** の順にクリックします。
1. ユーザー名を入力します。例：`TealiumS3User`。
1. 作成したユーザーにポリシーをアタッチします。
    1. **Permissions** タブで、**Attach existing policies directly** をクリックします。
    1. フルアクセスを許可するには、`AmazonS3FullAccess` ポリシーを検索してアタッチします。特定のバケットへのアクセスを制限する場合は、次の例のようなポリシーを作成できます。この例では、`YOUR_BUCKET_NAME` は、TealiumがイベントデータとオーディエンスデータをS3オブジェクトにアップロードするために使用するバケットです。
        ```json
        {
            "Version": "2012-10-17",
            "Statement": [
                {
                    "Effect": "Allow",
                    "Action": [
                        "s3:ListBucket",
                        "s3:PutObject",
                        "s3:GetObject",
                        "s3:ListBucketMultipartUploads",
                        "s3:ListMultipartUploadParts"
                    ],
                    "Resource": [
                        "arn:aws:s3:::YOUR_BUCKET_NAME",
                        "arn:aws:s3:::YOUR_BUCKET_NAME/*"
                    ]
                }
            ]
        }
        ```
1. キーを作成します。
    1. **Security credentials** タブに移動し、**Create Access Key** をクリックします。
    1. **Access Key ID** と **Secret Access Key** をコピーし、安全に保存します。
##### STS認証情報の構成

1. AWSマネジメントコンソールにログインし、IAM（Identity and Access Management）サービスに移動します。
1. **ロール**をクリックし、次に**ロールを作成**をクリックします。
1. **信頼されたエンティティ**のタイプとして、AWSアカウントを選択します。
1. **別のAWSアカウント**を選択し、TealiumのアカウントID `757913464184` を指定します。
1. （オプション）**外部IDを要求する**チェックボックスをオンにし、使用する外部IDを指定します。外部IDは最大256文字で、英数字（`A-Z`、`a-z`、`0-9`）と、ハイフン（`-`）、アンダースコア（`_`）、ピリオド（`.`）などの記号を使用できます。
1. ロール名を入力します。ロール名は `tealium-databricks` で始まる必要があります。例：`tealium-databricks-s3-test`
1. ロールにポリシーをアタッチします。
    1. **アクセス許可**タブで、**既存のポリシーを直接アタッチ**をクリックします。
    1. フルアクセスを許可するには、`AmazonS3FullAccess` ポリシーを検索してアタッチします。特定のバケットへのアクセスを制限する場合は、以下の例のようなポリシーを作成できます。この例で、`YOUR_BUCKET_NAME` は、TealiumがイベントおよびオーディエンスデータをS3オブジェクトにアップロードする際に使用するバケットです。
        ```json
        {
            "Version": "2012-10-17",
            "Statement": [
                {
                    "Effect": "Allow",
                    "Action": [
                        "s3:ListBucket",
                        "s3:PutObject",
                        "s3:GetObject",
                        "s3:ListBucketMultipartUploads",
                        "s3:ListMultipartUploadParts"
                    ],
                    "Resource": [
                        "arn:aws:s3:::YOUR_BUCKET_NAME",
                        "arn:aws:s3:::YOUR_BUCKET_NAME/*"
                    ]
                }
            ]
        }
        
        ```
1. 信頼ポリシーを作成します。
    1. **信頼関係**タブに移動し、**信頼関係を編集**をクリックします。
    1. 以下の例に示すように、作成したロールに対して指定した外部IDが信頼ポリシーで許可されており、Tealiumの本番環境アカウントIDが `757913464184` であることを確認します。
    1. Tealiumへの接続用に `EXTERNAL_ID` の値を構成します。IDは最大256文字で、英数字（`A-Z`、`a-z`、`0-9`）と、ハイフン（`-`）、アンダースコア（`_`）、ピリオド（`.`）などの記号を使用できます。
```json
{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Principal": {
                "AWS": "arn:aws:iam::757913464184:root"
            },
            "Action": "sts:AssumeRole",
            "Condition": {
                "StringEquals": {
                    "sts:ExternalId": "EXTERNAL_ID"
                }
            }
        }
    ]
}
```

#### Azure Blob Storageの構成

##### クライアント認証情報

AzureでアプリケーションのテナントID、クライアントID、クライアントシークレットを取得するには、次の手順を実行します。

**ステップ1：Azure Portalにアクセスする**

1. Azure Portalに移動します。
1. Azureアカウントでサインインします。

**ステップ2：アプリの登録に移動する**

1. 上部の検索バーに `Azure Active Directory` と入力して選択します。
1. 左側のメニューで、**アプリの登録**をクリックします。
1. 登録済みのアプリケーションを見つけます。

**ステップ3：テナントIDとクライアントIDを確認する**

1. アプリケーションをクリックします。
1. **概要**セクションで、次の情報を確認します。
    * **テナントID**（**ディレクトリID**とも呼ばれます）は、**テナントID**の下に表示されます。
    * **クライアントID**（**アプリケーションID**とも呼ばれます）は、**アプリケーション（クライアント）ID**として表示されます。

**ステップ4：クライアントシークレットを生成する**

1. 左側のメニューで、**証明書とシークレット**に移動します。
1. **クライアントシークレット**で、**新しいクライアントシークレット**をクリックします。
1. 説明を入力し、有効期限を選択します。
1. **追加**をクリックします。
1. シークレットを生成したら、ページを離れると再表示できないため、すぐにコピーしてください。

##### Shared Access Signature（SAS）

AzureでShared Access Signature（SAS）トークンを生成するには、次の手順を実行します。

**ステップ1：Azure Portalにアクセスする**

1. Azure Portalに移動します。
1. Azureアカウントでサインインします。

**ステップ2：保存アカウントに移動する**

1. 検索バーに `Storage accounts` と入力して選択します。
1. SASトークンを生成する保存アカウントを選択します。

**ステップ3：SASトークンを生成する**

オプション1：Azure Portalを使用する

1. **保存アカウント**で、**セキュリティとネットワーク**セクションにある**共有アクセス署名**に移動します。
1. 必要なアクセス許可（`Read`、`Write`、`Delete`、`List` など）を構成します。
1. トークンの有効期間を定義するため、有効期限の日時を構成します。
1. 許可するサービス（`Blob`、`File`、`Queue`、`Table`）を選択します。
1. **SASと接続文字列を生成する**をクリックします。
1. SASトークン、またはSASトークンを含む接続文字列をコピーします。

オプション2：Azure Storage Explorerを使用する

1. Azure Storage Explorerを開き、Azureアカウントにサインインします。
1. 保存アカウントを見つけ、*Blobコンテナー*またはファイル共有を右クリックします。
1. **共有アクセス署名を取得する**を選択します。
1. アクセス許可と有効期限を構成します。
1. **作成**をクリックし、生成されたSAS URLまたはトークンをコピーします。

オプション3：Azure CLIを使用する

1. Azure CLIで次のコマンドを実行し、SASトークンを生成します。
```sh
    az storage blob generate-sas \
        --account-name <your-storage-account> \
        --container-name <your-container> \
        --name <your-blob> \
        --permissions r \
        --expiry 2026-04-25T12:00:00Z \
        --output tsv
```

このコマンドはSASトークンを出力します。保存URLにこのトークンを追加することで、制御されたアクセスを提供できます。

##### 認可コードフロー（SSO）

**接続を確立**をクリックすると、認可コードフローと呼ばれる安全な認証プロセスが開始されます。このプロセスにより、認証情報を手動で入力することなく、アプリケーションにAzure Blob Storageへのアクセス権が付与されます。

次の処理が行われます。

1. **サインインへのリダイレクト：** Azure Active Directoryなど、組織のIDプロバイダー（IdP）に一時的にリダイレクトされ、既存の認証情報を使用してログインします。
1. **同意の付与**：認証後、Tealiumアプリが要求しているアクセス許可（具体的にはBlob Storageへのアクセス）を説明する同意画面が表示されます。
1. **Blob Storageへの安全なアクセス**：Azureのセキュリティポリシーを維持しながら、Tealiumアプリケーションが保存を操作できるようになります。

#### Google Cloud Storageの構成

##### Googleでサインイン

**Googleでサインイン**をクリックすると、Googleアカウントを使用してアプリケーションがGoogle Cloud Storageにアクセスできるようにする、安全な認可プロセスが開始されます。

次の処理が行われます。

1. **Googleサインインへのリダイレクト**：Googleの認証ページに一時的にリダイレクトされ、Googleアカウントの認証情報を使用してログインします。
1. **同意の付与**：サインイン後、Cloud Storageへのアクセスなど、Tealiumアプリが要求しているアクセス許可の詳細を示す同意画面が表示されます。
1. **認可コードの受信**：承認すると、Googleが1回限りの認可コードを生成し、アプリケーションに返します。
1. **Cloud Storageへの安全なアクセス**：Googleのセキュリティポリシーに準拠しながら、Tealiumアプリケーションが保存を操作できるようになります。

### DatabricksからAWS S3への接続

DatabricksをAWS S3インスタンスに接続するには、まずAWSインスタンスにIAMロールを作成する必要があります。このロールは、Databricksインスタンスで保存認証情報を作成するために使用されます。AWS IAMロールの作成方法について詳しくは、[Databricks：AWS S3に接続するための保存認証情報を作成する](https://docs.databricks.com/en/connect/unity-catalog/cloud-storage/storage-credentials.html)を参照してください。

保存認証情報を作成したら、データの取得元となるAWS S3インスタンス内の外部ロケーションを定義します。詳しくは、[Databricks：クラウド保存をDatabricksに接続するための外部ロケーションを作成する](https://docs.databricks.com/en/connect/unity-catalog/cloud-storage/external-locations.html)を参照してください。
### Databricks から Azure Blob Storage への接続

Databricks を Azure Blob Storage インスタンスに接続するには、Azure サービスプリンシパルまたはマネージド ID を使用して保存資格情報を作成する必要があります。これにより、Databricks は安全に認証し、Blob Storage にアクセスできます。詳細については、[Databricks：Azure Blob Storage に接続するための保存資格情報の作成](https://learn.microsoft.com/en-us/azure/databricks/connect/unity-catalog/cloud-storage/storage-credentials)を参照してください。

保存資格情報を構成した後、Databricks がデータの読み取りと書き込みに使用する外部ロケーションを Azure Blob Storage に定義します。詳細については、[Databricks：クラウド保存を Databricks に接続するための外部ロケーションの作成](https://learn.microsoft.com/en-us/azure/databricks/connect/unity-catalog/cloud-storage/external-locations)を参照してください。

### Databricks から Google Cloud Storage への接続

Google Cloud Storage を Databricks と統合するには、まず、保存バケットへのアクセスに必要な権限を持つサービスアカウントを Google Cloud で構成する必要があります。次に、このサービスアカウントを認証に使用するための保存資格情報を Databricks で作成します。詳細については、[Databricks：Google Cloud Storage に接続するための保存資格情報の作成](https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/storage-credentials)を参照してください。

保存資格情報を構成した後、Databricks がデータを操作するために必要なバケットと権限を指定して、Google Cloud Storage に外部ロケーションを定義する必要があります。詳細については、[Databricks：クラウド保存を Databricks に接続するための外部ロケーションの作成](https://docs.databricks.com/gcp/en/connect/unity-catalog/cloud-storage/external-locations)を参照してください。

## バッチ制限

このコネクターは、ベンダーへの大容量データ転送をサポートするために、バッチリクエストを使用します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルが公開されるまで、リクエストはキューに格納されます。

* リクエストの最大数：100,000
* 最も古いリクエストからの最大経過時間：1～60 分の範囲でカスタム TTL を構成できます。デフォルト値は 10 分です。
* リクエストの最大サイズ：10 MB

## 構成

コネクターマーケットプレイスに移動し、新しいコネクターを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクターを追加した後、次の構成を構成します。コネクターと各アクションには、それぞれ個別の有効化スイッチがあります。


<blockquote>
アクションを保存した後、コネクターとアクションの両方が有効になっていることを確認してください。有効になっていない場合、データは送信されません。
</blockquote>


* **クラウドソリューション**：使用しているクラウドソリューションを選択します。使用可能なオプションは、`Databricks Unity Catalog Volume`、`AWS S3`、`Azure Blob Storage`、`Google Cloud Storage` です。
* **Databricks ホスト URL**：Databricks ワークスペースの URL を指定します。例：`https://{ACCOUNT_NAME}.cloud.databricks.com`。
* **Databricks トークン**：Databricks アクセストークンを指定します。データを Databricks Unity Catalog Volume に送信する場合、このパラメーターは省略可能です。Databricks でアクセストークンを作成するには、Databricks のユーザーアバターをクリックし、**Settings > Developer > Access Tokens > Manage > Generate New Token** に移動します。

## ノートブックの作成


<blockquote>
コネクタから作成したノートブック、ジョブ、パイプラインは Databricks ワークスペースに作成され、Tealium では管理されません。削除するには、Databricks で削除してください。
</blockquote>


Databricks のノートブックは、実行可能なコード、可視化、説明テキストを含むドキュメントです。データの探索、可視化、共同作業に使用されます。コネクタの構成時に、構成手順で **ノートブックを作成**をクリックすると、新しいコネクタの作成と同時に新しいノートブックを作成できます。

1. コネクタの構成画面で、**ノートブックを作成**をクリックします。
1. **テーブル名**を入力します。スキーマはジョブの作成時に指定するため、このフィールドには追加しないでください。
    * 名前には英数字（`A-Z`、`a-z`、`0-9`）とアンダースコア（`_`）を使用できます。
    * スペースおよび `!`、`@`、`#`、`-`、`.` などの特殊文字は使用できません。
    * 名前では大文字と小文字が区別されます。たとえば、`tableName` と `tablename` は異なる名前とみなされます。
    * 名前の先頭に数字は使用できません。たとえば、`1table` は無効です。
1. **ノートブックパス**には、ノートブックの絶対パスを入力します。例：`/Workspace/Shared/data_ingestion/NOTEBOOK_NAME`。
    1. Databricks でノートブックの絶対パスを確認するには、Databricks ワークスペースに移動し、**ユーザー**セクションを展開します。
    1. ユーザーをクリックし、オプションメニューを展開します。
    1. **URL/パスをコピー > フルパス**をクリックします。パス名の形式は `/Workspace/Users/myemail@company.com` です。追加する仮想フォルダーとノートブック名をスラッシュ `/` で区切ります。例：`/Workspace/Users/myemail@company.com/virtualfolder/virtualsubfolder/MyNotebook`。
1. **クラウドバケット／ボリューム**：
    1. **クラウドバケット**では、データの送信先として接続する Google Cloud Platform（GCP）、Azure Blob Storage、または AWS S3 の保存バケットを選択します。
    1. **Databricks OAuth** 認証タイプを使用している場合は、代わりに Databricks Unity Catalog Volume を指定します。
1. **上書き**オプションは、指定したワークスペースに既存のノートブックがある場合に、それを上書きするかどうかを示します。


<blockquote>
ノートブックは個人ユーザーフォルダーではなく、`/Workspace/Shared/data_ingestion` などの共有ワークスペースフォルダーまたは Git フォルダーに保存してください。個人フォルダー内のノートブックは、そのユーザーが無効化されるとアクセスできなくなり、ジョブが停止します。
</blockquote>


## ジョブの作成

Databricks のジョブは、スケジュールまたは特定のトリガーに基づいてノートブックを自動実行します。ジョブを使用すると、データ処理、分析、レポート作成などのタスクを一定間隔で実行したり、特定のイベントを契機に実行したりできます。

1. コネクタの構成画面で、**ジョブを作成**をクリックします。
1. 処理ジョブの名前を入力します。
1. **カタログ**には、パイプラインデータの公開先として使用する Unity Catalog のカタログを指定します。
1. **ターゲット**には、上記のカタログ内でテーブルを公開または更新するスキーマを指定します。使用されるテーブルはノートブックで指定したテーブルであるため、ここではターゲットテーブルを指定しないでください。
1. **ノートブックパス**には、ノートブックの絶対パスを入力します。例：`/Workspace/Shared/data_ingestion/NOTEBOOK_NAME`。
    1. Databricks でノートブックの絶対パスを確認するには、Databricks ワークスペースに移動し、**ユーザー**セクションを展開します。
    1. ユーザーをクリックし、オプションメニューを展開します。
    1. **URL/パスをコピー > フルパス**をクリックします。パス名の形式は `/Workspace/Users/myemail@company.com` です。追加する仮想フォルダーとノートブック名をスラッシュ `/` で区切ります。例：`/Workspace/Users/myemail@company.com/virtualfolder/virtualsubfolder/MyNotebook`。
1. **クラウドバケット**または**ボリューム**では、Databricks に接続するクラウド保存バケットまたは Databricks Unity Catalog Volume を選択します。
1. **トリガータイプ**では、データを処理するタイミングを選択します。使用可能なオプションは次のとおりです。
    * **ファイル到着時**：新しいファイルが到着するたびにデータを処理します。
    * **スケジュール**：指定した繰り返しスケジュールでデータを処理します。
    * **Cron**：**Cron** フィールドで定義した繰り返しスケジュールでデータを処理します。
1. **開始時刻**には、ジョブ処理の開始時刻を `hh:mm` 形式で指定します。開始時刻のデフォルト値は `00:00` です。
1. **タイムゾーン**には、タイムゾーンを `country/city` 形式で指定します。例：`Europe/London`。開始時刻を指定する場合、このフィールドは必須です。
1. **Cron** には、スケジュール処理に使用する Quartz cron 式を入力します。たとえば、`20 30 * * * ?` は、毎時30分20秒にファイルを処理します。詳細については、[Quartz：Cron Trigger チュートリアル](https://www.quartz-scheduler.org/documentation/quartz-2.3.0/tutorials/crontrigger.html)を参照してください。

## ジョブとノートブックの作成

ノートブックとジョブを同時に作成するには、**ノートブックとジョブを作成**をクリックします。[ノートブックの作成](#create-a-notebook)および[ジョブの作成](#create-a-job)の手順に従ってください。


<blockquote>
各作成ボタンをクリックするたびに、Databricks に新しいノートブックまたはジョブが作成されます。**作成**をクリックするとリソースが作成され、フォームは開いたままになります。**作成して閉じる**をクリックすると、別の一組のリソースが作成されてからフォームが閉じます。**作成**をクリックした後にフォームを閉じるには、**作成して閉じる**ではなく、上隅にある **X** を使用してください。そうしないと、重複するジョブが作成されます。
</blockquote>


### ノートブックパスとジョブ ID の記録

コネクタにはノートブックパスもジョブ ID も保存されず、作成フォームは開くたびに空の状態で表示されます。ノートブックまたはジョブの作成後は、コネクタから構成を確認または編集できません。また、コネクタは既存のノートブックやジョブを検出しません。

後でパイプラインのトラブルシューティングを行う際にワークスペースを手作業で検索する必要がないように、作成時に Databricks で次の値を記録してください。

* ノートブックの絶対パス。
* ジョブ ID とジョブ名。
* ジョブの書き込み先となるカタログ、スキーマ、テーブル。
* ジョブの読み取り元となるボリュームパス。

既存のノートブックまたはジョブを使用する場合は、ノートブックとジョブを Databricks で直接作成し、コネクタのボタンは使用しないでください。コネクタのボタンは、データエンジニアリング担当者がいないアカウント向けの便利な機能であり、使用は必須ではありません。

### ターゲットテーブルごとに1つのコネクタを使用する

コネクタが使用するのは、最初のノートブックと最初のジョブのみです。同じコネクタで2つ目のノートブックまたはジョブを作成しても、データの保存先には影響しません。複数の Databricks テーブルに書き込むには、テーブルごとに1つのコネクタを作成し、次のルールに従ってください。

1. **ファイルパス**フィールドで、各コネクタにボリューム配下の固有のサブディレクトリを割り当てます。2つのコネクタで同じパスを共有すると、両方のテーブルに重複レコードが生成されます。
1. 1つのイベントが2つのコネクタに到達しないように、各コネクタに固有のデータソース、イベント仕様、またはイベントフィードを割り当てます。
1. コネクタごとに1つのノートブックと1つのジョブを作成します。

次の例は、2つのコネクタを使用する構成を示しています。

| コネクタ | アクション | ファイルパス | ターゲットテーブル |
| --- | --- | --- | --- |
| 完全なペイロード | イベントデータ全体を送信 | `/Volumes/CATALOG/SCHEMA/VOLUME/purchase_events_full_payload` | `CATALOG.SCHEMA.purchase_events_raw` |
| フラット化 | カスタムイベントデータを送信 | `/Volumes/CATALOG/SCHEMA/VOLUME/purchase_events_flattened` | `CATALOG.SCHEMA.purchase_events_flattened_raw` |
### スキーマ変更後に Auto Loader のチェックポイントをリセットする

生成されたノートブックは Auto Loader を使用します。Auto Loader は、すでに処理したファイルをボリュームのルートにある次のフォルダーに記録します。

* `/Volumes/CATALOG/SCHEMA/VOLUME/_auto_loader_checkpoints`
* `/Volumes/CATALOG/SCHEMA/VOLUME/_auto_loader_schema`

Databricks は両方のフォルダーを自動的に作成します。列の型を変更した場合など、テーブル定義を変更した後は、両方のフォルダーを削除してジョブを再実行してください。削除しない場合、Auto Loader はすでに検出したファイルをスキップするため、テーブルは空のままになります。


<blockquote>
チェックポイントフォルダーを削除すると、Auto Loader はすべてのソースファイルを最初から再処理します。これにより、ターゲットテーブルに重複レコードが作成される可能性があります。既存のチェックポイントとの互換性がなくなるスキーマ変更を行った場合にのみチェックポイントを削除し、ジョブを実行する前に、ターゲットテーブルが空であるか、重複排除されていることを確認してください。
</blockquote>


```python
dbutils.fs.rm("/Volumes/CATALOG/SCHEMA/VOLUME/_auto_loader_checkpoints", recurse=True)
dbutils.fs.rm("/Volumes/CATALOG/SCHEMA/VOLUME/_auto_loader_schema", recurse=True)
```
