## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **APIエンドポイント**  
（必須）アカウントがプロビジョニングされているインスタンスのAPIエンドポイントを選択します。  
詳細については、[Braze APIエンドポイント](https://www.braze.com/docs/developer_guide/rest_api/basics/#endpoints)を参照してください。
* **APIキー**  
（必須）`users.track`および`users.delete`の権限が有効になっているAPIキーを指定します。  
詳細については、[BrazeアプリグループREST APIキー](https://www.braze.com/docs/api/basics/?redirected=true#app-group-rest-api-keys)を参照してください。

追加情報については、Brazeドキュメントの[Brazeテクノロジーパートナー：Tealium](https://www.braze.com/docs/partners/data_and_infrastructure_agility/customer_data_platform/tealium/)を参照してください。

### ユーザーの追跡（バッチ／非バッチ）

できるだけ多くのIDパラメータをマッピングすることをお勧めします。複数のIDがマッピングされた状態でアクションがトリガーされると、次の優先順位に基づいて、空白ではない最初の値が選択されます。

* 外部ID
* Braze ID
* エイリアス名／エイリアスラベル

詳細については、[Braze API：ユーザーの追跡](https://www.braze.com/docs/api/endpoints/user_data/post_user_track/)を参照してください。

#### バッチと非バッチ  

* **バッチ**：大量のユーザープロファイルのバックフィルと同期に使用します。
* **非バッチ**：リアルタイムのユースケースに使用します。


<blockquote>
トラフィックのピーク時には、Brazeはバッチリクエストよりも非バッチリクエストを優先します。
</blockquote>


#### バッチ制限

このアクションでは、ベンダーへの大容量データ転送をサポートするために、バッチリクエストを使用します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルが公開されるまで、リクエストはキューに格納されます。

* リクエストの最大数：75
* 最も古いリクエストからの最大経過時間：60分
* リクエストの最大サイズ：1 MB

#### ユーザー属性の変更

次の操作を使用して、数値型のユーザー属性を変更します。

* 増加（正または負の値を使用可能）
* 減少
* 加算

既存の配列に値を追加、または既存の配列から値を削除して、配列属性を変更します。
#### イベント

イベント名は **Name** にマッピングする必要があります。

同じ長さの配列属性をマッピングすると、複数のイベントを送信できます。単一値の属性も使用でき、その場合は各イベントに適用されます。

| **パラメータ** | **説明** |
|:--------------|:----------------|
| App ID | アプリグループ内の特定のアプリに関連付けられた App Identifier API キー、または `app_id`。詳細については、[Braze API：App Identifier API キー](https://www.braze.com/docs/api/api_key/#the-app-identifier-api-key)を参照してください。 |
| Name | （必須）イベントの名前。|
| Time | イベントの時刻。値がマッピングされていない場合は、自動的に `now` に構成されます。|
| Update Existing Only (Events) | **true** または **false** に構成します。イベント値が存在しない場合は、デフォルトで新しく作成されます。**true** に構成すると、既存のイベントのみが更新され、新しいイベントは作成されません。|

#### イベントテンプレート変数

テンプレート変数をデータ入力として指定します。詳細については、[connector-template-variables](https://docs.tealium.com/connector-template-variables/)を参照してください。

ネストされたテンプレート変数には、ドット表記で名前を付けます（例：`items.name`）。

通常、ネストされたテンプレート変数は、データレイヤーのリスト属性から構築されます。

#### イベントテンプレート

Body Data で参照するテンプレートを指定します。詳細については、[about-connector-templates](https://docs.tealium.com/about-connector-templates/)を参照してください。

テンプレートは、サポートされているフィールドに二重波括弧で囲んだ名前を使用して挿入します。例：`{{SomeTemplateName}}`。

#### 購入

購入データをマッピングするには、Product ID、Currency、Price の値をマッピングする必要があります。同じ長さの配列属性をマッピングすると、複数のイベントを送信できます。単一値の属性も使用でき、その場合は各イベントに適用されます。

次のコードサンプルは、複数の商品購入を含む単一イベントを受信するための Braze のベストプラクティス例を示しています。

```json
// event to Tealium:
{
  [...]
  "tealium_event": "purchase",
  "product_name": ["Backpack", "Pencil", "Notebook"],
  "product_quantity": [1, 5, 3],
  "product_category": ["Travel", "Office", "Office"],
  "product_price": [39.95, 1.99, 3.99],
  "order_currency": "USD"
}
```

対応する商品配列属性を Braze のパラメータにマッピングします。

* `product_name` &gt; Product ID
* `product_quantity` &gt; Quantity
* `product_price` &gt; Price

この例では、各商品を適切に表す次の purchases オブジェクトが Braze に送信されます。

```json
// payload to Braze through Tealium Connector:
{
  "purchases": [
    {
      "external_id" : "user1",
      "app_id" : "11ae5b4b-2445-4440-a04f-bf537764c9ad",
      "product_id" : "Backpack",
      "currency" : "USD",
      "price" : 39.95,
      "time" : "2013-07-16T19:20:30+01:00",
    },
    {
      "external_id" : "user1",
      "app_id" : "11ae5b4b-2445-4440-a04f-bf537764c9ad",
      "product_id" : "Pencil",
      "currency" : "USD",
      "price" : 1.99,
      "time" : "2013-07-16T19:20:30+01:00",
    },
    {
      "external_id" : "user1",
      "app_id" : "11ae5b4b-2445-4440-a04f-bf537764c9ad",
      "product_id" : "Backpack",
      "currency" : "USD",
      "price" : 3.99,
      "time" : "2013-07-16T19:20:30+01:00",
    }
  ]
}
```

| **パラメータ**| **説明**|
|:-------------|:-----------------|
| App ID | イベントのアプリケーション ID。|
| Product ID | 商品 ID の配列。<br> 購入イベントでは必須です。|
| Currency | 購入に使用された通貨の ISO 4217 アルファベットコード。<br> 購入イベントでは必須です。|
| Price | 商品価格の配列。<br> 購入イベントでは必須です。|
| Quantity | 商品数量の配列。|
| Purchase Time | ISO 8601 形式の購入時刻。明示的にマッピングされていない場合は、自動的に `now` に構成されます。|
| Update Existing Only (Purchases) | （任意）値は `true` または `false` です。デフォルトでは、購入値が存在しない場合は新しく作成されます。`true` に構成すると、既存の購入のみが更新され、新しい購入は作成されません。 |

#### 購入テンプレート変数

テンプレート変数をデータ入力として指定します。詳細については、[connector-template-variables](https://docs.tealium.com/connector-template-variables/)を参照してください。

ネストされたテンプレート変数には、ドット表記で名前を付けます（例：`items.name`）。

通常、ネストされたテンプレート変数は、データレイヤーのリスト属性から構築されます。

#### 購入テンプレート

ネストされたオブジェクトを送信するためのテンプレートを定義します。

テンプレートが定義されている場合、**Purchases** セクションのマッピングは無視されます。

Body Data で参照するテンプレートを指定します。詳細については、[about-connector-templates](https://docs.tealium.com/about-connector-templates/)を参照してください。

テンプレートは、サポートされているフィールドに二重波括弧で囲んだ名前を使用して挿入します。例：`{{SomeTemplateName}}`。

#### バッチの有効期間

| **パラメータ** | **説明** |
|:--------------|:----------------|
| Batch Time To Live | （任意）バッチの有効期間（分）。1～60 の値を入力します。デフォルト値は 10 分です。間隔を短くするとデータがより早く送信されますが、API リクエストの頻度が増加する可能性があります。 |

### ユーザーの削除（非バッチ）

各アクションでは、External ID、Braze ID、User Alias のいずれか 1 つのみが必要ですが、できる限り多くの属性をマッピングすることをお勧めします。複数の ID がマッピングされている場合、次の優先順位に基づいて、最初の空白でない値が選択されます。

* External ID
* Braze ID
* Alias Name
* Alias Label

詳細については、[Braze API：ユーザー削除エンドポイント](https://www.braze.com/docs/api/endpoints/user_data/post_user_delete/)を参照してください。

#### パラメータ

| **パラメータ**    | **説明**|
|:-----------------|:---------------|
| External ID      | 削除するユーザーの External ID。|
| Braze ID         | 削除するユーザーの Braze ID。|
| User Alias Name  | 削除するユーザーのエイリアス名。ユーザーエイリアスを指定する場合は、Alias Name と Alias Label の両方を構成する必要があります。 |
| User Alias Label | 削除するユーザーのエイリアスラベル。ユーザーエイリアスを指定する場合は、Alias Name と Alias Label の両方を構成する必要があります。 |
| Customer Email Address | ユーザーのメールアドレス。 |
| Customer Phone Number | E.164 形式のユーザーの電話番号。 |
| Deletion Prioritization | 削除するユーザーを識別するパラメータとして **Customer Email Address** を使用する場合は必須です。削除リクエストの優先順位を指定する配列です。指定できる値は、`most_recently_updated` と、`identified`（External ID を持つユーザー）または `unidentified`（External ID を持たないユーザー）のいずれかです。 |

### ユーザーのサブスクリプショングループステータスの更新（非バッチ）

詳細については、[Braze API：サブスクリプショングループエンドポイント](https://www.braze.com/docs/api/endpoints/subscription_groups/)を参照してください。

#### パラメータ

| **パラメータ**| **説明**|
|:-------------|:---------------|
| Group Type | （必須）管理するサブスクリプショングループのタイプ（`SMS` または `EMAIL`）。|
| Update Type | （必須）構成するサブスクリプション状態（`SUBSCRIBE` または `UNSUBSCRIBE`）。|
| Subscription Group ID  | （必須）サブスクリプショングループの ID。|
| External ID | ユーザーの External ID。複数のユーザーも指定できます。|
| Email | （EMAIL サブスクリプショングループで使用）<br> ユーザーのメールアドレス。<br> `EMAIL` グループで External ID が構成されていない場合、Email は必須です。|
| Phone | （SMS サブスクリプショングループで使用）<br> E.164 形式の電話番号。<br> 例：`+1415555371`<br> `SMS` グループで External ID が構成されていない場合、Phone は必須です。 |

### 複数のサブスクリプショングループにわたるユーザーのサブスクリプショングループステータスの更新（非バッチ）

#### パラメータ

| **パラメータ** | **説明** |
|:--------------|:----------------|
| Group Type | （必須）管理するサブスクリプショングループのタイプ（`SMS`、`EMAIL`、または `SMS` と `EMAIL` の両方）。|
| Update Type | （必須）構成するサブスクリプション状態（`SUBSCRIBE` または `UNSUBSCRIBE`）。 |
| Subscription Group ID  | （必須）サブスクリプショングループの ID。ユーザーのステータスを複数のサブスクリプショングループで同時に更新するには、配列型属性をマッピングします。|
| External ID | ユーザーの External ID。<br> Email が構成されていない場合、External ID は必須です。|
| Email | （EMAIL サブスクリプショングループで使用）<br> ユーザーのメールアドレス。<br> `EMAIL` グループで External ID が構成されていない場合、Email は必須です。|
| Phone | （SMS サブスクリプショングループで使用）<br> E.164 形式の電話番号。<br> 例：`+1415555371`<br> `SMS` グループで External ID が構成されていない場合、Phone は必須です。 |
### キャンペーンメッセージの送信

#### バッチ制限

このアクションでは、ベンダーへの大量データ転送をサポートするためにバッチリクエストを使用します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまでキューに格納されます。

* リクエストの最大数：50
* 最も古いリクエストからの最大経過時間：10分
* リクエストの最大サイズ：1 MB

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| キャンペーンID | （必須）キャンペーンID。 |
| 送信ID | 特定のメッセージ送信用にBrazeによって生成されるか、ユーザーが作成するキー。分析はこのキーに基づいて追跡されます。 |
| エイリアス名 | エイリアスの値。 |
| エイリアスラベル | エイリアスのキー。 |

## よくある質問

### このコネクタは他のBrazeインテグレーションとどのように連携しますか？

Track User APIに加えて、Brazeには追加のデータ収集方法があり、いずれもBrazeでのユーザー属性のマッピングをサポートしています。Tealiumは、Webおよびネイティブモバイル向けのBraze SDKを、次の2つの独立した類似のインテグレーションでサポートしています。

* [Braze Web SDKタグの構成](https://docs.tealium.com/braze-web-sdk-tag/)、[Braze SDKの初期構成](https://www.braze.com/docs/developer_guide/platform_integration_guides/web/initial_sdk_setup/)
* AndroidおよびiOS/Swift向けTealium Remote Command for Braze（[詳細](https://docs.tealium.com/platforms/remote-commands/integrations/braze/)）

これらのインテグレーションは、コネクタのイベントアクションおよび購入アクションで収集されるデータと同様のユーザー行動データをBrazeが収集するための代替手段です。
