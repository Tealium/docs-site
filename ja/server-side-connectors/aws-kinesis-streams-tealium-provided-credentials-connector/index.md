## Tealium ロールを AWS アカウントに追加する

コネクタを構成する前に、Tealium アカウント ID 用のロールを作成し、信頼されたエンティティとして構成する必要があります。

1. **Identity and Access Management**（IAM）コンソールで、**Details**タブにある Kinesis ストリームの Amazon Resource Name（ARN）を確認します。
1. **Policies > Create Policy**に移動します。ポリシーを初めて作成する場合は、**Get Started**、**Create Policy**の順にクリックします。
1. Kinesis Stream の ARN を入力します。
1. **{} JSON**をクリックします。
1. 次のポリシーを入力し、`arn:aws:kinesis:us-east-1:123456789:stream/example`を手順 1 で確認した ARN に置き換えます。

  ```
  {
    "Version": "2023-06-01",
    "Statement": [
      {
        "Effect": "Allow",
        "Action": [
          "kinesis:PutRecord",
          "kinesis:PutRecords"
                  ],
        "Resource": "arn:aws:kinesis:us-east-1:123456789:stream/example"
      }
    ]
  }
```

1. **Next Step**をクリックします。
1. **Policy Name**に「**TealiumKinesis**」と入力します。
1. **Create Policy**をクリックします。
1. **Roles > Create Role**に移動します。
1. **Trusted entity type**で、**AWS Account**を選択します。
1. **Another AWS account**を選択します。
1. **Account ID**に「`757913464184`」と入力します。
1. **Next: Permissions**をクリックします。
1. **TealiumKinesis**ポリシーを選択します。
1. **Next: Review**をクリックします。
1. Name に「**TealiumUser**」と入力します。
1. **Create Role**をクリックします。

Kinesis によって、次のようなロールの ARN が生成されます。

```
arn:aws:kinesis:us-east-1:123456789:role/example
```

詳細については、[IAM を使用した Amazon Kinesis Data Streams リソースへのアクセス制御](https://docs.aws.amazon.com/streams/latest/dev/controlling-access.html)および [IAM ポリシーとユーザーの作成](https://docs.aws.amazon.com/streams/latest/dev/tutorial-stock-data-kplkcl-iam.html)を参照してください。

## 構成の構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **リージョン**  
（必須）リージョンを選択します。
* **引き受けるロール：ARN**  
（任意）引き受けるロールの Amazon Resource Name（ARN）を指定します。例：`arn:aws:iam::222222222222:role/myrole`。[IAM ロールへの切り替え](http://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_use_switch-role-api.html)を参照してください。
* **引き受けるロール：セッション名**  
（必須）引き受けるロールセッションの識別子を指定します。長さの制約：最小 2 文字、最大 64 文字。
* **引き受けるロール：外部 ID**  
（任意）外部識別子を指定します。[外部 ID の使用方法](http://docs.aws.amazon.com/IAM/latest/UserGuide/id_roles_create_for-user_externalid.html)を参照してください。

コネクタを構成したら、**Test Connection**をクリックして、コネクタが Amazon に接続できることを確認します。

## アクション

アクションの名前を入力し、ドロップダウンメニューからアクションタイプを選択します。

次のセクションでは、各アクションのパラメータとオプションを構成する方法について説明します。

### アクション構成 - イベントデータを Kinesis Stream に送信

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ストリーム名 | データの送信先となるストリームを選択します。IAM ポリシーで `kinesis:ListStreams` 権限が付与されていない場合は、カスタム値を手動で入力します。 |
| パーティションキー | （必須）パーティションキーは、ストリーム内のデータをシャードにグループ化します。 |
| 順序付け用シーケンス番号 | Kinesis データストリームのシャード内におけるデータレコードのシーケンス番号です。 |
| 明示的ハッシュキー | パーティションキーのハッシュ化に使用するキーです。 |
| 属性名を出力 | 属性名が更新された場合、ペイロード内の名前に更新内容が反映されます。 |

### アクション構成 - 訪問データを Kinesis Stream に送信

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ストリーム名 | データの送信先となるストリームを選択します。IAM ポリシーで `kinesis:ListStreams` 権限が付与されていない場合は、カスタム値を手動で入力します。 |
| パーティションキー | （必須）パーティションキーは、ストリーム内のデータをシャードにグループ化します。 |

| 明示的ハッシュキー | パーティションキーのハッシュ化に使用するキーです。 |
| 現在の訪問データを訪問データに含める | 現在の訪問データをペイロードに追加します。「現在の訪問のイベントデータを除外」が選択されていない場合、イベントの訪問データも含まれます。 |
| 現在の訪問のイベントデータを除外 | 現在の訪問データからイベントデータを除外します。 |
| 属性名を出力 | 属性名が更新された場合、ペイロード内の名前に更新内容が反映されます。 |

### アクション構成 - バッチ処理されたイベントデータを Kinesis Stream に送信

#### バッチ制限

このアクションでは、ベンダーへの大量データ転送に対応するため、バッチリクエストを使用します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまで、リクエストはキューに保持されます。

* リクエストの最大数：500
* 最も古いリクエストからの最大経過時間：10 分
* リクエストの最大サイズ：5 MB

| --- | --- |
| ストリーム名 | データの送信先となるストリームを選択します。IAM ポリシーで `kinesis:ListStreams` 権限が付与されていない場合は、カスタム値を手動で入力します。 |

| 明示的ハッシュキー | パーティションキーのハッシュ化に使用するキーです。 |
