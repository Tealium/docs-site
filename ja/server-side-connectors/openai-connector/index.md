## 仕組み

このコネクタは、カスタムプロンプトとマッピングされた Tealium データを使用して OpenAI モデルを呼び出し、その応答を JSON イベントとして Tealium Collect に送信してリアルタイムエンリッチメントを行います。


<blockquote>
OpenAI コネクタは、大量のイベントではなく、対象を絞った価値の高いインタラクションに使用してください。過度に使用すると、OpenAI アカウントでレート制限が適用されたり、API コストが増加したりする可能性があり、Tealium の受信イベント量も増加します。
</blockquote>


## 使用量とコストに関する考慮事項

OpenAI コネクタを有効化する前に、OpenAI アカウントの制限、使用量階層、料金モデルを確認してください。イベントやオーディエンスのトリガーによっては、コネクタから大量のリクエストが生成され、予期しない使用量や超過料金が発生する可能性があります。

詳細については、[OpenAI Developers：レート制限](https://developers.openai.com/api/docs/guides/rate-limits)を参照してください。

**主な考慮事項**

* **使用量階層とレート制限**  
  OpenAI では、アカウント階層に基づき、1 分あたりのリクエスト数とトークン数で測定されるレート制限が適用されます。高頻度のイベントや大規模なオーディエンスでは、これらの制限にすぐに達し、スロットリングやリクエストの失敗が発生する可能性があります。
* **料金とトークン消費量**  
  OpenAI の料金は、モデルが処理する入力トークンと出力トークンの数に基づいて計算されます。プロンプトが長いほど、ペイロードが大きいほど、また高性能なモデルを使用するほど、リクエストあたりのコストが増加します。使用予定の各モデルの料金を確認してください。
* **月間支出と予算管理**  
  予定外の支出を防ぐため、OpenAI アカウントで使用量の上限またはアラートを構成してください。制限を構成しない場合、自動化されたワークフローによって多額のコストが発生する可能性があります。
* **トリガー量**  
  ページビューなど、量が多く価値の低いイベントにはコネクタを関連付けないでください。意味のある顧客行動を表し、管理可能な頻度で発生するイベントまたはオーディエンスを使用してください。

## ベストプラクティス

このコネクタを最大限に活用するには、効果的なソリューションを構築するための次のガイドラインに従ってください。

* **価値の高いトリガー**：豊富なコンテキストや意味のある顧客入力を含むイベントフィードまたはオーディエンストリガーを選択します。大量に発生するユースケースでこのコネクタをトリガーすると、OpenAI アカウントで追加コストが発生したり、リクエストが失敗したりする可能性があります。
* **具体的に記述する**：モデルが何を評価し、各出力フィールドをどのように決定するかについて、詳細を記述します。
* **プロンプトパラメータ**：**プロンプトパラメータ**セクションで Tealium 属性をプレースホルダー名にマッピングし、二重中括弧を使用してプロンプト内で参照します。たとえば、属性をプレースホルダー `product_id` にマッピングした場合、プロンプトには `{{product_id}}` と記述します。

## API 情報

このコネクタは、次のベンダー API を使用します。

* API 名：OpenAI API
* API バージョン：v1
* API エンドポイント：`https://api.openai.com/v1`
* ドキュメント：[OpenAI API](https://platform.openai.com/docs/api-reference)

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。
* **API キー**：リクエストの認証に使用する OpenAI API キーです。このキーには、**All** または **Restricted** のいずれかの権限で応答（モデル推論）を作成する権限が必要です。**Read Only** 権限は使用できません。詳細については、[OpenAI：API キー権限の割り当て](https://help.openai.com/en/articles/8867743-assign-api-key-permissions)を参照してください。

コネクタを構成した後、**完了**をクリックします。

| アクション名 | 訪問プロファイル | イベントデータ |
| --- | :---: | :---: |
| OpenAI にプロンプトを送信 | ✓ | ✓ |
| OpenAI にプロンプトを送信（非推奨） | ✓ | ✓ |

### OpenAI にプロンプトを送信

このアクションは、カスタムプロンプトとマッピングされた Tealium データを OpenAI モデルに送信します。コネクタは、構造化された JSON 出力を Tealium Collect に送信してリアルタイムエンリッチメントを行います。

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| モデル | このプロンプトで使用する OpenAI モデル（**gpt-4.1-mini** や **gpt-4.1** など）を選択します。<br>パフォーマンスとコストの要件を満たし、構造化出力（JSON）に最適化されたモデルを使用することを推奨します。 |

#### Tealium コンテキスト

コネクタは、AI モデルに送信するプロンプトと構造化出力スキーマに、Tealium 識別子（`tealium_account`、`tealium_profile`、`tealium_visitor_id`）を自動的に含めます。これらの値は現在のイベントから取得されます。プロンプト内で参照する必要はありません。

このマッピングセクションを使用して、必須の `tealium_event` 値を構成し、必要に応じてデフォルトの識別情報を上書きします。

| ベンダーパラメータ | 説明 |
| --- | --- |
| Tealium イベント | （必須）Tealium に返される AI 応答に含める `tealium_event` 値です。コネクタは、AI の結果を Tealium に転送するときに、このイベント名を使用します。 |
| Tealium データソース | このコネクタに関連付けられたデータソースキーです。 |
| Tealium アカウント | アカウント値を上書きします。デフォルトでは、現在のイベント値が使用されます。 |
| Tealium プロファイル | プロファイル値を上書きします。デフォルトでは、現在のイベント値が使用されます。 |
| Tealium 訪問 ID | 訪問 ID を上書きします。デフォルトでは、現在のイベント値が使用されます。 |

#### プロンプトパラメータ

このマッピングセクションを使用して、Tealium 属性値をプロンプトに渡します。左側の列にある Tealium 属性を、右側の列にあるプレースホルダー名にマッピングします。二重中括弧を使用して、**プロンプト**フィールド内でプレースホルダー名を参照します。

たとえば、属性 `product_review_text` をプレースホルダー名 `review_text` にマッピングした場合、実行時に属性値を挿入するには、プロンプトに `{{review_text}}` と記述します。

#### イベントペイロード

**イベントペイロードを追加**を有効にすると、完全なイベントペイロードが `{{event_payload}}` としてプロンプトテンプレートに含まれます。

#### プロンプト

選択したモデルに送信するプロンプトを入力します。

* `{{review_text}}`、`{{product_name}}` など、マッピングされたプレースホルダー名を二重中括弧で参照します。
* **イベントペイロードを追加**を有効にした後、`{{event_payload}}` を参照します。
* モデルが各出力フィールドをどのように決定し、構成するかを記述します。
* JSON 形式に関する指示（たとえば、「JSON のみを返す」）は含めないでください。コネクタは、**構造化出力**のマッピングによって JSON 構造を自動的に適用します。

#### モデルの詳細構成

| パラメータ | 説明 |
| --- | --- |
| temperature | ランダム性と創造性を制御します。 |
| max_output_tokens | モデルが生成できるトークンの最大数です。 |
| max_tool_calls | 1 回の応答で処理される組み込みツール呼び出しの最大数です。 |
| top_p | 上位 p の確率質量からのみサンプリングすることで、多様性を制御します。 |
| parallel_tool_calls | モデルによるツール呼び出しの並列実行を許可するかどうかを指定します。デフォルトは `true` です。 |
| prompt_cache_key | キャッシュ率を最適化するため、類似するリクエストの応答を OpenAI がキャッシュする際に使用されます。 |
| service_tier | リクエストの処理に使用する処理タイプを指定します。 |
| tool_choice | 応答を生成するときに、モデルが使用するツールをどのように選択するかを制御します。 |
#### 構造化出力（JSONスキーマ）

このセクションでは、AIモデルがレスポンスで返すフィールドを定義します。他のマッピングセクションとは異なり、**構造化出力**ではTealium属性をマッピングしません。代わりに、出力フィールド名、データ型、および必須かどうかを定義します。

コネクタは、これらの定義を`text.format`を使用したJSONスキーマとしてOpenAIに送信します。これにより、モデルは自由形式のテキストではなく、スキーマに一致する構造化JSONを返す必要があります。その後、コネクタはレスポンスを解析し、イベントとしてTealium Collectに転送します。少なくとも1つのフィールドを定義する必要があります。

スキーマには、Tealiumコンテキストフィールドである`tealium_account`、`tealium_profile`、`tealium_visitor_id`、`tealium_event`が自動的に含まれます。

各行では、次の3つの入力を使用して1つの出力フィールドを定義します。

| 入力 | 説明 |
| --- | --- |
| 必須／任意 | モデルにこのフィールドを必ず返させるには、**必須**を選択します。フィールドをスキーマに含めるものの、必須にはしない場合は、**任意**を選択します。デフォルトは必須です。 |
| データ型 | 出力フィールドのデータ型：`string`、`integer`、`number`、または`boolean`。デフォルトは`string`です。データ型は、値に使用する形式をモデルに指示します。型が一致しない場合、検証に失敗する可能性があります。 |
| 属性名 | 出力フィールドの名前。この名前はJSONレスポンス内のキーとして表示されます。エンリッチメント用の値を取得するには、一致するイベント属性を作成します。 |

#### デバッグモード

OpenAIの未加工レスポンスをTealium Collectに転送せずに受け入れるには、**デバッグモードを有効化**を選択します。完全な処理を有効にする前に、Traceを使用してレスポンス形式を検証してください。

#### 例：レビューのセンチメントを分類する

この例では、顧客による製品レビューのセンチメントを分類するように構成されたアクションを示します。

**トリガー**：`product_review_submitted`イベントが発生すると、イベントフィードが起動します。

**Tealiumコンテキスト**：

| イベント属性 | ベンダーパラメータ |
| --- | --- |
| `ai_response` | Tealiumイベント |

**プロンプトパラメータ**：

| Tealium属性 | プレースホルダー名 |
| --- | --- |
| `product_review_text` | `review_text` |
| `product_name` | `product_name` |

**イベントペイロード**：無効。

**プロンプト**：

```wrap
A customer submitted a review for {{product_name}}:

{{review_text}}

Classify the customer's sentiment as one of: "dissatisfied", "neutral", or "satisfied". Provide a confidence score between 0 and 1.
```

**構造化出力（JSONスキーマ）**：

| 必須／任意 | データ型 | 属性名 |
| --- | --- | --- |
| 必須 | string | `ai_review_sentiment` |
| 必須 | number | `ai_confidence_score` |

**結果**：コネクタは、`tealium_event: "ai_response"`、`ai_review_sentiment`、および`ai_confidence_score`を含むJSONイベントをTealium Collectに返します。エンリッチメント用にこれらの値を取得するには、一致するイベント属性を作成します。

### OpenAIにプロンプトを送信（非推奨）

このアクションは、カスタムプロンプトおよびマッピングされたTealiumデータを使用してOpenAIモデルを呼び出します。モデルが有効なJSONイベントオブジェクトを返した場合、このイベントはアカウントに送り返され、生成された値をリアルタイムエンリッチメントで取得できます。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| モデル | このプロンプトに使用するOpenAIモデル（例：**gpt-4.1-mini**または**gpt-4.1**）を選択します。<br>パフォーマンスとコストの要件に対応し、構造化出力（JSON）向けに最適化されたモデルを使用することをお勧めします。詳細については、[OpenAI Developers：本番環境のベストプラクティス](https://developers.openai.com/api/docs/guides/production-best-practices)を参照してください。 |
| イベントペイロードを追加 | （イベントアクションで使用可能）プロンプトテンプレート内で変数`{{event_payload}}`として使用するイベントペイロードを含めるには、このチェックボックスをオンにします。 |
| 訪問プロファイルを追加 | （オーディエンスアクションで使用可能）プロンプトテンプレート内で変数`{{visitor_profile}}`として使用する訪問プロファイルを含めるには、このチェックボックスをオンにします。 |
| 現在の訪問を追加 | （オーディエンスアクションで使用可能）現在の訪問を変数`{{visitor_profile}}`内に含めるには、このチェックボックスをオンにします。 |
| プロンプト | 選択したOpenAIモデルに送信するプロンプトを入力します。一貫性があり、機械可読な出力を得るために、次のガイドラインに従ってください。<br><br>マッピングされたパラメータを参照するには、**二重波括弧**（`{{ }}`）を使用します。例：`{{tealium_account}}`、`{{tealium_visitor_id}}`、`{{visitor_profile}}`。<br><br>最初に**イベントペイロードを追加**チェックボックスを有効にしてから、`{{event_payload}}`を使用してプロンプトにイベントペイロードを含めます。<br><br>曖昧な表現を避けてください。出力を確実に解析できるよう、プロンプトは決定論的なものにする必要があります。<br><br>レスポンスとして返す有効なTealiumイベントJSONオブジェクトを定義します。コネクタがイベントをTealium Collectエンドポイントに転送できるよう、このイベントJSONに`tealium_account`、`tealium_profile`、`tealium_visitor_id`、および出力変数を含めることをモデルに明示的に指示します。<br><br>コネクタは、モデルにJSONを返すよう強制する指示をプロンプトに自動的に追加します。<br><br>プロンプトの例については、[仕組み](#how-it-works)を参照してください。|

#### モデルの詳細構成

| **パラメータ** | **説明** |
| --- | --- |
| `temperature` | ランダム性と創造性を制御します。 |
| `max_output_tokens` | モデルが生成できるトークンの最大数。 |
| `max_tool_calls` | 1つのレスポンスで処理できる組み込みツールの合計呼び出し回数の上限。 |
| `top_p` | 確率質量の上位pのみからサンプリングすることで、多様性を制御します。 |
| `parallel_tool_calls` | モデルがツール呼び出しを並列実行できるかどうかを指定します。デフォルトは`true`です。 |
| `prompt_cache_key` | 類似したリクエストに対するレスポンスをOpenAIがキャッシュし、キャッシュヒット率を最適化するために使用されます。 |
| `service_tier` | リクエストの処理に使用する処理タイプを指定します。 |
| `tool_choice` | レスポンスを生成するときに、使用するツールをモデルが選択する方法を指定します。 |
| デバッグモード | デバッグモードが有効な場合、コネクタはOpenAIの未加工レスポンスをTealium Collectに送信せずに受け入れます。完全な処理を有効にする前に、Traceを使用してレスポンス形式を検証してください。 |
