## API 情報

このコネクタでは、次のベンダー API を使用します。

* API 名：X Ads API
* API バージョン：v12
* API エンドポイント：`https://ads-api.x.com/`
* ドキュメント：[X Custom Audiences API](https://developer.x.com/en/docs/x-ads-api/audiences/api-reference)

## バッチ制限

このコネクタでは、ベンダーへの大量のデータ転送に対応するため、リクエストをバッチ処理します。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまで、リクエストはキューに格納されます。

* リクエストの最大数：1000
* 最も古いリクエストからの最大経過時間：60 分
* リクエストの最大サイズ：2 MB

## 前提条件

1. [開発者アカウント](https://developer.x.com/en/apply-for-access)に登録します。`Essential` と `Elevateddeveloper` のどちらのアクセス権でも Ads API にアクセスできます。必要なアクセス権を判断するには、[アクセスレベル](https://developer.x.com/en/docs/x-api/getting-started/about-x-api#v2-access-level)を参照してください。
1. [開発者アプリ](https://developer.x.com/en/apps)を作成し、トークンを安全に保管します。
1. [Ads API へのアクセス](https://developer.x.com/en/docs/x-ads-api/apply)をリクエストします。申請には正しい App ID を必ず記載してください。App ID は、[Developer Portal](https://developer.x.com/en/portal/dashboard)の **Projects &amp; Apps** で確認できます。例：`16489123`

If you are already building on the X Developer Platform and have a developer account, skip to step 3.
</blockquote>


## 仕組み

X カスタムオーディエンスを使用すると、X 広告を表示する対象を制御できます。X 広告では、顧客にとって最も重要な事柄にメッセージをリアルタイムで結び付けるための強力なコンテキストが提供されます。リアルタイムのポストにエンゲージすることで、ビジネスの成長に役立つ形で会話に影響を与えることができます。

オーディエンスは、[X Ads](http://ads.x.com) アカウントでオーディエンスを確認および管理できるツールです。**Tools > Audiences** に移動してアクセスできます。

そこから、キャンペーンのターゲティングでカスタムオーディエンスを使用し、重要なユーザーに直接リーチできます。Tealium では、Customer Data Platform（CDP）のユーザーインターフェイスから X カスタムオーディエンスを作成し、オーディエンスデータを利用してオーディエンスリストにデータを追加できます。また、X Ads アカウントでオーディエンスリストを作成して CDP に取り込み、ユーザーを追加または削除することもできます。リターゲティングできるオーディエンスの例には、以前の顧客、まだコンバージョンに至っていない Web サイト訪問、高価値顧客などがあります。

Tealium は、カスタムオーディエンスリストへのユーザーの追加または削除のために X に送信できるハッシュ化された識別子のリストを提供します。X は照合を実行し、X でのメディア購入に利用できるセグメントを生成します。リストは X の @ハンドルと照合されるため、キャンペーンでユーザーを直接ターゲティングでき、関連性の高いマーケティングが可能になります。

## 考慮事項

* 「Partner User ID」以外のすべてのユーザー識別子は、SHA256 ハッシュ方式を使用してハッシュ化し、[正規化](https://developer.x.com/en/docs/ads/audiences/overview/user-data#data-normalization)する必要があります。
* 「User Identifier is already hashed」チェックボックスがオフの場合、コネクタアクションはマッピングされた値を正規化してハッシュ化します。
* カスタムオーディエンスを作成すると、最初に処理期間があり、その間にカスタムオーディエンス内のユーザーが X のシステムによって X の @ハンドルと「照合」されます。これにより、そのアカウントにプロモ広告を配信できるようになります。
  * カスタムオーディエンス内のすべてのユーザーが X のアクティブユーザーとは限らないため、最終的なカスタムオーディエンスのサイズがコネクタアクションの実行件数よりも小さくなることがあります。
  * すべてのカスタムオーディエンスが CDP に表示されますが、キャンペーンでユーザーを適切にターゲティングできるのは、配信ステータスが `Ready` のオーディエンスのみです。このステータスは、**X Ads account &gt; Audiences** セクションで確認できます。

* オーディエンスをターゲティングできるのは、X が所有および運営するクライアントで過去 90 日以内にアクティブだったユーザーが 100 人以上一致する場合のみです。
* 通常、オーディエンスへの変更は 6～8 時間ごとに実行されるバッチで処理されます。オーディエンスへの変更を処理している間も、更新対象の既存オーディエンスには影響しません。
* CDP から作成されたオーディエンスリストは、Ads Campaign Manager 内に「List」タイプとして追加されます。
* X のデータを使用して、X ユーザーの潜在的に機密性の高い特性を導出または推測しないことを推奨します。これらの特性の一覧については、[X API の制限対象となる使用方法の詳細](https://developer.x.com/en/developer-terms/more-on-restricted-use-cases)を参照してください。

## 構成の構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **Ad Account ID**
  * （必須）X Ad Account ID を指定します。
  * Account ID は、ログイン時のアカウント URL で確認できます。
  * 例：URL が `https://ads.x.com/accounts/1234abcd/` の場合、アカウント ID は `1234abcd` です。

## カスタムオーディエンス作成の概要

X カスタムオーディエンスコネクタの **Configuration** 画面内に、Create Custom Audience オーバーレイが表示されます。オーディエンスリストの作成時に必須となる値は、**Name** フィールドのみです。

以前は、`list_type` パラメータを使用してオーディエンスのユーザー識別子タイプ（メールアドレス、X User ID、Partner User ID など）を指定していました。しかし現在は、同じオーディエンスに対して複数のユーザー識別子を使用できるため、このフィールドは不要になりました。

## アクション

| アクション名 | 訪問プロファイル | イベントデータ |
| --- | :---: | :---: |
| カスタムオーディエンスにユーザーを追加 | ✓ | ✓ |
| カスタムオーディエンスにユーザーを追加（複数の識別子） | ✓ | ✓ |
| カスタムオーディエンスからユーザーを削除 | ✓ | ✓ |
| カスタムオーディエンスからユーザーを削除（複数の識別子） | ✓ | ✓ |
| Do Not Reach リストにユーザーを追加 | ✓ | ✓ |
| Do Not Reach リストからユーザーを削除 | ✓ | ✓ |

アクションの名前を入力し、ドロップダウンメニューからアクションタイプを選択します。

次のセクションでは、各アクションのパラメータとオプションを構成する方法について説明します。

### アクション — カスタムオーディエンスにユーザーを追加
#### ユーザー識別子

次のパラメーターのうち、少なくとも1つを指定する必要があります。

| **パラメーター** | **型** | **説明** |
| --- | --- | --- |
| メールアドレス | 文字列 | 前後の空白が削除され、小文字に変換され、SHA256でハッシュ化済みのプレーンテキストのメールアドレスを指定します。ハッシュ化されていないメールアドレスをマッピングする場合は、［ユーザー識別子のハッシュ化］チェックボックスをオンにします。 |
| 電話番号 | 文字列 | 前後の空白が削除され、小文字に変換され、SHA256でハッシュ化済みのプレーンテキストの電話番号を指定します。ハッシュ化されていない電話番号をマッピングする場合は、［ユーザー識別子のハッシュ化］チェックボックスをオンにします。 |
| デバイスID | 文字列 | 前後の空白が削除され、小文字に変換され、SHA256でハッシュ化済みのデバイスIDを指定します。この値には、[iOS広告識別子](https://developer.apple.com/Library/ios/documentation/AdSupport/Reference/ASIdentifierManager_Ref/ASIdentifierManager.html)、[Google広告ID](https://developer.android.com/google/play-services/id.html)、またはこれらを利用できない場合は[Android ID](https://developer.android.com/google/play-services/id.html)を使用する必要があります。ハッシュ化されていないデバイスIDをマッピングする場合は、［ユーザー識別子のハッシュ化］チェックボックスをオンにしてください。 |
| Twitterハンドル | 文字列 | 前後の空白が削除され、小文字に変換され、SHA256でハッシュ化済みのXハンドルを指定します。ハッシュ化されていないXハンドルをマッピングする場合は、［ユーザー識別子のハッシュ化］チェックボックスをオンにします。 |
| Twitter ID | 文字列 | 前後の空白が削除され、小文字に変換され、SHA256でハッシュ化済みのX IDを指定します。X IDは、Xの各アカウントに割り当てられる一意の値です。同じIDを持つユーザーは存在しません。アカウントは@ハンドルを変更できますが、X IDを変更することはできません。ハッシュ化されていないX IDをマッピングする場合は、［ユーザー識別子のハッシュ化］チェックボックスをオンにします。 |
| パートナーユーザーID | 文字列 | パートナーユーザーIDを指定します。ハッシュ化されていないパートナーユーザーIDをマッピングする場合は、［ユーザー識別子のハッシュ化］チェックボックスをオンにします。 |
| ユーザー識別子のハッシュ化 | ブール値 | ユーザー識別子がすでにハッシュ化されている場合は、このチェックボックスをオンにします。それ以外の場合、コネクターはマッピングされた値を[正規化](https://developer.x.com/en/docs/ads/audiences/overview/user-data#data-normalization)してハッシュ化します。 |
