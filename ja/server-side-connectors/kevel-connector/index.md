Kevel（旧称Adzerk）は、リテールメディアおよび広告配信プラットフォームです。Kevelコネクタは、ファーストパーティデータを使用した広告ターゲティングのために、Tealiumの訪問データとイベントデータを次の2つのKevel製品へ送信します。

* **Kevel Ad Server UserDB：** Kevel Ad Serverが広告を選択する際のターゲティングに使用するユーザーデータベースです。このコネクタは、ユーザーレコードのカスタムプロパティ、関心、セグメントメンバーシップ、オプトアウトステータス、およびGDPR同意を構成し、リクエストに応じてユーザーレコードを削除します。
* **Kevel Audience：** Kevelのオーディエンス管理製品です。このコネクタは、Kevel Audienceセグメントにユーザーを追加したり、セグメントからユーザーを削除したりします。

このコネクタには、Ad Serverセグメントを作成、更新、削除するための管理タスクと、Kevel Audienceセグメントを作成するための管理タスクも含まれています。

## API情報

このコネクタは、次のベンダーAPIを使用します。

* Kevel Ad Serverのユーザーデータ
  * **API名**：Kevel UserDB API
  * **APIバージョン**：v1
  * **APIエンドポイント**：`https://e-{network_id}.adzerk.net/udb/{network_id}`
  * **ドキュメント**：[Kevel：UserDB](https://dev.kevel.com/reference/userdb)および[Kevel：ユーザーセグメント](https://dev.kevel.com/reference/segments)
* Kevel Ad Serverのセグメントと広告主
  * **API名**：Kevel Management API
  * **APIバージョン**：v1
  * **APIエンドポイント**：`https://api.kevel.co/v1`
  * **ドキュメント**：[Kevel：Management APIの概要](https://dev.kevel.com/reference/campaign-api-overview)
* Kevel Audienceのセグメントメンバーシップ
  * **API名**：Kevel Audience Segment Manager API
  * **APIバージョン**：1.0
  * **APIエンドポイント**：`https://segments.cdp.{your-company}.audience.kevel.com`（Kevel AudienceアカウントのSegment Manager URL）
  * **ドキュメント**：[Kevel Audience：Segment Manager](https://docs.audience.kevel.com/api/http/segment-manager)

## 構成

Connector Marketplaceに移動し、新しいコネクタを追加します。コネクタを追加する一般的な手順については、[コネクタについて](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加したら、次の構成を構成します。

* **Network ID**
  * （必須）KevelネットワークID。ネットワークIDは、Kevel UIのURL（`app.kevel.co/#!/{networkId}/`）に含まれる数字です。たとえば、URLが`https://app.kevel.co/#!/12345/`の場合、ネットワークIDは`12345`です。
  * `12345`のような整数を入力します。
* **Ad Server API Key**
  * （Ad Serverアクションでは必須）Kevel Ad Server APIキー。
  * APIキーを取得するには、Kevel UIを開いて**Settings**に移動し、APIキーを生成またはコピーします。
* **Kevel Audience API Token**
  * （Kevel Audienceアクションでは必須）Kevel Audience APIトークン。
* **Kevel Audience Segment Manager URL**
  * （Kevel Audienceアクションでは必須）アカウント用のKevel Audience Segment Manager APIのURL。形式は`https://segments.cdp.{your-company}.audience.kevel.com`です。
  * URLは`https://`で始まり、ホスト名が`.audience.kevel.com`で終わる必要があります。このコネクタは、その他のホスト名、443以外のポート、クエリ文字列、およびフラグメントを拒否します。
* **Kevel Audience Region**
  * （Kevel Audienceアクションでは必須）Kevel Audienceアカウントのリージョン：`us-east-1`、`us-west-2`、`eu-central-1`、`eu-west-1`、`ap-southeast-1`、`ap-southeast-2`、`ap-northeast-2`、または`ap-south-1`。

必要な構成は、使用するアクションと管理タスクによって異なります。

| Kevel製品 | アクションと管理タスク | 必須構成 |
| --- | --- | --- |
| Kevel Ad Server | すべてのAd Serverアクション、Ad Serverセグメントの管理タスク、およびセグメントと広告主のドロップダウンリスト | **Network ID**および**Ad Server API Key** |
| Kevel Audience | すべてのKevel Audienceアクション、Create Kevel Audience Segment管理タスク、およびKevel Audienceセグメントのドロップダウンリスト | **Network ID**、**Kevel Audience API Token**、**Kevel Audience Segment Manager URL**、および**Kevel Audience Region** |

Kevel AudienceアカウントのAPIトークン、Segment Manager URL、およびリージョンは、Kevelから提供されます。これらの値を取得するには、Kevelのアカウントチームにお問い合わせください。

### Native Segmentsデスティネーション

Kevel Audienceアクションは、ネットワークの**Kevel - Native Segments**デスティネーションに関連付けられたセグメントを使用します。Create Kevel Audience Segment管理タスクは、新しいセグメントをこのデスティネーションに自動的に関連付けます。**Kevel Audience Region**構成のリージョンにKevel - Native Segmentsデスティネーションがネットワーク内に存在しない場合、Kevelはエラーを返します。デスティネーションを構成するには、Kevelのアカウントチームにお問い合わせください。

### 接続をテストする

認証情報を確認するには、**Test Connection**をクリックします。このテストでは、認証情報を入力した各APIを確認します。

* **Ad Server APIキー：** Kevel Management APIからセグメントリストを読み取り、Kevel UserDBからテスト用ユーザーレコードを読み取ります。このテストでは、APIキーとネットワークIDを確認します。
* **Kevel Audience APIトークン：** ネットワークIDとリージョンに対応するKevel Audienceセグメントを一覧表示します。このテストには、Segment Manager URLとリージョンが必要です。

少なくとも1組の認証情報を入力してください。Ad Server APIキーもKevel Audienceのいずれのフィールドも入力していない場合、Kevel Audienceフィールドの一部のみを入力した場合、またはいずれかのチェックに失敗した場合、テストは失敗します。

コネクタを構成したら、**Done**をクリックします。

## セグメントの管理

このコネクタには、Kevelセグメントを管理するための次の管理タスクが含まれています。セグメントを作成した後、アクションのセグメントドロップダウンリストでそのセグメントを選択します。ドロップダウンリストには、新しいセグメントから順に表示されます。最大10,000件のAd Serverセグメントまたは広告主と、最大2,000件のKevel Audienceセグメントが読み込まれます。ネットワークにそれ以上の数が存在する場合は、セグメントIDまたは広告主IDを直接入力してください。

### Ad Serverセグメントを作成する

Kevel Ad Serverでセグメントを作成するには、**Create Ad Server Segment**をクリックし、次の値を入力します。このタスクには**Ad Server API Key**が必要です。

| **パラメータ** | **説明** |
| --- | --- |
| Segment Name | （必須）セグメントの名前。1～200文字で指定します。 |
| Segment Category | （任意）Kevel内のセグメントのカテゴリー。 |
| Segment Description | （任意）セグメントの説明。 |

Kevelでは、同じ名前を持つ複数のセグメントを作成できます。セグメントを作成する前に、同じ名前の既存セグメントがないか、セグメントのドロップダウンリストを確認してください。

### Ad Serverセグメントを更新する

Ad Serverセグメントの名前、カテゴリー、または説明を変更するには、**Update Ad Server Segment**をクリックし、次の値を入力します。このタスクには**Ad Server API Key**が必要です。

| **パラメータ** | **説明** |
| --- | --- |
| Segment | （必須）更新するセグメントを選択します。 |
| Segment Name | （必須）セグメントの新しい名前。1～200文字で指定します。 |
| Segment Category | （任意）セグメントの新しいカテゴリー。現在のカテゴリーを維持するには空欄のままにします。このタスクではカテゴリーを消去できません。 |
| Segment Description | （任意）セグメントの新しい説明。現在の説明を維持するには空欄のままにします。このタスクでは説明を消去できません。 |

### Ad Serverセグメントを削除する

KevelネットワークからAd Serverセグメントを削除するには、**Delete Ad Server Segment**をクリックし、セグメントを選択します。このタスクには**Ad Server API Key**が必要です。削除は元に戻せません。存在しないセグメントIDに対してもKevelは成功を返すため、成功メッセージだけでは、どのセグメントが削除されたかを確認できません。

| **パラメータ** | **説明** |
| --- | --- |
| Segment | （必須）削除するセグメントを選択します。 |


<blockquote>
Kevelは、存在しないセグメントIDをエラーを返さずに受け入れます。削除されたセグメントを引き続き参照しているアクションは成功しますが、効果はありません。セグメントを削除した後、そのセグメントを使用しているアクションを更新してください。
</blockquote>

### Kevel Audience セグメントを作成する

Kevel Audience でセグメントを作成するには、**Kevel Audience セグメントを作成**をクリックし、次の値を入力します。このタスクには、**ネットワーク ID**と Kevel Audience の構成が必要です。

| **パラメータ** | **説明** |
| --- | --- |
| セグメント名 | （必須）セグメントの名前。同じ名前のセグメントが存在する場合、Kevel はエラーを返します。 |
| セグメントカテゴリー | （任意）Kevel Audience 内のセグメントのカテゴリー。 |
| セグメントの説明 | （任意）セグメントの説明。 |
| 静的セグメント | （任意）セグメントを静的として指定するには、このチェックボックスを選択します。静的セグメントでは、メンバー構成が時間の経過にかかわらず安定しています。Kevel Forecast では静的セグメントのみを使用できます。 |

Kevel Audience は、**Kevel Audience リージョン**構成で指定されたリージョンにセグメントを作成し、ネットワークの **Kevel - Native Segments** 宛先に関連付けます。

## アクション

**続行**をクリックして、コネクタのアクションを構成します。アクションの名前を入力し、リストからアクションタイプを選択します。

| アクション名 | AudienceStream | EventStream |
| ----------- | :------------: | :---------: |
| ユーザーのカスタムプロパティを構成 | ✓ | ✓ |
| ユーザーのインタレストを追加 | ✓ | ✓ |
| ユーザーを広告サーバーセグメントに追加 | ✓ | ✓ |
| ユーザーを広告サーバーセグメントから削除 | ✓ | ✗ |
| ユーザーをリターゲティングセグメントに追加（レガシー） | ✓ | ✗ |
| ユーザーをオプトアウト | ✓ | ✗ |
| GDPR 同意を構成 | ✓ | ✗ |
| ユーザーを削除 | ✓ | ✗ |
| ユーザーを Kevel Audience セグメントに追加（バッチ処理） | ✓ | ✓ |
| ユーザーを Kevel Audience セグメントから削除（バッチ処理） | ✓ | ✗ |

表の最初の 9 つのアクションは、Kevel UserDB に書き込む広告サーバーアクションです。最後の 3 つは Kevel Audience アクションです。各グループに必要な構成については、[構成](#configuration)を参照してください。

広告サーバーアクションでは、最大 1,024 文字のユーザーキーによってユーザーを識別します。コネクタは、ユーザーキーの先頭と末尾にある空白を削除します。ユーザーキーは、サイトまたはアプリが Kevel の広告決定リクエストで送信するユーザーキーと一致する必要があります。一致しない場合、Kevel はユーザーに表示する広告を選択するときに、保存されたデータを使用できません。


<blockquote>
Kevel UserDB は、広告サーバーへの書き込みごとに同じ成功レスポンスを返します。そのため Tealium は、存在しないセグメント ID など、Kevel が受け入れても論理的には誤っている値を検出できません。既知のユーザーキーを使用して各アクションをテストし、Kevel で結果を確認してください。
</blockquote>


### ユーザーのカスタムプロパティを構成

Kevel UserDB のユーザーレコードにカスタムプロパティを構成します。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）Kevel UserDB 内のユーザーレコードのキー。最大 1,024 文字です。 |
| カスタムプロパティ | （必須）Tealium 属性をカスタムプロパティ名にマッピングします。少なくとも 1 つのプロパティをマッピングしてください。コネクタは、数値、ブール値、文字列を元のデータ型のまま送信します。1 回のリクエストに含まれるカスタムプロパティのサイズは、8 KB（8,192 バイト）を超えることはできません。 |


<blockquote>
各リクエストによって、ユーザーのすべてのカスタムプロパティが置き換えられます。Kevel は、新しいプロパティを保存済みのプロパティとマージしません。リクエストに含まれていない保存済みプロパティはすべて削除されます。これには、訪問またはイベントに対して属性の値がないマッピング済みプロパティも含まれます。マッピング済みプロパティのいずれにも値がない場合、コネクタはリクエストを送信せず、Kevel は保存済みプロパティを保持します。2 つのアクションが同じユーザーに異なるプロパティを構成すると、各アクションによってもう一方のアクションのプロパティが削除されます。保持するすべてのプロパティを 1 つのアクションでマッピングしてください。
</blockquote>


### ユーザーのインタレストを追加

Kevel UserDB のユーザーレコードに 1 つのインタレストを追加します。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）Kevel UserDB 内のユーザーレコードのキー。最大 1,024 文字です。 |
| インタレスト | （必須）ユーザーレコードに追加する 1 つのインタレスト（例：`sports`）。Kevel は送信された値をそのまま保存し、カンマでは分割しません。たとえば、Kevel は `news,tech` を `news,tech` という名前の 1 つのインタレストとして保存します。複数のインタレストを追加するには、インタレストごとに 1 つのアクションを構成します。 |

### ユーザーを広告サーバーセグメントに追加

ユーザーを 1 つ以上の広告サーバーセグメントに追加します。ユーザーの既存のセグメントメンバーシップは維持されます。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）Kevel UserDB 内のユーザーレコードのキー。最大 1,024 文字です。 |
| セグメント | （必須）ユーザーを追加するセグメントを選択するか、セグメント ID を入力します。各 ID は、先頭にゼロが付かない整数です。1～1,000 個のセグメントを入力します。コネクタは重複するセグメント ID を削除します。 |

Kevel は、セグメントが存在するかどうかを確認せず、すべてのセグメント ID を受け入れます。セグメントに一致しない ID を使用しないように、ドロップダウンリストからセグメントを選択してください。

### ユーザーを広告サーバーセグメントから削除

ユーザーを 1 つ以上の広告サーバーセグメントから削除します。Kevel は、指定されたセグメント ID のみを削除します。ユーザーのその他のセグメントメンバーシップは維持されます。ユーザーが属していないセグメントを削除しても影響はありません。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）Kevel UserDB 内のユーザーレコードのキー。最大 1,024 文字です。 |
| セグメント | （必須）ユーザーを削除するセグメントを選択するか、セグメント ID を入力します。各 ID は、先頭にゼロが付かない整数です。1～1,000 個のセグメントを入力します。コネクタは重複するセグメント ID を削除します。 |

Kevel は、セグメントが存在するかどうかを確認せず、すべてのセグメント ID を受け入れます。セグメントに一致しない ID を使用しないように、ドロップダウンリストからセグメントを選択してください。

### ユーザーをリターゲティングセグメントに追加（レガシー）

従来の Kevel リターゲティングエンドポイントを通じて、ユーザーを広告主のリターゲティングセグメントに追加します。Kevel は、このエンドポイントに関するドキュメントを提供しなくなりました。新しい構成では、代わりに広告サーバーのセグメントアクションを使用してください。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）Kevel UserDB 内のユーザーレコードのキー。最大 1,024 文字です。 |
| 広告主 | （必須）リターゲティングセグメントを所有する Kevel 広告主を選択します。値には広告主 ID を指定する必要があります。これは先頭にゼロが付かない整数です。 |
| セグメント | （必須）リターゲティングセグメントとして使用する広告サーバーセグメントを選択します。値にはセグメント ID を指定する必要があります。これは先頭にゼロが付かない整数です。 |

Kevel は書き込みごとに同じ成功レスポンスを返すため、Tealium は存在しない広告主 ID またはセグメント ID を検出できません。両方の値をドロップダウンリストから選択してください。

### ユーザーをオプトアウト

Kevel UserDB のユーザーレコードにオプトアウトステータスを構成します。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）Kevel UserDB 内のユーザーレコードのキー。最大 1,024 文字です。 |


<blockquote>
このコネクタを使用してオプトアウトを取り消すことはできません。
</blockquote>


### GDPR 同意を構成

Kevel UserDB のユーザーレコードに GDPR 同意ステータスを構成します。Tealium での同意管理の詳細については、[サーバーサイドの同意管理](https://docs.tealium.com/server-side-consent-management/)を参照してください。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）Kevel UserDB 内のユーザーレコードのキー。最大 1,024 文字です。 |
| GDPR 同意 | （必須）ユーザーの GDPR 同意ステータス。ユーザーが同意した場合は `true`、同意しなかった場合は `false` です。値では大文字と小文字が区別されません。コネクタは値をブール値として Kevel に送信し、それ以外の値を拒否します。 |

### ユーザーを削除

Kevel UserDB からユーザーレコードとそのすべてのデータを完全に削除します。

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| ユーザーキー | （必須）削除するユーザーレコードのキー。最大 1,024 文字です。 |


<blockquote>
削除を取り消すことはできません。このアクションは実行されるたびにユーザーレコードを削除するため、削除を要求したユーザーに対してのみトリガーしてください。
</blockquote>


### ユーザーを Kevel Audience セグメントに追加（バッチ処理）

ユーザーを Kevel Audience セグメントに追加します。ユーザーが Kevel Audience に存在しない場合、Kevel がユーザーを作成します。
#### バッチ制限

このアクションでは、ベンダーへの大量のデータ転送をサポートするためにバッチリクエストを使用します。並列処理により、イベントが順不同でベンダーに到達する場合があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまでキューに保持されます。

* リクエストの最大数：50
* 最も古いリクエストからの最大経過時間：15分
* リクエストの最大サイズ：1 MB

Kevel Audience が1回のリクエストにつき最大50件のメンバーシップを受け付けるため、コネクターは各バッチを1件のリクエストとして Kevel に送信します。


<blockquote>
このアクションと「Kevel Audience セグメントからユーザーを削除（バッチ）」アクションでは、別々のバッチが使用されます。短時間のうちに同じユーザーを同じセグメントに追加してから削除した場合、Kevel は2つの変更をどちらの順序でも適用する可能性があります。
</blockquote>


#### パラメーター

| **パラメーター** | **説明** |
| --- | --- |
| ユーザーIDタイプ | （必須）ユーザーIDのタイプ。タイプの一覧については、[ユーザーIDタイプ](#user-id-types)を参照してください。 |
| ユーザーID | （必須）ユーザーID。コネクターは、ユーザーIDタイプに応じて値をフォーマットまたはハッシュ化します。 |
| セグメント | （必須）ユーザーを追加する Kevel Audience セグメントを選択するか、`es_02f28ebe` などのセグメントIDを入力します。セグメントIDは、1～128文字の英字、数字、ハイフン、またはアンダースコアで構成されます。 |


<blockquote>
Kevel で Kevel Audience セグメントを削除しても、そのセグメントを対象とするバッチアクションについて、Kevel は引き続き成功を報告し、メンバーシップを保持します。セグメントを削除するときは、それらのアクションを削除または更新してください。
</blockquote>


#### ユーザーIDタイプ

| ユーザーIDタイプ | Kevel のユーザーIDタイプ | マッピングする値 |
| --- | --- | --- |
| メール（SHA-256を適用） | `email_sha256` | プレーンテキストのメールアドレス。コネクターはアドレスの前後の空白を削除して小文字に変換し、有効なメールアドレスであることを確認してから、SHA-256でハッシュ化します。 |
| メールSHA-256（ハッシュ化済み） | `email_sha256` | SHA-256でハッシュ化する前に前後の空白を削除して小文字に変換したメールアドレスを表す、64文字の16進数文字列。 |
| メールMD5（ハッシュ化済み） | `email_md5` | MD5でハッシュ化する前に前後の空白を削除して小文字に変換したメールアドレスを表す、32文字の16進数文字列。 |
| メールSHA-256 Base64（ハッシュ化済み） | `email_sha256b64` | SHA-256でハッシュ化する前に前後の空白を削除して小文字に変換し、そのハッシュをURLセーフなBase64でエンコードしたメールアドレス。 |
| 電話番号E.164（SHA-256を適用） | `phone_e164_sha256` | `+14155552671` や `0044 20 7946 0958` など、国番号を含む電話番号。コネクターは、スペース、ピリオド、ハイフン、丸括弧を削除し、先頭の `00` を `+` に置き換え、`+` がない場合は追加してから、結果をSHA-256でハッシュ化します。コネクターは欠落している国番号を追加できないため、`4155552671` などの国内電話番号は別の番号としてハッシュ化されます。 |
| 電話番号E.164 SHA-256（ハッシュ化済み） | `phone_e164_sha256` | 先頭の `+` を含むE.164形式の電話番号をSHA-256でハッシュ化した、64文字の16進数文字列。 |
| CRM ID | `crm` | ユーザーのCRM ID。コネクターは先頭と末尾のスペースを削除し、それ以外は値を変更せずに送信します。 |
| Kevel Audience ファーストパーティCookie | `1pCookie` | Kevel Audience のファーストパーティCookie ID。コネクターは先頭と末尾のスペースを削除し、それ以外は値を変更せずに送信します。 |
| Android 広告ID | `gaid` | Android搭載デバイスのGoogle広告ID。コネクターは先頭と末尾のスペースを削除し、それ以外は値を変更せずに送信します。 |
| iOS IDFA | `idfa` | iOSデバイスの広告識別子（IDFA）。コネクターは先頭と末尾のスペースを削除し、それ以外は値を変更せずに送信します。 |

ハッシュ化済みのユーザーIDタイプについては、コネクターは16進数値を小文字に変換します。ユーザーIDタイプに対して指定された長さまたは形式に一致しない値は拒否されます。

コネクターは、空のユーザーID、および値 `null`、`undefined`、`none` を拒否します。このチェックでは大文字と小文字は区別されません。

### Kevel Audience セグメントからユーザーを削除（バッチ）

Kevel Audience セグメントからユーザーを削除します。セグメントのメンバーではないユーザーを削除しても、影響はありません。

#### バッチ制限

このアクションでは、ベンダーへの大量のデータ転送をサポートするためにバッチリクエストを使用します。並列処理により、イベントが順不同でベンダーに到達する場合があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまでキューに保持されます。

* リクエストの最大数：50
* 最も古いリクエストからの最大経過時間：15分
* リクエストの最大サイズ：1 MB

Kevel Audience が1回のリクエストにつき最大50件のメンバーシップを受け付けるため、コネクターは各バッチを1件のリクエストとして Kevel に送信します。


<blockquote>
このアクションと「Kevel Audience セグメントにユーザーを追加（バッチ）」アクションでは、別々のバッチが使用されます。短時間のうちに同じユーザーを同じセグメントに追加してから削除した場合、Kevel は2つの変更をどちらの順序でも適用する可能性があります。
</blockquote>


#### パラメーター

| **パラメーター** | **説明** |
| --- | --- |
| ユーザーIDタイプ | （必須）ユーザーIDのタイプ。タイプの一覧については、[ユーザーIDタイプ](#user-id-types)を参照してください。 |
| ユーザーID | （必須）ユーザーID。コネクターは、ユーザーIDタイプに応じて値をフォーマットまたはハッシュ化します。 |
| セグメント | （必須）ユーザーを削除する Kevel Audience セグメントを選択するか、`es_02f28ebe` などのセグメントIDを入力します。セグメントIDは、1～128文字の英字、数字、ハイフン、またはアンダースコアで構成されます。 |

このアクションのユーザーIDタイプ、ユーザーIDのルール、およびセグメントの要件は、[Kevel Audience セグメントにユーザーを追加（バッチ）](#add-users-to-kevel-audience-segment-batched)と同じです。

## レート制限

Kevel では、次のレート制限が適用されます。

* **Kevel Ad Server（UserDBおよびManagement API）：** ネットワークごとに毎秒10リクエスト。この制限は、管理タスク、ドロップダウンリスト、およびその他のツールからのリクエストを含む、そのネットワークのすべてのリクエストに適用されます。
* **Kevel Audience：** すべてのエンドポイントを合わせて毎秒250リクエスト。

2つのバッチアクションを除き、各アクションは実行されるたびに1件のリクエストを送信します。レート制限を超えたリクエストは失敗する可能性があります。大量のイベントまたはオーディエンスからこれらのアクションをトリガーする前に、想定されるリクエストレートをこれらの制限と比較してください。
