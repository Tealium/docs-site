## 変更内容

[Google 広告カスタマーマッチコネクタ](https://docs.tealium.com/google-ads-customer-match-connector/)に、Google Data Manager API を使用する次の 2 つの新しいアクションを導入します。

* リストへのユーザーの追加（Data Manager API）  
* リストからのユーザーの削除（Data Manager API）

これらのアクションは、コネクタ UI にある既存の「リストへのユーザーの追加」および「リストからのユーザーの削除」アクションとほぼ同じ構成ですが、従来の Google Ads API ではなく、Google の Data Manager API を介してオーディエンスの更新を送信します。

さらに、コネクタ構成に、Google 広告アカウントと Tealium の間にプロダクトリンクを確立するリンク手順が追加されました。新しい Data Manager API アクションを使用する前に、このリンクが必要です。

## Data Manager API アクションを導入する理由

Google Data Manager API は、今後のカスタマーマッチデータ取り込みにおける戦略的な基盤です。

コネクタをこの API に移行すると、次のメリットがあります。

* Google 広告の顧客アカウントと Tealium の間で正式なプロダクトリンクを使用するため、Tealium が承認済みデータパートナーとしてお客様に代わって処理を実行できます。  
* 継続的なオーディエンス更新でユーザーレベルの OAuth トークンに依存する必要がなくなり、プロダクトリンクの確立後は、Tealium がデータパートナー統合を使用してデータ取り込みを管理できます。  
* 同意、利用規約、データ形式（識別子の正規化やハッシュ化を含む）に関する Google のカスタマーマッチ要件に準拠できます。  
* Google による Google Ads API と Data Manager API の進化に伴い、構成の長期的な安定性を高められます。

## 既存の Google Ads API アクションの非推奨化

[Google 広告カスタマーマッチコネクタ](https://docs.tealium.com/google-ads-customer-match-connector/)の既存の Google Ads API カスタマーマッチアクションは、今後のリリースで非推奨になります。

それまでは、次の点に注意してください。

* 既存のアクションは引き続き動作します。  
* 将来の変更を最小限に抑えるため、可能な限り早く新しい Data Manager API アクションへ移行することを強く推奨します。  
* 従来のアクションを削除する前に、標準のリリースチャネルを通じて、スケジュールおよび破壊的変更についてお知らせします。

## 新しい Data Manager API アクションについて

新しいアクションは、[Google 広告カスタマーマッチコネクタ](https://docs.tealium.com/google-ads-customer-match-connector/)内で、既存の Google 広告カスタマーマッチアクションとともに表示されます。

* **リストへのユーザーの追加（Data Manager API）**
* **リストからのユーザーの削除（Data Manager API）**

主なポイントは次のとおりです。

* **UI レイアウト**：これらのアクションの構成画面は、既存の Google 広告カスタマーマッチアクションとほぼ同じ構成であるため、ほとんどのマッピングと構成を同様に使用できます。

* **同意と規約**：Data Manager では、取り込み呼び出しごとに明示的な同意とカスタマーマッチの利用規約が必要です。コネクタは、必要な同意フィールドと規約フィールドがペイロードに含まれていることを保証します。

* **識別子の形式**：メールアドレス、電話番号、住所などの、プレーンテキストまたは事前にハッシュ化された識別子をマッピングします。

  * **SHA256 ハッシュを適用**：Tealium は、Google が要求する正規化（前後の空白削除、小文字化、ハッシュ化）を実行します。
  * **SHA256 でハッシュ化済み**：コネクタは、値が `0x` プレフィックスを含まず、正確に 64 個の 16 進文字で構成された有効な SHA-256 16 進文字列であることを検証します。
  * **無効な識別子**：コネクタは、リクエストを送信する前に無効な値を削除します。レコードに有効な識別子と無効な識別子の両方が含まれている場合は、有効な識別子のみが送信されます。検証後に有効な識別子が残っていない場合、アクションは検証エラーで失敗し、再試行されません。
  * **住所情報**：国コード、名、姓、郵便番号の 4 つのフィールドがすべて必要です。住所フィールドが 1 つでも欠けている場合、コネクタはリクエストから住所オブジェクト全体を削除します。

* **リストキーのタイプ**：Data Manager API を使用して作成および管理されるリストでは、`CONTACT_ID`（メール、電話番号、住所）、`USER_ID`（ファーストパーティ ID）、`MOBILE_ID`（デバイス ID）などのリストキータイプを使用します。リストのキータイプと互換性のある識別子をマッピングしてください。

**マネージャー顧客 ID** のオーバーライドや、その他の Google Ads API 固有のセクションは、Data Manager API アクションでは使用されません。Data Manager の構成は、プロダクトリンクと、選択したリストおよび識別子を使用して処理されます。

## 移行前の準備

Google Data Manager API アクションを使用する前に、Google 広告アカウントと Tealium の間にプロダクトリンクを作成してください。

プロダクトリンクは、Tealium または Google 広告のいずれかで作成できます。

### Tealium でプロダクトリンクを作成する

Tealium からプロダクトリンクを作成する場合は、Google OAuth トークンに Data Manager API のスコープが含まれるように、コネクタを再認証してください。

1. 既存の[Google 広告カスタマーマッチコネクタ](https://docs.tealium.com/google-ads-customer-match-connector/)を開きます。
1. **Google でログイン**をクリックし、Google アカウントで再度ログインします。
1. 認証時に、コネクタは既存の Google 広告の権限に加えて、`https://www.googleapis.com/auth/datamanager` へのアクセスをリクエストします。
1. コネクタ構成の **顧客 ID を Tealium にリンク**セクションを使用して、プロダクトリンクを作成します。

### Google 広告でプロダクトリンクを作成する

Google Ads Data Manager からプロダクトリンクを作成することもできます。この方法では、プロダクトリンクを作成するために Tealium で Google OAuth フローを実行する必要はありません。

詳細については、[Google 広告カスタマーマッチコネクタ](https://docs.tealium.com/google-ads-customer-match-connector/)を参照してください。

カスタマーマッチのユーザーリストを所有する Google 広告アカウント用のプロダクトリンクを作成します。アクションで**顧客 ID のオーバーライド**を使用する場合は、そのアクションで使用される各リスト所有顧客アカウントがプロダクトリンクの対象になっていることを確認してください。

## 既存の Google Ads API アクションから移行する方法

目的は、動作の変更を最小限に抑えながら、既存の各 Google 広告カスタマーマッチアクションを、対応する Google Data Manager API アクションへ移行することです。

### 手順 1：既存のアクションを新しい Google Data Manager API に移行する

既存のアクションを基に新しいアクションを作成するか（テスト中に両方を並行して実行する場合に推奨）、既存のアクションをそのまま切り替えます。

#### オプション A - 既存のアクションを新しい Google Data Manager API アクションにコピーする

既存の各 Google Ads API アクションについて、次の手順を実行します。

1. コネクタの**アクション**タブで、既存の Google 広告カスタマーマッチアクションを見つけます。  
1. **新しいアクションにコピー**オプションを使用して、構成を複製します。  
1. 新しいコピーで、アクションタイプを Data Manager API アクションに変更します。たとえば、**リストへのユーザーの追加（Data Manager API）**または**リストからのユーザーの削除（Data Manager API）**を選択します。  
1. 次の点を確認します。  
   * 同じユーザーリストが選択されていること、またはオーバーライドフィールドが Data Manager 用の正しいリスト ID 形式を使用するように更新されていること。  
   * 必須の識別子マッピングがすべて構成され、リストのキータイプと一致していること。たとえば、`CONTACT_ID` リストの場合は、ハッシュ化されたメールアドレス、ハッシュ化された電話番号、または住所フィールドのうち少なくとも 1 つ、`USER_ID` リストの場合はファーストパーティのユーザー ID、`MOBILE_ID` リストの場合はモバイルデバイス ID が必要です。  
1. 新しい Data Manager API アクションを保存します。

この方法では、新しい API に切り替えながら、既存のトリガー条件とフィールドマッピングの大部分を再利用できます。

#### オプション B - アクションを新しい Data Manager API アクションタイプに切り替える

コピーを作成せずにアクションを新しい API に切り替える場合は、次の手順を実行します。

1. コネクタのアクションタブで、既存の Google 広告カスタマーマッチアクションを見つけます。  
1. 右上のメニューにある**アクションタイプを変更**オプションを使用して、アクションのタイプを切り替えます。  
1. アクションの Data Manager API バージョンを選択します。  
1. 選択したユーザーリストとマッピングが保持されていることを確認します。  
1. Data Manager API アクションを保存します。
### ステップ2：テストと検証

アクションをコピーした場合（オプションA）でも、その場で切り替えた場合（オプションB）でも、次の手順を実行します。

1. 新しいData Manager APIアクションを実行するイベントを発生させます。  
1. Google Adsで、対象のカスタマーマッチリストが想定どおりにユーザーの受信を開始していること（追加アクションの場合）、または想定どおりにユーザーが削除されていること（削除アクションの場合）を確認します。  
1. Tealiumコネクタのログで、Data Managerに関連するエラー（無効な識別子、同意に関する問題、リスト構成の問題など）がないか確認し、必要に応じてマッピングを調整します。

### ステップ3：旧アクションのクリーンアップ（該当する場合）

アクションのコピーを作成し、新しいData Manager APIアクションを検証済みの場合は、次の手順を実行します。

1. コネクタの**アクション**タブに戻ります。  
1. 更新の重複を防ぐため、古いGoogle Adsカスタマーマッチアクションを無効化または削除します。

オプションBを使用してアクションをその場で切り替えた場合、そのアクションについて追加のクリーンアップは必要ありません。

以上の手順を完了すると、Google Adsカスタマーマッチ構成は、TealiumでGoogle Data Manager APIを使用するように完全に移行されます。

## よくある質問

**Google Adsのカスタマーマッチリストを作り直す必要はありますか？**  
いいえ。既存のGoogle AdsカスタマーマッチリストがGoogle Data Manager APIに対応し、そのキータイプが送信する識別子と一致していれば、新しいアクションでそのリストを使用できます。また、コネクタでリスト管理操作を利用できる場合は、それを使用してGoogle Data Manager APIから直接リストを作成または管理することもできます。

**移行しない場合はどうなりますか？**  
当面は、既存のGoogle Ads APIベースのアクションも引き続き機能します。ただし、これらのアクションは廃止が予定されているため、アクションが削除された場合や、Googleが基盤となるAds APIを変更した場合、最終的にはそれらを使用してGoogle Adsのカスタマーマッチオーディエンスを管理できなくなる可能性があります。今すぐ移行することで、将来の中断を最小限に抑え、Google Data Managerを使用する推奨の方法に構成を合わせることができます。

**同意とデータガバナンスを引き続き管理できますか？**  
はい。エンドユーザーの同意を取得および管理し、適用される法律とGoogleのポリシーに従ってデータがGoogleと共有されるようにする責任は、引き続きお客様にあります。同意の観点では、新しいGoogle Data Manager APIアクションは既存のアクションと同じように動作します。コネクタはリクエストペイロード内のGoogleの両方の同意フィールドに対して常に`GRANTED`を送信し、適切な同意を得たユーザーのみがGoogleに送信されるようにするため、上流の同意およびオーディエンスロジックに依存します。
