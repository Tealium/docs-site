## 構成

コネクタマーケットプレイスにアクセスして新しいコネクタを追加します。コネクタを追加する一般的な手順については、[コネクタについて](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、以下の構成を構成します：

* **認証タイプ**
  * **SASL/PLAIN**（デフォルト）：ユーザー名とパスワードを使用して認証します。
  * **SASL SCRAM-SHA-512**：SCRAM-SHA-512 チャレンジレスポンス認証を使用します。このオプションを選択する前に、Kafka ブローカーが `SCRAM-SHA-512` メカニズムをサポートするように構成してください。
* **ブートストラップサーバー**
  * （必須）エンドポイントの Kafka ブートストラップサーバー。例えば、Conduktor Gateway ホストまたは Kafka ブローカー：`gateway.customer-domain.com:6969`。
  * エンドポイントは、通常、PrivateLink、VPN、またはネットワークピアリングを通じて Tealium からアクセス可能である必要があります。
* **CA証明書（PEM）**
  * Kafka ブローカーまたはゲートウェイによって提示される TLS 証明書を検証するために使用される PEM エンコードされた CA 証明書チェーン。
  * エンドポイントが内部 PKI、プライベート CA、または自己署名証明書を使用している場合に必要です。
* **ホスト名検証の無効化**
  * TLS 証明書とホスト名が一致するかどうかの検証を無効にします。
  * SNI や非標準のホスト名を使用する場合は、この構成を無効にします。デフォルト：検証有効。
* **Confluent スキーマレジストリ URL**
  * （オプション）スキーマレジストリの URL。例：`https://schema-registry.example.com:8081`。
  * カスタムアクションでスキーマ検証を使用する場合に必要です。
* **Confluent スキーマレジストリ ユーザー名**
  * （オプション）HTTP Basic 認証を使用してスキーマレジストリに認証するためのユーザー名。
  * スキーマレジストリが認証を要求する場合に必要です。
* **Confluent スキーマレジストリ パスワード**
  * （オプション）HTTP Basic 認証を使用してスキーマレジストリに認証するためのパスワードまたは API シークレット。
  * スキーマレジストリが認証を要求する場合に必要です。
* **サービスアカウントユーザー名**
  * （必須）ブローカーとの認証に使用される Kafka プリンシパル。
  * SASL/PLAIN の場合は SASL ユーザー名を、SASL SCRAM-SHA-512 の場合は SCRAM プリンシパルを入力します。
* **サービスアカウントトークン / パスワード**
  * （必須）サービスアカウントプリンシパルの認証情報。
  * SASL/PLAIN の場合は JWT トークンまたは同等の認証情報を、SASL SCRAM-SHA-512 の場合は SCRAM パスワードを入力します。
* **圧縮タイプ**
  * Kafka に送信されるメッセージの圧縮アルゴリズム。帯域幅と保存コストを削減します。
  * デフォルトは `GZIP`です。
* **最大メッセージサイズ（バイト）**
  * 一回のリクエストで送信される単一メッセージまたはバッチの最大サイズ（バイト単位）。大きな訪問プロファイルを収容するためにこの値を増やしますが、ブローカーの構成と一致することを確認してください。
  * デフォルトは `1,048,576` バイト（1 MB）。最大は `2,097,152` バイト（2 MB）です。
  * この値は Kafka ブローカーの `message.max.bytes` 構成を超えてはなりません。
* **クライアント ID**
  * 各リクエストにブローカーに送信される識別子で、ログ記録、モニタリングの帰属、およびクォータの強制に使用されます。
  * デフォルトは次の形式で自動生成された識別子です：`tealium-{account}-{profile}-{connectorId}`。
  * サポートされる文字は、文字、数字、ピリオド (`.`)、ハイフン (`-`)、アンダースコア (`_`)です。
* **確認（acks）**
  * メッセージが正常に書き込まれたと見なされる前に必要なブローカーの確認の数を指定します。
  * **0**：確認なし。最も速いが、無音のデータ損失のリスクがあります。
  * **1**：パーティションリーダーがローカルに書き込んだ後にメッセージを確認します。配信保証付きで最も速いです。
  * **All**：すべての同期レプリカが確認する必要があります。50〜100ミリ秒の遅延が追加されますが、データ損失のリスクがなくなります。
* **パーティショナー戦略**
  * メッセージキーが構成されている場合を除き、パーティションが指定されていない場合にプロデューサーがメッセージをパーティションに割り当てる方法を制御します。
  * **デフォルト**：最適なスループットのためにスティッキーバッチングを使用します。
  * **ラウンドロビン**：すべてのパーティションにメッセージを均等に分配します。
* **プロデューサー - 再接続バックオフ**
  * 接続失敗後にブローカーに再接続する前に待機する時間（ミリ秒単位）。
  * デフォルトは `50` ミリ秒です。
* **プロデューサー - リトライ**
  * 送信操作が失敗した場合の最大リトライ試行回数。
  * 空白の場合、Kafka クライアントのデフォルトが使用されます。
* **プロデューサー - リトライバックオフ**
  * 同じレコードのリトライ試行間の待機時間（ミリ秒単位）。
  * デフォルトは `100` ミリ秒です。

## アクション

| アクション名 | AudienceStream | EventStream |
| ----------- | :------------: | :---------: |
| すべてのイベントデータを送信 | ✗ | ✓ |
| すべての訪問データを送信 | ✓ | ✗ |
| カスタムイベントデータを送信 | ✗ | ✓ |
| カスタム訪問データを送信 | ✓ | ✗ |
| すべてのログイベントを送信 | ✗ | ✓ |
| ログイベントを送信 | ✗ | ✓ |

**次へ** をクリックするか、**アクション** タブに進んでコネクタアクションを構成します。

次のセクションでは、各アクションのパラメータとオプションの構成方法について説明します。

### すべてのイベントデータを送信

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| トピック | トピックを選択するか、トピックIDを入力します。 |
| データ形式 | データ配信の形式を指定します：`JSON`、`STRING`、または `BINARY`。 |
| パーティションID | （オプション）パーティションIDを選択します。空白の場合、メッセージキーまたはラウンドロビンに基づいて Kafka のデフォルトパーティショナーが使用されます。 |
| ヘッダー | （オプション）Kafka レコードヘッダーに追加されるキーと値のペアのセット。 |
| メッセージキー | （オプション）生のメッセージキーを指定します。データ形式が `BINARY` に構成されている場合、この値は送信前にエンコードされます。 |
| タイムスタンプ | （オプション）メッセージのタイムスタンプを ISO 8601 UTC 形式 `YYYY-MM-DDThh:mm:ssZ` で指定します。提供されていない場合、現在のタイムスタンプが使用されます。 |
| 属性名の印刷 | デフォルトでは属性キーが使用されます。このオプションを有効にすると、代わりに属性名がキーとして使用されます。 |
| バッチの有効期限 | バッチの有効期限を分単位で指定します（1から60の間）。デフォルト：10。 |

| メッセージキー | （オプション）生のメッセージキーを指定します。データ形式が **BINARY** に選択された場合、Tealium はこの値を送信前にエンコードします。 |

### カスタムイベントデータを送信


#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| トピック | トピックを選択するか、トピックIDを入力してください。 |
| データ形式 | データ配信の形式を指定してください: `JSON`, `STRING`, `BINARY`。 |
| スキーマ | (オプション) スキーマレジストリからスキーマ主題を選択してください。スキーマレジストリのURLが構成されている必要があります。 |
| メッセージデータ | メッセージデータを構築するための値を提供してください。テンプレートを使用する場合は、テンプレート名を参照し、カスタムメッセージ定義にマッピングしてください。テンプレートが使用される場合、他のキー値ペアは無視されます。 |
| パーティションID | (オプション) パーティションIDを選択してください。空白の場合、Kafkaのデフォルトパーティショナーがメッセージキーまたはラウンドロビンに基づいて使用されます。 |
| ヘッダー | (オプション) Kafkaレコードヘッダーに追加されるキー値ペアのセット。 |
| メッセージキー | (オプション) 生のメッセージキーを指定してください。データ形式として**BINARY**を選択した場合、Tealiumはこの値をエンコードして送信します。 |
| タイムスタンプ | (オプション) メッセージのタイムスタンプをISO 8601 UTC形式 `YYYY-MM-DDThh:mm:ssZ` で指定してください。提供されない場合、現在のタイムスタンプが使用されます。 |
| バッチの有効時間 | バッチの有効時間（分単位で1から60の間）。デフォルト: 10。 |
