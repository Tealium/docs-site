## API情報

このコネクタは、次のベンダーAPIを使用します。

* API名：Confluent REST Proxy for Kafka
* APIバージョン：v3
* APIエンドポイント：`https://github.com/confluentinc/kafka-rest`

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **APIキー**：（必須）Confluent CloudのAPIキー。
* **APIシークレット**：（必須）Confluent CloudのAPIシークレット。
* **ブートストラップサーバー**：（必須）プロトコルとポートを除いた、Confluent Cloud Kafka RESTエンドポイントのホスト名。たとえば、エンドポイントが`https://pkc-12345.us-west4.gcp.confluent.cloud:443`の場合は、`pkc-12345.us-west4.gcp.confluent.cloud`と入力します。
* **クラスターID**：（必須）Confluent CloudのクラスターID（例：`lkc-12345`）。

これらの構成の詳細については、次を参照してください。

* [Confluent Cloud：APIキーを使用したConfluent Cloudへの認証](https://docs.confluent.io/cloud/current/security/authenticate/workload-identities/service-accounts/api-keys/overview.html)
* [Confluent Cloudクラスター：Cloud Consoleでクラスターの詳細を確認する方法](https://docs.confluent.io/cloud/current/clusters/cluster-faq.html#how-do-i-view-cluster-details-with-ccloud-console-short)

コネクタを構成したら、**完了**をクリックします。

## アクション

| アクション名 | 訪問プロファイル | イベントデータ |
| --- | :---: | :---: |
| イベントデータ全体を送信 | ✗ | ✓ |
| カスタムイベントデータを送信 | ✗ | ✓ |
| 訪問データ全体を送信 | ✓ | ✗ |
| カスタム訪問データを送信 | ✓ | ✗ |
| ログイベントを送信 | ✗ | ✓ |
| ログイベント全体を送信 | ✗ | ✓ |

アクションの名前を入力し、アクションタイプを選択します。

次のセクションでは、各アクションのパラメータとオプションを構成する方法について説明します。

### イベントデータ全体を送信

#### バッチ制限

このコネクタは、ベンダーへの大量のデータ転送に対応するため、バッチリクエストを使用します。並列処理により、イベントが順不同でベンダーに到達する場合があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまで、リクエストはキューに保持されます。

* リクエストの最大数：100
* 最も古いリクエストからの最大経過時間：60分
* リクエストの最大サイズ：10 MB

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| トピックID | トピックを選択するか、トピックIDを入力します。 |
| パーティションID | パーティションIDを選択します。 |
| データ形式 | データ配信の形式を指定します。指定可能な値：`JSON`、`STRING`、または`BINARY`。 |
| ヘッダー | オプションのパラメータ。ヘッダープロパティと値を列挙したキーと値のペアのセットです。 |
| メッセージキー | 未加工のメッセージキーを指定します。データ形式として`BINARY`を選択した場合、Tealiumはこの値をエンコードしてから送信します。 |
| タイムスタンプ | ISO 8601 UTC形式のトピックタイムスタンプ。例：`YYYY-MM-DDThh:mm:ssZ`。タイムスタンプを指定しない場合は、現在のタイムスタンプが使用されます。 |
| バッチの有効期間 | バッチアクションを送信する頻度を指定するため、有効期間（TTL）を構成します。1～60分の値を入力します。デフォルト値は60分です。 |
| 属性名を出力 | デフォルトでは、属性IDがキー名として使用されます。代わりに属性名をキー名として使用する場合は、このチェックボックスをオンにします。属性名が更新されると、ペイロード内のキー名も更新されます。 |
| ストリーミングモードを有効化 | レコードの送信時にConfluentストリーミングAPIを使用するには、このオプションを有効にします。これにより、大量のトラフィックをより効率的に処理できますが、イベントがConfluentに送信されるタイミングは変わりません。 |
