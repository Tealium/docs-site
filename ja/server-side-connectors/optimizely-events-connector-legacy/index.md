## コネクタのアクション

| アクション名 | 訪問プロファイル | イベントデータ |
| --- | :---: | :---: |
|イベントを送信| ✗| ✓|

## 構成の構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **パーソナルトークン**
  * 認証するには、次のリンクから生成したトークンをリクエストヘッダーで使用します：<http://app.optimizely.com/v2/profile/api>。
  * このドキュメント内のすべての API リクエスト例では、同じヘッダーを使用します。
  * 認証の詳細については、[パーソナルトークン](https://developers.optimizely.com/x/authentication/personal-token)を参照してください。

## アクション構成 — パラメータとオプション

**続行**をクリックして、コネクタのアクションを構成します。アクションの名前を入力し、リストからアクションタイプを選択します。

### アクション — イベントを送信

#### パラメータ

|**パラメータ**| **説明**|
|---| ---|
|アカウント ID|  <ul><li>これらのイベントの関連付け先となる Optimizely アカウント。</li></ul> |
|判定のエンリッチ化|  <ul><li>値は `true` または `false` です。</li><li>Optimizely Easy Event Tracking 機能を有効にするには、`true` に構成する必要があります。</li><li>このフィールドの詳細については、[Event API リファレンス](https://developers.optimizely.com/x/events/api/#api_reference)を参照してください。</li><li>[Optimizely によるコンバージョンのカウント方法](https://help.optimizely.com/Analyze_Results/How_Optimizely_counts_conversions)も参照してください。</li></ul> |
|キャンペーン ID|  <ul><li>（必須）この実験を含むキャンペーンの ID。</li></ul> |
|実験 ID|  <ul><li>（必須）訪問に提示された実験の ID。</li><li>パーソナライゼーションキャンペーンでは、どの実験にも振り分けられなかった訪問について、キャンペーンのリーチを正確に計算するため、実験 ID として明示的に `null` を送信します。</li></ul> |
|バリエーション ID|  <ul><li>（必須）訪問に提示されたバリエーションの ID。</li><li>パーソナライゼーションキャンペーンでは、どの実験にも振り分けられなかった訪問について、キャンペーンのリーチを正確に計算するため、バリエーション ID として明示的に `null` を送信します。</li></ul> |
|キャンペーンホールドバックかどうか|  <ul><li>値は `true` または `false` です。</li><li>`true` の場合、選択されたエクスペリエンスはキャンペーンレベルで保留されました。</li><li>パーソナライゼーションでは必須です。それ以外の場合は省略してください。</li></ul> |
|タイムスタンプ|  <ul><li>（必須）イベントが生成された時刻のタイムスタンプ。Unix エポックからの経過時間をミリ秒単位で指定します。</li><li>ユーザーが値を指定しなかった場合、デフォルトで `{{unixTimestampMs}}` を送信します。</li></ul> |
|UUID|  <ul><li>（必須）このイベントの一意の識別子。</li><li>`{{uuid}}` を使用して自動的に作成されます。</li><li>誤って、または不正に再送されたリクエストを重複排除するために、Optimizely のバックエンドで使用されます。</li><li>Optimizely は、`entity_id`、`uuid`、`timestamp` が同じイベントを検出し、そのうちの 1 つだけを保存します。</li><li>送信する前に、各イベントで一意の `uuid` または `timestamp` が使用されていることを確認してください。</li></ul> |
|エンティティ ID|  <ul><li>（任意）この属性に対応するエンティティの ID。</li><li>カスタム属性（`type="custom"`）の場合にのみ必要です。</li><li>その他の属性タイプでは無効です。</li></ul> |
|イベント名|  <ul><li>このイベントのイベントキー（別名 API 名）。</li></ul> |
|イベントデータ|  <ul><li>キーと値のペアで指定する追加のイベントデータ。</li></ul> |
|タグ|  <ul><li>（任意）タグに関連するキーと値の属性。</li><li>使用する場合は、キーのうち 2 つとして `type` と `value` を含める必要があります。</li></ul> |
|イベントタイプ|  <ul><li>イベントのタイプ。</li><li>たとえば、`decision_point` を示すには、タイプを `campaign_activated` にする必要があります。</li></ul> |
|イベント値|  <ul><li>イベントに関連付けられたスカラー値。</li><li>収益以外の数値を指定する必要があります。</li></ul> |
|訪問 ID|  <ul><li>（必須）訪問の一意の識別子。</li></ul> |
|属性|  <ul><li>このリクエストの時点で訪問に関連付けられている属性。</li></ul> |
|セッション ID|  <ul><li>これらのイベントのセッションコンテキストが存在する場合に、そのコンテキストを識別する一意の識別子。</li><li>省略した場合、Optimizely バックエンドはセッションを推定してセッションベースの結果を計算します。特定の `visitor_id` から最初のイベントを受信した時点でセッションを開始し、その訪問からイベントを受信しない状態が 30 分間続くとセッションを終了します。</li><li>セッションの最長時間は 24 時間です。</li></ul> |
|IP の匿名化|  <ul><li>通常、Optimizely は各リクエストのクライアント IP アドレスを保存します。</li><li>値は `true` または `false` です。<ul><li>このフラグを `true` に構成すると、IP アドレスの最後のオクテットが保存前に切り捨てられます。</li><li>`false` に構成すると、IP アドレス全体が保存されます。</li></ul> </li><li>Web ブラウザーまたはモバイルクライアントのコンテキストに実装され、エンドユーザーを識別する情報の保存を制限するポリシーまたは規制の対象となる、この API の利用者にとって特に重要です。</li><li>このフラグは、アカウントおよびプロジェクト構成の IP 匿名化構成とは独立しています。後者は、Optimizely クライアントがこのフラグを構成する方法のみを制御します。</li><li>このフラグを構成する場合は、IP フィルタリング機能を使用する際に注意が必要です。完全修飾された明示的な IP アドレスはフィルターとして機能しません（イベントが IP でフィルタリングされる前に匿名化が行われます）。</li></ul> |
|クライアント名|  <ul><li>デバッグ目的での使用を推奨します。</li><li>このイベントを生成したシステムの一意の識別子。</li><li>慣例として、次の例に似た形式にします：`organization_name/system_name`</li><li>Event API の完全な説明については、[Event API リファレンス](https://developers.optimizely.com/x/events/api/#api_reference)を参照してください。</li></ul> |
|クライアントバージョン|  <ul><li>デバッグ目的での使用を推奨します。</li><li>このイベントを生成したシステムのバージョン識別子。</li></ul> |
|プロジェクト ID|  <ul><li>（任意）Recommendations 製品を使用している場合にのみ、プロジェクト ID を渡す必要があります。</li></ul> |
