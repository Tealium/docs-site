## Google Data Manager API アクションへの移行

以下のアクションは古いGoogle Ads APIを使用しています：

* リマーケティングリストへのユーザー追加
* リマーケティングリストからのユーザー削除

以下の置き換えアクションを使用してください。これらはGoogle Data Manager APIに基づいています：

* リストへのユーザー追加（Data Manager API）
* リストからのユーザー削除（Data Manager API）

詳細については、[Google Data Manager API 移行ガイド](https://docs.tealium.com/google-data-manager-api-migration-guide/)を参照してください。

## 構成

コネクタマーケットプレイスにアクセスし、新しいコネクタを追加します。コネクタの追加方法については、[コネクタについて](https://docs.tealium.com/about-connectors/)の記事を参照してください。


<blockquote>
このコネクタを追加する際には、ベンダーのデータプラットフォームポリシーを受け入れるよう求められます。
</blockquote>


コネクタを追加した後、以下の構成を構成します：

* **カスタマーID**：（必須）管理する広告アカウントのカスタマーIDを提供してください。
* **マネージャーカスタマーID**：（オプショナル）クライアントカスタマーにアクセスする場合、マネージャーカスタマーIDを構成し、広告アカウントへのフルアクセスが必要です。

### ユーザーリストの作成

ユーザーリストを作成するには、**ユーザーリストの作成**をクリックし、次の情報を入力します：

| **パラメータ** | **説明** |
| --- | --- |
| リスト名 | （必須）ユーザーリストの名前。 |
| リストタイプ | （必須）リストのタイプ。これは、このリストで使用されるユーザー識別情報のタイプに影響します：<ul><li>`CONTACT_INFO`：顧客情報（メールアドレス、電話番号、物理アドレスなど）からユーザーを照合します。</li><li>`CRM_ID`：広告主が生成し割り当てたユーザーIDからユーザーを照合します。</li><li>`MOBILE_ADVERTISING_ID`：モバイルデバイスID（広告ID/IDFA）からユーザーを照合します。</li></ul> |
| アプリID | モバイル広告リストタイプに必要です。データをGoogle Ads APIに送信するモバイルアプリケーションを一意に識別する文字列です。 |
| リストメンバーシップの寿命 | （オプショナル）ユーザーがリストに最後に追加されてからリストに残る日数。数値は`0`から`540`の間でなければなりません。デフォルトの寿命は540日です。 |
| リストの説明 | （オプショナル）リストの説明。 |

### ユーザー識別子

各アクションにはユーザー識別子が必要です。ベンダーはこれらの値が正規化され、SHA-256でハッシュ化されていることを要求します。マップされたユーザー識別子の値は、次の要件を満たすことが期待されます：

* 小文字
* テキストの先頭と末尾からの空白のトリミング
* SHA-256でのハッシュ化

既に正規化されハッシュ化された属性をマップすることも、コネクタに正規化とハッシュ化を行わせることもできます。シナリオに適したマッピングを選択してください。

必要なユーザー識別子は、選択されたユーザーリストタイプに基づいています。ユーザーリストタイプは次のいずれかになります：

* Google Ads API：
  * `CONTACT_INFO`
  * `CRM_ID`
  * `MOBILE_ADVERTISING_ID`
* Google Data Manager API：
  * `CONTACT_ID`
  * `MOBILE_ID`
  * `USER_ID`

次のユーザー識別子フィールドがサポートされています：

| ユーザー識別子フィールド | 説明 |
|---| ---|
| `CONTACT_INFO` (Google Ads API)|  ハッシュ化されたメール、ハッシュ化された電話番号、または住所情報を提供します。このユーザーデータタイプには、以下にリストされているすべての住所情報フィールドが必要です。<ul><li>**住所情報：国コード**：ユーザーの住所の2文字の国コード、ISO 3166-1 alpha-2形式。</li><li>**住所情報：名（既にSHA256ハッシュ化されている）**：空白をトリミングし、小文字にし、SHA256でハッシュ化された名を提供します。</li><li>**住所情報：名（SHA256ハッシュを適用）**：プレーンテキストの名を提供し、コネクタがこの値をSHA256ハッシュでハッシュ化します。</li><li>**住所情報：姓（既にSHA256ハッシュ化されている）**：空白をトリミングし、小文字にし、SHA256でハッシュ化された姓を提供します。</li><li>**住所情報：姓（SHA256ハッシュを適用）**：プレーンテキストの姓を提供し、コネクタがこの値をSHA256ハッシュでハッシュ化します。</li><li>**住所情報：郵便番号**：ユーザーの住所の郵便番号を提供します。</li><li>**メールアドレス（既にSHA256ハッシュ化されている）**：空白をトリミングし、小文字にし、SHA256でハッシュ化されたメールアドレスまたはメールアドレスの配列を提供します。</li><li>**メールアドレス（SHA256ハッシュを適用）**：プレーンテキストのメールアドレスまたはメールアドレスの配列を提供し、コネクタがこれらの値をSHA256ハッシュでハッシュ化します。</li><li>**電話番号（既にSHA256ハッシュ化されている）**：空白をトリミングし、SHA256でハッシュ化された電話番号または電話番号の配列を提供します。</li><li>**電話番号（SHA256ハッシュを適用）**：プレーンテキストの電話番号または電話番号の配列を提供し、コネクタがこれらの値をSHA256ハッシュでハッシュ化します。</li></ul> |
|`CRM_ID` (Google Ads API)|  <ul><li>**ユーザーID**：（必須）顧客マッチアップロード用に広告主が割り当てたユーザーID。</li></ul> |
|`MOBILE_ADVERTISING_ID` (Google Ads API)|  <ul><li>**モバイルID**：（必須）モバイルデバイスID（広告ID/IDFA）。</li></ul> |
|`CONTACT_ID` (Data Manager API)| **連絡先情報**：メールアドレス、電話番号、住所。住所情報を提供する場合、4つのフィールドすべてが必要です：国コード、名、姓、郵便番号。住所情報フィールドが欠けている場合、コネクタはリクエストから住所オブジェクト全体を削除します。削除後にユーザーデータが残っていない場合、アクションは検証エラーで失敗し、再試行されません。 |
|`MOBILE_ID` (Data Manager API)|  **モバイルID**：モバイルデバイスID。 |
|`USER_ID` (Data Manager API)|  **ユーザーID**：第一者識別子。 |

### リストへのユーザー追加（Data Manager API）

#### API情報

このコネクタは次のベンダーAPIを使用します：

* API名：Google Data Manager API
* APIバージョン：v1
* APIエンドポイント：`https://datamanager.googleapis.com`
* ドキュメント：[Google Data Manager API](https://developers.google.com/data-manager/api/reference/rest)

#### バッチ制限

このアクションは、ベンダーへの大量データ転送をサポートするためにバッチリクエストを使用します。並行処理により、イベントがベンダーに順不同で到達する可能性があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかの閾値に達するか、プロファイルが公開されるまでリクエストはキューに入れられます：

* 最大リクエスト数：10,000
* 最古のリクエストからの最大時間：60分
* リクエストの最大サイズ：40 MB

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| ユーザーリスト | Data Manager APIからユーザーリストを選択します。詳細については、[Data Manager API: カスタマーマッチの概要](https://developers.google.com/data-manager/api/devguides/audiences/google-ads/customer-match)を参照してください。 |

#### ユーザー識別子

| パラメータ | 説明 |
| --- | --- |
| カスタマーIDのオーバーライド | （オプショナル）コネクタ構成のカスタマーIDを上書きするカスタマーIDを提供します。このオプションを使用する場合は、ユーザーリストIDのオーバーライドも使用する必要があります。 |
| ユーザーリストIDのオーバーライド | （オプショナル）必要セクションのユーザーリストを上書きするユーザーリストIDを提供します。このフィールドを使用すると、イベント属性を使用してユーザーリストIDを入力できます。カスタマーIDのオーバーライドを使用する場合は、このフィールドが必要です。値はリストIDでなければなりません。例：`9310271231`。 |

マッピングオプションについては、[リストへのユーザー追加（Data Manager API）](#add-user-to-list-data-manager-api)を参照してください。

### リマーケティングリストへのユーザー追加（非推奨）


#### バッチ制限

このコネクタアクションは、ベンダーへの大量データ転送をサポートするためにバッチリクエストを使用できます。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかの閾値に達するか、プロファイルが公開されるまでキューに入れられます：

* リクエストの最大数：33,000
* 最古のリクエストからの最大時間：60分
* リクエストの最大サイズ：40 MB

#### API情報

このコネクタは以下のベンダーAPIを使用します：

* API名：Google Ads API
* APIバージョン：v24
* APIエンドポイント：`https://googleads.googleapis.com/`
* ドキュメント：[Google Ads API](https://developers.google.com/google-ads/api/docs/start)

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| リマーケティングリスト | リマーケティングユーザーリストを選択します。詳細については、[Google Ads: リマーケティングとオーディエンスターゲティング](https://developers.google.com/google-ads/api/docs/remarketing/overview)を参照してください。利用可能なオプションには、ファーストパーティCRMデータタイプのユーザーリストのみが含まれます。ユーザーリストを作成するには、[ユーザーリストの作成](#create-user-list)を参照してください。|
| カスタマーIDオーバーライド | （オプション）コネクタ構成のカスタマーIDを上書きするためのカスタマーIDを提供します。このオプションを使用する場合は、**ユーザーリストIDオーバーライド**も入力する必要があります。 |
| マネージャーカスタマーIDオーバーライド | （オプション）**カスタマーIDオーバーライド**を使用してクライアントカスタマーにアクセスする場合は、マネージャーカスタマーIDを提供します。 |
| ユーザーリストIDオーバーライド | （オプション）ユーザーリストのリソース名（リストIDとタイプ）を上書きするために提供します。このフィールドは、EventStream変数を使用してユーザーリストIDを入力することを可能にします。**カスタマーIDオーバーライド**を使用する場合は必須です。値は次の形式である必要があります `ID:TYPE`、例えば `123456:CONTACT_INFO`。 |

#### 同意

**リマーケティングリストへのユーザー追加** アクションを使用する際、コネクタは `adUserData` と `adPersonalization` パラメータに対して `GRANTED` の値を送信します。同意していない訪問がリストに追加されるのを防ぐために、訪問プロファイルの同意状態をチェックするルールを持つオーディエンスを作成します。そして、同意を与えていない訪問をリストから削除するために **リマーケティングリストからユーザーを削除** アクションを使用します。

### リマーケティングリストからユーザーを削除（非推奨）

マッピングオプションについては、[リマーケティングリストへのユーザー追加](#add-user-to-remarketing-list-deprecated)を参照してください。
