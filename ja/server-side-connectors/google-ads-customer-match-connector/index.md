## Google Data Manager API アクションへの移行

次のアクションでは、旧バージョンの Google Ads API が使用されます。

* リマーケティングリストにユーザーを追加
* リマーケティングリストからユーザーを削除

Google Data Manager API に基づく、次の代替アクションを使用してください。

* リストにユーザーを追加（Data Manager API）
* リストからユーザーを削除（Data Manager API）

詳細については、[Google Data Manager API 移行ガイド](https://docs.tealium.com/google-data-manager-api-migration-guide/)を参照してください。

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。


<blockquote>
このコネクタを追加すると、ベンダーのデータプラットフォームポリシーへの同意を求められます。
</blockquote>


コネクタを追加した後、次の構成を構成します。

* **顧客 ID**：（必須）管理する広告アカウントの顧客 ID を指定します。
* **マネージャー顧客 ID**：（任意）クライアント顧客にアクセスする場合は、マネージャー顧客 ID を構成し、そのアカウントに Google 広告アカウントへの完全アクセス権を付与する必要があります。

コネクタを構成した後、**完了**をクリックします。

### ユーザーリストの作成

ユーザーリストを作成するには、**ユーザーリストを作成**をクリックし、次の情報を入力します。

| **パラメータ** | **説明** |
| --- | --- |
| リスト名 | （必須）ユーザーリスト名。 |
| リストタイプ | （必須）リストのタイプ。この構成は、このリストで使用するユーザー識別情報のタイプに影響します。<ul><li>`CONTACT_INFO`：メールアドレス、電話番号、住所などの顧客情報に基づいてユーザーを照合します。</li><li>`CRM_ID`：広告主が生成して割り当てたユーザー ID に基づいてユーザーを照合します。</li><li>`MOBILE_ADVERTISING_ID`：モバイルデバイス ID（広告 ID／IDFA）に基づいてユーザーを照合します。</li></ul> |
| アプリ ID | モバイル広告リストタイプでは必須です。Google Ads API にデータを送信するモバイルアプリケーションを一意に識別する文字列です。 |
| リストのメンバーシップ有効期間 | （任意）ユーザーが最後にリストへ追加されてから、そのリストに保持される日数。`0`～`540`の数値を指定する必要があります。デフォルトの有効期間は 540 日です。 |
| リストの説明 | （任意）リストの説明。 |

## Google 広告と Tealium のリンク

Google Data Manager API アクションを使用するには、Google 広告と Tealium の間にプロダクトリンクが必要です。このリンクは、Tealium または Google 広告のどちらからでも作成できます。どちらの方法も、新しい Data Manager API アクションと、従来の Google Ads API アクションから移行したアクションをサポートします。

### オプション 1：Tealium でプロダクトリンクを作成する

コネクタの構成画面からリンクプロセスを完了するには、このオプションを使用します。

1. Tealium で Google 広告カスタマーマッチコネクタを開きます。
1. 新しいコネクタの場合は、Google で認証します。既存のコネクタの場合は、認証情報に Google Data Manager API のスコープが含まれるように再認証します。
1. コネクタの構成画面で、**顧客 ID を Tealium にリンク**セクションを探します。
1. カスタマーマッチのユーザーリストを所有する Google 広告の顧客 ID を入力します。
1. **プロダクトリンクを作成**をクリックし、確認メッセージが表示されるまで待ちます。
1. Data Manager API アクションを構成または移行してから、適切なユーザーリストを選択し、リストのキータイプと一致する識別子をマッピングします。

アクションで**顧客 ID のオーバーライド**を使用する場合は、そのアクションで使用するユーザーリストを所有する顧客アカウントごとにプロダクトリンクを作成します。

### オプション 2：Google 広告でプロダクトリンクを作成する

Tealium の Google OAuth フローを使用せずに Google 広告でプロダクトリンクを作成するには、このオプションを使用します。

1. Google 広告にログインします。
1. **ツール > データマネージャー**に移動します。
1. **+ プロダクトを接続**をクリックします。
1. 利用可能なプロダクトから Tealium を選択します。
1. プロンプトが表示された場合は、ユースケースとして**オーディエンス**を選択します。
1. 顧客データポリシーを確認して同意し、リンクを完了します。
1. Tealium で、リンク済みの Google 広告顧客アカウントと適切なユーザーリストを使用して、Data Manager API アクションを構成または移行します。

リンク後も、コネクタアクションを構成し、そのアクションに必要な顧客 ID とユーザーリストの構成を指定する必要があります。

### マネージャーアカウントのリンク

各顧客アカウントを個別にリンクする代わりに、Google 広告のマネージャーアカウントに対してプロダクトリンクを作成できます。マネージャーアカウントのリンクは、そのマネージャーアカウントと、配下のクライアントアカウントで使用できます。

アクションを構成する際は、オーディエンスの更新を受信する特定の Google 広告アカウントの顧客 ID を使用します。マネージャーアカウントのリンクは、親マネージャーアカウントや、リンクされたマネージャーアカウントの子ではないアカウントなど、そのマネージャーアカウント階層外のアカウントには適用されません。

対象の Google 広告アカウントには必要な権限も付与されている必要があります。また、対象のユーザーリストは、アクションで使用する顧客アカウントに属している必要があります。

| アクション名 | ビジタープロファイル | イベントデータ |
| ------------| :------------: | :---------: |
| リストにユーザーを追加（Data Manager API） | ✓ | ✓ |
| リストからユーザーを削除（Data Manager API） | ✓ | ✓ |
| リマーケティングリストにユーザーを追加（非推奨）| ✓ | ✓ |
| リマーケティングリストからユーザーを削除（非推奨）| ✓ | ✓ |
### ユーザー識別子

各アクションにはユーザー識別子が必要です。ベンダーの要件により、これらの値は正規化し、SHA-256 でハッシュ化する必要があります。マッピングされた各ユーザー識別子の値は、次の要件を満たす必要があります。

* 小文字であること
* テキストの先頭と末尾の空白が削除されていること
* SHA-256 でハッシュ化されていること

すでに正規化およびハッシュ化されている属性をマッピングすることも、コネクタで正規化およびハッシュ化することもできます。ユースケースに適したマッピングを選択してください。

必要なユーザー識別子は、選択したユーザーリストタイプに基づきます。ユーザーリストタイプは、次のいずれかです。

* Google Ads API:
  * `CONTACT_INFO`
  * `CRM_ID`
  * `MOBILE_ADVERTISING_ID`
* Google Data Manager API:
  * `CONTACT_ID`
  * `MOBILE_ID`
  * `USER_ID`

次のユーザー識別子フィールドがサポートされています。

| ユーザー識別子フィールド | 説明 |
|---| ---|
| `CONTACT_INFO` (Google Ads API)| ハッシュ化されたメールアドレス、ハッシュ化された電話番号、または住所情報を指定します。このユーザーデータタイプでは、以下に示すすべての住所情報フィールドが必須です。<ul><li>**住所情報：国コード**：ユーザーの住所の国コードを、ISO 3166-1 alpha-2 形式の2文字で指定します。</li><li>**住所情報：名（SHA256 でハッシュ化済み）**：前後の空白を削除し、小文字に変換して SHA256 でハッシュ化した名を指定します。</li><li>**住所情報：名（SHA256 ハッシュを適用）**：プレーンテキストの名を指定すると、コネクタがこの値を SHA256 でハッシュ化します。</li><li>**住所情報：姓（SHA256 でハッシュ化済み）**：前後の空白を削除し、小文字に変換して SHA256 でハッシュ化した姓を指定します。</li><li>**住所情報：姓（SHA256 ハッシュを適用）**：プレーンテキストの姓を指定すると、コネクタがこの値を SHA256 でハッシュ化します。</li><li>**住所情報：郵便番号**：ユーザーの住所の郵便番号を指定します。</li><li>**メールアドレス（SHA256 でハッシュ化済み）**：前後の空白を削除し、小文字に変換して SHA256 でハッシュ化したメールアドレスまたはメールアドレスの配列を指定します。</li><li>**メールアドレス（SHA256 ハッシュを適用）**：プレーンテキストのメールアドレスまたはメールアドレスの配列を指定すると、コネクタがこれらの値を SHA256 でハッシュ化します。</li><li>**電話番号（SHA256 でハッシュ化済み）**：前後の空白を削除し、SHA256 でハッシュ化した電話番号または電話番号の配列を指定します。</li><li>**電話番号（SHA256 ハッシュを適用）**：プレーンテキストの電話番号または電話番号の配列を指定すると、コネクタがこれらの値を SHA256 でハッシュ化します。</li></ul> |
|`CRM_ID` (Google Ads API)| <ul><li>**ユーザー ID**：（必須）カスタマーマッチへのアップロード用に広告主が割り当てたユーザー ID。</li></ul> |
|`MOBILE_ADVERTISING_ID` (Google Ads API)| <ul><li>**モバイル ID**：（必須）モバイルデバイス ID（広告 ID／IDFA）。</li></ul> |
| `CONTACT_ID` (Data Manager API) | **連絡先情報**：メールアドレス、電話番号、および住所。事前にハッシュ化されたメールアドレスと電話番号の値は、64文字の16進数で構成された有効な SHA-256 文字列である必要があります。コネクタは、リクエストを送信する前に無効な値を削除します。住所情報には、国コード、名、姓、郵便番号の4つのフィールドがすべて必要です。住所フィールドが1つでも欠けている場合、コネクタは住所オブジェクト全体を削除します。検証後に有効なユーザー識別子が残っていない場合、アクションは検証エラーで失敗し、再試行されません。 |
|`MOBILE_ID` (Data Manager API)| **モバイル ID**：モバイルデバイス ID。 |
|`USER_ID` (Data Manager API)| **ユーザー ID**：ファーストパーティ識別子。 |

### ユーザーをリストに追加（Data Manager API）

#### API 情報

このコネクタは、次のベンダー API を使用します。

* API 名：Google Data Manager API
* API バージョン：v1
* API エンドポイント：`https://datamanager.googleapis.com`
* ドキュメント：[Google Data Manager API](https://developers.google.com/data-manager/api/reference/rest)

#### バッチ制限

このアクションでは、ベンダーへの大容量データ転送をサポートするために、バッチリクエストを使用します。並列処理により、イベントが順不同でベンダーに到達する場合があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまで、リクエストはキューに保持されます。

* リクエストの最大数：10,000
* 最も古いリクエストからの最大経過時間：60分
* リクエストの最大サイズ：40 MB

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| ユーザーリスト | Data Manager API からユーザーリストを選択します。詳細については、[Data Manager API：カスタマーマッチの概要](https://developers.google.com/data-manager/api/devguides/audiences/google-ads/customer-match)を参照してください。 |

#### ユーザー識別子

| パラメータ | 説明 |
| --- | --- |
| 顧客 ID の上書き | （任意）コネクタ構成の顧客 ID を上書きする顧客 ID を指定します。このオプションを使用する場合は、ユーザーリスト ID の上書きも使用する必要があります。 |
| ユーザーリスト ID の上書き | （任意）必須セクションのユーザーリストを上書きするユーザーリスト ID を指定します。このフィールドを使用すると、イベント属性からユーザーリスト ID を構成できます。顧客 ID の上書きを使用する場合、このフィールドは必須です。値は `9310271231` のようなリスト ID である必要があります。 |

#### IP データ

| パラメータ | 説明 |
| --- | --- |
| IP アドレス | 顧客とのインタラクション中に取得された IP アドレス。 |
| 観測開始時刻 | セッション中に、その IP アドレスから最初にインタラクションが行われた時刻。 |
| 観測終了時刻 | セッション中に、その IP アドレスから最後にインタラクションが行われた時刻。 |

### ユーザーをリマーケティングリストに追加（非推奨）


<blockquote>
このアクションは非推奨であり、今後のリリースで削除されます。[ユーザーをリストに追加（Data Manager API）](#add-user-to-list-data-manager-api)に移行してください。後継アクションを使用するには、コネクタを再認証し、[Google Ads を Tealium にリンク](#link-google-ads-to-tealium)してください。
</blockquote>


#### バッチ制限

このコネクタアクションでは、ベンダーへの大容量データ転送をサポートするために、バッチリクエストを使用できます。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまで、リクエストはキューに保持されます。

* リクエストの最大数：33,000
* 最も古いリクエストからの最大経過時間：60分
* リクエストの最大サイズ：40 MB

#### API 情報

このコネクタは、次のベンダー API を使用します。

* API 名：Google Ads API
* API バージョン：v24
* API エンドポイント：`https://googleads.googleapis.com/`
* ドキュメント：[Google Ads API](https://developers.google.com/google-ads/api/docs/start)

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| リマーケティングリスト | リマーケティングユーザーリストを選択します。詳細については、[Google Ads：リマーケティングとオーディエンスターゲティング](https://developers.google.com/google-ads/api/docs/remarketing/overview)を参照してください。選択肢には、ファーストパーティ CRM データタイプのユーザーリストのみが含まれます。ユーザーリストを作成するには、[ユーザーリストの作成](#create-user-list)を参照してください。|
| 顧客 ID の上書き | （任意）コネクタ構成の顧客 ID を上書きする顧客 ID を指定します。このオプションを使用する場合は、**ユーザーリスト ID の上書き**も入力する必要があります。 |
| マネージャー顧客 ID の上書き | （任意）**顧客 ID の上書き**を使用してクライアント顧客にアクセスする場合は、マネージャー顧客 ID を指定します。 |
| ユーザーリスト ID の上書き | （任意）ユーザーリストを上書きするユーザーリストのリソース名（リスト ID とタイプ）を指定します。このフィールドを使用すると、Event Streaming 変数からユーザーリスト ID を構成できます。**顧客 ID の上書き**を使用する場合、このフィールドは必須です。値は `ID:TYPE` の形式にする必要があります（例：`123456:CONTACT_INFO`）。 |

#### 同意

**ユーザーをリマーケティングリストに追加**アクションを使用すると、コネクタは `adUserData` および `adPersonalization` パラメータに `GRANTED` の値を送信します。同意していない訪問がリストに追加されないようにするには、訪問プロファイルの同意ステータスを確認するルールを含むオーディエンスを作成します。次に、**リマーケティングリストから削除**アクションを使用して、同意していない訪問をリストから削除します。
### リマーケティング リストからユーザーを削除（非推奨）


<blockquote>
このアクションは非推奨であり、今後のリリースで削除される予定です。[リストからユーザーを削除（Data Manager API）](#remove-user-from-list-data-manager-api)に移行してください。代替アクションを使用するには、コネクタを再認証し、[Google 広告を Tealium にリンク](#link-google-ads-to-tealium)してください。
</blockquote>


マッピングオプションについては、[リマーケティング リストにユーザーを追加](#add-user-to-remarketing-list-deprecated)を参照してください。
