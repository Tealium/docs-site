## Google Data Manager API アクションへの移行

以下のアクションは、古いGoogle Ads APIを使用しています：

* リマーケティングリストへのユーザー追加
* リマーケティングリストからのユーザー削除

以下の置き換えアクションを使用してください。これらはGoogle Data Manager APIに基づいています：

* リストへのユーザー追加（Data Manager API）
* リストからのユーザー削除（Data Manager API）

詳細については、[Google Data Manager API 移行ガイド](https://docs.tealium.com/google-data-manager-api-migration-guide/)を参照してください。

## 構成

コネクタマーケットプレイスにアクセスし、新しいコネクタを追加します。コネクタの追加方法についての一般的な指示については、[コネクタについて](https://docs.tealium.com/about-connectors/)の記事を参照してください。


<blockquote>
このコネクタを追加する際には、ベンダーのデータプラットフォームポリシーを受け入れるよう求められます。
</blockquote>


コネクタを追加した後、以下の構成を構成します：

* **カスタマーID**：（必須）管理する広告アカウントのカスタマーIDを提供してください。
* **マネージャーカスタマーID**：（オプショナル）クライアントカスタマーにアクセスする場合、マネージャーカスタマーIDを構成し、広告アカウントへの完全なアクセス権を持っている必要があります。

### ユーザーリストの作成

ユーザーリストを作成するには、**ユーザーリストの作成**をクリックし、次の情報を入力します：

| **パラメータ** | **説明** |
| --- | --- |
| リスト名 | （必須）ユーザーリストの名前。 |
| リストタイプ | （必須）リストのタイプ。これは、このリストで使用されるユーザー識別情報のタイプに影響します：<ul><li>`CONTACT_INFO`：顧客情報（メールアドレス、電話番号、物理的住所など）からユーザーを照合します。</li><li>`CRM_ID`：広告主が生成し割り当てたユーザーIDからユーザーを照合します。</li><li>`MOBILE_ADVERTISING_ID`：モバイルデバイスID（広告ID/IDFA）からユーザーを照合します。</li></ul> |
| アプリID | モバイル広告リストタイプに必要です。データがGoogle Ads APIに送信されるモバイルアプリケーションを一意に識別する文字列。 |
| リストメンバーシップの寿命 | （オプショナル）ユーザーがリストに最後に追加されてからリストに残る日数。0から540の間の数字を指定する必要があります。デフォルトの寿命は540日です。 |
| リストの説明 | （オプショナル）リストの説明。 |

## Google AdsとTealiumのリンク

Google Data Manager APIアクションは、Google AdsとTealium間の製品リンクを必要とします。リンクはTealiumまたはGoogle Adsのいずれかで作成できます。どちらのオプションも新しいData Manager APIアクションと、レガシーGoogle Ads APIアクションから移行されたアクションをサポートします。

### オプション1：Tealiumで製品リンクを作成する

このオプションを使用して、コネクタ構成からリンキングプロセスを完了します。

1. TealiumでGoogle Adsカスタマーマッチコネクタを開きます。
1. 新しいコネクタの場合はGoogleで認証します。既存のコネクタの場合は、Google Data Manager APIスコープを含む資格情報で再認証します。
1. コネクタ構成で**TealiumにカスタマーIDをリンク**セクションを見つけます。
1. カスタマーマッチユーザーリストを所有するGoogle AdsカスタマーIDを入力します。
1. **製品リンクの作成**をクリックし、確認メッセージを待ちます。
1. Data Manager APIアクションを構成または移行し、適切なユーザーリストを選択し、リストキータイプに一致する識別子をマッピングします。

アクションが**カスタマーIDオーバーライド**を使用する場合、アクションに使用されるユーザーリストを所有する各顧客アカウントに製品リンクを作成します。

### オプション2：Google Adsで製品リンクを作成する

このオプションを使用して、TealiumのGoogle OAuthフローを使用せずにGoogle Adsで製品リンクを作成します。

1. Google Adsにサインインします。
1. **ツール > データマネージャー**に移動します。
1. **+ 製品を接続**をクリックします。
1. 利用可能な製品からTealiumを選択します。
1. 必要に応じて、使用ケースとして**オーディエンス**を選択します。
1. 顧客データポリシーを確認し、同意した後、リンクを完了します。
1. Tealiumで、リンクされたGoogle Ads顧客アカウントと適切なユーザーリストを使用してData Manager APIアクションを構成または移行します。

リンク後も、アクションに必要な顧客IDとユーザーリストの構成をコネクタアクションで構成する必要があります。

### マネージャーアカウントのリンク

Google Adsマネージャーアカウントの製品リンクを作成することもできます。これにより、そのマネージャーアカウントとその下のクライアントアカウントでリンクを使用できます。

アクションを構成する際は、オーディエンス更新を受け取る特定のGoogle AdsアカウントのカスタマーIDを使用します。マネージャーアカウントリンクは、そのマネージャーアカウント階層外のアカウント（親マネージャーアカウントやリンクされていない子アカウントなど）には拡張されません。

ターゲットのGoogle Adsアカウントには必要な権限があり、ターゲットユーザーリストはアクションに使用される顧客アカウントに属している必要があります。

### ユーザー識別子

各アクションにはユーザー識別子が必要です。ベンダーはこれらの値が正規化され、SHA-256を使用してハッシュ化されることを要求します。各マップされたユーザー識別子の値は、以下の要件を満たすことが期待されます：

* 小文字
* テキストの先頭と末尾からの空白のトリム
* SHA-256でハッシュ化

すでに正規化されハッシュ化された属性をマッピングすることも、コネクタに正規化とハッシュ化を許可することもできます。シナリオに適したマッピングを選択してください。

必要なユーザー識別子は、選択されたユーザーリストのタイプに基づいています。ユーザーリストのタイプは以下のいずれかになります：

* Google Ads API:
  * `CONTACT_INFO`
  * `CRM_ID`
  * `MOBILE_ADVERTISING_ID`
* Google Data Manager API:
  * `CONTACT_ID`
  * `MOBILE_ID`
  * `USER_ID`

以下のユーザー識別子フィールドがサポートされています：

| ユーザー識別子フィールド | 説明 |
|---| ---|
| `CONTACT_INFO` (Google Ads API)|  ハッシュ化されたメール、ハッシュ化された電話番号、または住所情報を提供します。このユーザーデータタイプには、以下にリストされているすべての住所情報フィールドが必要です。<ul><li>**住所情報: 国コード**: ユーザーの住所の2文字の国コード、ISO 3166-1 alpha-2形式。</li><li>**住所情報: 名 (既にSHA256ハッシュ化)**: 空白トリムされ、小文字化され、SHA256ハッシュ化された名を提供します。</li><li>**住所情報: 名 (SHA256ハッシュを適用)**: プレーンテキストの名を提供し、コネクタがこの値をSHA256ハッシュでハッシュ化します。</li><li>**住所情報: 姓 (既にSHA256ハッシュ化)**: 空白トリムされ、小文字化され、SHA256ハッシュ化された姓を提供します。</li><li>**住所情報: 姓 (SHA256ハッシュを適用)**: プレーンテキストの姓を提供し、コネクタがこの値をSHA256ハッシュでハッシュ化します。</li><li>**住所情報: 郵便番号**: ユーザーの住所の郵便番号を提供します。</li><li>**メールアドレス (既にSHA256ハッシュ化)**: 空白トリムされ、小文字化され、SHA256ハッシュ化されたメールアドレスまたはメールアドレスの配列を提供します。</li><li>**メールアドレス (SHA256ハッシュを適用)**: プレーンテキストのメールアドレスまたはメールアドレスの配列を提供し、コネクタがこれらの値をSHA256ハッシュでハッシュ化します。</li><li>**電話番号 (既にSHA256ハッシュ化)**: 空白トリムされ、SHA256ハッシュ化された電話番号または電話番号の配列を提供します。</li><li>**電話番号 (SHA256ハッシュを適用)**: プレーンテキストの電話番号または電話番号の配列を提供し、コネクタが値をSHA256ハッシュでハッシュ化します。</li></ul> |
|`CRM_ID` (Google Ads API)|  <ul><li>**ユーザーID**: (必須) 顧客マッチアップロード用に広告主が割り当てたユーザーID。</li></ul> |
|`MOBILE_ADVERTISING_ID` (Google Ads API)|  <ul><li>**モバイルID**: (必須) モバイルデバイスID (広告ID/IDFA)。</li></ul> |
| `CONTACT_ID` (Data Manager API) | **連絡先情報**: メールアドレス、電話番号、および住所。事前にハッシュ化されたメールおよび電話の値は、64の16進数文字を含む有効なSHA-256 16進数文字列である必要があります。コネクタは無効な値を削除してからリクエストを送信します。住所情報には、国コード、名、姓、郵便番号の4つのフィールドが必要です。いずれかの住所フィールドが欠けている場合、コネクタは住所オブジェクト全体を削除します。有効なユーザー識別子が検証後に残っていない場合、アクションは検証エラーで失敗し、再試行されません。 |
|`MOBILE_ID` (Data Manager API)|  **モバイルID**: モバイルデバイスID。 |
|`USER_ID` (Data Manager API)|  **ユーザーID**: 第一者識別子。 |

### リストへのユーザー追加 (Data Manager API)

#### API情報

このコネクタは以下のベンダーAPIを使用します：

* API名: Google Data Manager API
* APIバージョン: v1
* APIエンドポイント: `https://datamanager.googleapis.com`
* ドキュメント: [Google Data Manager API](https://developers.google.com/data-manager/api/reference/rest)

#### バッチ制限

このアクションは、ベンダーへの大量データ転送をサポートするためにバッチリクエストを使用します。イベントの順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかの閾値が満たされるか、プロファイルが公開されるまでキューに入れられます：

* 最大リクエスト数: 10,000
* 最古のリクエストからの最大時間: 60分
* リクエストの最大サイズ: 40 MB

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| ユーザーリスト | Data Manager APIからユーザーリストを選択します。詳細については、[Data Manager API: 顧客マッチ概要](https://developers.google.com/data-manager/api/devguides/audiences/google-ads/customer-match)を参照してください。 |

#### ユーザー識別子

| パラメータ | 説明 |
| --- | --- |
| 顧客IDオーバーライド | (オプション) コネクタ構成の顧客IDを上書きする顧客IDを提供します。このオプションを使用する場合、ユーザーリストIDオーバーライドも使用する必要があります。 |
| ユーザーリストIDオーバーライド | (オプション) 必要セクションのユーザーリストを上書きするユーザーリストIDを提供します。このフィールドを使用すると、イベント属性を使用してユーザーリストIDを入力できます。このフィールドは、顧客IDオーバーライドを使用する場合に必要です。値はリストIDでなければなりません。例：`9310271231`。 |

#### IPデータ

| パラメータ | 説明 |
| --- | --- |
| IPアドレス | 顧客とのやり取り中にキャプチャされたIPアドレス。 |
| 観察開始時間 | セッション中のIPアドレスからの最初のインタラクションの時間。 |
| 観察終了時間 | セッション中のIPアドレスからの最後のインタラクションの時間。 |

### リマーケティングリストへのユーザー追加 (非推奨)

#### バッチ制限

このコネクタアクションは、ベンダーへの大量データ転送をサポートするためにバッチリクエストを使用することができます。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかの閾値が満たされるか、プロファイルが公開されるまでキューに入れられます：

* 最大リクエスト数: 33,000
* 最古のリクエストからの最大時間: 60分
* リクエストの最大サイズ: 40 MB

#### API情報

このコネクタは以下のベンダーAPIを使用します：

* API名: Google Ads API
* APIバージョン: v24
* APIエンドポイント: `https://googleads.googleapis.com/`
* ドキュメント: [Google Ads API](https://developers.google.com/google-ads/api/docs/start)

#### パラメータ

| **パラメータ** | **説明** |
| --- | --- |
| リマーケティングリスト | リマーケティングユーザーリストを選択します。詳細については、[Google Ads: リマーケティングおよびオーディエンスターゲティング](https://developers.google.com/google-ads/api/docs/remarketing/overview)を参照してください。利用可能なオプションには、第一者CRMデータタイプのユーザーリストのみが含まれます。ユーザーリストを作成するには、[ユーザーリストの作成](#create-user-list)を参照してください。|
| 顧客IDオーバーライド | (オプション) コネクタ構成の顧客IDを上書きする顧客IDを提供します。このオプションを使用する場合、**ユーザーリストIDオーバーライド**も入力する必要があります。 |
| マネージャー顧客IDオーバーライド | (オプション) **顧客IDオーバーライド**を使用してクライアント顧客にアクセスする場合、マネージャー顧客IDを提供します。 |
| ユーザーリストIDオーバーライド | (オプション) ユーザーリストを上書きするユーザーリストリソース名（リストIDとタイプ）を提供します。このフィールドを使用すると、EventStream変数を使用してユーザーリストIDを入力できます。このフィールドは、**顧客IDオーバーライド**を使用する場合に必要です。値は次の形式でなければなりません：`ID:TYPE`、例えば `123456:CONTACT_INFO`。 |

#### 同意

**リマーケティングリストへのユーザー追加**アクションを使用する場合、コネクタは`adUserData`および`adPersonalization`パラメータに`GRANTED`の値を送信します。リストに追加されないようにするために、訪問のプロファイル同意状態をチェックするルールを持つオーディエンスを作成します。その後、**リマーケティングリストから削除**アクションを使用して、同意を与えていない訪問をリストから削除します。
