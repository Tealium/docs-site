## API情報

このコネクタは以下のベンダーAPIを使用します：

* API名：Amazon Ads Events API
* APIバージョン：v1
* APIエンドポイント：`https://advertising-api.amazon.com`
* ドキュメント：[Amazon Ads Events API](https://advertising.amazon.com/API/docs/en-us/guides/events/events)
* タグドキュメント：[Amazon Advertising Tag](https://docs.tealium.com/amazon-advertising-tag/)

## コネクタのヒント

タグとコネクタを使用したハイブリッド構成を推奨します。この構成により、データの耐久性が最大化され、サーバーサイドのシグナルとのイベントマッチングが向上し、リアルタイムのクライアントサイドシグナルを保持しながらデータフローの連続性が維持されます。

## 構成

コネクタマーケットプレイスにアクセスして、新しいコネクタを追加します。コネクタの追加方法についての一般的な説明は、[About Connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、以下の構成を構成します：

* **APIベースURL**：（必須）APIベースURLを選択します。
* **Amazon広告主ID**：（必須）Amazon広告アカウントIDを入力します。

## Webイベントの重複排除

Amazon Adsサーバータグからのイベントを重複排除するために、次の命名規則でイベント属性として送信されるイベントIDを使用してこのコネクタを構成します：

```nohl
amazon_event_id_{EVENT_NAME}_{TAG_UID}
```

タグのUIDは、Tealium iQの**タグ**テーブルまたはタグ詳細画面で見つけることができます：

![](https://docs.tealium.com/images/server-side-connectors/amazon-ad-server-tag-uid.png)

例えば、UIDが`170`のタグからのチェックアウトイベントは、次の属性値を送信します：

```json
{
  "amazon_event_id_checkout_170": "028b2ade7478..."
}
```

同じタグからのページビューイベントは、次の属性と値を送信します：

```json
{
  "amazon_event_id_pageView_170": "028b2ade7478..."
}
```

各タイプのイベントに対して別々のアクションを使用します。イベント固有のイベントID属性を`Event ID`にマッピングし、対応するイベント名を`Event Name`にマッピングします。例えば：

| Tealium属性  | Amazonパラメータ  |
|:-------------------------|:-------------------|
| `amazon_event_id_checkout_170` (属性)   | Event ID           |
| `"Checkout"` (カスタムテキスト) | Event Name         |

### 自動重複排除

**自動重複排除**の値が入力されている場合、コネクタは対応するイベントID属性を探します。Tealium iQを使用している場合、このセクションが入力されていれば`Event ID`を追加する必要はありません。ただし、Tealium iQを使用せずにEventStreamを使用している場合は、以下のアプローチが依然として必要になる場合があります。

コネクタは次の操作順序に従います：

* **自動重複排除**が入力され、値がデータレイヤーで見つかった場合（例：`amazon_event_id_checkout_170`）、この値は`Event ID`にマッピングされたものより優先されます。
* **自動重複排除**が入力されているが、値が見つからない場合、入力されている場合はマッピングされた`Event ID`が使用されます。

### コンバージョン送信

#### バッチ制限

このアクションは、ベンダーへの高容量データ転送をサポートするためにバッチリクエストを使用します。並行処理により、イベントがベンダーに順不同で到達する可能性があります。イベントの順序が重要な場合は、イベントにシーケンス値を追加します。詳細については、[Batched Actions](https://docs.tealium.com/batched-actions/)を参照してください。次のいずれかの閾値に達するか、プロファイルが公開されるまでリクエストはキューに入れられます：

* 最大リクエスト数：500
* 最古のリクエストからの最大時間：10分
* リクエストの最大サイズ：1 MB

#### パラメータ

| パラメータ | 説明 |
| --- | --- |
| コンバージョンタイプ | インポートされるイベントのコンバージョンタイプを選択します。可能な値は`ADD_TO_SHOPPING_CART`, `APPLICATION`, `CHECKOUT`, `CONTACT`, `LEAD`, `OFF_AMAZON_PURCHASES`, `MOBILE_APP_FIRST_START`, `PAGE_VIEW`, `SEARCH`, `SIGN_UP`, `SUBSCRIBE`, `OTHER`です。 |
| コンバージョンソース | インポートされるイベントのコンバージョンソースを選択します。可能な値は`ANDROID`, `FIRE_TV`, `IOS`, `OFFLINE`, `WEBSITE`, `MEASUREMENT_PARTNER`です。 |

#### コンバージョンデータ


<blockquote>

`Name`フィールドをページ名、ページURL、パス名、クエリ文字列、検索用語などの高カーディナリティまたは動的データにマッピングしないでください。これにより、制限がすぐに使い果たされる可能性があります。
</blockquote>

| 値 | イベントの値。 |

#### ユーザーデータ

Amazonは、最も正確なものから最も不正確なものまで、識別子を評価することによってアップロードされたレコードをAmazon Adsユーザーと照合します。サポートされている識別子タイプは3つあります：ハッシュ化されたPII、モバイル広告ID（MAIDs）、および外部IDです。

メールはAmazonアカウントの作成に使用される主要な認証情報であり、Amazonのアイデンティティグラフで最も広範囲にわたるカバレッジを持っているため、最も高いマッチ率を生み出します。電話とMAIDは単独の識別子として機能しますが、マッチ率は低くなります。電話番号はホーム庭内のメンバーやキャリアによって再利用される可能性があります。MAIDは継続的に廃止されています。


<blockquote>
マッチ率を最大化するために、メールを優先として複数の識別子タイプをマッピングすることをお勧めします（例：メール + 電話 + MAID）。現在のマッチ率が許容できる場合、ハッシュ化されたメールを追加することが最も影響力のある改善策です。
</blockquote>

#### 変換定義の作成

変換定義を作成するには、**変換定義の作成**をクリックし、次の情報を提供してください：

* **広告プロファイル**：（必須）この変換のための広告プロファイルを選択します。
* **変換定義名**：（必須）変換定義の名前。
* **ソースタイプ**：（必須）変換のソースタイプを選択します。利用可能なタイプには、`ADD_TO_SHOPPING_CART`, `APPLICATION`, `CHECKOUT`, `CONTACT`, `LEAD`, `OFF_AMAZON_PURCHASES`, `PAGE_VIEW`, `SEARCH`, `SIGN_UP`, `SUBSCRIBE`, `OTHER`があります。
* **変換タイプ**：（必須）変換のタイプを選択します。利用可能なタイプには、`ANDROID`, `FIRE_TV`, `IOS`, `OFFLINE`, `WEBSITE`があります。
* **カウント方法**：（必須）変換定義のために、24時間のウィンドウ内でユーザーごとにすべての変換イベントを使用するか、最初の変換イベントのみを使用するかを決定する方法を選択します。利用可能な方法には、`EVERY`と`FIRST`があります。
* **変換値**：（オプション）変換の値。デフォルト値は`1`で、**送信変換**アクションでマッピングを通じて上書きすることができます。

変換定義を保存するには、**完了**をクリックしてください。

広告データマネージャコンソールの変換ページまたはTerms API（`POST /adm/terms`）を使用して、利用規約を必ず受け入れてください。

| MAID | モバイル識別子。可能な値は `MAID`, `ADID`, `IDFA`, `FIREADID` です。 |
