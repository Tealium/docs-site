## API情報

このコネクタは、次のベンダーAPIを使用します。

* API名：Amazon Ads Events API
* APIバージョン：v1
* APIエンドポイント：`https://advertising-api.amazon.com`
* ドキュメント：[Amazon Ads Events API](https://advertising.amazon.com/API/docs/en-us/guides/events/events)
* タグのドキュメント：[Amazon Advertisingタグ](https://docs.tealium.com/amazon-advertising-tag/)

## コネクタに関するヒント

タグとコネクタの両方を使用するハイブリッド構成をお勧めします。この構成により、データの耐障害性を最大限に高め、サーバーサイドシグナルによるイベントマッチングを改善し、リアルタイムのクライアントサイドシグナルを維持しながらデータフローの継続性を確保できます。

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **APIベースURL**：（必須）APIベースURLを選択します。
* **Amazon広告主ID**：（必須）Amazon AdvertisingアカウントIDを入力します。
* **Amazon AdsマネージャーアカウントID**：（任意）広告主IDに関連付けられたAmazon Adsマネージャーアカウントの識別子です。値が入力されている場合、Tealiumはその値を`Amazon-Ads-Manager-AccountId`リクエストヘッダーとして送信します。構成されていない場合、コネクタはこのヘッダーを省略します。

## Webイベントの重複排除

Amazon Ads Serverタグからのイベントを重複排除するようにこのコネクタを構成するには、次の命名規則に従ってイベント属性として送信されるイベントIDを使用します。

```nohl
amazon_event_id_{EVENT_NAME}_{TAG_UID}
```

タグのUIDは、タグ管理の**タグ**テーブルまたはタグの詳細画面で確認できます。

![](https://docs.tealium.com/images/server-side-connectors/amazon-ad-server-tag-uid.png)

たとえば、UIDが`170`のタグからのチェックアウトイベントでは、次の属性値が送信されます。

```json
{
  "amazon_event_id_checkout_170": "028b2ade7478..."
}
```

同じタグからのページビューイベントでは、次の属性と値が送信されます。

```json
{
  "amazon_event_id_pageView_170": "028b2ade7478..."
}
```

イベントタイプごとに個別のアクションを使用します。イベント固有のイベントID属性を`Event ID`にマッピングし、対応するイベント名を`Event Name`にマッピングします。例：

| Tealium属性 | Amazonパラメータ |
|:-------------------------|:-------------------|
| `amazon_event_id_checkout_170`（属性） | イベントID |
| `"Checkout"`（カスタムテキスト） | イベント名 |

### 自動重複排除

**自動重複排除**の値が入力されている場合、コネクタは対応するイベントID属性を検索します。このセクションに値が入力され、タグ管理を使用している場合は、`Event ID`を追加する必要はなくなります。ただし、タグ管理を使用せずにイベントストリーミングを使用する場合は、次の方法が引き続き必要になることがあります。

コネクタは次の順序で処理します。

* **自動重複排除**に値が入力され、その値がデータレイヤー内に存在する場合（例：`amazon_event_id_checkout_170`）、この値が`Event ID`にマッピングされた値より優先されます。
* **自動重複排除**に値が入力されていても、その値が見つからない場合は、値が入力されていれば、マッピングされた`Event ID`が使用されます。

### コンバージョンを送信

#### バッチ処理の制限

このアクションは、ベンダーへの大量のデータ転送をサポートするために、バッチリクエストを使用します。並列処理により、イベントが順不同でベンダーに到達する場合があります。順序が重要な場合は、イベントにシーケンス値を追加してください。詳細については、[バッチアクション](https://docs.tealium.com/batched-actions/)を参照してください。リクエストは、次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまでキューに入れられます。

* リクエストの最大数：500
* 最も古いリクエストからの最大経過時間：10分
* リクエストの最大サイズ：1 MB

#### ユーザーデータ

Amazon は、アップロードされたレコードを、精度の高い識別子から低い識別子の順に評価して Amazon Ads ユーザーと照合します。サポートされる識別子の種類は、ハッシュ化された PII、モバイル広告 ID（MAID）、外部 ID の 3 種類です。

メールアドレスは、Amazon アカウントの作成に使用される主要な認証情報であり、Amazon の ID グラフで最も広く網羅されているため、最も高いマッチ率を実現します。電話番号と MAID は単独の識別子として機能しますが、マッチ率は低くなります。電話番号は世帯内の複数のメンバーで共有される場合や、通信事業者によって再利用される場合があります。MAID は段階的な廃止が進められています。

次の識別子タイプでは、ハッシュ化は必要ありません：MAID、Ramp ID、Real ID、Merkle ID、Kantar ID、IP、Match ID。


<blockquote>
マッチ率を最大化するには、メールアドレスを優先し、複数の識別子タイプ（例：メールアドレス + 電話番号 + MAID）をマッピングすることをお勧めします。現在のマッチ率が許容範囲内である場合、ハッシュ化されたメールアドレスの追加が、最も大きな改善効果を得られる方法です。
</blockquote>

#### コンバージョン定義の作成

コンバージョン定義を作成するには、**コンバージョン定義を作成**をクリックし、次の情報を入力します。

* **広告プロファイル**：（必須）このコンバージョンに使用する広告プロファイルを選択します。
* **コンバージョン定義名**：（必須）コンバージョン定義の名前。
* **ソースタイプ**：（必須）コンバージョンのソースタイプを選択します。使用可能なタイプは、`ADD_TO_SHOPPING_CART`、`APPLICATION`、`CHECKOUT`、`CONTACT`、`LEAD`、`OFF_AMAZON_PURCHASES`、`PAGE_VIEW`、`SEARCH`、`SIGN_UP`、`SUBSCRIBE`、`OTHER` です。
* **コンバージョンタイプ**：（必須）コンバージョンのタイプを選択します。使用可能なタイプは、`ANDROID`、`FIRE_TV`、`IOS`、`OFFLINE`、`WEBSITE` です。
* **カウント方法**：（必須）コンバージョン定義について、24 時間以内に取り込まれたユーザーごとのコンバージョンイベントをすべて使用するか、最初のイベントのみを使用するかを決定する方法を選択します。使用可能な方法は、`EVERY` と `FIRST` です。
* **コンバージョン値**：（任意）コンバージョンの値。デフォルト値は `1` で、**コンバージョンを送信**アクションのマッピングによって上書きできます。

コンバージョン定義を保存するには、**完了**をクリックします。

コンバージョンページの Ads Data Manager コンソール、または Terms API（`POST /adm/terms`）を使用して、必ず利用規約に同意してください。
