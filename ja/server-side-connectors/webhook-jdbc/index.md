このコネクタは、次のデータベースと互換性があります。

* Amazon Redshift
* MariaDB
* MySQL
* PostgreSQL
* SQL Server

## バッチ制限

このコネクタは、ベンダーへの大量のデータ転送に対応するため、バッチリクエストを使用します。リクエストは、次の3つのしきい値のいずれかに達するまでキューに格納されます。

* リクエストの最大数：1,000
* 最も古いリクエストからの最大経過時間：60分
* リクエストの最大サイズ：100 MB

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **ユーザー名**：Tealiumからデータベースにログインするためのユーザー名です。セキュリティ上の理由から、このユーザーには、これらの[IPアドレス](https://docs.tealium.com/ip-allow-list/)からの接続のみを許可してください。
* **パスワード**：指定したユーザー名のパスワードです。
* **JDBC URL**：接続を確立するための完全修飾JDBC URLです（例：`jdbc:postgresql://host:5432/dbname?p1=a&p2=b`）。
* **追加プロパティ**：接続を確立するときにプロパティとして渡す、カンマ区切りのペアのセットです。たとえば、`prop1=a,prop2=b`を指定すると、接続は次のように調整されます。

コネクタを構成したら、**完了**をクリックします。

    ```java
    props.setProperty("prop1", "a");
    props.setProperty("prop2", "b");
    Connection conn = DriverManager.getConnection(url, props);
    ```

### 列のデータ型

属性をテーブル列に簡単にマッピングできるように、列名にはデータ型がエンリッチメントされて表示されます。たとえば、`VARCHAR`型の`customer_id`という列がある場合、マッピングリストには`customer_id//VARCHAR`と表示されます。

### バッチ構成

バッチ処理をサポートするすべてのアクションでは、次のパラメータを使用できます。

| **パラメータ** | **説明** |
| --- | --- |
| バッチの存続時間 | 存続時間（`TTL`）を構成して、バッチアクションを送信する頻度を指定します。`1`～`60`分の値を入力します。デフォルト値は`10`分です。 |
| 最大クエリサイズ | クエリの最大サイズをメガバイト単位で構成します。デフォルト値は`1`です。最大値は`100`です。 |

| **パラメータ** | **説明** |
| --- | --- |
| スキーマ | 接続するスキーマ名です。 |
| テーブル | 接続するテーブル名です。 |
| ペイロード | JSONデータオブジェクトを保存する列を選択します。 |
| タイムスタンプ | タイムスタンプを記録する列を選択します。 |

#### ログイベントのリソース属性

これらのフィールドには、テレメトリが記録されるエンティティに関する情報が格納されます。

#### ログイベントのHTTP属性

これらのフィールドには、ログシステム内のHTTPリクエストとレスポンスが記録されます。

HTTP配列全体を単一の列にマッピングする場合は、`http`属性をマッピングします。ターゲット列の型が`VARIANT`の場合は未加工の配列が送信され、それ以外の場合は文字列に変換されます。

#### ログイベントの結果属性

これらのフィールドには、処理が成功したか、エラーが発生したかなど、処理の結果が記録されます。

#### ログイベントのその他の属性

これらのフィールドには、ログに記録されたイベントに関する追加のメタデータが格納されます。

### カスタムクエリの実行

このアクションを使用して、カスタムSQLステートメントを実行します。

使用できるのは `INSERT`、`UPDATE`、`MERGE` ステートメントのみですが、`SELECT` サブクエリを含めることができます。同じクエリに複数の `INSERT`、`UPDATE`、`MERGE` ステートメントを含めると、エラーが発生します。

この機能を使用するには、属性を名前付きプレースホルダーにマッピングし、SQL内で `:MY_PLACEHOLDER` 形式を使用して参照します。たとえば、ブール属性を `:my_bool_param` という名前のプレースホルダーにマッピングした場合、その値をマッピングされた属性の値に置き換える箇所で、クエリ内の `:my_bool_param` を参照します。

例：

```sql
-- Example
INSERT INTO redshift_table
(col1, col2) VALUES (:col1Value, :col2Value)

-- Example
UPDATE redshift_table
SET col1 = :col1Value, col2 = :col2Value
WHERE col3 = :col3Value

-- Example
UPDATE redshift_table
SET col2 = (
  SELECT new_col2 FROM source_table WHERE source_table.col1 = redshift_table.col1
)
WHERE EXISTS (
  SELECT 1 FROM source_table WHERE source_table.col1 LIKE :col1Value
);
```

#### パラメーター

| **パラメーター** | **説明** |
| --- | --- |
| Schema | 接続先のスキーマ名。 |
| Query Parameters | クエリ内で置き換えるプレースホルダーにパラメーターをマッピングします。パラメーターは `:ParameterName` 形式で指定する必要があります。少なくとも1つのパラメーターをマッピングする必要があります。 |
| Query | `SQL` 属性に渡す未加工のステートメント。 |
