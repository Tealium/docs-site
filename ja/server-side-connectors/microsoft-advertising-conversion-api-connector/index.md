## 概要

広告主は、Microsoft Advertising Conversion APIを使用して、WebおよびオフラインのコンバージョンイベントをMicrosoft Advertisingに直接送信します。このコネクタにより、アトリビューションのエンリッチメント、シグナルの耐障害性、およびプライバシーを重視した測定が可能になります。

Microsoft Advertising Conversion APIは、単独の統合として使用することも、Microsoft UETタグと併用することもできます。二重配信の構成では、UETタグがクライアント側のイベントをリアルタイムで送信し、Cookieの消失、JavaScriptの制限、またはオフラインコンバージョンが発生した場合には、Conversion APIがイベントを確実に配信します。両方の方法を使用することで冗長性が確保され、カスタマージャーニー全体のカバレッジが向上します。

## バッチ処理の制限

このコネクタは、ベンダーへの大容量データ転送をサポートするため、リクエストをバッチ処理します。詳細については、「Batched Actions」を参照してください。リクエストは、次のいずれかのしきい値に達するか、プロファイルがパブリッシュされるまでキューに格納されます。

* リクエストの最大数：1,000
* 最も古いリクエストからの最大経過時間：10分
* リクエストの最大サイズ：1 MB

## 前提条件

* **Microsoft Adsアカウント**：UETタグとCAPIへのアクセス権を持つ、有効なMicrosoft Advertisingアカウント。
* **UETタグID**：オンラインまたはオフラインのコンバージョンについて、Tealiumによるサーバー側トラッキングのみを使用する場合でも、Microsoftではアトリビューションとオーディエンスの関連付けにUETタグIDが必要です。Microsoft AdsプラットフォームでUETタグIDを確認してください。必要に応じて、既存のタグを使用するか、新しいUETタグIDをプロビジョニングします。
* **アクセストークン**：CAPI用のMicrosoft Developerトークン。詳細については、[アクセストークンの生成](#generate-access-token)を参照してください。
* **コンバージョン目標**：MicrosoftがCAPIイベントを正しくアトリビューションできるようにするため、UETタグに関連付けられたコンバージョン目標を少なくとも1つ作成します。
    1. **Tools > Conversion Goals**に移動します。
    1. **+ New Conversion Goal**をクリックします。
    1. 目標タイプ（購入、リード、予約など）を選択します。
    1. UETタグIDに関連付けます。

## 構成

コネクタマーケットプレイスに移動し、新しいコネクタを追加します。詳細については、[about-connectors](https://docs.tealium.com/about-connectors/)を参照してください。

コネクタを追加した後、次の構成を構成します。

* **UET tagID**：既存のタグを使用するか、Microsoft Advertisingアカウントで新しいUETタグIDをプロビジョニングできます。
* **Access Token**：Microsoft Advertisingアカウントのアクセストークン。

コネクタを構成したら、**Done**をクリックします。

### アクセストークンの生成

Microsoft Advertising Conversion APIのアクセストークンを生成するには、次の手順に従います。

1. Microsoft Adsアカウントで、**Conversions > UET tag**に移動します。
1. タグ名にカーソルを合わせ、鉛筆アイコンをクリックします。
    * **Industry**の値を選択する必要がある場合があります。
1. **Save and next**をクリックします。
1. **Use Conversions API**をクリックします。
1. **Save and next**をクリックします。
1. 後で参照できるように、トークンを安全な場所に保存します。このトークンは接続の確立に必要です。
1. タグを保存します。

## 重複排除

Microsoft Advertising Universal Event Tracking（UET）タグからのイベントを重複排除するようにこのコネクタを構成するには、次の命名規則に従ってイベント属性として送信されるイベントIDを使用します。

```
microsoft_event_id_{EVENT_NAME}}_{TAG_ID}}
```

タグのUIDは、タグ管理のタグテーブルまたはタグの詳細画面で確認できます。

たとえば、UIDが88のタグからの購入イベントでは、次の属性値が送信されます。

```
microsoft_event_id_purchase_88: “084b1cda7461…”
```

同じタグからのページ読み込みイベントでは、次の属性値が送信されます。

```
microsoft_event_id_pageload_88: “028b2ade7478…”
```

### 自動重複排除

Automatic Deduplicationの値が入力されている場合、コネクタは対応するイベントID属性を検索します。このセクションに値が入力されており、タグ管理を使用している場合は、Event IDを追加する必要はありません。ただし、タグ管理を使用せずにEventStreamを使用する場合は、次の方法が引き続き必要になることがあります。

コネクタは、次の優先順位で処理します。

* Automatic Deduplicationに値が入力されており、その値がデータレイヤーで見つかった場合（例：`microsoft_purchase_id_88`）、この値がEvent IDにマッピングされた値より優先されます。
* Automatic Deduplicationに値が入力されており、タグIDを含むバージョンが見つからないものの、従来のバージョン（IDがエンリッチメントされていないもの）が見つかった場合は、その値が使用されます（例：`microsoft_purchase_id`）。
* Automatic Deduplicationに値が入力されているものの、その値が見つからない場合は、Event IDにマッピングされた値が入力されていれば、その値が使用されます。

## オフラインコンバージョン

Microsoft Advertising Conversion APIコネクタを通じてオフラインイベントと店舗イベントを処理するには、必須パラメータを含めるようにコネクタを構成します。

オンラインコンバージョンの場合、アトリビューションは通常リアルタイムで行われます。オフラインコンバージョンの場合、Microsoftは最大90日前まで遡ったイベントをサポートしています。イベントをリアルタイムに近いタイミングで送信するほど、アトリビューションの精度が向上します。

### 前提条件

* **オフラインコンバージョンのインポートを有効にする**：Tealiumから送信されたCAPIイベントをMicrosoft Adsが取り込めるようにするには、この機能を有効にする必要があります。
    1. **Tools > Offline Conversions**に移動します。
    1. **Import Conversions**を選択します。
    1. **Microsoft (Offline conversions via API)**を選択します。
* **コンバージョン目標をUETタグに関連付ける**：Microsoftが広告インタラクションにコンバージョンをアトリビューションできるようにするには、この構成を有効にする必要があります。
    1. **Tools > Conversion Goals**に移動します。
    1. **+ New Conversion Goal**をクリックします。
    1. オフラインイベントに関連する目標タイプ（**In-Store Purchase**、**Phone Booking**、**Loan Application**など）を選択します。
    1. **Goal Source**で、**Offline Conversions (Import via file or API)**を選択します。
    1. 目標を既存のUETタグIDに関連付けます。
* **UETタグIDが存在することを確認する**：タグ自体がデプロイされていない場合でも、目標で参照されているUETタグIDがMicrosoft Adsに存在することを確認します。
* **イベントとともにクリックIDまたはハッシュ化されたPIIを渡す**：これにより、Microsoftは照合を実行できます。
## ベストプラクティス

* **クリック ID を永続化する**：Microsoft Click ID（`msclkid`）は、コンバージョントラッキングに不可欠です。Microsoft Ads で自動タグ構成が有効になっている場合、ユーザーが広告をクリックすると、この識別子がランディングページ URL にクエリパラメータとして追加されます。[Persist Data Values 拡張機能](https://docs.tealium.com/persist-data-value-extension/)を使用してクリック ID を永続化すると、サーバー側で利用できるようになります。Cookie 属性をサーバー側でマッピングしてください。クリック ID がない場合、Microsoft はコンバージョンを発生元の広告クリックに関連付けられない可能性があり、アトリビューションの損失や入札最適化の低下につながります。
* **クリックのたびにページ読み込みイベントを発生させる**：すべてのページビューまたはシングルページアプリケーション（SPA）のナビゲーションで、ページ読み込みイベントを 1 回発生させる必要があります。また、1 つ以上のカスタムイベントを発生させることもできます。各カスタムイベントは、`pageLoadId` パラメータを介してページ読み込みイベントにリンクされます。
* **Microsoft ID Beacon Sync を有効にする**：ID 解決とリマーケティングのパフォーマンスを向上させるため、Microsoft UET タグで Microsoft ID Beacon Sync を有効にします。この機能はデバイス間の ID 統合をサポートし、オンライン行動とオフラインコンバージョンを照合する能力を向上させます。
* **デフォルトで同意済み**：デフォルトでは、Microsoft はすべてのイベントを同意済みの状態として処理します。明示的な同意シグナルを使用する必要がある場合は、`adStorageConsent` パラメータで次のオプションを使用できます。
    * `G` = 同意済み。
    * `D` = 拒否。拒否されたイベントは、コンバージョンアトリビューションやリターゲティングを含む、いかなる広告目的にも使用されません。
* **電話番号とメールアドレスの厳格な形式**：SHA256 でハッシュ化された PII を使用する場合は、次の書式ルールに従ってください。
    * 電話番号は E.164 標準に従って書式構成します。
    * メールアドレスの場合：
        * メールアドレスの先頭と末尾から空白文字を削除します。
        * 文字列を小文字にします。
        * `+` と `@` の間にあるすべての文字を削除します（たとえば、`user+withplus@example.com` は `user@example.com` になります）。
        * `@` より前のピリオドを削除します（たとえば、`us.er@example.com` は `user@example.com` になります）。
        * メールアドレスに `@` 記号が含まれていることを確認します。
        * すべてのスペースを削除します。
        * `@` の後に `.com` などのピリオドが含まれていることを確認します。
        * ピリオドで始まったり終わったりしていないことを確認します。
        * アクセント記号をすべて削除します（たとえば、`à`）。
* UET タグで **Event ID Generation** を有効にして、自動重複排除を有効化します。**Automatic Deduplication** マッピングセクションに **Tag ID** を入力します。Microsoft は配信方法間で一致する ID を検出し、重複カウントを防止します。この手順は、データの整合性を維持するために、二重配信の構成で重要です。

## よくある質問

* **UET タグなしで Microsoft Advertising Conversion API を使用できますか？**  
はい。ただし、推奨されません。Microsoft Advertising Conversion API は単独でも機能しますが、Microsoft は UET タグと Conversion API の両方を実装することを強く推奨しています。両方の方法を使用すると、シグナル損失を補うことでアトリビューションの精度が向上します。
* **タグとコネクタで同じコンバージョンを送信できますか？**  
はい。必須ではありませんが、強く推奨されます。Microsoft は、過剰カウントを防ぐための重複排除をサポートしています。両方のチャネルからコンバージョンを送信することで耐障害性が確保され、一方が失敗しても、もう一方でイベントを正しくアトリビューションできます。
* **クリック ID なしでコンバージョンを送信できますか？**  
必要な場合、またはクリック ID を利用できない場合に限り可能です。クリック ID は、コンバージョンを Microsoft/Bing 広告のクリックに関連付ける最も正確な方法です。フォールバックとしてハッシュ化された PII を送信することもできますが、特にスマート自動入札やレポートでは、コンバージョンの照合品質が低下する可能性があります。
* **このコネクタをリードフォームや電話通話に使用できますか？**  
はい。このコネクタを使用して、リードフォームの入力完了、事前審査の送信、コールセンターイベントを送信できます。これは、オフラインコンバージョン量が多い金融、自動車、旅行業界に最適です。

| Tealium iQ Tag ID | タグ管理のタグIDを指定すると、コネクタはタグ管理から送信されたイベントID値を自動的に検索します。 |

##### 自動マッピングの無効化

| **パラメータ** | **説明** |
