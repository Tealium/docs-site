この例では、小売業者の Tealium 環境全体で 1 人の顧客 Alex を追跡します。

## Web サイトとアプリからイベントを収集する

Alex はログインせずに小売業者の Web サイトを訪れ、複数のランニングシューズを閲覧します。収集タグは各商品の閲覧をイベントとして Tealium に送信します。各イベントには、商品 ID やカテゴリなどの属性が含まれます。Tealium は Alex の新しい匿名ビジタープロファイルを作成し、イベントを受信するたびに更新します。その後、Alex がモバイルアプリを開くと、Tealium はアプリ用に別のビジタープロファイルを作成します。

詳細については、[顧客データを収集する](https://docs.tealium.com/collect-customer-data/)を参照してください。

## プロファイルを統合して属性を更新する

Alex はメールアドレスを使用してアプリにログインします。メールアドレスがビジター ID 属性に構成され、ビジタースティッチングによって Alex の Web とアプリのプロファイルが 1 つに統合されます。エンリッチメントにより Alex のお気に入りカテゴリがランニングシューズに構成され、Alex は `High-intent shoppers` オーディエンスに追加されます。

詳細については、[ビジタープロファイルを構築する](https://docs.tealium.com/build-visitor-profiles/)を参照してください。

## データをリアルタイムでアクティベートする

Alex はランニングシューズをカートに追加しますが、購入せずにサイトを離れます。Alex は `Cart abandoners` オーディエンスに追加され、オーディエンスアクションが Alex のプロファイルデータをメールプラットフォームに送信し、そのプラットフォームからリマインダーが送信されます。翌日、Alex はアプリを開きます。アプリは Alex の最新のプロファイルデータをリクエストし、ランニングシューズを最初に表示します。

詳細については、[顧客データをアクティベートする](https://docs.tealium.com/activate-customer-data/)を参照してください。

## データクラウドからデータを追加する

毎晩、小売業者のデータクラウド内のモデルが、顧客の離反リスクをスコアリングします。クラウドデータソースが Alex のスコアをインポートし、Alex のプロファイルが更新されます。これとは別に、マーケティングチームは、最近購入した顧客のセグメントを Tealium にデータをコピーすることなくインプレースでアクティベートし、それらの顧客を有料メディアキャンペーンから除外します。

詳細については、[データクラウドを活用する](https://docs.tealium.com/work-with-your-data-cloud/)を参照してください。

## AI エージェントに顧客のコンテキストを提供する

Alex は、注文の遅延についてサポートに問い合わせます。AI エンリッチメントは、Alex の最近の閲覧履歴から、Alex が商品を比較していることをすでに推測しています。サポートチームの AI エージェントは、Context API MCP サーバーを通じて Alex のプロファイルを取得し、離反リスクスコアが高いことを確認して、次回の注文で利用できる割引を提案します。

詳細については、[Tealium で AI を使用する](https://docs.tealium.com/use-ai-with-tealium/)を参照してください。

## 同意の変更を尊重する

Alex は Web サイトでマーケティングへの同意を撤回します。同意管理ツールがマーケティングタグをブロックし、同意オーケストレーションによって、イベントコネクタからマーケティングベンダーへの Alex のイベント送信が停止されます。Alex をオーディエンスコネクタの対象から除外するために、小売業者は手動の同意適用を使用します。

詳細については、[顧客データをガバナンスする](https://docs.tealium.com/govern-customer-data/)を参照してください。
