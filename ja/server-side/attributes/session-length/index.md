## 仕組み

セッションの長さによって、訪問が終了するタイミングが決まります。新しいイベントが発生しないままセッションの長さに達すると、訪問が終了し、訪問終了時の処理が実行されます。その訪問から次のイベントが送信されると、新しい訪問が開始されます。イベントの発生状況にかかわらず、訪問の最大時間は24時間です。

## セッションの長さ

Customer Data Platform（CDP）では、イベントを送信するプラットフォームに基づいて、デフォルトのセッションの長さが構成されます。

* **Web**：複数のイベントがある場合は30分、後続イベントのない単一イベントの場合は10分。
* **Mobile App**：2分。
* **Omnichannel**：1分。
* **File Import**：1分。
* **Collect API**：30分。
* **All Others**：30分。

プラットフォームは、`platform` という名前の予約済み属性について、次の値に基づいて判定されます。

* **Mobile**：`platform` が `android`、`ios`、`win`、`bb10`、または `native_mobile` のいずれかに構成されている場合。
* **Web**：`platform` が `web` に構成されているか、構成されていない場合。

## セッションの長さをカスタマイズする

セッションの長さをカスタマイズするには、セッションの最初のイベントで、データレイヤー変数 `_dc_ttl_` にミリ秒単位の値を構成します。`_dc_ttl_` の最小値は `5000`（5秒）、最大値は `1800000`（30分）です。たとえば、セッションの長さを5分に構成するには、イベントに `"_dc_ttl_": 300000` を追加します。一度構成したセッションの長さは変更できません。


<blockquote>
カスタムのセッションの長さを構成する場合は、`platform` 変数を構成しないでください。`platform` にカスタム値を構成すると、セッションの長さはデフォルトの30分になります。
</blockquote>
