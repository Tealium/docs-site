## 仕組み

タイムライン属性は、指定された期間に発生したイベントのリストを記録します。キャプチャされたイベントによって、キャプチャされた属性値とタイムスタンプを含むエントリがタイムラインに生成されます。タイムスタンプには、イベントの発生時刻、または別の属性から取得した日時を使用できます。タイムスタンプは Unix/Epoch 形式で記録されます。

タイムライン属性は、訪問スコープと訪問スコープで使用できます。

![](https://docs.tealium.com/images/server-side/screenshot-2019-11-11-at-1.26.28-pm.png)

### サイズ制限

タイムライン属性のエントリ数は最大100件に制限されています。タイムラインがこの上限に達すると、最も古いエントリから破棄されます（先入れ先出し）。たとえば、タイムラインに100件のエントリが含まれている状態で新しいエントリが追加されると、最初のエントリが削除されます。

タイムラインの最大期間は365日です。

また、タイムライン属性は、暗号化および圧縮後のプロファイルの最大サイズ（400 KB）によっても制限されます。

## 属性データのキャプチャ

イベントのタイムスタンプに加えて、イベント発生時に1つ以上の属性値をキャプチャすることもできます。キャプチャされた属性値により、イベント発生時の詳細情報が得られます。エンリッチメントを使用して集計できる属性タイプは数値と集計のみであるため、キャプチャに有用な属性タイプも数値と集計のみです。

たとえば、購入ごとの注文合計を追跡するには、購入タイムラインで属性 `order_total` をキャプチャします。


<blockquote>
[Trace](https://docs.tealium.com/about-trace/) で最新の訪問プロファイルを表示し、タイムラインを確認してください。
</blockquote>


## エントリの有効期限

タイムライン内のエントリは、構成された日数が経過すると期限切れになるように構成できます。この有効期限はタイムライン内のエントリにのみ適用され、タイムライン属性自体には適用されません。有効期限は各訪問の開始時に評価されます。エントリが有効期限より古い場合、そのエントリはタイムラインから削除されます。

数値エントリを使用すると、タイムラインのエントリに基づく移動合計や移動平均値を容易に作成できるため、タイムラインは数値との併用に適しています。

## ベストプラクティス

タイムラインのエントリ数は100件に制限されています。他の属性と同様に、タイムラインも[圧縮後400 KB](https://docs.tealium.com/about-attributes/#storage-capacity-limits)という訪問プロファイルの最大サイズに影響します。

タイムライン属性を効率的に使用するため、次の方法をお勧めします。

* 必要以上に長期間、情報をタイムラインに保存しないでください。タイムラインのエントリに有効期限を構成してください。
* AudienceStore や別のコネクタにタイムラインのエントリを送信するなど、特別なユースケースがない限り、他の属性をタイムラインに保存しないでください。ほとんどの属性タイプをタイムラインに保存できますが、タイムラインから他の顧客データプラットフォーム（CDP）属性にエンリッチできるのは、数値と集計のみです。たとえば、タイムラインのエントリに含まれる数値の合計を取得したり、エントリに含まれる集計を集約したりできます。他の属性タイプも保存できますが、保存した値を集約するエンリッチメントはありません。
<blockquote>
タイムラインのエントリに他の属性を保存すると、訪問プロファイルのサイズが増加します。
</blockquote>

* タイムラインを戦略的に使用することで、各タイムラインのエントリ数とタイムラインの総数を最小限に抑えることができます。
  * タイムライン属性を使用してイベントを効率的にカウントするには、対象イベントの発生時に訪問数を増分し、訪問終了時にその訪問数をタイムラインに保存します。
  * 訪問開始時に総数を取得するには、合計エンリッチメントを使用してタイムライン属性内の訪問数を加算し、数値属性に保存します。その後、訪問中にこの数値を増分することで、常に最新の状態を維持できます。
  * 同じ期間に複数の数値を保存する場合は、すべてを1つのタイムラインに保存します。

## エンリッチメント

### タイムラインの更新

このエンリッチメントを使用して、タイムラインにエントリを記録します。このエンリッチメントを追加するには、**エントリを作成**をクリックし、**タイムラインを更新**を選択します。

エントリのタイムスタンプを記録する方法として、次のいずれかのオプションを選択します。

* **イベント受信時刻（デフォルト）**  
イベントの発生時に、エントリのタイムスタンプが自動的に構成されます。
* **日付に基づく**  
エントリのタイムスタンプが別の属性の値に構成されます。文字列属性を選択する場合は、[日付フォーマッター](https://docs.tealium.com/date-attribute/)も使用して、想定される値と一致する日時パターンを作成する必要があります。

エントリ内の属性値をキャプチャするには、ドロップダウンリストから属性を選択し、**属性を追加**をクリックします。追加した属性は、キャプチャ対象の属性として表示されます。エントリにキャプチャする属性ごとに、この手順を繰り返します。

#### 例

**属性名**：過去60日間の注文  
**キャプチャされた属性：** `order_subtotal` および `order_total`  

**JSON データの例**：

```json
"Orders Last 60 Days" : [
  {
    "timestamp" : 1576862494000,
    "snapshot" : {
      "order_total" : 44.00,
      "order_subtotal" : 38.00
    }
  },
  {
    "timestamp" : 1577640094000,
    "snapshot" : {
      "order_total" : 100.00,
      "order_subtotal" : 95.00
    }
  },
  {
    "timestamp" : 1578849694000,
    "snapshot": {
      "order_total" : 60.00,
      "order_subtotal" : 59.00
    }
  }
]
```

### タイムラインイベントの有効期限の構成

このエンリッチメントを使用して、エントリが記録されてからの日数に基づき、そのエントリをタイムラインから削除する時期を決定します。有効期限の構成より古い各エントリは、タイムラインから自動的に削除されます。タイムラインエントリの有効期限は、訪問の開始時に評価されます。


<blockquote>
有効期限はタイムライン自体には適用されず、タイムライン内のエントリにのみ適用されます。
</blockquote>


## スティッチングのマージルール

スティッチングのマージルール（有効になっている場合）は、2つの訪問プロファイルをスティッチングするときに属性の最終値を決定する、属性ごとのオプションルールです。

タイムライン属性では、次のスティッチングのマージルールがサポートされます。

* **タイムラインをマージ**：イベントをマージし、最も短い有効期限（構成されている場合）を適用します。

詳細については、[stitching-merge-rules](https://docs.tealium.com/stitching-merge-rules/)を参照してください。
