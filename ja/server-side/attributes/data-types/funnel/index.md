ファネル属性は、訪問および訪問のスコープで使用できます。

![](https://docs.tealium.com/images/server-side/screenshot-2019-11-11-at-1.26.28-pm.png)

ほとんどのユースケースでは、ファネル属性を訪問スコープの属性として構成することをお勧めします。これにより、各サイト訪問の終了時にファネルがリセットされ、セッションごとに顧客のアクションが新たに評価されます。

このアプローチでは、訪問ごとに顧客行動を追跡し、その情報を使用してオーディエンスのセグメンテーションを動的に行えるという利点があります。

たとえば、顧客が最初の訪問でステップ2まで完了すると、その段階に到達したユーザーのオーディエンスセグメントに分類されます。その後の訪問で同じ顧客がファネルのステップ4まで進むと、ステップ2のオーディエンスから除外され、ステップ4に到達したユーザーを表す新しいオーディエンスに追加されます。

## 仕組み

ファネル属性は、ユーザーが実行した一連のアクションをステップとして追跡します。これらのステップにより、開始から完了までの訪問の進捗を測定します。構成されたルールが発生すると、ステップが記録されます。ステップが記録される際には、そのステップに関する情報のスナップショットとして属性値も取得できます。最後のステップは常に必須ですが、それ以外のファネルステップは必須または任意に構成できます。

ファネルの例として、`Checkout Funnel`、`Purchase Funnel`、`Lead-Generator Funnel`などがあります。

### サイズ制限

ファネル属性には保存容量の制限はありませんが、暗号化および圧縮後のプロファイルの最大サイズ（400 KB）による制限は引き続き適用されます。

### 必須ステップと任意ステップ

ファネルを構成する際には、すべてのステップ（必須と任意の両方）を想定される順序で定義します。

#### 必須ステップ

必須としてマークされたステップは、ファネル構成で定義された順序どおりに発生した場合に記録されます。訪問が必須ステップを順序どおりに実行しなかった場合、そのステップはファネルに記録されません。つまり、必須ステップは順序どおりに発生した場合にのみ記録されます。

3つの必須ステップ（ステップ1、ステップ2、ステップ3）を持つファネルの動作例：

|訪問が実行したステップ|ファネルに記録されたステップ|
|---|---|
|ステップ1|ステップ1|
|ステップ3（順序外）|ステップ1|
|ステップ2|ステップ1、ステップ2|
|ステップ3|ステップ1、ステップ2、ステップ3|

#### 任意ステップ

必須としてマークされていないステップは、任意と見なされます。任意ステップは、ファネルで定義された正確な順序で発生した場合にのみ記録されます。訪問は任意ステップをスキップでき、その場合もファネルは後続のステップを記録し続けます。ただし、任意ステップをスキップした後で実行しても、そのステップはファネルに記録されず、遡って補完されることもありません。つまり、任意ステップが順序外で実行された場合、ファネルには記録されません。

1つの任意ステップを持つファネル（ステップ1、ステップ2（任意）、ステップ3、ステップ4）の動作例：

|訪問が実行したステップ|ファネルに記録されたステップ|
|---|---|
|ステップ1|ステップ1|
|ステップ3（任意のステップ2をスキップ）|ステップ1、ステップ3|
|ステップ2|ステップ1、ステップ3（ステップ2は遡って補完されない）|
|ステップ3|ステップ1、ステップ3|

ファネル追跡では、特に訪問レベルの属性を使用してユーザーの進捗を判断する場合、ユーザーが異なる段階でファネルから離脱し、再び入るといった実際の行動を考慮することが重要です。

例：

1. ステップ1：ユーザーがホームページ`example.com`を訪問します。
1. ステップ2：ユーザーが`example.com/subpage`に移動します。  
この時点で、ユーザーのファネル属性は最後に完了したステップを反映して「ステップ2」とマークされます。
1. ユーザーがサイトを離れます（ファネルから離脱します）。
1. 後の訪問で、ユーザーはホームページを経由せず、`example.com/subpage`に直接アクセスします。

ステップ1が必須のファネルでは、次へ進む前にユーザーがステップ1を再度完了することをシステムが要求します。ユーザーはホームページから再度ファネルに入っていないため、ファネルロジックが停止し、ステップ2以降に進んだとは認識されません。

**ステップ1を任意に構成することが役立つ理由**  
ステップ1を任意に構成すると、ファネルロジックではステップ1を再度トリガーする必要がなくなります。これにより、ユーザーは次のことが可能になります。

* ステップ2（サブページ）から直接セッションを開始する。
* ファネルの進捗が正しく関連付けられる。
* 後続のステップでも継続して追跡される。

この構成は、特に次のシナリオで役立ちます。

* ユーザーがさまざまな地点からファネルに入る可能性がある（常に先頭から入るとは限らない）。
* 複数のセッションまたはデバイスが関係する。
* ファネル追跡の障害を減らし、アトリビューションの精度を向上させたい。

### 属性データの取得

ファネルの各ステップを記録するだけでなく、ステップが発生した際に1つ以上の属性値を取得することもできます。取得したデータにより、ステップ発生時の訪問の状態に関する詳細情報が得られます。


<blockquote>
Funnel attributes are accessible in AudienceStore, but not in AudienceDB or in data layer enrichment.
</blockquote>


![](https://docs.tealium.com/images/server-side/attributes/capture_values_of_funnel_attribute.png)

## エンリッチメント

### ステップの作成

このエンリッチメントを使用して、ファネル内にステップを作成します。ファネルステップを追加すると、リストの最上部に表示されているステップがファネルの最初のステップとなり、最下部に表示されているステップが最後の必須ステップとなります。新しいステップはリストの最上部に追加されます。

ファネルステップを作成するには：

1. **ステップを作成**をクリックします。
1. ステップのタイトルを入力します。
1. （任意）属性値を取得するには、属性を選択して**属性を追加**をクリックします。
1. 任意ステップの場合は、**必須**チェックボックスをオフにします。
1. タイミングオプションとルールを選択します。

ファネル内の各ステップについて、これらの手順を繰り返します。

すべてのステップを入力したら、ドラッグして正しい順序に並べ替えます。

## 例

### 例：購入

次の例では、商品ページからカートページとチェックアウトページを経て購入ページに至る、基本的な購入ファネルを示します。

#### ステップ1：商品の表示

取得するデータ：`product_name`


[
  [
    {
      "input": "tealium_event",
      "operator": "equals",
      "filter": "product_view"
    }  
  ]  
]


#### ステップ2：カートの表示

取得するデータ：なし


[
  [
    {
      "input": "tealium_event",
      "operator": "equals",
      "filter": "cart_view"
    }  
  ]  
]


#### ステップ3：チェックアウト

取得するデータ：なし  


[
  [
    {
      "input": "tealium_event",
      "operator": "equals",
      "filter": "checkout"
    }  
  ]  
]


#### ステップ4：購入完了

取得するデータ：`order_id`および`order_total`


[
  [
    {
      "input": "tealium_event",
      "operator": "equals",
      "filter": "purchase"
    }  
  ]  
]


すべてのステップが必須です。ステップが完了すると、訪問が購入ファネルを進むのに伴い、そのステップは直ちに完了済みとして処理されます。この追跡とファネル処理のパターンは、訪問が商品を正常に購入するまで続きます。一方、訪問がファネル内のいずれかのステップを完了できなかった場合、購入は未完了と見なされます。

#### ファネルからの離脱

ユーザーがファネルのどこで離脱したかを把握することは、多くのマーケティングキャンペーンにおいて重要です。Customer Data Platform（CDP）では、最後に完了したステップを確認できます。

まず、ファネルの各ステップに対して複数のルールを作成する必要があります。たとえば、ルール **コンバージョンファネル - ステップ1完了** では、**ステップ1 - 商品** が完了しているかどうかを確認します。

![](https://docs.tealium.com/images/server-side/attributes/conversion_funnel_step_1_complete.png)

次に、**コンバージョンファネル - 最後に完了したステップ** という名前の文字列属性を作成します。この文字列属性にはファネルの各ステップに対応するエンリッチメントを構成し、上記のルールを使用して、ファネルの各ステップが完了しているかどうかを確認します。

![](https://docs.tealium.com/images/server-side/attributes/conversion_funnel_last_step_completed.png)

#### 放棄

すべてのページビューが考慮されるように、放棄はセッションの終了時に判定する必要があります。これを行うには、**カート放棄者** という名前のバッジを作成します。このバッジは、訪問の終了時にコンバージョンファネルを確認し、ファネルが開始されたものの完了していないかどうかを判定します。

![](https://docs.tealium.com/images/server-side/attributes/assign_cart_abandoner_badge.png)

また、コンバージョンファネルが完了した場合は、**ページビュー** イベントの発生時にバッジを削除します。

![](https://docs.tealium.com/images/server-side/attributes/remove_cart_abandoner_badge.png)

#### オーディエンス

次に、新しく作成したバッジを利用するオーディエンスを追加できます。ターゲティングできるように、オーディエンス条件ではメールアドレスなどのユーザー識別子が存在することを検証します。

![](https://docs.tealium.com/images/server-side/attributes/audience_using_cart_abandoner_badge.png)

#### アクション

このオーディエンスを使用して任意のコネクタをトリガーし、顧客をWebサイトに呼び戻してコンバージョンを促すことができます。

**対象者**：この例では、顧客のメールアドレスを使用して、ユーザーが誰であるかをベンダーに通知します。

**内容**：訪問がカートを放棄したことと、どのステップで放棄したかをベンダーに通知します。

![](https://docs.tealium.com/images/server-side/attributes/funnel_audience_conversion_action.png)

#### トレース

この仕組みを確認するには、トレースを実行し、コンバージョンファネルの各ステップを順に進みます。

## スティッチングのマージルール

スティッチングのマージルール（有効になっている場合）は属性ごとに構成できる任意のルールで、2つの訪問プロファイルをスティッチングしたときの属性の最終値を決定します。

ファネル属性では、次のスティッチングのマージルールがサポートされています。

* **ファネルをマージ**：各ファネルステップについて、最も早い有効な発生を保持し、順序の整合性を維持します。

詳細については、[stitching-merge-rules](https://docs.tealium.com/stitching-merge-rules/)を参照してください。
