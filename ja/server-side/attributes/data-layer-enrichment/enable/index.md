## 仕組み

データレイヤーエンリッチメントでは、次の2つの公開された認証不要のAPIを通じて訪問データにアクセスできます。

* [Data Layer Enrichment API](https://docs.tealium.com/get-data-layer-enrichment-api/)：フィルタリングせずに訪問プロファイル全体を返します。
* [Profile Definition API](https://docs.tealium.com/get-profile-definition-api/)：プロファイルのバッジ定義とオーディエンス定義を返します。

この構成は、[タグ管理のデータレイヤーエンリッチメント構成](https://docs.tealium.com/configure-data-layer-enrichment-iq/)とは別のものです。タグ管理の構成では、どの顧客データプラットフォーム（CDP）プロファイルからデータレイヤーに属性を提供するかを指定します。この構成でData Layer Enrichment APIへのアクセスが制御されることはありません。

データレイヤーエンリッチメントを有効にすると、両方のAPIが利用可能になり、有効なリクエストに対してデータを返します。

データレイヤーエンリッチメントを無効にすると、Data Layer Enrichment APIとProfile Definition APIの両方が、空のJSONオブジェクトを含む`200`レスポンスを返します。これらのAPIに依存する既存の連携では、APIからデータを受信できなくなります。Tealium Collectタグもこのエンドポイントを使用して訪問属性を取得するため、データレイヤーエンリッチメントを無効にすると、タグ管理のクライアントサイド属性同期も停止します。

既存のプロファイルでは、データレイヤーエンリッチメントがデフォルトで有効になっています。新しいプロファイルでは、デフォルトで無効になっています。新しいプロファイルでデータレイヤーエンリッチメントを構成する場合は、APIを使用する前にこの構成を有効にしてください。

## データレイヤーエンリッチメントを有効または無効にする

1. 管理メニューで、**データレイヤーエンリッチメント**をクリックします。
1. **データレイヤーエンリッチメント**を有効または無効にします。
1. **保存**をクリックします。
1. 変更内容を保存してパブリッシュします。

## ドメイン許可リスト

デフォルトでは、データレイヤーエンリッチメントはリクエスト元のドメインにかかわらず、TAPID Cookieが存在する場合はそのCookieに基づいて訪問プロファイルを検索します。

許可リストを作成すると、信頼されていないドメインがTAPID Cookieに基づいて訪問プロファイルにアクセスすることを防止できます。

データレイヤーエンリッチメントでは、リクエストのドメインと構成した許可リストに応じて、次のように訪問IDを取得します。

* **ドメインが一致する場合**  
リファラーが許可リスト内のドメインと一致する場合、データレイヤーエンリッチメントは、サードパーティーTAPID Cookieが存在すれば、そのCookie内の訪問IDを使用します。それ以外の場合は、URLパス内の訪問IDを使用します。
* **ドメインが一致しない場合**  
リファラーが許可リスト内のドメインと一致しない場合、データレイヤーエンリッチメントはTAPID Cookieを無視し、URLパス内の訪問IDを使用します。

### サブドメイン

ドメインを許可リストに追加すると、そのドメインのすべてのサブドメインが自動的に含まれます。たとえば、`example.com`を許可すると、`*.example.com`に一致するすべてのサブドメインが含まれます。

```
http://example.com
https://mobile.example.com/xyz/index.html
http://app.mobile.example.com
```

### 許可リストを作成する

信頼できる特定のドメインからのリクエストのみに制限するには、プロファイルで許可リストを作成します。

1. **管理メニュー > データレイヤーエンリッチメント**に移動します。
1. 信頼するドメインをカンマ区切りで入力します。プロファイルごとに最大250個のドメインを追加できます。ドメインの前に`http`または`https`プロトコルを含めないでください（例：`example.com`）。
1. **保存**をクリックします。
1. 変更内容を保存してパブリッシュします。

## データレイヤーエンリッチメントを無効にする場合

次の場合は、データレイヤーエンリッチメントを無効にします。

* プライバシーまたはコンプライアンス上の理由から、訪問データの公開範囲を制限する場合。
* 外部システムまたはベンダーによるアクセスを制限する場合。
* 訪問プロファイルデータにアクセスできるシステムの数を減らす場合。

## 認証済みアクセスを使用する

データレイヤーエンリッチメントAPIは公開されており、認証は不要です。

訪問データへの認証済みアクセスが必要な場合は、Context APIを使用してください。詳細については、[Context APIについて](https://docs.tealium.com/about-context-api/)を参照してください。
