## 制限付きデータとは？

制限付きデータとは、以下に該当するデータを含む属性を指します。

* ✔ 非公開または個人的なデータ
* ✔ プライバシー法によって保護されているデータ
* ✔ アクセス制御の対象となるデータ

デフォルトでは、属性は制限されておらず、さまざまな送信先に渡される可能性があります。属性には **Restricted Data** という構成があり、Customer Data Hub の外部にデータを送信する一部の処理に属性が含まれないようにできます。属性のエンリッチメントには影響しません。

## 制限付き属性の特定

左側のナビゲーションパネルにあるフィルターを使用して、一覧表示する属性の種類を選択できます。制限付きデータを含む属性を特定するには、**Restricted Data** チェックボックスをクリックします。

![](https://docs.tealium.com/images/server-side/restricted-attributes-filter.png)

属性の詳細を編集すると、該当する場合はプロパティセクションに **Restricted Data** フィールドが表示されます。属性を制限付きデータとしてマークするには、このチェックボックスをオンにします。

![](https://docs.tealium.com/images/server-side/restricted-attributes-checkbox-example.png)

## 制限付き属性

制限付きデータの構成は、以下のサービスに適用されます。

* **EventStoreおよびEventDB**  
デフォルトでは、制限付き属性はイベントフィードから除外されます。この動作は、各フィードの構成で変更できます。
<blockquote>
データソースとしてイベントフィードを使用するコネクタは、イベントフィードの構成にかかわらず、常に制限付き属性を受信します。
</blockquote>

* **データレイヤーエンリッチメント**  
デフォルトでは、Customer Data Platform（CDP）によるデータレイヤーエンリッチメントを使用してページ上のデータレイヤーに返される訪問属性から、制限付き属性が除外されます。Tealium Collectタグが最新の訪問プロファイルをリクエストすると、CDPは制限されていない属性を返します。この動作は変更できません。
* **Context API**  
デフォルトでは、制限付き属性をエンジンのレスポンスに含めることはできません。認証を必須とするように構成されたエンジンでは、エンジン構成で **Allow PII** を有効にすると、制限付き属性を含めることができます。詳細については、[Context APIエンジンの管理](https://docs.tealium.com/context-api-manage-engines/)を参照してください。

制限付きデータの構成は、以下のサービスには適用されません。

* **AudienceStoreおよびAudienceDB**  
デフォルトでは、AudienceDBに送信する場合でも、AudienceStoreコネクタを使用してエクスポートする場合でも、制限付き属性は常に含まれます。この動作は変更できません。
* **コネクタ（Webhookを含む）**  
デフォルトでは、マッピングを通じてベンダーに送信する場合でも、訪問プロファイルの一部として送信する場合でも、制限付き属性は常に含まれます。この動作は変更できません。

<blockquote>
コネクタリクエストに1つ以上の制限付き属性が含まれている場合は、警告メッセージが表示されます。
</blockquote>


## まとめ

* 属性を制限付きとしてマークすると、選択したTealiumサービスにその属性が送信されないように保護できます。
* EventStore、EventDB、データレイヤーエンリッチメント、およびContext APIでは、デフォルトで制限付きデータの構成が適用されます。
* 認証を必須とするように構成されたContext APIエンジンでは、**Allow PII** を有効にすると制限付き属性を含めることができます。
* AudienceStore、AudienceDB、およびコネクタでは、制限付きデータの構成は適用されません。
* 制限付き属性は、すべてのエンリッチメントで使用できます。
