## 仕組み

イベントヘルスは、受信イベントの品質をリアルタイムで監視する一連の機能です。イベントが次の条件を満たしているかを確認します。

* 一貫した構造（定義済みのスキーマなど）に従っている。
* 必須として指定した属性が含まれている。
* Webサイト、アプリ、その他のデータソースで同じ実装を使用している。

イベントヘルスには、次の構成要素があります。

* **[イベント仕様]()**：イベント仕様では、イベントタイプに必要な属性を定義し、インストール用のコード例を提供します。イベント仕様を作成すると、ライブイベントチャートを使用してイベントのデータ品質がリアルタイムで検証されます。
* **[イベントフィード]()**：イベントフィードは、属性に基づく特定の条件に一致するイベントをグループ化します。イベント仕様によって自動的に生成されるフィードに加えて、カスタムイベントフィードを作成できます。フィードは、コネクタ、またはEventDBやEventStoreなどのデータ保存ソリューションに送信できます。
* **[ライブイベント]()**：ライブイベントチャートには、すべてのデータソースおよびすべてのイベントフィードのデータがリアルタイムで表示されます。**データソース**フィルターと**イベントフィード**フィルターを使用すると、表示対象をトラフィックの一部に絞り込めます。イベント仕様が有効な場合、属性の検証結果に基づいて受信イベントの品質がチャートに表示されます。

これらの構成要素が連携して、データレイヤーの健全性を示します。

### 利点

正確なリアルタイムデータの収集と品質確保には、健全で適切に構造化されたデータレイヤーが不可欠です。データを最も価値のある資産として扱うことで、信頼できる実用的なインサイトに基づいてビジネス上の意思決定を行えます。イベントヘルスには、これを実現するための次の利点があります。

* **データへの信頼**：検証済みのイベントにより、分析データと顧客データの信頼性が確保されます。
* **トラブルシューティングの迅速化**：明確なエラー通知により、問題の検出と修正に必要な時間を短縮できます。
* **一貫したデータ品質**：コネクタやデータストアなどのダウンストリームシステムが、均一で高品質なデータを受信できます。
* **確信を持った意思決定**：信頼できるデータは、ビジネス上の意思決定とカスタマーエクスペリエンスの向上に役立ちます。
* **継続的な改善**：検証結果を使用してトラッキングコードとイベント仕様を調整することで、有効なイベントの割合を高め、仕様を実際のイベントトラッキングと整合させることができます。

### イベントの例

次の例では、各検証ステータスについて説明します。これらは、`video_complete`イベントに関する次のイベント仕様に基づいています。

<!-- GAP：whiteui-eventspecifications-videocomplete.pngを、各属性に定義されたタイプ（String、Number）、4つの必須属性で有効になっている必須構成、およびオプションのString属性としてのvideo_qualityが表示されたvideo_complete仕様のスクリーンショットに置き換える -->

この仕様には、`tealium_event`の値（`video_complete`）が記載され、`video_id`、`video_length`、`video_name`、`video_platform`の4つの必須属性が定義されています。また、オプションの文字列属性として`video_quality`も定義されています。各属性には、受信イベントが一致する必要のあるデータタイプが定義されています。

#### 有効なイベントの例

有効ステータスのイベントは、次の条件を満たします。

* いずれかのイベント仕様に一致する`tealium_event`値がある。
* 正しいデータタイプを持つすべての必須属性が含まれている。
* すべてのプラットフォーム（Webやモバイルなど）で同じ構造に従っている。

例として、次のイベントについて考えます。

```json
{
    "tealium_event": "video_complete",
    "video_id": "xWlEk2i9r5Q",
    "video_length": 300,
    "video_name": "How to track videos in Tealium",
    "video_platform": "YouTube",
    "video_quality": "1080p"
}
```

`tealium_event`の値が`video_complete`であるため、このイベントは`video_complete`仕様に照らしてチェックされます。このイベントには、正しいデータタイプを持つすべての必須属性とオプション属性が含まれているため、有効と判定されます。

![](https://docs.tealium.com/images/server-side/valid-video-complete-event.png)
<!-- GAP：valid-video-complete-event.pngを、緑色のヘッダーと属性ごとの仕様検証結果が表示され、すべての属性とその検証ステータスを確認できる、有効なvideo_completeイベントの詳細のスクリーンショットに置き換える -->

#### 無効なイベントの例

次のイベントは、前述の`video_complete`仕様に照らしてチェックされますが、1つ以上の必須属性が欠落しているか、想定外の値が含まれています。

```json
{
    "tealium_event": "video_complete",
    "video_id": "xWlEk2i9r5Q",
    "video_length": "300 seconds",
    "video_platform": "YouTube"
}
```

このイベントが無効なのは、仕様では数値が要求されているのに`video_length`属性が文字列であり、必須の`video_name`属性が欠落しているためです。

次のイベントも無効です。すべての必須属性が存在し、正しいデータタイプになっていますが、`video_quality`はオプションの文字列属性であるのに、イベントでは数値が送信されています。

```json
{
    "tealium_event": "video_complete",
    "video_id": "xWlEk2i9r5Q",
    "video_length": 300,
    "video_name": "How to track videos in Tealium",
    "video_platform": "YouTube",
    "video_quality": 1080
}
```

存在するオプション属性は、仕様で定義されたデータタイプと一致する必要があります。イベントに存在しないオプション属性は評価されません。

![](https://docs.tealium.com/images/server-side/invalid-video-complete-event.png)

属性、データタイプ、要件のエラーを特定して、問題のトラブルシューティングと解決を行います。

#### 不明なイベントの例

不明なイベントとは、`tealium_event`の値がどのイベント仕様にも一致しないイベント、または`tealium_event`属性が欠落しているイベントです。

次のイベントには`tealium_event`値がありません。

```json
{
    "video_id": "xWlEk2i9r5Q",
    "video_length": 300,
    "video_name": "How to track videos in Tealium",
    "video_platform": "YouTube"
}
```

イベントに`tealium_event`属性がないため、どの仕様に対しても分類できず、不明（`No Spec`）としてマークされます。

同様に、次のイベントも、`video_search`のイベント仕様がないため、不明なイベントとしてマークされます。

```json
{
    "tealium_event": "video_search",
    "video_name": "How to track videos in Tealium",
    "video_platform": "YouTube"
}
```

## ワークフロー

次のワークフローを使用して、生のイベントデータから、監視および検証済みのイベントへと移行します。目標は、明確なイベント仕様を確立し、その仕様に照らしてライブトラフィックを検証し、データ品質の問題に迅速に対処することです。

### ステップ1 - イベントと不明な属性を検出する

ライブイベントチャートの**すべてのイベント**フィードで、受信トラフィックを確認します。

![](https://docs.tealium.com/images/server-side/whiteui-eventstream-liveeventfeed.png)

このビューには、まだ特定していない属性を含め、現在の実装が本番環境でどのように動作しているかが表示されます。

![](https://docs.tealium.com/images/server-side/whiteui-eventstream-liveeventsandfeeds-add-unknown-attribute.png)

この情報を基に、イベント仕様を作成するための主要なイベントとその属性のリストを作成します。

詳細については、[ライブイベント]()を参照してください。
### ステップ 2 - リアルタイムイベントからイベント仕様を作成する

**ライブイベント**ページまたは**イベント仕様**ページで、検出した属性を使用して主要なイベントのイベント仕様を作成します。カスタマージャーニーで最も重要なイベント（`sign_up`、`login`、`add_to_cart`、`purchase` など）から始めます。各属性について、データ型と、その属性が必須かどうかを構成します。

![](https://docs.tealium.com/images/server-side/whiteui-eventspecifications-videocomplete.png)
<!-- ギャップ：whiteui-eventspecifications-videocomplete.png を、各属性に定義された型（String、Number）、4 つの必須属性に対して有効になっている必須構成、およびオプションの String 属性として構成された video_quality を示す video_complete 仕様のスクリーンショットに置き換える -->

イベント仕様を作成すると、一致する `tealium_event` 値を持つイベントがその仕様に照らして検証され、**有効**、**無効**、または**仕様なし**としてマークされます。イベント仕様ごとに対応するイベントフィードが作成され、コネクタ、EventDB、または EventStore で有効にできます。

![](https://docs.tealium.com/images/server-side/video-complete-event-feed.png)

これで、重要なイベントには、Tealium がリアルタイムで検証する文書化されたコントラクトが構成されました。一致するイベントは、リンクされたフィードを通じて後続のワークフローで使用できます。

詳細については、[イベント仕様の管理]()を参照してください。

### ステップ 3 - イベントの健全性を監視し、問題をトリアージする

ライブイベントチャートとイベント仕様の詳細ページを使用して、イベントの健全性を継続的に監視します。**有効**、**無効**、**仕様なし**のフィルターを使用して、特定の健全性ステータスに絞り込みます。**データソース**と**イベントフィード**を使用して、チャートをトラフィックの一部に絞り込みます。

![](https://docs.tealium.com/images/server-side/whiteui-eventstream-liveevents-filter-drop-down-lists.png)

継続的に監視することで、リグレッションをすばやく検出できます。たとえば、新しいリリースによって必須属性が送信されなくなった場合や、未定義の新しいイベント名が導入された場合などです。

このビューでは、仕様ごと、およびすべてのトラフィック全体について、どのイベントが正常で、どのイベントに対応が必要かを確認できます。

詳細については、[ライブイベント]()および[イベント仕様について]()を参照してください。

トレース ID を使用すると、自分でトリガーしたイベント以外のすべての受信イベントを除外できます。トレース ID は、イベントを手動でテストするためにイベントトラッキングコードへ挿入する、一時的な一意の識別子です。新規または更新されたイベント仕様を検証する際、テスト中に自分でトリガーしたイベントだけを確認できるため、トレース ID が役立ちます。

詳細については、[トレース ID の使用](https://docs.tealium.com/about-live-events/#use-a-trace-id)を参照してください。

### ステップ 4 - 修正、反復、および復旧の確認

監視から得られたインサイトを使用して、データ品質の問題を修正します。

* 無効なイベントについては、イベントサンプルを調べて、欠落している属性や形式が正しくない属性を確認します。必須属性が欠落しているかデータ型が正しくない場合、および存在するオプション属性のデータ型が正しくないかデータ値ルールを満たしていない場合は、すべて無効なイベントになります。必要に応じて、実装を更新するか仕様を調整します。
* 仕様がないイベントについては、仕様を作成するか、対象外のノイズとして扱うかを決定します。ライブイベントチャートで任意のイベントをクリックし、それを新しいイベント仕様の基礎として使用します。

イベント仕様を作成または更新した後、データを再度テストします。

検証結果を使用してトラッキングコードと仕様の両方を改良すると、イベントの健全性が向上します。時間の経過とともに有効なイベントの割合が増加し、仕様とビジネスにおけるイベントのトラッキング方法との整合性が維持されます。

詳細については、[ライブイベント]()および[イベント仕様の管理]()を参照してください。

### ステップ 5 - 成功指標とカバレッジを追跡する

イベントの健全性を利用すると、検出から解決へと進むことができます。

ライブイベントチャートで、主要なイベントについて緑色のバー（有効なイベント）を確認し、赤色（無効）および青色（仕様なし）のセグメントが減少していることを確認します。

**イベント仕様**の概要ページと詳細ページで、選択した期間におけるイベントごとの**合計ボリューム**、**有効なイベント**、**無効なイベント**、および**仕様なし**の件数を監視します。

![](https://docs.tealium.com/images/server-side/event-health-table.png)

これらの指標は、変更によってデータ品質が向上しているかどうか、および次にどこへ重点を置くべきかを示します。

* 無効なイベントの急増は、多くの場合、実装の変更、新しい属性値、または誤ったデータ型で送信されているオプション属性を示します。
* 仕様がないイベントの増加は、新しいイベントタイプまたは不足している仕様があることを示します。
* 不明な属性は、データ型が不明であると示されます。イベント仕様やその他の機能で使用できるように、イベントの詳細ビューから直接定義します。
* 属性の欠落または誤りが原因でイベントが無効になっている場合は、新しいイベントが仕様に準拠するように、トラッキングコードまたはタグ管理構成を更新します。

* [イベント仕様の管理]()：イベント仕様を作成および管理し、イベントをリアルタイムで検証します。
* [イベントフィード]()：イベント仕様から自動的に作成され、コネクタやデータ保存ソリューションに送信できるイベントフィードについて説明します。
* [ライブイベント]()：受信イベントをリアルタイムで表示し、イベント仕様に基づいてその健全性を反映するライブイベントチャートについて説明します。
