## 仕組み

イベント仕様（「イベントスペック」とも呼ばれます）は、イベントの[データレイヤー](https://docs.tealium.com/an-introduction-to-the-data-layer/)を表します。イベント仕様を使用すると、[ライブイベントチャート](https://docs.tealium.com/about-live-events/)またはイベント仕様の詳細ビューで、イベントのデータ品質をリアルタイムに検証できます。

イベント仕様には、以下で構成される一連の定義が含まれます。

* イベント名と、そのイベントに関連付けられた仕様を表す `tealium_event` 属性。たとえば、`tealium_event` 属性の値が `video_complete` の場合、システムは `video_complete` という名前のイベント仕様を検索し、その仕様に基づいて受信イベントを検証します。イベント仕様を使用すると、目的および想定されるデータ構造に基づいてイベントを分類、管理できます。
* そのイベントで想定されるデータを記述する属性のリスト。属性は、`video_id`、`video_length`、`video_platform` などの個別の情報です。これらの属性を定義することで、システムが受信すべきデータを明確に示せます。属性を定義すると、チームは一貫したデータ構造を維持し、エラーを減らし、トラブルシューティングを簡素化できます。
* 文字列、数値、ブール値など、想定されるデータ型。データ型を定義することで、各属性に正しい種類の情報が含まれていることを確認できます。データ型を定義すると、エラーが減少し、データの一貫性が向上するほか、異なるシステム間でのイベントの検証と処理が容易になります。
* 有効なイベントに必須であるかどうか。イベントが有効と見なされるには、必須属性がそのイベントに存在する必要があります。必須属性を指定することで、正確な分析と意思決定に不可欠な重要情報が常に含まれるようになります。

検証時には、各属性について、存在の有無、データ型、および構成されたデータ値ルールが評価されます。必須属性が存在しない場合や検証に失敗した場合、そのイベントは無効になります。任意属性が存在していても、型チェックまたはデータ値ルールに違反した場合、そのイベントは無効になります。イベントに存在しない任意属性は評価されず、結果にも影響しません。データ値ルールの構成については、[属性への検証ルールの追加](https://docs.tealium.com/manage-event-specifications/#add-a-validation-rule-to-an-attribute)を参照してください。


<blockquote>
検証はイベントごとに100属性までに制限されています。最初に必須属性がアルファベット順で評価され、次に任意属性がアルファベット順で評価されます。上限を超えた属性は検証されません。
</blockquote>


イベント仕様によってデータが除外されることはありません。イベントが無効な場合でも、システムはそのイベントを処理します。

### イベント仕様の例

たとえば、`video_complete` イベントには、以下の属性とデータが含まれます。

```json
{
    "tealium_event"  : "video_complete", // name of event and specification
    "video_id"       : "xWlEk2i9r5Q",
    "video_length"   : 300,
    "video_name"     : "How to track videos in Tealium",
    "video_platform" : "YouTube",
}
```

この `video_complete` イベントのイベント仕様には、以下が含まれます。

* `tealium_event` 属性によって、イベントが `video_complete` として識別されます。
* **Definitions**テーブルには、イベントに関するコンテキスト情報が表示されるほか、必須属性、想定されるデータ型、および有効なイベントに必須であるかどうかが定義されます。

### 利点

イベント仕様は、データ管理において主に次の2つの利点を提供します。

* すべてのプラットフォームでイベントの実装を標準化する。
* 受信イベントのデータ品質を評価する。

## 検証ステータス属性

検証の実行後、仕様と一致したイベントのペイロードには、予約済みの文字列属性 `tealium_event_spec_status` が含まれます。

この属性には、以下の値があります。

| ステータス | 説明 |
|---|---|
| `PASS` | イベントが仕様と一致し、検証に合格しました。 |
| `FAIL` | イベントが仕様と一致しましたが、検証に失敗しました。 |
| 存在しない | イベントが仕様と一致しないため、この属性はペイロードに追加されません。 |

`tealium_event_spec_status` 属性は予約されています。受信イベントにこの属性がすでに含まれている場合、偽装を防ぐため、処理の前に値が削除されます。

ダウンストリームシステムで検証ステータスを使用するには、`tealium_event_spec_status` を[イベント属性](https://docs.tealium.com/manage-es-attributes/)として定義します。エンリッチメントは必要ありません。

属性を定義すると、イベント属性をサポートするコネクタ、イベントフィード、およびその他の機能で使用できます。

## イベント仕様の統計を表示する

![](https://docs.tealium.com/images/server-side/event-health-table.png)

**Event Health**ウィンドウには、すべてのイベント仕様の統計の合計が表示されます。テーブルには、個々のイベント仕様の統計が表示されます。期間を選択すると、その期間の統計を表示できます。

**Event Health**ウィンドウには、以下の統計が表示されます。

* **Total Volume**  
選択した期間内に受信したイベントの総数。
* **Valid Events**  
有効なイベント仕様の要件を満たすイベントの数。有効なイベントには、`tealium_event` 属性の既知の値と、仕様で定義されたすべての必須属性が含まれています。有効なイベントが多いほど、データ品質が高いことを示します。件数が多い場合、実装環境から仕様で想定されるデータが送信されていることを示します。
* **Invalid Events**  
イベント仕様と一致しているものの、1つ以上の属性が存在しないか無効であるイベントの数。必須属性が存在しないかデータ型が正しくない場合、および存在する任意属性のデータ型が正しくないか、構成されたデータ値ルールに違反した場合、いずれもイベントは無効になります。これらの問題は、イベントを送信する実装コードを修正するか、イベント仕様を調整することで解決できます。
* **No Spec**  
一致するイベント仕様がないイベントの数。No Specイベントには、`tealium_event` 属性がないか、対応するイベント仕様がありません。

**Defined Events**テーブルには、既存のすべてのイベント仕様と、各イベント仕様の**Total Volume**、**Valid Events**、**Invalid Events**、および**No Spec**の統計が一覧表示されます。

## イベント仕様の詳細を表示する

**Defined Events**テーブルで任意のイベント仕様をクリックすると、その詳細が表示されます。

ページ上部には、その仕様と一致するイベントの総数や、有効、無効、および仕様なしのイベントの割合など、イベント仕様に関する統計が表示されます。

**Definitions**テーブルには、イベントに関するコンテキスト情報が表示されるほか、必須属性、想定されるデータ型、および有効なイベントに必須であるかどうかが定義されます。

## ライブイベントでのイベント仕様

イベント仕様を作成してトラッキングコードを実装した後、ライブイベントチャートを使用して受信イベントをリアルタイムで表示し、そのデータ品質を評価します。
