## 処理順序の概要

Customer Data Platform（CDP）はEvent Streamingと緊密に統合されているため、この概要ではイベントを受信した時点から説明します。

デフォルトの処理順序は次のとおりです。

* イベントを受信
* イベント属性をエンリッチ
*訪問および訪問属性をエンリッチ
    * 訪問プロファイルを取得
    * 訪問ID属性をエンリッチ
    * 訪問プロファイルをスティッチ
* オーディエンスを評価
* コネクタをトリガー

![](https://docs.tealium.com/images/server-side/asorderofprocessing.png)

## エンリッチメントのタイミングと条件

エンリッチメントは、タイミングと条件の2つの観点で評価されます。

エンリッチメントのタイミングによって、条件を評価する時点が決まります。これはインターフェイスに**WHEN**構成として表示され、Customer Data Platform（CDP）で提供される次のオプションに限定されます。

* **New Visitor**：訪問の最初の訪問。
* **New Visit**：既存の訪問による再訪問。
* **Visit Ended**：訪問セッションの終了。
* **Any Event**：New Visitor、New Visit、Visit Endedを除く任意のイベント。

エンリッチメント条件によって、属性値を更新するかどうかが決まります。条件はインターフェイスにルールとして表示され、論理演算子を使用して構成します。

## 処理順序の詳細

### イベントの受信

Tealium Collectからイベントを受信します。

### イベント属性のエンリッチメント

イベント属性のエンリッチメントが評価されます。

### 訪問および訪問属性のエンリッチメント

#### 訪問プロファイルの取得

訪問および訪問属性は訪問プロファイルに保存されるため、これらの属性をエンリッチする最初の手順は、訪問プロファイルを取得することです。`tealium_visitor_id`が既存のプロファイルと一致する場合、そのプロファイルがエンリッチされます。`tealium_visitor_id`が既存のプロファイルと一致しない場合、新しいプロファイルが作成され、エンリッチされます。

訪問および訪問属性のエンリッチメントは、そのタイミングと条件に基づいて評価されます。

次の例では、`Cart Abandoner`バッジの属性エンリッチメントが、以下に基づいて評価されます。

* **WHEN**：Visit Ended
* **ルール**：`cart_total_items greater than 0`

![](https://docs.tealium.com/images/server-side/asprocessingcartabandoner.png)

**Enable Rule Dependency Checking**が有効になっている場合、ルール内の依存関係に対応するため、エンリッチメントが正しい順序で実行されます。

**Enrichment Order Respects UI Order**が有効になっている場合、エンリッチメントはユーザーインターフェイスに表示される順序で実行され、必要に応じて依存関係のチェックに基づく調整が行われます。それ以外の場合、エンリッチメントは属性ID順に実行されます。

#### 訪問ID属性のエンリッチメント

訪問ID属性をエンリッチするように構成されたユーザー識別子がイベントに含まれている場合、次のすべての条件が満たされたときにのみ訪問ID属性が構成されます。

* 訪問ID属性に既存の値がない。
* エンリッチメントルールの評価結果が`true`である。
* エンリッチされた値が[訪問IDの最小要件](https://docs.tealium.com/visitor-id-attribute/)を満たしている。

訪問ID属性が複数ある場合、属性ID順に評価されます。

#### 訪問プロファイルのスティッチ

エンリッチされた訪問ID属性が複数の訪問プロファイルと一致する場合、それらは新しい訪問プロファイルに統合されます。

### オーディエンスの評価

CDPは訪問プロファイルを評価し、その訪問がどのオーディエンスに参加または離脱すべきかを決定します。オーディエンスルールが`true`の場合、訪問はオーディエンスに参加し、オーディエンスルールが`false`の場合、オーディエンスから離脱します。訪問プロファイルがオーディエンスに参加、またはオーディエンスから離脱すると、コネクタアクションがトリガーされます。

### コネクタのトリガー

CDPはトリガーを評価し、開始するコネクタアクションを決定します。トリガー条件が満たされると、コネクタアクションが開始されます。コネクタ条件には、次のいずれかを指定できます。

* **Joined Audience**：訪問が今回の訪問中にオーディエンスに参加した。
* **Left Audience**：訪問が今回の訪問中にオーディエンスから離脱した。このアクションは、訪問が削除された場合には実行されません。詳細については、[訪問の削除](https://docs.tealium.com/visitor-search/#deleting-a-visitor)を参照してください。
* **In Audience at start of visit**：訪問が訪問開始時にオーディエンスに属していた。
* **In Audience at end of visit**：訪問が訪問終了時にオーディエンスに属していた。
