## 始める前に

訪問 ID 属性を作成する前に、どのイベント属性がユーザーに適したユーザー識別子であるかを判断します。ユーザー識別子の値は、訪問ごとに一意である必要があります。ユーザー識別子は、条件を満たすイベントに一致するルールを使用して、訪問文字列属性に値を構成するために使用されます。訪問文字列属性を使用して、ユーザー識別子が訪問ごとに一意であることを確認します。訪問間で訪問文字列属性が一意であることを確認したら、その属性を使用して訪問 ID 属性に値を構成します。

この例では、ユーザー識別子として `customer_id` を、条件を満たすイベントとして `purchase` イベントを使用します。

## ステップ 1：ルールを作成する

訪問 ID 属性を作成する前に、訪問 ID 属性に値を割り当てるタイミングを指定するルールを作成する必要があります。

次の手順に従い、`customer_id` が割り当てられ、その値が「none」ではない場合に、訪問 ID 属性を `customer_id` に構成するルールを作成します。

1. **Server-Side Tools &gt; Manage Rules** に移動します。
1. **+ Add Rule** をクリックします。**Create Rule** ダイアログが表示されます。
1. **Title** を入力します。この例では「customer_id is assigned」と入力します。
1. **+ Attribute Condition** をクリックします。
1. 属性として `customer_id` を選択し、演算子のドロップダウンリストから **is assigned** を選択します。
1. **+ Attribute Condition** をクリックし、属性として `customer_id`、演算子として **does not equal (ignore case)** を選択して、値に `"none"` と入力します。
1. **Save** をクリックします。  
    ![](https://docs.tealium.com/images/server-side/as-create-rule-check-for-none.png)

## ステップ 2：訪問文字列属性を作成する

Audience Discovery での検証に使用する一時的な文字列属性を作成します。データを検証せずに訪問 ID 属性を作成すると、訪問プロファイルが誤ってスティッチされる可能性があります。

次の手順に従って文字列属性を作成します。

1. **Customer Data Platform (CDP) &gt; Visitor/Visit Attributes** に移動します。
1. **+ Add Attribute** をクリックします。
1. **Add Attribute** ダイアログで、スコープとして **Visitor** を選択し、**Continue** をクリックします。
1. **Choose a data type** で **String** を選択し、**Continue** をクリックします。  
    ![](https://docs.tealium.com/images/server-side/as-add-attribute-2.png)
1. **Add Attribute** ダイアログで **Title** を入力し、必要に応じて **Notes** を入力します。
1. **Add Enrichment** をクリックし、**Set String** を選択します。![](https://docs.tealium.com/images/server-side/as-addenrichment.png)

1. **Set String** ダイアログで、**Set String to** に `customer_id` を選択します。
1. **WHEN** で **ANY EVENT** を選択します。
1. **Choose a rule** フィールドで、ステップ 1 で作成したルールを選択します。
1. **Finish** をクリックします。

## ステップ 3：本番環境にパブリッシュする

CDP がデータの収集を開始できるように、ルールと属性を保存して本番環境にパブリッシュします。CDP でデータを検証できるようになるまでの待機時間は、Web サイトのユーザー数と収集するデータの種類によって異なります。すべての訪問が利用できるファーストパーティ Cookie を使用している場合、データは 15 分以内に表示されます。

## ステップ 4：データを検証する

選択した属性が一意であることを確認するには、Audience Discovery を使用して、アクティブな訪問全体における属性値の分布を確認します。詳細については、[Audience Discovery]()を参照してください。

**適切でない訪問文字列属性**

適切でない訪問文字列属性とは、数百人のユーザーが同じ値を持つ属性です。スティッチが有効になっている場合、これらのユーザーはすべて 1 つの訪問プロファイルに統合されてしまいます。これは明らかに正しくありません。

たとえば、「unknown」が複数存在する場合は、それらを除外する条件をルールに追加できます。多数の訪問が同じ訪問文字列属性値を持つ場合は、文字列属性に値を構成する別のユーザー識別子を選択し、結果を再度検証してください。

**適切な訪問文字列属性**

適切な訪問文字列属性では、同じ値を持つユーザーはごく少数に限られます。値が「none」のユーザーが複数存在する場合がありますが、すべての訪問が値を持つわけではないため、これは正常です。訪問が同じ値を持つ理由を特定するのが難しい場合もあります。同じ訪問文字列属性が 2 人の訪問に割り当てられている割合が全訪問の 1% 未満であれば、選択したユーザー識別子を使用して訪問 ID 属性に値を構成し、訪問スティッチを有効にしても問題ありません。

## ステップ 5：訪問 ID 属性を作成する

適切な訪問文字列属性であることを確認したら、訪問 ID 属性を作成します。訪問 ID を検証に使用した文字列属性に構成し、新しく作成したルールを選択します。データの記録を開始するため、保存して本番環境にパブリッシュします。

## ステップ 6：訪問スティッチを有効にする

訪問 ID 属性を作成したら、[Support Desk にアクセス](https://support.tealiumiq.com/)し、アカウントの訪問スティッチを有効にするよう依頼してください。

## Trace を使用して動作を確認する

構成が稼働状態になった後、スティッチは次のように行われます。

1. 訪問がコンピューターから Web サイトにログインします。訪問プロファイル A が作成され、訪問 ID 属性が取得されます。その後、セッションが終了します。
1. 後で同じ訪問がモバイルデバイスから Web サイトにログインします。訪問プロファイル B が作成され、訪問 ID 属性が取得されます。
1. CDP は、プロファイル A とプロファイル B が訪問 ID 属性について同じ値を共有していると判断し、両方のプロファイルをスティッチしてプロファイル C に統合します。
