## 動作方法

サーバーサイドの構成に項目を追加、編集、または削除する際には、変更を保存して保持する必要があります。構成の変更は自動的には保存されません。サインアウトするかブラウザを閉じると、保存されていない変更は破棄されます。

変更を保存した後、ログアウトするかウィンドウを閉じても、構成は保存され、次にそのアカウントにログインするユーザーに引き継がれます。

変更を保存すると、現在ロードされているプロファイルのバージョンのリビジョンを作成します。バージョン履歴を整理しておくために、関連する変更のまとまりを作業する際にのみ新しいバージョンを作成することをお勧めします。このアプローチにより、単一のプロジェクトの一部としての更新を追跡しやすくなり、必要に応じて以前の状態に戻すことができます。また、不要なブランチでバージョン履歴が散らかることもありません。

ただし、バージョンまたはリビジョンを保存しても、変更が本番システムに適用されるわけではありません。変更を本番環境でアクティブにするには、バージョンも公開する必要があります。

## 変更の保存または公開

**保存/公開**をクリックすると、変更の保存方法を選択する以下の画面が表示されます。各オプションは特定のシナリオに対応するように設計されており、構成を効果的に管理するのに役立ちます：

![](https://docs.tealium.com/images/server-side/save-publish/save-your-changes.png)

* **新しいバージョンとして保存**  
現在のバージョンに変更を保存するか、新しいバージョンまたは新しいチームバージョンを開始するかを選択します。このチェックボックスはデフォルトでは選択されていません。長期的なプロジェクトを開始するために変更を新しいバージョンとして保存する場合は、**新しいバージョンとして保存**を選択します。
* **最新の公開変更を含む**  
公開されたバージョンより遅れている場合にこのオプションが表示されます。このプロファイルで公開された最新の変更を含めるかどうかを選択します。このオプションを選択しない場合、他のバージョンからの公開変更はあなたのバージョンに統合されません。公開するとき、このチェックボックスはデフォルトで選択されています。
![](https://docs.tealium.com/images/server-side/save-publish/integrate-changes-by-others.png)
* **バージョン名**  
バージョンに名前を入力します。この名前はさまざまな画面に表示され、このバージョンの変更を要約する説明的な名前を選んでください。デフォルトでは、**バージョン**フィールドに日付とタイムスタンプが表示されます。現在のバージョンに保存する場合、バージョン名を変更することはできません。
* **ノート**  
(必須) 保存する変更についてのノートを入力します。ノートは他のユーザーに変更を伝えるのに役立ちますし、将来このバージョンに戻る必要がある場合、変更内容を思い出すのにも役立ちます。
* **バージョンの公開**  
このバージョンを公開したい場合は、**バージョンの公開**を選択します。

### 変更の確認

![](https://docs.tealium.com/images/server-side/save-publish/review-changes.png)

**保存される変更**または**公開される変更**のテーブルには、保存している変更と最新の公開バージョンから含まれる変更に関する情報が表示されます：

* 変更される項目のタイプ（オーディエンス、属性など）。
* 項目の名前。
* 項目に対して行われたアクション（**作成**、**更新**、または**削除**）。
* 変更の状態（**保存済み**、**未保存**、または**公開済み**）。
* 変更を行ったユーザー。

このテーブルには、システムによって生成された変更が含まれている場合があります。たとえば、イベント仕様を追加すると、システムは自動的にそのイベント仕様に関連するルールを作成し、それがこのテーブルに未保存の変更として表示されます。

### 検証警告

プロファイルにアクティブな検証警告がある場合、変更テーブルの上に**警告**セクションが表示されます。各警告は影響を受ける項目を特定し、問題を説明します。項目を確認または修正するには、それをクリックして開きます。

警告は保存または公開をブロックしません。いつでも進めることができますが、本番環境で予期しない問題を避けるために、公開する前に警告を解決することをお勧めします。

### 除外された削除

バージョンで項目を削除したが、その項目が最新の公開バージョンにまだ存在する場合、削除は適用されません。これは、公開された構成の依存関係を壊す可能性があるためです。これらの項目は**除外された削除**セクションに表示されます。プラットフォームは削除を適用せず、項目を保持します。

項目を永久に削除するには、まずその項目に依存するものを解決してから、公開バージョンから削除します。

### 項目の上書きと削除

最新の公開バージョンで更新された項目を編集した場合、公開するときにあなたの変更がその更新を上書きします。この動作は、システムが現在のバージョンで最近行われた編集を優先するために発生します。意図しない結果を避けるために、**保存される変更**または**公開される変更**のテーブルを注意深く確認し、あなたの更新が最新の公開変更と一致することを確認してください。

項目を永久に削除するには、公開バージョンから削除します。公開バージョンではないバージョンから項目を削除して保存し、公開すると、プラットフォームは公開時に削除された項目を復元します。これは、オーディエンスに必要な属性など、依存関係のある項目の誤って削除されるのを防ぐためです。

## 履歴情報

履歴情報はウィンドウの右側に表示されます：

* **最新の公開バージョン**：最も最近の公開バージョンのバージョン名、タイムスタンプ、ユーザー、およびそのバージョンについてのノートを表示します。
* **バージョンの状態**：現在のバージョン（保存された変更や未保存の変更を含む）と現在の公開バージョンを比較し、次のいずれかの状態メッセージを表示します：
  * **公開バージョンより先行しています**  
  あなたのバージョンには、現在の公開バージョンにない変更が含まれています。
  * **最新の状態です**  
  あなたの現在のバージョンと最新の公開バージョンが一致しています。
  * **公開バージョンより遅れています**  
  公開バージョンには、あなたのバージョンにない変更が含まれています。バージョンを作業している間に他のユーザーが異なるバージョンで変更を公開すると、それらの更新をあなたのバージョンに統合して一貫性を保ち、競合を避ける必要があります。**最新の公開変更を含む**オプションを使用して、最新の公開更新をあなたのバージョンにマージし、最新の構成に基づいて変更を構築します。このステップは、複数のユーザーが同じプロファイルで協力する場合に特に重要であり、重要な更新が上書きされるのを防ぎます。統合された変更は**保存される変更**または**公開される変更**のテーブルに**公開済み**として表示されます。
