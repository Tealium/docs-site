## よくある質問

#### クライアントサイドプロファイルからユーザーを削除すると、そのユーザーはサーバーサイドプロファイルからも削除されますか？
いいえ。ユーザーがクライアントサイドとサーバーサイドの両方に存在する場合、一方からユーザーを削除しても、もう一方には影響しません。

#### クライアントサイドプロファイルへのアクセスを許可せずに、サーバーサイドプロファイルへのアクセス権をユーザーに付与できますか？
はい。ユーザーがすでにアカウントに存在し、サーバーサイドのプロファイルへの権限を付与されている場合は、**タグ管理 > ユーザーの管理**に移動し、クライアントサイドインターフェイスからそのユーザーを削除します。詳細については、上記の「サーバーサイド専用ユーザーの追加」を参照してください。

#### 「現在および今後のすべてのプロファイル」オプションは、サーバーサイドの権限にどのような影響を与えますか？
サーバーサイドユーザーには影響しません。すべてのサーバーサイドユーザーには、新しいすべてのサーバーサイドプロファイルに対して、デフォルトで**アクセス権なし**の権限ロールが構成されます。

#### ユーザーがサーバーサイドでは1つのプロファイルにのみアクセスでき、クライアントサイドではどのプロファイルにもアクセスできない場合はどうなりますか？
ユーザーがログイン画面でサーバーサイドを選択すると、該当するアカウント／プロファイルが自動的に読み込まれます。ユーザーがクライアントサイドへのログインを試みると、アクセスが拒否されたことを示すメッセージがモーダルに表示されます。

#### サーバーサイド管理者は、サーバーサイドプロファイルに対する自身の権限を変更できますか？
はい。サーバーサイド管理者ユーザー（**アカウントの管理**権限を付与されたユーザー）は、自身を含むすべてのサーバーサイドユーザーの権限を変更できます。

#### サーバーサイド管理者は、すべてのサーバーサイドプロファイルの権限を管理できますか？
はい。サーバーサイド管理者ユーザーのアクセス権は、アカウントレベルの権限である**アカウントの管理**権限によって付与されます。この権限レベルを持つユーザーは、サーバーサイドインターフェイスの**ユーザーの管理**画面にアクセスし、すべてのプロファイルに対するユーザー権限を管理できます。

#### 新しいサーバーサイド権限は、Omnichannel File Status APIにどのような影響を与えますか？
[Omnichannel File Status API](https://docs.tealium.com/about-omnichannel-file-status-api/)へのアクセス制御は、サーバーサイド権限機能の正式リリース時に変更されます。[APIでの認証にAPIキーが必要](https://docs.tealium.com/api-keys/)という標準要件に加えて、ユーザーには該当するCustomer Data Hubアカウントへの読み取りアクセス権が必要です。[v1 API](https://docs.tealium.com/omnichannel-file-status-objects-v1/)を使用するユーザーに必要なのは、Customer Data Hubアカウントへの読み取りアクセス権のみです。

#### サーバーサイド管理者は、アカウントに新しいユーザーを追加できますか？
いいえ。**アカウントの管理**権限では、アカウントへの新しいユーザーの追加や、アカウントからのユーザーの削除は許可されません。プロファイルへのアクセス権を削除することはできますが、新しいユーザーをアカウントに招待したり、アカウントからユーザーを完全に削除したりできるのは、タグ管理ワークフローで**ユーザーの管理**権限を割り当てられたユーザーのみです。

#### この機能によって、TiQ内でユーザー管理アクセス権を付与または制御する方法は変わりますか？
いいえ。タグ管理の**ユーザーの管理**権限は、引き続きビジネスアカウントに対するユーザーの追加または削除を許可する権限です。**ユーザーの管理**権限のみを持つユーザーは、サーバーサイドの権限を管理できません。
