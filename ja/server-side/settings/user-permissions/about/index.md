## 仕組み

サーバーサイドのユーザー権限では、Tealium のクライアントサイドインターフェイスとサーバーサイドインターフェイスへのアクセスを分離することにより、各プロファイルに対するユーザーのアクセスレベルを制御できます。サーバーサイドの **Manage Users** 画面では、次の操作を実行できます。

* **新規ユーザーへのアクセス権の付与**  
新規ユーザーは、タグ管理でアカウントに追加されます。新規ユーザーを追加すると、サーバーサイドのユーザー権限リストに表示され、プロファイルごとにサーバーサイドへのアクセス権を付与できるようになります。アカウントに新規ユーザーを追加するには、**Manage Users** 権限が必要です。サーバーサイドでロールを割り当てるには、**Manage Account** 権限が必要です。
* **アクセス権の指定**  
アカウント管理者は、ユーザーが作業する必要のある領域にのみアクセス権を付与できます。また、あるプロファイルのクライアントサイド製品に対して、同じプロファイルのサーバーサイド製品には適用されない保存およびパブリッシュ権限を付与することもできます。
* **今後作成されるプロファイルの権限構成**  
アクティブなプロファイルでは、今後作成されるプロファイルの権限を構成できます。これにより、ユーザー管理者は、アカウントに新しく作成されるプロファイルのユーザーに対して、プロファイルレベルの権限ロールを定義できます。
* **ユーザーの一括追加と編集**  
ユーザーを一括で追加および編集でき（1回につき最大25ユーザー）、ユーザープロファイルを検索したり、権限タイプでユーザーを絞り込んだりできます。

## 管理者ユーザー

サーバーサイドインターフェイスの管理者だけが、サーバーサイドユーザーの権限を変更できます。サーバーサイドの権限ロールには、この機能を付与するものはありません。


<blockquote>
サーバーサイドの管理者になるには、クライアントサイドインターフェイスで **Manage Account** 権限を持っている必要があります。
</blockquote>


アカウントにユーザーを追加できるのは、クライアントサイドの **Manage Users** 権限のみです。タグ管理でのユーザー権限の管理について詳しくは、[タグ管理でのユーザー権限の管理](https://docs.tealium.com/about-user-permissions/)を参照してください。

## サーバーサイドの権限ロール

サーバーサイドへのアクセスは、事前定義された権限ロールを使用して制御されます。アカウント内の各プロファイルについて、ユーザーにはアクセスレベルを決定する権限ロールが割り当てられます。

次の表では、使用可能な4つのサーバーサイド権限ロールについて説明します。

| 権限ロール | 説明 |
|:---|:---|
| **アクセス不可（デフォルト）** | <ul><li>これは、アカウント管理者以外のすべてのユーザーに対するデフォルトのロールです。</li><li>**アクセス不可**権限ロールでは、サーバーサイドプロファイルへのアクセス権は一切付与されません。</li><li>ユーザーがサーバーサイドへのアクセスを試みると、そのプロファイルへのアクセスはブロックされ、**アクセスが拒否されました**というメッセージが表示されます。</li></ul> |
| **閲覧者** | <ul><li>**閲覧者**権限では、サーバーサイドプロファイルへの読み取り専用アクセスが付与されます。</li><li>このロールのユーザーはプロファイル構成を参照できますが、**保存／パブリッシュ**は無効です。このロールのユーザーは変更を保存できません。</li></ul> |
| **編集者** | <ul><li>**編集者**権限では、サーバーサイドプロファイルの編集および保存アクセス権が付与されます。</li><li>このロールでは保存できますが、パブリッシュはできません。</li><li>このロールのユーザーは、**Profile Admin > Settings** メニューから構成にアクセスして編集することもできます。</li></ul> |
| **パブリッシャー<br>（管理者のデフォルト）** | <ul><li>これは、アカウント管理者のデフォルトのロールです。</li><li>**パブリッシャー**権限では、**編集者**ロールと同じアクセス権に加えて、プロファイルを保存およびパブリッシュする権限が付与されます。</li></ul> |

サーバーサイド製品とクライアントサイド製品のプロファイルアクセス権は、相互に独立しています。たとえば、特定のプロファイルについて、サーバーサイド製品の権限に影響を与えることなく、クライアントサイド製品の保存およびパブリッシュ権限を付与できます。また、クライアントサイドでユーザーのプロファイルへのアクセス権を削除または変更しても、サーバーサイドでは削除または変更されません。
