## 仕組み

コネクタは、Tealium と別のベンダーとの間でデータをリアルタイムに送信する統合機能です。コネクタには、ベンダーがサポートする API を表すアクションが用意されています。アクションは、フィードから受信したイベント、またはオーディエンス内での訪問のステータスに基づいてリアルタイムにトリガーされます。アクションは、Tealium 属性をベンダーが要求するパラメータに関連付けるマッピングに基づいてデータを送信します。

[Data Cloud Activation](https://docs.tealium.com/about-data-cloud-activation/) では、セグメントデータは Tealium システムに永続化または保存されません。データを取得して構成済みのコネクタに送信した後、Tealium はそのデータを破棄します。

### 用語

* **コネクタ**  
コネクタは、ベンダーへの接続を表します。接続は、アカウント ID、ユーザー名とパスワード、API キー、その他の認証方法などの認証情報を使用して構成します。
* **アクション**  
アクションは、コンバージョンのトラッキング、カスタムオーディエンスの構築、リードの管理などのベンダー操作です。アクションはベンダーのサービスによって異なります。1 つのコネクタに複数のアクションを関連付けることができます。
* **トリガー**
  * イベントコネクタでは、フィード内のリアルタイムイベントごとにアクションがトリガーされます。
  * オーディエンスコネクタでは、オーディエンス内での訪問のステータスに基づいてアクションがトリガーされます。
    * **オーディエンスへの参加**：訪問がこの訪問中にオーディエンスに参加しました。
    * **オーディエンスからの離脱**：訪問がこの訪問中にオーディエンスから離脱しました。訪問が削除された場合、このアクションは発生しません。詳細については、[訪問の削除](https://docs.tealium.com/visitor-search/#deleting-a-visitor)を参照してください。
    * **訪問開始時にオーディエンスに所属**：訪問開始時に訪問がオーディエンスに所属していました。
    * **訪問終了時にオーディエンスに所属**：訪問終了時に訪問がオーディエンスに所属していました。
* **コネクタメタデータ**  
コネクタのコンテキスト（オーディエンス名、アクション ID など）を記述する、マッピング可能な値です。手動でコピー＆ペーストすることなく、コネクタ情報をダウンストリームに渡すために使用します。詳細については、[コネクタメタデータ](https://docs.tealium.com/add-connector/#connector-metadata)を参照してください。
* **フリークエンシーキャップ**  
コネクタアクションはリアルタイムに実行されますが、一部のアクションはトリガーされるまでに待機時間が設けられるように設計されています。フリークエンシーキャップを使用すると、アクションが即座にトリガーされないように休止期間を構成できます。詳細については、[action-frequency-capping-amp-prioritization](https://docs.tealium.com/action-frequency-capping-amp-prioritization/)を参照してください。
* **ソース**  
ソースは、処理対象となるデータの取得元を示します。ソースには、オーディエンスまたはイベントフィードを指定できます。

### 同意カテゴリ

マーケットプレイスの各コネクタでは、利用可能なアクションごとに 1 つ以上の同意カテゴリが割り当てられています。コネクタアクションの同意情報は、**アクションの詳細**画面の**追加の詳細**に表示されます。

![](https://docs.tealium.com/images/server-side/eventstream-connector-consent-categories.png)

Customer Data Platform（CDP）は **CDP** 同意カテゴリに、DataAccess は **Big Data** 同意カテゴリに分類されます。サーバーサイドの同意に関する詳細については、[同意構成マネージャー](https://docs.tealium.com/ja/consent/client-side/consent-management/consent-preferences-dialog/manage/)を参照してください。

### 再試行

コネクタアクションが失敗した場合、1 分後、5 分後、30 分後の間隔で 3 回再試行されます。後続のいずれかの再試行でリクエストが成功した場合、そのリクエストは UI で成功として報告されます。3 回の再試行がすべて失敗した場合、リクエストは破棄され、UI でエラーとして報告されます。

次のいずれかのエラーコードが発生すると、再試行が実行されます。

* 408 – 禁止
* 429 – リクエスト過多
* 500 – 内部サーバーエラー
* 502 – 不正なゲートウェイ
* 503 – サービス利用不可
* 504 – ゲートウェイタイムアウト

**応答タイムアウト - ベンダー API が 5000 ミリ秒以内に応答しませんでした**という応答を受信した場合、再試行は実行されません。リクエストペイロードは送信されましたが、ベンダーから許容時間である 5 秒以内に応答がありませんでした。ベンダー側ではリクエストが成功している可能性がありますが、応答を受信するまでに 5 秒を超えたため、失敗として扱われます。

### 過負荷保護

コネクタは、データハンドラーの複数のインスタンスを通じてアクションを実行します。データハンドラーで、ベンダーとの通信エラーが発生する場合があります。エラーが構成済みのしきい値を超えると、エラー率が低下するまで、Tealium はベンダーへのデータ送信を一時停止または抑制できます。

たとえば、あるインスタンスの全体的な失敗率が 100 回の試行あたり 40% を超えると、そのインスタンスはアクションの処理を 1 分間一時停止します。その後、インスタンスはキュー内のアクションの半分を処理しようとします。この 50 回の試行で失敗率が引き続き 20% を超えている場合、インスタンスは再試行する前にさらに 60 秒間一時停止します。それ以外の場合、インスタンスは通常の処理を再開します。

Tealium は、お客様に最大限の成功率とパフォーマンスを提供するため、必要に応じて各レベルのしきい値を有効化し、調整します。

### 制限付きデータ

制限付きデータの構成はコネクタには適用されません。制限付きデータとしてマークされた属性は、マッピングを通じて送信する場合でも、訪問プロファイルの一部として送信する場合でも、常に含まれます。この動作は変更できません。詳細については、[制限付きデータ](https://docs.tealium.com/about-restricted-data/)を参照してください。

### IP 許可リスト

使用するコネクタに、リクエストを受け付けるシステムに関する厳格なルールがある場合、Customer Data Hub の IP アドレスを許可リストに追加できます。コネクタリクエストを送信する IP アドレスについては、[Customer Data Hub の IP アドレス]()を参照してください。

### 訪問 ID の同期

Tealium とサードパーティベンダー間での訪問 ID の照合精度を向上させるには、Cookie マッチングタグを使用します。Cookie マッチングタグは、Tealium とベンダー間で訪問識別子を同期します。このタグはサードパーティ識別子をリクエストし、匿名 ID を受信して Cookie に保存します。これにより、コネクタアクションでより正確なトラッキングと充実したデータを利用できます。詳細については、[永続的な Cookie マッチングについて](https://docs.tealium.com/about-persistent-cookie-matching/)を参照してください。

## 画面の操作

### 概要画面

コネクタの概要画面には、各コネクタについて次のデータが表示されます。

* **アクション**  
データタイプ（イベントおよび訪問）ごとに構成されたコネクタアクションの数。この列の合計に関するタイムラインを表示するには、情報（i）アイコンをクリックします。
* **合計ボリューム**  
コネクタでトリガーされたアクションの数。
* **成功**  
成功したアクションの数。
* **エラー**  
エラーになったアクションの数。
* **更新日**  
コネクタが最後に変更された日付。
* **ラベル**  
コネクタに適用されているラベル。
* **ステータス**  
コネクタのステータス。**アクティブ**、**非アクティブ**、または**非推奨**のいずれかです。

**メトリクスをエクスポート**をクリックすると、すべてのコネクタのメトリクス（合計ボリューム、成功数、エラー数、再試行数）をエクスポートできます。データは CSV ファイルとしてダウンロードされます。

コネクタのメニューを展開すると、**ラベルを編集**、**複製**、**削除**の追加アクションにアクセスできます。

![](https://docs.tealium.com/images/server-side/connectors/connector-menu-expanded.png)

詳細については、[コネクタの追加]()を参照してください。
### 詳細画面

コネクターアクションをクリックすると、コネクターの詳細画面が表示されます。デフォルトでは **Overview** タブが表示され、成功したアクション、エラーが発生したアクション、配信ステータスのグラフなど、アクションの傾向に関する情報を確認できます。

![](https://docs.tealium.com/images/server-side/connectors/connector-details-status.png)

傾向データは、**Past 24 hours**、**Past 7 days**、または **Past 30 days** の期間で表示できます。デフォルトは **Past 24 hours** です。成功したアクションは緑色、エラーは青色で表示されます。グラフの任意の部分をクリックすると、その表示範囲のデータの概要を確認できます。

#### アクションのサンプリングされたエラーを表示する

コネクターアクションのエラー情報を表示するには、次の手順を実行します。

1. **Connect > Connectors** に移動し、コネクターを選択します。
1. **Actions** タブをクリックし、エラーが発生しているアクションを選択します。  
**Action Details** 画面が表示されます。
1. **Trends** で、**24 Hours**、**7 Days**、**30 Days**、またはカスタムの日付範囲を選択します。
1. グラフの下に、エラーメッセージの一覧が表示されます。各エントリには、エラーカテゴリー、メッセージ、レポートに含まれるエラー数、およびそのエラーの合計発生回数が表示されます。
1. エラーの詳細を表示するには、一覧のエントリをクリックします。  
詳細ビューには、影響を受けたコードのサンプルと、曜日、日付、時刻を含むタイムスタンプが表示されます。

#### サンプリングされたエラーをエクスポートする

コネクターのサンプリングされたエラーをエクスポートするには、次の手順を実行します。

1. **Connect > Connectors** に移動し、コネクターを選択します。
1. **Actions** タブをクリックし、エラーが発生しているアクションを選択します。  
**Action Details** 画面が表示されます。
1. **Export Sampled Errors** をクリックします。  
エラーがCSVファイルにエクスポートされ、デフォルトのダウンロード先に保存されます。
1. CSVファイルを開いて詳細を確認するか、さらなる共同作業のために他のユーザーとファイルを共有します。

### 非推奨のコネクターとアクション

コネクターやアクションは非推奨になる場合があります。これは、将来的にサポートが終了したり、削除されたりする可能性があることを意味します。通常、コネクターやアクションが新しいバージョン、または代わりに使用すべき新しいコネクターやアクションに置き換えられた場合に非推奨となります。

非推奨には、次の2種類があります。

* **機能上の非推奨** – コネクターまたはアクションは非推奨であり、将来的に削除される可能性がありますが、引き続き動作します。
* **完全な非推奨** – コネクターまたはアクションは非推奨であり、動作しなくなります。完全に非推奨となったコネクターのアクションは実行されません。
