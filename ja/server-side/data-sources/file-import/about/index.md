## 前提条件

* CDP **または**
* Event Streaming API Hub


<blockquote>
正常にインポートするには、CSV ファイルを正しくフォーマットする必要があります。ファイル形式とデータ形式については、[インポート用 CSV ファイルの準備](https://docs.tealium.com/prepare-a-csv-file-for-import/)を参照してください。
</blockquote>


## 仕組み

Tealium サーバーを使用して、Amazon S3 バケットなどのファイルサービスに接続し、ファイルを読み取ってデータをインポートします。インポートされた各行はイベントとして処理されます。インポート後、データをエンリッチし、既存の訪問プロファイルに統合して、他のベンダーに送信できます。

### 処理速度

ファイルインポートは履歴データ向けのバッチ取り込みプロセスであり、リアルタイムのイベントデータを対象としたものではありません。  
ファイルの行は、マルチテナント環境における各リージョンの負荷に応じて変動する速度で処理されますが、ほとんどのファイルは 24 時間以内に処理されます。

大量のイベントデータをリアルタイムで処理するには、次のいずれかを使用してください。

* [HTTP API](https://docs.tealium.com/endpoint-spec/)
* [Advanced HTTP API](https://docs.tealium.com/http-api-advanced-incoming-webhook-setup-guide/)

### イベント

Tealium のデフォルトの[データ収集処理順序](https://docs.tealium.com/server-side-order-of-operations/)では、ファイルインポートデータソースからのイベントは _Event received_ ステップの前に処理され、処理順序は変更されません。

ファイルインポートイベントは、他のデータソースからのイベントと同じ方法で Event Streaming と Customer Data Platform（CDP）に送信されますが、次の重要な例外があります。

* **ブラウザー固有の属性**：ユーザーエージェントなど、ブラウザー固有の属性には値が構成されません。
* **エンリッチメント**：CDP の事前読み込み属性に対するエンリッチメントは、事前読み込み属性の **First Visit** を除き、実行されません。
* **関数**：データ変換関数は実行されません。
* **単一ページの訪問**：受信イベントには、単一ページの訪問および訪問に関する条件は適用されません。他のデータソースからの単一ページの訪問および訪問は、CDP に保持されません。単一ページの訪問および訪問について詳しくは、[CDP では単一ページの訪問をどのように処理しますか？](https://docs.tealium.com/single-event-visitor/)（Tealium へのログインが必要）を参照してください。
* **訪問の長さ**：ファイルインポートイベントによって開始された訪問は 60 秒間継続します。
* **訪問 ID マッピング**：ファイルインポートデータソースの構成で CDP 訪問 ID 属性をマッピングすると、訪問 ID は選択した列の値に直接構成されます。

さらに、ファイルインポートデータソースから受信するデータでは、次のイベント属性を使用できます。

* `_source_file`（文字列）- イベントに関連付けられたファイルの名前。
* `_file_line_num`（整数）- イベントに関連付けられたファイルの行番号。

## ファイルインポートデータソースの構成

ファイルインポートをデータソースとして構成するには、次の 2 つの手順があります。

1. **列のマッピングとファイル転送サービスの構成**  
ファイルインポートデータソースを構成するには、CSV ファイルの列を Tealium のイベント属性にマッピングし、ファイル転送サービスを選択します。
<blockquote>
列のマッピングを容易にするため、列ラベルと最大 1,000 行のデータを含むサンプル CSV ファイルをアップロードしてください。
</blockquote>

1. **ファイル転送サービスへのファイルのアップロード**  
データソースを構成したら、CSV ファイルをファイルサービスにアップロードします。ファイルのアップロードは Tealium の外部で行います。

## 手順 1：CSV 列のマッピングとファイル転送サービスの構成

### 列のマッピング

列マッピングの構成では、CSV ファイルの各列に対応するイベント属性を指定します。列名は Customer Data Hub の属性名と異なることが多いため、このマッピングによってデータが正しくインポートされるようにします。たとえば、CSV ファイルに `postalCode` という列があり、対応するイベント属性の名前が `customer_zip` である場合、両者を関連付けるためにこれらの列をマッピングする必要があります。

マッピングは、既存のイベント仕様またはカスタムイベントに基づいて構成できます。

#### イベント仕様のマッピング

CSV ファイルの各行はイベントとして処理されます。イベント仕様のマッピングを選択すると、**Column Mapping** テーブルでイベント属性が事前に選択されます。各行は、選択した仕様のイベント（例：`tealium_event = "purchase"`）として処理されます。

#### カスタムマッピング

カスタムイベントマッピングを選択した場合は、各 CSV 列に対応するイベント属性を指定します。各行は、次のイベント識別子を持つイベントとして処理されます。

`tealium_event = "imported"`

#### 訪問 ID のマッピング

インポートしたデータを Web、モバイル、HTTP API などの他のソースと確実に統合するには、ファイルインポートのソースファイルの各行に、一意の訪問 ID を含む列があることを確認してください。その後、訪問 ID 列と対応するイベント属性を、訪問 ID 属性（CDP で訪問を識別するための一意の属性タイプ）にマッピングできます。マッピングされたイベント属性の値は `tealium_visitor_id` 属性に割り当てられ、既存の訪問プロファイルと直接照合されます。

AudienceStream の訪問 ID マッピングについて詳しくは、[Tealium データソースを使用した訪問の識別](https://docs.tealium.com/visitor-identification-data-sources/)を参照してください。

### ファイル転送サービス

ファイル転送サービスは、インポートするファイルをアップロードするための安全な場所です。Tealium は、次のファイル転送サービスをサポートしています。

* Amazon S3
  * [AWS S3 バケット](https://docs.tealium.com/aws-s3/)
  * [Tealium S3 バケット](https://docs.tealium.com/tealium-s3/)  
* [Microsoft Azure File/Blob Storage](https://docs.tealium.com/azure/)
* [SFTP](https://docs.tealium.com/sftp/)

#### Tealium S3 のファイル保持

ファイルインポート構成で Tealium S3 バケットを使用することにより、次のファイル保持ポリシーに同意したものとみなされます。

* **1～3 年** - Tealium S3 バケットへのファイルのアップロードから 1 年後、ファイルは長期保存用のリポジトリに移動されます。ファイルには最長 3 年間アクセスできます。長期保存からファイルを取得する際は、要求する項目のサイズと数に応じて、少額から中程度のサービス料金が発生します。ファイルを取得するには、Tealium サポートにお問い合わせください。
* **3 年以上** - Tealium S3 バケットへのファイルのアップロードから 3 年後、ファイルは完全に削除されます。ビジネス上の要件により 3 年を超える保存が必要な場合は、より長いデータ保持期間を顧客契約に明記する必要があります。保持期間の延長を申請するには、Tealium サポートにお問い合わせください。
## ステップ2：ファイル転送サービスにファイルをアップロードする

ファイルインポートデータソースの構成が完了したら、選択したファイル転送サービスにファイルをアップロードします。

Tealium は、次の順序でファイルをインポートします。
1. **新しいファイルの確認**  
システムは、10分ごとにファイル転送サービス上の新しいファイルを確認します。
1. **新しいファイルのコピー**  
新しいファイルが検出されると、そのファイルはファイル転送元からコピーされ、Customer Data Hub で処理されます。
1. **ファイル名のプレフィックスとファイルインポートデータソースの照合**  
ファイル名のプレフィックスを使用して、ファイル内のデータをインポートするときに使用するファイルインポートデータソースを特定します。
1. **ファイルの処理**  
ヘッダー行を読み取り、インポートする属性を特定します。ヘッダー行の読み取り後、次の処理が実行されます。
    1. **訪問の検索** — 訪問IDを使用して、CDP内の訪問レコードを検索します。既存の訪問レコードが見つからない場合は、新しいレコードが作成されます。
<blockquote>
同じ訪問IDを持つ行をグループ化すると、インポート時間を短縮できます。
</blockquote>

    1. **属性のエンリッチメント** - インポートされた属性とアカウント内の既存のエンリッチメントに基づいて、訪問レコードがエンリッチされます。
