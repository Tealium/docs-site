## サポートされているベンダー

クラウドデータソースの構成は、どのベンダーでもほぼ同じです。ベンダー固有の構成の詳細については、以下を参照してください。

* [Amazon Redshift](https://docs.tealium.com/amazon-redshift-cloud-data-source/)
* [Databricks](https://docs.tealium.com/databricks-cloud-data-source/)
* [Google BigQuery](https://docs.tealium.com/google-bigquery-cloud-data-source/)
* [Snowflake](https://docs.tealium.com/about-snowflake-cloud-data-source/)

## クラウドデータソースの作成

クラウドデータソースを作成するには、次の手順を実行します。

1. **Connect > Data Sources**に移動します。
1. **+ Add Data Source**をクリックします。
1. **Categories**で**Data Warehouse**をクリックし、ベンダーを選択します。
1. **Name**フィールドに、ユースケースに関連するデータソースの一意の名前を入力します。
1. **Continue**をクリックします。

## 接続の確立

インポートするデータを構成する前に、クラウドデータソースへの接続を確立する必要があります。接続とは、Tealiumをクラウドデータソースに接続するための、再利用可能なベンダー認証情報の構成です。

1. **Connection Configuration**画面でデータソース名を確認し、リストから既存の接続を選択するか、**+**アイコンをクリックして接続を作成します。
1. 新しい接続の場合は、接続情報を入力して**Save**をクリックし、**Connection Configuration**画面に戻ります。
1. **Establish Connection**をクリックします。

ベンダーへの接続の詳細については、以下を参照してください。

* [Amazon Redshift](https://docs.tealium.com/amazon-redshift-cloud-data-source/#create-a-connection)
* [Databricks](https://docs.tealium.com/databricks-cloud-data-source/#create-a-connection)
* [Google BigQuery](https://docs.tealium.com/google-bigquery-cloud-data-source/#create-a-connection)
* [Snowflake](https://docs.tealium.com/snowflake-cloud-data-source/#create-a-connection)

## 処理の構成

### 処理の有効化

変更を保存してパブリッシュした直後にデータのインポートを開始するには、**Enable Processing**をオンにします。構成が完了するまではこの構成をオフのままにして、後で処理を有効にすることもできます。

### クエリの実行頻度

Tealiumがデータを取得する頻度を構成します。次の処理オプションから選択します。

* ほぼリアルタイム  
処理は2秒ごとに実行されます。
* 毎時  
処理は毎時0分に実行されます。
* 毎日  
処理は指定した時刻に1日1回実行されます。
* 毎週  
処理は指定した曜日と時刻に週1回実行されます。

### バッチサイズ

次のいずれかのバッチオプションを選択します。

* **Default**：バッチあたり1,000レコード。
* **Custom**：1,000レコードを超えるカスタムバッチを作成します。
* **No limit**：使用可能なすべてのデータを処理する、上限のないバッチを作成します。

## クエリの構成

**Query Configuration**画面で、BasicまたはAdvanced構成モードを選択します。

* Basicモード：データソース構成で指定されたデフォルトのスキーマを使用してデータをインポートします。1つのテーブルまたはビューのデータのみを処理できます。
* Advancedモード：高度なSQLエディターを使用して、結合する1つ以上のテーブルを指定できます。テーブルは複数のスキーマに属していてもかまいません。

### ステップ1：クエリの作成

#### Basicモード

Basicモードでは、クエリに含めるテーブルと列を選択します。選択項目には、増分列、タイムスタンプ列、または増分列とタイムスタンプ列の両方を含める必要があります。

必要に応じてSQLの`WHERE`句を追加し、カスタム条件に一致するレコードのみをインポートできます。SQLの`WHERE`句では、ネストされた`SELECT`文はサポートされません。複数のテーブルを結合するには、Advancedモードを使用します。

#### Advancedモード

Advancedモードでは、SQLエディターを使用して有効な読み取り専用SQLクエリを入力し、1つ以上のテーブルまたはスキーマに接続します。SQLエディターは、`CAST`や`JOIN`などの高度なSQLコマンドをサポートしています。選択項目には、増分列、タイムスタンプ列、または増分列とタイムスタンプ列の両方を含める必要があります。クエリの構成が完了したら、**Continue to Query Mode**をクリックします。

##### SQLクエリのベストプラクティス

* **計算フィールド**  
Advanced SQLクエリは、計算（派生）フィールドをサポートしています。計算値はバッチ取得のたびに再評価され、ベンダーによって動作が異なる場合があります。クエリモードの列（タイムスタンプ、増分、またはタイムスタンプと増分）に計算フィールドを使用すると、データのインポートでエラー（行のスキップや取り込みのループなど）が発生する可能性があります。クエリモードの列には計算フィールドを使用しないことをお勧めします。
* **LIMIT句**  
Tealiumデータソースはストリーミング方式であるため、LIMIT句を使用してもインポートされるデータの総量は削減されません。テストで処理するレコード数を変更するには、WHERE句またはエンドツーエンドテストを使用します。詳細については、[構成のテスト](https://docs.tealium.com/manage-cloud-data-source/#test-configuration)を参照してください。
* **読み取り専用**  
読み取り専用のSQLクエリのみがサポートされています。クエリでスキーマやデータを変更しないようにしてください（たとえば、`DELETE`、`UPDATE`、`INSERT`、`DROP`、`ALTER`の使用）。

##### SQLライター

データソースSQLライターは、自然言語のプロンプトからSQLクエリを生成するAIアシスタントです。SQLライターを使用するには、[AI構成](https://docs.tealium.com/ai-features/)でこの機能を有効にします。

SQLライターを使用してクエリを生成するには、次の手順を実行します。

1. **+ Select Tables**をクリックし、クエリのコンテキストとして使用するスキーマとテーブルを選択します。
1. **AI Assistant**をクリックして、SQLライターパネルを開きます。
1. 必要なクエリを自然言語で記述します。SQLを生成する前に、アシスタントからテーブルや列について追加の質問が行われる場合があります。
    ```wrap
    Show me all customers who made a purchase in the last 30 days. Join with the orders table on customer_id and include their email address, total spend, and most recent order date.
    ```
1. クエリをコピーしてSQLエディターに貼り付けます。


<blockquote>
クエリをテストする前に、**Step 2. Set Query Mode**に進み、クエリモードを選択する必要があります。
</blockquote>


### ステップ2：クエリモードの構成

クエリモードでは、新しい行、変更された行、またはその両方をインポート対象として選択する方法を指定します。

* **Timestamp + Incrementing**（推奨）を選択する場合は、タイムスタンプ列と厳密に単調増加する列の2つを選択する必要があります。
* **Timestamp**または**Incrementing**を選択する場合は、新しい行と変更された行の両方、または新しい行のみを検出するために使用する列を選択する必要があります。

詳細については、を参照してください。

完了したら、**Test Query**をクリックして結果をプレビューします。

### ステップ3：テストクエリのプレビュー

テストクエリのプレビューを使用して、クエリ結果を検証します。

### ソーステーブルの列の変更

データソースを構成した後にソーステーブルの列が変更された場合、必要な対応は変更の種類によって異なります。

* **列名の変更**：クエリビルダーで使用している列の名前がソーステーブルで変更された場合は、データソースを複製する必要があります。
  1. **Data Sources**画面のデータソースアクションメニューから**Duplicate**オプションを選択します。
  1. 複製したデータソースで、新しい列名を使用するようにクエリビルダーを更新します。
  1. **Set Processing Start**を使用して、新しいデータソースの取り込み開始位置を構成します。詳細については、[処理開始位置の構成]()を参照してください。
* **列の追加**：
  * ソーステーブルに新しい列が追加され、その列を取り込む必要がない場合、対応は不要です。
  * 追加された列がタイムスタンプ列または増分列の場合は、列名が変更された場合と同様にデータソースを複製します。
  * その他の種類の新しい列の場合：
    1. データソースの処理を**Off**に切り替え、保存してパブリッシュします。
    1. データソースを編集し、クエリビルダーに列を追加して、列マッピングを追加します。
    1. 処理の切り替えを**On**に構成します。
    1. もう一度保存してパブリッシュします。
## 列をマッピングする

列マッピングテーブルを使用して、事前構成された列ラベルをイベント属性にマッピングするか、マッピングする列ラベルを手動で入力します。イベント属性にマッピングされていない列は無視されます。

列ラベルごとに、対応するイベント属性をリストから選択します。

## 訪問 ID をマッピングする

クラウドデータソースを Customer Data Platform（CDP）で使用するには、列を訪問 ID 属性にマッピングします。訪問 ID を表す列を選択し、対応する訪問 ID 属性にマッピングします。


<blockquote>
AudienceStream の**訪問 ID マッピング**は、デフォルトで有効になっています。訪問 ID マッピングを無効にすると、訪問のスティッチングでエラーが発生する可能性があります。詳細については、[Tealium データソースを使用した訪問の識別]()を参照してください。
</blockquote>


## 概要

この最後のステップでは、概要を確認して必要な修正を行い、プロファイルを保存してパブリッシュします。構成を編集するには、**Previous**をクリックして、変更するステップに戻ります。

1. イベント属性と訪問 ID のマッピングを確認します。
1. **Finish**をクリックしてデータソースを作成し、構成画面を終了します。新しいデータソースが**Data Sources**ダッシュボードに表示されます。
1. **Save/Publish**をクリックして変更内容を保存し、パブリッシュします。

インポートのアクティビティを確認するには、**Data Sources**に移動してデータソースを展開します。

## ステータス

クラウドデータソースを構成すると、次のいずれかのステータスが表示される場合があります。

| **ステータス** | **説明** |
|------------------|-----------------|
| **Failed** | 認証失敗などの接続エラーが発生しており、エラーが解決されるまでインポートは停止します。インポート中に発生した行レベルのエラーによってこのステータスになることはありません。これらのエラーはログに記録され、データソースは**Running**のままとなります。 |
| **Inactive** | データソースは作成されましたが、一度も有効化されておらず、ほかのステータスにも移行していません。 |
| **Initializing** | コネクタが初めて起動しているか、**Stopped**状態から再開しています。これは、**Running**または**Scheduled**に移行する前の一時的な状態です。 |
| **Running** | コネクタがデータのクエリとインポートを実行しています。 |
| **Scheduled** | 次回のインポートの実行がスケジュールされています。この状態は、**Initializing**または**Running**の後に続く場合があります。 |
| **Stopped** | 以前は有効だったデータソースが現在は無効になっています。有効化されるまで、データのインポートは実行されません。 |
| **Unassigned** | タスクはクラウドワーカーへの割り当てを待機しています。 |

## 構成をテストする

データソース、セグメント、またはアクティベーションを有効にする前に、データソースとクエリをテストすることをお勧めします。ただし、テストを実行すると、セグメントがアクティブ化されたり、有効なアクションがトリガーされたり、ダウンストリームシステムに影響したりする可能性があります。意図しない結果を防ぐため、コネクタと関数を無効にし、テストレコードを制限して、受信者と調整してください。

データソースの構成をテストするには、次の手順を実行します。

![](https://docs.tealium.com/images/early-access/cloudstream/cloudstream_test_configuration.png)

1. Data Sources 画面でデータソースを見つけ、編集アイコンをクリックします。
1. データソースウィンドウの右上隅にあるアクションボタンをクリックし、**End-to-End Testing**をクリックします。
1. 出力の受信方法を選択します。
    * **New Trace Session**：出力が、最大 10 件のレコードを含む新しいトレースセッションに表示されます。このオプションは、エンドツーエンドの検証とログの詳細を確認する場合に最適です。
    * **Existing Trace Session**：出力が、すでに開始しているトレースセッションに表示されます。**Trace ID**を入力し、**Join Trace**をクリックします。
    * **Direct Output**：未加工の出力結果が画面に表示されます。データレコードにトレース ID は追加されず、トレースも利用できません。このオプションは、クエリと属性マッピングをすばやく確認する場合に最適です。
1. テストで処理する行数を選択します。最大行数は 10 行です。
1. **Test Query**で、テストに含める列をテーブルから選択します。列の**X**をクリックすると、リストから削除できます。少なくとも 1 つの列を選択する必要があります。
1. **From Table**で、クエリ対象のテーブルを選択します。**Select Columns**ボックスが、選択したテーブルの列で更新されます。
1. **Where**に、テーブルに対して実行する SQL クエリを入力します。
1. **Check Query**をクリックして SQL を検証し、必須フィールドが構成されていることを確認します。
1. 結果は、**Query Result Preview**タブのテーブルに表示されます。![](https://docs.tealium.com/images/early-access/cloudstream/cloudstream_test_check_query.png)
1. **Start Test**をクリックして構成テストを開始します。

右側のサイドバーには、テスト完了までの推定時間を示す進行状況バーと、テストでエラーが発生したかどうかを示すステータスメッセージが表示されます。

![](https://docs.tealium.com/images/early-access/cloudstream/cloudstream_test_output.png)

テストが完了すると、結果が表示されます。

![](https://docs.tealium.com/images/early-access/cloudstream/cloudstream_test_results.png)

* トレースでテストの実行状況を確認するには、**Join Trace**をクリックします。
* テストが失敗した場合は、次の操作を実行できます。
     * **Edit Test Configuration**をクリックして構成を変更します。
     * **Retry Test**をクリックして、現在の構成で再度テストを実行します。
## 処理開始位置の構成

データソースは、クラウドデータのビューまたはテーブルに対するクエリを開始する日付、または増分値の位置を追跡します。この位置をリセットまたは手動で構成することで、ビューまたはテーブル内のどこからクエリを開始するかを制御できます。

たとえば、最近のメーリングリストのアクティベーションにエラーがあり、100件のレコードが処理され、現在の増分位置が342であるとします。メールアクティベーションを修正した後にこれらのレコードを再処理するには、開始位置を242に構成します。データソースを再起動すると、その位置からレコードがクエリされ、修正されたメールが送信されます。

開始位置を管理できるのは、次の条件を満たしている場合のみです。

* 現在のプロファイルが公開されている。
* クエリモードが **Timestamp + Incrementing (Recommended)**、**Timestamp**、または **Incrementing** である。クエリモードが **Full Resync** の場合、開始位置は管理できません。
* データソースが停止している。
    * データソースのステータスが実行中、スケジュール済み、または失敗の場合、開始位置を編集できません。現在の開始位置に関する情報のみ確認できます。
    * ステータスが初期化中、非アクティブ、または接続エラーの場合、開始位置は利用できません。

データソースの開始位置を管理するには、次の手順を実行します。

![](https://docs.tealium.com/images/early-access/cloudstream/manage_offset.png)

1. **Data Sources** 画面でデータソースを見つけ、編集アイコンをクリックします。
1. データソースの詳細ウィンドウの右上隅にあるアクションボタンをクリックし、**Set Processing Start** をクリックします。
1. 使用できる開始位置の構成方法は、**Processing Start Timestamp** と **Incrementing Start Point** です。使用可能な開始位置は、クエリモードによって決まります。
1. **Timestamp Column** で、テーブル内のタイムスタンプを表す列を選択します。
1. **New Timestamp** で、データをインポートする際の開始位置として使用する日時を選択します。
    * 新しいタイムスタンプには過去の日時を指定する必要があります。未来の日時は指定できません。
    * 現在のタイムスタンプフィールドには、現在使用されている開始位置が表示されます。
1. **Incrementing column** で、テーブルに追加される各行の増分値を表す列を選択します。
1. **New Increment** に、データをインポートする際の開始位置として使用する数値を入力します。
    * 新しい開始位置は正の整数でなければなりません。
    * 現在の開始位置フィールドには、開始位置として現在使用されている位置が表示されます。

**Validate Processing Start Changes** をクリックして、新しい開始位置からインポートされるデータをプレビューします。テーブルにはサンプル行が表示されます。また、開始位置を調整した後に処理される行数の見積もりも表示されます。

![](https://docs.tealium.com/images/early-access/cloudstream/validate_offset.png)

新しい開始位置の構成を確定するには、**Done** をクリックします。変更を破棄するには、**Cancel** をクリックします。  
開始位置を変更した後、データソースを再起動します。
