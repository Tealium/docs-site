<blockquote>
AudienceStreamで訪問IDマッピングを無効にすると、訪問スティッチングでエラーが発生する可能性があります。最適な訪問スティッチング結果を得るには、訪問IDマッピングを有効にしておいてください。
</blockquote>



## 仕組み

ファイルインポートまたはSnowflakeデータソースを使用してオフラインの顧客データをアップロードすると、インポートされた各行がイベントとして処理されます。インポートしたデータをWeb、モバイル、HTTP APIなどの他のソースとスティッチングするには、データソースの各行に、そのデータを顧客に関連付ける一意の訪問IDを含む列があることを確認してください。


<blockquote>
詳細については、[訪問スティッチングについて](https://docs.tealium.com/about-visitor-stitching/)を参照してください。
</blockquote>


訪問IDマッピングを使用すると、データ内の訪問識別列に、1つ以上の訪問ID属性値を割り当てることができます。訪問ID列の値は`tealium_visitor_id`に割り当てられ、既存の訪問プロファイルと照合されます。訪問ID属性にマッピングされたどの列にも値がない場合は、ランダムな`tealium_visitor_id`値が生成されます。

次の例は、各行／イベントの`tealium_visitor_id`がどのように構成されるかを示しています。

`__acme_main__1234_100120394__`

各パラメータの意味は次のとおりです。
* `acme` - アカウント名。
* `main` - Tealium Customer Data Hubのプロファイル名。
* `1234` - Customer Data Platform（CDP）内の訪問ID属性の数値ID。
* `100120394` - 訪問ID属性に構成されるCSVファイル内の値。

訪問IDの詳細については、[匿名ID、ユーザー識別子、訪問ID属性](https://docs.tealium.com/anonymous-user-visitor-id-attributes/)を参照してください。

## 訪問IDマッピングを無効にする場合

ファイルインポートまたはSnowflakeデータソースを構成する際に、AudienceStreamで訪問IDマッピングを有効にする必要がない特定のユースケースがあります。

* TealiumプロファイルでCDPが有効になっていない場合。
* CDPがWebまたはアプリでユーザーを識別するために使用したものと同じ匿名訪問IDに基づくデータをインポートする場合。この場合は、AudienceStreamで訪問IDマッピングを無効にし、この訪問IDを含む列をイベント属性`tealium_visitor_id`に直接マッピングします。

## 属性エンリッチメントを使用する場合（ファイルインポートのみ）

次の場合、最適な訪問スティッチング結果を得るには、CSVファイル内のソースデータを変更してください。CSVファイルのデータを編集できない場合は、訪問ID属性の手動エンリッチメントを使用します。

* アップロードするファイルの訪問識別列に誤った値が含まれている可能性がある場合。Tealiumへアップロードする前に誤った値を確実に削除するようデータをフィルタリングできない場合は、AudienceStreamで訪問IDマッピングを無効にし、訪問IDのエンリッチメントを手動で構成します。
<blockquote>
ファイルに誤った訪問ID値が含まれている状態で訪問IDマッピングが有効になっていると、訪問ID値を検証できず、訪問スティッチングでエラーが発生する可能性があります。
</blockquote>

* ファイルインポートによってアップロードされたデータを、訪問IDに割り当てる前に変換する必要がある場合。たとえば、列の値を連結する、小文字に変換する、またはプレフィックスやサフィックスをエンリッチメントする必要がある場合です。可能な場合は、必要な変換を適用した列をソースCSVファイルに含めることをお勧めします。変換をファイル自体に含められない場合は、AudienceStreamで訪問IDマッピングを無効にし、訪問IDのエンリッチメントを手動で構成します。
