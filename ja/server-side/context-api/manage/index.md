## エンジンの作成


<blockquote>
エンジンの属性を選択する前に、プロファイルの変更が公開されていることを確認してください。
</blockquote>


エンジンを作成するには、以下の手順を完了します：

1. **Activate > Context API** に移動し、**+ New Engine** をクリックします。
1. **Details** 画面で、以下のエンジン詳細を構成します：
    * **Name**: エンジンの名前を入力します。
    * **Enable Engine**: エンジンをオンまたはオフに切り替えます。デフォルトではエンジンエンドポイントはオフです。エンジンを有効にし、訪問がアクティブなセッションを記録し、システムでイベントを生成した後、訪問のデータが利用可能になります。
    
<blockquote>
認証とPIIの許可はリクエストによりのみ利用可能です。これらの機能を試してみたい場合は、[サポートに連絡](https://docs.tealium.com/support/)してください。
</blockquote>

    * **Authentication**: このエンドポイントへのリクエストが認証を必要とするかどうかを制御します。
        * **Public** (デフォルト): エンジンIDを持つ任意の呼び出し元がエンドポイントを呼び出すことができます。
        * **Require Authentication**: 認証されたクライアントのみがエンジンを呼び出すことができます。認証されていないリクエストは401エラーを返します。呼び出し元はDeveloper PortalでContext APIを購読し、`Authorization` ヘッダーにベアラートークンを含める必要があります。詳細については、[dev-portal-subscriptions](https://docs.tealium.com/dev-portal-subscriptions/)を参照してください。
    * **Allow PII**: **Require Authentication** が選択されている場合のみ利用可能です。オンの場合、制限された（PIIとマークされた）属性が **Response** 画面で標準属性とともに選択可能になります。自動的には何も選択されません。
        * **Allow PII** をオフにすると、すぐにエンジンからすべての制限された属性が削除されます。変更が有効になる前に、影響を受ける属性をリストする確認ダイアログが表示されます。これらの属性は復元できません。
        * **Allow PII** をオフにしても、以前に保存されたPIIは削除されません。以前に保存されたデータをアクセス不可能にするには、**Allow PII** をオフにした後にエンジンデータをパージしてください。詳細については、[データのパージ](#purge-data)を参照してください。
        * **Public** に戻すと、**Allow PII** は自動的にオフになり、同じ確認ダイアログがトリガーされます。
    * **Domain Allow List**: このエンドポイントを使用できるドメインを指定します。詳細については、[Context API について > Domain allow list](https://docs.tealium.com/about-context-api/#domain-allowlist)を参照してください。
1. **Next** をクリックします。
1. **Response** 画面で、エンジンに含めるオーディエンス、バッジ、および属性を選択します。**Example Response** パネルを使用して選択を確認します。
<blockquote>
**Select all current and future audiences** 機能を使用する場合、後でオーディエンスが削除されたとしても、エンジンデータをパージするか、データが期限切れになるまで Context API エンジンに含まれ続ける可能性があります。
</blockquote>

1. ペイロードでオーディエンスと訪問属性のID（UID）または名前を使用するかどうかを選択します。大きなレスポンスでIDではなくオーディエンス、バッジ、および属性の名前を使用すると、ペイロードサイズに影響を与える可能性があります。
1. **Next** をクリックしてエンジンを作成します。
1. **Summary** 画面で、エンドポイントの詳細を含む一意のエンドポイントURLを確認します。
1. **Done** をクリックします。エンジンを作成した後、プロファイルを公開する必要はありません。

訪問データは、エンジンが有効になり、訪問がアクティブなセッションを持っている後に収集されます。

## エンジンの編集

エンジンを編集するには、Context API 画面に移動し、更新したいエンジンをクリックします。編集画面から、エンジンの詳細とレスポンス構成を更新し、エンジンデータをパージし、エンジンをオンまたはオフに切り替え、認証とPIIの構成を調整することができます。

編集画面から **Allow PII** をオフにすると、[エンジンの作成](#create-an-engine)で説明されている同じ確認ダイアログがトリガーされます。


<blockquote>
エンジンを編集した後、プロファイルを公開する必要はありません。Context API エンジンの変更は、構成変更を保存してから5分後に利用可能になります。
</blockquote>


## データのパージ

次の状況でエンジンデータのパージを推奨します：

* エンジン構成に含まれているオーディエンス、バッジ、または属性の名前を変更または削除する場合。
* エンジン構成からオーディエンス、バッジ、または属性を削除する場合。
* エンジンで **Allow PII** をオフにする場合。制限された属性は直ちに将来のレスポンスから削除されますが、以前に保存されたデータはパージするまでエンジンに残ります。パージすると、そのデータはアクセス不可能になります。

データのパージについての詳細は、[Context API について > データのパージ](https://docs.tealium.com/about-context-api/#purge-data)を参照してください。

必要に応じてエンジンデータをパージするための2つの方法が Context API にはあります：

1. **Context API** 画面で、データをパージしたいエンジンの隣にあるアクションメニューをクリックし、**Purge Data** を選択します。
1. **Edit Engines** 画面で、スライドアウトアクションから **Purge Data** をクリックします。

データをパージした後、以前に保存されたエンジンデータは返されなくなります。
