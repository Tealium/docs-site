</blockquote>


コンテキストAPIは、AudienceStream APIの一部であり、ライブ訪問コンテキストの迅速でターゲットされたスライスを取得します。完全な訪問プロファイルを返すのではなく、アプリ、サービスワークフロー、またはAIシステムが特定の決定やエクスペリエンスに必要なオーディエンス、バッジ、属性のみを返します。コンテキストAPIをTealiumのクライアントサイドアプリケーション、`utag.js`がインストールされている場所、Tealium for Mobile、またはLangChainのような任意のエージェントベースのAIフレームワークに統合します。

## 動作原理

コンテキストAPIは、_エンジン_ と呼ばれる構成を使用して、現在の訪問に必要なデータのみを取得するためにAPIレスポンスをカスタマイズします。たとえば、完全な訪問プロファイルを取得するのではなく、エンジン構成で選択したオーディエンス、バッジ、属性データのみをコンテキストAPIが取得します。

エンジンを構成した後、コンテキストAPIはワークフローに統合するためのユニークなエンドポイントを作成します。

### 使用例

コンテキストAPIは、リアルタイムの訪問データが必要な場合にいつでも使用できます。これには以下が含まれます：

* パーソナライゼーション（最初のページおよびそれ以降）、アクティブなセッションが確立される前の匿名訪問の検索を含む。
* データエンリッチメントロジックと組み合わせた次の最適なアクション。
* デバイスやチャネルをまたいだ訪問ID検索を使用したカスタマーサービスおよびクロスチャネルエクスペリエンス。
* 管理されたMCPサーバーを介したAIおよびエージェントベースのシステム。
* 企業グレードのAPI管理とコンプライアンス。

たとえば、訪問がウェブサイトやアプリに戻ったとき、訪問データのためにユニークなコンテキストAPIエンドポイントへのリクエストが行われます。コンテキストAPIは必要なデータのみを提供するように最適化されているため、APIはリアルタイムでストリームライン化されたレスポンスをアプリに送り返します。その重要なデータを使用して、訪問のためのパーソナライズされたエクスペリエンスをトリガーする追加のロジックをアクティブにすることができます。

### エンジン

コンテキストAPIエンジンを使用すると、各ユニークなエンドポイントに格納する訪問データを構成し、それらのエンドポイントにアクセスできるドメインを構成できます。

エンジンを構成するとき、使用例に必要なオーディエンス、バッジ、属性のみを選択します。コンテキストAPIエンジンは、構築する際にJSONレスポンスを表示するため、リクエストの正確性と範囲を確認できます。

訪問がアクティブなセッションをログし、システムでイベントを生成した後、訪問データが利用可能になります。たとえば、訪問がサイトを訪れたとき、コンテキストAPIは新しい訪問イベントがエンジン構成で定義されたオーディエンス、バッジ、属性に影響を与えるかどうかを判断します。訪問データが更新される必要がある場合にのみ、各エンジンのユニークなデータストアにデータが書き込まれます。

エンジンはデータストアをリアルタイムで更新するため、訪問がブランドとのやり取りをするにつれて、APIエンドポイントのデータは最新の状態を保ちます。

デフォルトでは、特定のビジネスケースごとにカスタマイズされたエンジンを作成できるように、プロファイルごとに最大10個のエンジンを有効にすることができます。追加のエンジンを有効にする必要がある場合は、Tealiumサポートに連絡してください。

### 読み取りと書き込み

_読み取り_ は、エンジンから訪問データを取得するリクエストです。データが見つかるかどうかに関わらず、読み取りはクォータにカウントされます。Tealiumがレート制限のために読み取りを拒否した場合、料金は発生しません。

_書き込み_ は、エンジンによって格納された訪問プロファイルデータを更新することです。ステッチされた訪問の場合、コンテキストAPIは関連する各訪問IDに対して別々の書き込みを実行します。これには、匿名IDや構成された訪問ID値などが含まれます。書き込みの総数は、エンジンの数とステッチされた訪問にリンクされた関連訪問IDの数に依存します。

たとえば、訪問が2台のデバイスからサイトを訪れた場合、次の2つの匿名IDが発生します：

* デスクトップ匿名ID `tealium_visitor_id` = `abc123`.
* モバイル匿名ID `tealium_visitor_id` = `bcd234`.

これにより、訪問プロファイルAとBが作成されます：

![](https://docs.tealium.com/images/server-side/visitor-stitching-example-first-visit.png)
![](https://docs.tealium.com/images/server-side/visitor-stitching-example-second-visit.png)  

訪問のメールアドレスは `user@example.com` で、構成された訪問ID属性に値が入力され、両方のデバイスに関連付けられたプロファイルを新しいマスタープロファイル（C）にステッチします。

![](https://docs.tealium.com/images/server-side/visitor-stitching-profile-c-created.png)

アカウントに単一のエンジンがあり、訪問に書き込みの対象となる属性がある場合、システムは各訪問プロファイルに対してそのデータを1回書き込みます：

* 訪問ID検索が有効な場合、3回の書き込み（3つの訪問プロファイル × 1エンジン）。
* 訪問ID検索が無効な場合、2回の書き込み（2つの訪問プロファイル × 1エンジン）。

![](https://docs.tealium.com/images/server-side/moments-api/moments-api-visitor-stitching-1.png)

アカウントに同一の構成を持つ5つのエンジンがあり、訪問に書き込みの対象となる属性がある場合、システムは各訪問プロファイルに対してそのデータを5回書き込みます：

* 訪問ID検索が有効な場合、15回の書き込み（3つの訪問プロファイル × 5エンジン）。
* 訪問ID検索が無効な場合、10回の書き込み（2つの訪問プロファイル × 5エンジン）。

![](https://docs.tealium.com/images/server-side/moments-api/moments-api-visitor-stitching-2.png)

訪問スティッチングについての詳細は、[about-visitor-stitching](https://docs.tealium.com/about-visitor-stitching/)を参照してください。

### エンドポイント

コンテキストAPIは、各エンジンに対してユニークなエンドポイントを作成します。訪問データはJSONオブジェクトとして返されます。

Tealiumは、ペイロードサイズが1kB以下の場合、平均コンテキストAPIエンドポイントパフォーマンスを60ミリ秒とベンチマークしています。

訪問データを取得するには、[Tealium iQ Advanced JavaScript Code Extension](https://docs.tealium.com/advanced-javascript-code-extension/)を構成して、[Context APIエンドポイント](https://docs.tealium.com/context-api-endpoint/)にリクエストを行います。


<blockquote>
エンジンをオンにしてからアクティブなセッションを持っていない訪問のデータは利用できません。
</blockquote>


### MCPサーバー

コンテキストAPI管理MCPサーバーは、AIシステムおよびLLMに訪問プロファイルデータへの安全でリアルタイムのアクセスを提供します。Tealiumがサーバーをホストおよび管理するため、デプロイまたは維持するインフラストラクチャはありません。AIエージェントは、パーソナライゼーション、分析、および自動化のためにターゲットされた顧客コンテキストを取得するためにサーバーに接続します。

サーバーは、標準エンドポイントを通じて利用可能な同じ検索方法で、匿名IDおよび訪問ID属性の検索をサポートします。

詳細については、[context-api-mcp-server](https://docs.tealium.com/context-api-mcp-server/)を参照してください。

### 訪問識別子

コンテキストAPIエンドポイントは、Tealiumの匿名IDと訪問ID属性の両方を使用して訪問データを取得するGETリクエストをサポートします。

* **匿名ID**：サイト訪問ごとまたはアプリ使用ごとに訪問に割り当てられる一意で匿名の値です。匿名IDは、同じブラウザーやアプリからの複数の訪問を通じて訪問を追跡しますが、異なるブラウザーやデバイス間では追跡しません。
* **訪問ID属性**：AudienceStream内の特別な属性タイプで、ユーザー識別子からその値を取得し、訪問スティッチングに使用されます。

詳細については、[匿名ID、ユーザー識別子、および訪問ID属性](https://docs.tealium.com/anonymous-user-visitor-id-attributes/)を参照してください。
### ガバナンス


<blockquote>
認証とPIIの許可はリクエストによってのみ利用可能です。これらの機能を試してみたい場合は、[サポートに連絡してください](https://docs.tealium.com/support/)。
</blockquote>


Context APIには、安全で本番環境に適したデプロイメントのための組み込みコントロールが含まれています：

* **認証**: 各エンジンを**Public**または**Require Authentication**に構成します。認証されたエンジンは、Developer Portalからの有効なベアラートークンを持つリクエストのみを受け付けます。PIIまたは制限されたデータを返すエンジンに推奨されます。詳細については、[dev-portal-subscriptions](https://docs.tealium.com/dev-portal-subscriptions/)を参照してください。
* **PIIアクセスコントロール**: [制限されたデータ](https://docs.tealium.com/about-restricted-data/)としてマークされた属性は、デフォルトでAPIレスポンスから除外されます。認証されたエンジンは、エンジン構成で**Allow PII**が有効になっている場合、制限された属性を含めることができます。
* **ドメイン許可リスト**: エンジンエンドポイントへのクエリを許可するドメインを制限します。
* **フィルタールール**: エンジンに書き込まれる、およびエンジンから読み取られる訪問を制限します。詳細については、[フィルタールール](#filter-rule)を参照してください。
* **権限**: ロールベースのアクセスを使用して、誰がエンジンを作成、編集、または削除できるかを制御します。
* **データの消去**: 訪問の記録に影響を与えることなく、いつでも古いエンジンデータをアクセス不可能にします。

詳細については、[ドメイン許可リスト](#domain-allowlist)、[権限](#permissions)、および[データの消去](#purge-data)を参照してください。

## 制限

Context APIには以下のデフォルト制限があります：

* 全エンジンを通じたプロファイルごとの読み取りレート制限: 200リクエスト/秒/プロファイル
* プロファイルごとに有効なエンジンの最大数: 10
* エンジンごとの訪問ごとに保存できるContext APIデータの最大サイズ: 1 kB 
<blockquote>
訪問の属性データがデータストアの制限を超える場合、その訪問のためには保存されません。
</blockquote>

* Context APIエンドポイントで利用可能なデータ: 新しいイベントが処理されない場合の30日間の保持

使用例により高い制限が必要な場合は、Tealiumアカウントマネージャーに連絡してください。

## データの消去

Context APIでは、データの消去機能を使用して古いエンジンデータをアクセス不可能にすることができます。

以下の例は、エンドポイントからデータを消去したい場合の状況を説明しています：

* エンジン構成に含まれるオーディエンス、バッジ、または属性の名前の変更または削除。
* 属性の個人識別情報（PII）ステータスの変更。属性のPIIステータスを変更すると、機密情報がAPIエンドポイントに依然として保存されている可能性があります。
* エンジン構成からオーディエンス、バッジ、または属性を削除する。
* エンジンで**Allow PII**をオフにする。制限された属性は直ちに将来のレスポンスから削除されますが、以前に保存されたデータは消去するまでエンジンに残ります。消去すると、そのデータはアクセス不可能になります。

エンジンで使用されているオーディエンス、バッジ、または属性がAudienceStreamまたはエンジン構成から削除された場合、そのアイテムは今後エンドポイントには表示されません。削除された属性を含むエンジンデータは変更されません。一般に、依存関係の削除がエンドポイント統合に破壊的変更を引き起こす場合、エンジンデータを消去することを検討するかもしれません。


<blockquote>
データの消去はContext APIエンジンデータにのみ影響します。訪問の記録は影響を受けません。
</blockquote>


エンジンデータの消去についての詳細は、[Context APIエンジンの管理 > データの消去](https://docs.tealium.com/context-api-manage-engines/#purge-data)を参照してください。

## ドメイン許可リスト


<blockquote>
APIエンドポイントをテストした後にドメイン許可リストを作成することをお勧めします。
</blockquote>


許可リストは、信頼できないドメインがContext APIエンドポイントへのリクエストを行うのを防ぎます。エンジンを構成するときに特定のドメインを許可リストに追加します。

Context APIは、`Referer` HTTPリクエストヘッダーのドメインとContext APIエンジンで定義された許可リストを比較することによってエンドポイントへの呼び出しを許可または制限します：

* ドメインが一致する場合: リクエストは処理されます。
* ドメインが一致しない場合: リクエストは処理されず、403エラーが返されます。

ドメインをリストに記載しない場合、すべてのドメインが許可されます。

### サブドメイン

ドメインを許可リストに追加すると、そのすべてのサブドメインが自動的に含まれます。たとえば、`example.com`を許可すると、`*.example.com`に一致する任意のサブドメインが含まれます。

## 権限

Context APIの機能は、以下の権限レベルを通じて管理されます：

* **エンジンの作成、編集、削除およびエンジンデータの消去**
  * 編集者または発行者のレガシー権限
  * プラットフォーム権限での書き込みまたは削除アクセス
* **エンジンリストの表示**
  * 閲覧者のレガシー権限またはプラットフォーム権限での読み取りアクセス

## フィルタールール

フィルタールールは、各エンジンの**詳細**タブで構成するオプションの条件です。アクティブにすると、そのエンジンに書き込まれ、読み取られる訪問を制限します。

フィルタールールを使用して、同意を得た訪問のみがアクセス可能であることを保証するための同意エンリッチメント、またはテストまたは限定範囲のエンジンでの請求可能な書き込み量を減らすためのコストコントロールに使用します。

デフォルトでは、すべての訪問が書き込まれ、読み取り可能です。フィルタールールを追加すると、両方の動作が変更されます：

* **書き込み**: 訪問の属性がルール条件に一致する場合のみ、エンジンへの書き込みがトリガーされます。
* **読み取り**: エンジンはフィルターに一致する訪問のみを返します。一致しない訪問は404を返します。たとえその訪問に対して以前に書き込みが行われていたとしてもです。

フィルタールールは訪問属性のみを使用して構築されます。訪問やイベント属性は条件として使用できませんし、**has changed**演算子も使用できません。


<blockquote>
**フィルタールール**セクションは、プロファイルがバージョン管理された保存に移行された後にのみ表示されます。レガシーエンジンをお持ちの場合は、フィルタールールを構成する前に[移行](https://docs.tealium.com/context-api-manage-engines/#migrate-engine-configuration)を完了してください。
</blockquote>


フィルタールールを追加または削除する手順については、[フィルタールールの追加](https://docs.tealium.com/context-api-manage-engines/#add-a-filter-rule)を参照してください。

## Context APIとData Layer Enrichment APIの比較

Context APIと[Data Layer Enrichment API](https://docs.tealium.com/data-layer-enrichment-public-api/)はどちらもライブ訪問データを取得することができますが、使用例、構成、実装が異なります。これら2つの訪問プロファイルデータ取得方法の違いについて詳しく知るために、以下の比較を参照してください。

| | **Context API**| **Data Layer Enrichment API**|
|---|---|---|
|**使用例**| 最初のページのパーソナライゼーションおよびそれ以降のための現在の訪問データへのリアルタイムアクセス。| 初回処理イベント後のリアルタイムからほぼリアルタイムで利用可能なライブ訪問データ。|
|**レート**| 200リクエスト/秒 | - |
|**アクティブな訪問セッションが必要** | いいえ | はい|
|**利用可能なデータ**| オーディエンス、バッジ、または[サポートされている属性データタイプ](https://docs.tealium.com/context-api-endpoint/#objects)。<br>オーディエンスとバッジの名前とIDが利用可能。 | 訪問ID、ファネル、タイムラインを除く属性が属性IDでリストされます。バッジとオーディエンスの場合、名前が利用可能。<br>バッジ名の場合は、[Profile Definition API](https://docs.tealium.com/get-profile-definition-api/)と組み合わせます。|
|**ルックアップID**| Tealium匿名IDまたは訪問ID属性値 | Tealium匿名ID|
|**認証されたエンドポイント**| オプション。エンジンはDeveloper Portalを通じて認証を要求することができます。 | いいえ|
|**PIIへのアクセス** | オプション。**Allow PII**が有効になっている認証済みエンジンでは、制限された属性を含めることができます。 | いいえ |
|**カスタムレスポンスオブジェクト** | はい | いいえ|
|**実装**|API| APIまたはTealium Collectタグ|

## はじめに

Context APIを使用するワークフローには、次のステップが含まれます：

1. パーソナライズされたエクスペリエンスを作成するために必要なオーディエンス、バッジ、および属性を検討します。
1. 訪問データを必要とするカスタマイズされたエンドポイントを提供するためにContext APIエンジンを作成します。
1. エンドポイントをTealiumのクライアントサイドアプリケーション、utag.jsがインストールされている場所、またはTealium for Mobileに統合します。
1. データを収集して活用します。
