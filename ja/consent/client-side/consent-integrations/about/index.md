同意適用フレームワークは、Tealium iQ Tag Managementの外部で取得された同意シグナルを適用する、クライアント側の同意連携の中核機能です。この機能は、顧客の同意が得られていない場合や、同意が曖昧な場合にトラッキングをブロックします。

同意連携では、サポートされている同意管理プラットフォーム（CMP）に対して、オプトイン（GDPR形式）とオプトアウト（CCPA形式）の両方の適用パターンをサポートしています。連携では、テンプレートを使用してほとんどのCMPまたはカスタムソリューションをサポートできます。

## 要件

同意連携には、`utag.js`バージョン4.49以降が必要です。

## 以前のバージョンのサポート

以前のバージョンの`utag.js`でサポートを有効にするには、**uTag Loader**テンプレートを編集し、`##UTGEN##`パブリッシュエンジンフラグの下に`##UTCM##`を追加します。

![](https://docs.tealium.com/images/iq-tag-management/utcm-utag-loader-template.png)

**uTag Loader**テンプレートの更新方法について詳しくは、[テンプレートの更新](https://docs.tealium.com/manage-templates/#update-a-template)を参照してください。

## 同意の概念

以下の用語は、同意連携フレームワークで使用される概念を説明しています。

* **目的**：Webサイトのユーザーが同意または拒否できる、特定のデータ利用目的です。
* **目的グループ**：タグが割り当てられる適用ポリシーを表す目的のグループです。
* **適用除外**：適用が不要であり、同意の決定に基づいてタグをブロックする必要がないシナリオです。適用除外は、同意連携の適用ルールがどれも該当しない場合の動作とは異なります。明示的な適用除外がある場合、または一致する同意連携と適切な同意の決定がある場合を除き、タグの実行は許可されません。
* **適用ルール**：同意連携または適用除外をいつ適用するかを決定するルールです。
* **同意の決定**：ユーザーが同意した目的の配列です。ユーザーが能動的に決定したか（`explicit`）、していないか（`implicit`）を示す`type`属性が含まれます。
* **暗黙的な決定**：ユーザーの行動から推測される決定です。サイトにアクセスすることで、ユーザーはサイトのプライバシーポリシーに記載されている必要なタグに同意します。ユーザーは自身のデータの販売に異議を唱えることができますが、デフォルトでは有効です（「自分のデータを共有または販売してもよい」という暗黙的な決定があります）。
* **明示的な決定**：ユーザーがどのトラッキングに同意するかについて行う、明確かつ正確な同意の決定です。
* **連携**：CMPから同意の決定を取得する機能と構成（事前に読み込まれたもの、またはカスタム）のセットです。

## 仕組み

同意連携は、同意が得られていないタグをブロックすることで、CMPからの同意の決定を適用します。連携がアクティブな場合、タグを実行するには、事前に目的グループ内の目的にタグを割り当てる必要があります。目的に割り当てられたタグを実行するには、ユーザーがその目的に同意する必要があります。

各同意連携は、単一のCMPと通信する方法を基盤となるフレームワークに指示します。一度にアクティブにできる連携は1つだけです。ただし、必要に応じて**適用ルール**を使用し、競合することなく複数のアクティブな連携を条件付きで適用できます。


<blockquote>
CMPをページに挿入するタグは、同意連携と互換性がありません。連携では、タグが読み込まれる前にCMPからのシグナルが必要です。CMPを同意連携と統合するには、Pre LoaderまたはDOM Ready拡張機能を使用するか、Tealium iQの外部でCMPをページに追加してください。
</blockquote>


Tealium iQダッシュボードでサポート対象のCMPとの連携を構成するか、**Custom template**を編集してカスタム連携を作成できます。

## サポートされている連携

現在サポートされている連携の完全な一覧については、[サポートされているベンダー連携](https://docs.tealium.com/vendor-specific-configuration/)を参照してください。

## タグの再実行

各タグの**Map Tags**画面には、**Tag Refire**スイッチがあります。

![](https://docs.tealium.com/images/early-access/map-tags.png)

このオプションを有効にすると、ユーザーの各アクションに対してタグを2回実行できます。1回目は暗黙的な決定に対して、2回目は明示的な決定に対して実行されます。マッピングされた目的に同意が得られていない場合、タグは実行されません。

ほとんどのタグでは再実行は必要ありません。このオプションを有効にすると、イベントの重複や二重トラッキングが発生する可能性があります。この機能を有効にする際は注意してください。

サーバー側の再実行については、[サーバー側イベントの再実行](#server-side-event-refiring)を参照してください。

## 同意の決定データ

同意連携は、各イベントのデータレイヤーに同意の決定データを追加します。このデータには、クライアント側変数とサーバー側属性の両方が含まれます。

これらの変数は、Tealium Collectタグによって自動的に送信されます。`tealiumCmpIntegration.GetCurrentConsentDecision()`メソッドを使用してアクセスしない限り、拡張機能から直接利用することはできません。

### クライアント側変数

| 変数 | 説明 |
|----------|-------------|
| `tci.consent_type` | 同意タイプ：`implicit`または`explicit`。 |
| `tci.purposes_with_consent_all` | 処理済みおよび未処理の、同意が得られたすべての目的の配列。 |
| `tci.purposes_with_consent_processed` | 処理済みの、同意が得られた目的の配列。 |
| `tci.purposes_with_consent_unprocessed` | 未処理の、同意が得られた目的の配列。 |

**クライアント側データの例：**

```json
{
  "tci.consent_type": "implicit",
  "tci.purposes_with_consent_all": ["C0001", "C0002", "C0003"],
  "tci.purposes_with_consent_processed": ["C0001", "C0002"],
  "tci.purposes_with_consent_unprocessed": ["C0003"]
}
```

### 拡張機能から同意の決定にアクセスする

拡張機能で現在の同意の決定オブジェクトにアクセスするには、`tealiumCmpIntegration.GetCurrentConsentDecision()`メソッドを使用します。

次のコマンドは、現在の同意の決定を`b`オブジェクトに追加します。

```js
b.current_consent_decision = tealiumCmpIntegration.getCurrentConsentDecision()
```

### サーバー側属性

Tealium Collectは、各イベントペイロードの一部として同意属性を送信します。これらの属性は、使用しているサーバー側ツールに関係なく送信されます。

| 属性                               | 説明                 |
| --------------------------------------- | --------------------------- |
| `tci.purposes_with_consent_unprocessed` | 同意の更新後にまだ処理されていない目的の配列。重複を回避するため、**Tag Refire**が有効な場合に使用します。 | |
| `tci.purposes_with_consent_all`         | すでに処理済みのものを含む、同意が得られたすべての目的の配列。**Tag Refire**が無効な場合に使用します。 |

**サーバー側ペイロードの例：**

```json
{
  "event_name": "page_view",
  "tci.purposes_with_consent_unprocessed": ["C0003"],
  "tci.purposes_with_consent_all": ["C0001", "C0002", "C0003"]
}
```

### サーバー側イベントの再実行

サーバー側コネクタを使用しているアカウントでは、Tealium Collectタグの**Tag Refire**を有効にすることで、同意の変更（`implicit`から`explicit`への変更）によってサーバー側の処理が再度トリガーされるようになります。

サーバー側の再実行を有効にするには、次の手順を実行します。

1. **Map Tags**画面でTealium Collectタグの**Tag Refire**を有効にします。これにより、`refiringAllowed`オプションが自動的に構成され、同意の決定が変更されたときにタグを再実行できるようになります。
1. コネクタアクションに、`tci.purposes_with_consent_unprocessed`属性を確認する条件を追加します。これにより、未処理の目的のみが処理され、イベントの重複を防止できます。
### 完全な同意イベントの例

以下は、同意決定変数を含む完全なイベントオブジェクトの例です。

```json
{
  "event_name": "page_view",
  "tci.consent_type": "implicit",
  "tci.purposes_with_consent_all": ["C0001", "C0002", "C0003"],
  "tci.purposes_with_consent_processed": ["C0001", "C0002"],
  "tci.purposes_with_consent_unprocessed": ["C0003"]
}
```

この例では、次のようになります。

* 同意タイプは `implicit` です。
* 3つの目的について同意が得られています。
* 2つの目的はすでに処理されています。
* 1つは未処理のままであり、サーバーサイドで処理できます。

## JavaScriptコンソールの使用

有効になっている場合、`utag.js` が読み込まれているページのブラウザーコンソールで、同意統合を操作できます。JavaScriptコンソールを使用すると、イベントごとにCMPから取得される現在の同意決定を確認できます。同意決定がキャッシュされることはないため、常に最新の状態に保たれます。

フレームワークv1.4.0以降、同意決定によって停止された場合にのみ、タグがブロックされたと報告されます。ロードルールを満たさなかったタグは、ブロック数に含まれなくなりました。

詳細については、[同意統合の検証とデバッグ](https://docs.tealium.com/validate-and-debug-consent-integrations/)を参照してください。

## 同意レジスター

同意統合では、Tealium同意レジスターを使用して、同意構成が読み込まれたとき、または更新されたときにイベントを発行できます。これらの変更はページ上でグローバルに利用できるため、Webサイト全体で同意決定をより簡単に管理できます。詳細については、[Tealium同意レジスター](https://docs.tealium.com/consent-register/)を参照してください。


<blockquote>
同意レジスターを使用するには、同意統合フレームワークのテンプレートバージョン1.2.0以降が必要です。このテンプレートを更新する方法については、[テンプレートの更新](https://docs.tealium.com/manage-templates/#update-a-template)を参照してください。
</blockquote>
