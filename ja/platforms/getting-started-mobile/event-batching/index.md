イベントのバッチ処理は、複数のイベントを1つのHTTPリクエストで送信することにより、モバイルデバイスとTealium間のデータ転送を最適化するTealium Collectモジュールの機能です。イベントのバッチ処理では、重複するデータレイヤー変数を排除し、gzipで圧縮されたペイロードを受け入れるよう最適化された専用のデータ収集エンドポイントを使用します。

## バッチとキュー

イベントのバッチ処理とは、デバイスがネットワーク経由でデータを送信する方法を指します。イベントキューとは、送信前にデバイスがデータを一時的に保存する方法を指します。イベントのバッチ処理では、トラッキングされた各イベントを個別のリクエストで送信するのではなく、複数のイベントを1つのネットワークリクエストにまとめます。

デバイスは、以下の条件でバッチ処理を使用します。

* **Publish Configuration > Mobile Library Publishing > Batching**でバッチ処理が有効になっている。詳細については、[モバイルプロファイルの作成](https://docs.tealium.com/create-mobile-profile/#batching)を参照してください。
* デバイスに安定したインターネット接続がない。接続が利用可能になるまで、デバイスはイベントを保存します。
* ユーザーが**Consent Manager**で構成を選択していない。ユーザーが**Consent Manager**の構成を選択するまで、デバイスはイベントを保存します。詳細については、[同意管理について](https://docs.tealium.com/about-consent-management/)を参照してください。

デバイスのバッチ送信動作は、デバイス上のアプリの状態によって異なります。

* ユーザーがアプリをバックグラウンドに移行した場合：
  * デバイスは、ライフサイクルの「sleep」イベントを送信します。
  * インターネット接続が利用可能な場合、アプリがバックグラウンドに移行する前に生成されたイベントを、デバイスが直ちに送信します。
* ユーザーがアプリをフォアグラウンドに移行した場合：
  * デバイスは、ライフサイクルの「wake」イベントとともに、キュー内のイベントを送信します。

イベントのバッチ処理は、キューが空になるまで複数のイベントを一度に処理することで、イベントキューと連携します。

たとえば、デバイスがオフラインになり、イベントキューに25件のイベントが蓄積されたとします。デバイスがオンラインに戻ると、キューが空になるまで10件ずつのバッチで処理します。この場合、各10件のイベントを含む2つのバッチリクエストと、残りの5件のイベントを含む1つのバッチが送信され、合計3つのネットワークリクエストのみで25件のイベントがトラッキングされます。


<blockquote>
バッチサイズの上限は10イベントです。
</blockquote>


## 利点

イベントのバッチ処理には、以下の利点があります。

* 送信されるデータの合計サイズを削減できます。
* 同じ数のイベントを送信する際のネットワークリクエスト数を削減できます。
* デバイスのバッテリーパフォーマンスを向上できます。

### データレイヤーの最適化

Tealiumモバイルライブラリは、アプリ名、画面解像度、OSバージョンなど、多くの[デバイス情報をデータレイヤーに送信します](https://docs.tealium.com/ja/platforms/getting-started-mobile/data-layer/)。これらの値はイベント間で変化しませんが、デバイスはすべてのネットワークリクエストにこれらの変数を含めます。イベントのバッチ処理では、これらの共通変数をバッチごとに1回だけ送信することで、データレイヤーを最適化します。

### ペイロードの圧縮

デバイスは、HTTPリクエストのサイズを最小限に抑えるため、イベントバッチのペイロードをgzipで圧縮します。この圧縮により、各ネットワークリクエストのサイズが最大90%削減されます。

### タグ管理でのイベントのバッチ処理

**Tag Management**モジュールを使用し、イベントのバッチ処理が有効になっている場合、デバイスは通常どおりこれらのイベントをキューに格納し、その後、WKWebViewインスタンスに対する個別のJavaScript呼び出しとして送信します。デバイスは構成済みのタグを個別にトリガーするため、デバイスから複数のリクエスト（バッチ内のイベントごとに1つ）が送信されます。リアルタイムでイベントを送信する場合と比べて、デバイスの無線通信機能を起動する頻度が低くなるため、バッテリー消費が軽減されます。
