## 概要

`utag.view()`と`utag.link()`の両方の呼び出しで、ロードルールが再評価されます。

`utag.js` 4.26ファイルによるクエリ文字列パラメータとメタタグの処理方法が変更され、デフォルトでは小文字に変換されなくなりました。プロファイル内でクエリ文字列パラメータまたはメタタグをデータソースとして指定している場合は、データレイヤータブでデータソース名を更新し、大文字と小文字を正確に一致させる必要があります。

## カスタムスクリプトソースはブロッキングタグになる

ブロッキングタグとは、他のタグよりも先に実行する必要があるタグです。タグの[カスタムスクリプトソースの詳細構成](https://docs.tealium.com/manage-templates/)に場所を入力すると、そのタグは自動的にブロッキングタグになります。このタグ自体は引き続き非同期で読み込まれますが、後続の非同期スクリプトはその完了を待ちます。たとえば、`utag.10.js`はブロッキングタグが完了するまで読み込まれません。

**ベストプラクティス：** タグ用のカスタムJavaScriptを読み込みたいものの、ブロッキングタグにはしたくない場合は、[Tealium Generic Tag](https://docs.tealium.com/tealium-generic-tag/)を使用して読み込んでください。

## Waitフラグの改善

[Waitフラグは、タグ構成内の詳細構成です](https://docs.tealium.com/manage-templates/)。

**Wait Flag**が「No」に構成されているタグは、`utag.js`ファイルの読み込み直後に読み込まれ、配信されます。**Wait Flag**が「No」に構成されているタグのうち、先に読み込まれたタグは、タグ管理での順序に関係なく先に配信される場合があります。たとえば、タグ2がタグ1より先に読み込まれ、タグ管理の「タグ」タブではタグ1がタグ2より上に配置されている場合でも、その順序にかかわらずタグ2が先に配信されることがあります。以前は、タグはタグ管理で指定された順序で実行されていました。そのため各タグは、自身より上位に配置されているタグが読み込まれるまで待機してから読み込まれていました。

これにより、同じプロファイル内で、Wait Flagが「No」に構成されたタグと「Yes」に構成されたタグを混在させられるようになりました。

## トラッキング呼び出しによる新しいタグの読み込み

最初のページ読み込み後、後続の`utag.view()`呼び出しではロードルールが再評価され、新しいタグが読み込まれます。以前のバージョンでは、`utag.view`の呼び出しで新しいタグを読み込むことはできませんでした。この機能は、`utag.js` 4.26でデフォルトで有効になっています。

現在の動作を維持するには、この機能を無効にしてください。詳細については、以下の[`utag.cfg.load_rules_ajax`フラグ](https://docs.tealium.com/ja/platforms/javascript/settings/)を参照してください。


<blockquote>
`utag.link()`呼び出しでは新しいタグは読み込まれません。これを行うのは`utag.view()`呼び出しだけです。
</blockquote>


## UIDによるタグの読み込み

高度な実装、特にAJAXを使用する実装では、`utag.view()`呼び出しを使用して新しいタグを読み込み、タグのUID（タグ管理の「タグ」タブに表示されるUID）に基づいて配信します。これにより、すべてのロードルールが迂回されます。

```javascript
utag.view({page_name : "New Page"}, null, [5]);
```

* パラメータ1：データレイヤー
* パラメータ2：コールバック関数（またはnull）
* パラメータ3：読み込んで配信するUIDの配列

## 新しいメタタグの読み取り

以前のバージョンの`utag.js`では、`name=`を持つ次のようなメタタグが取得されていました。

```html
<meta name="keywords" content="Apple,Tab" />
```

新しい`utag.js` 4.26では、`property= `を持つメタタグも取得されるようになりました（「Open Graph」メタタグを参照）。

```html
<meta property="og:type" content="video.movie" /> 
```

## クエリ文字列またはメタ変数の小文字化

これは、`utag.data`のデフォルト動作に関するロジックの変更です。自動的に小文字に変換するには、[`utag.cfg.lowerqp`フラグ](#utagcfglowerqp)を`true`に構成します。ただし、デフォルト構成では大文字と小文字が混在した状態が維持されます。


<blockquote>
以前の`utag.js`の動作との後方互換性を維持するには、`utag.cfg.lowerqp`フラグをtrueに構成してください。
</blockquote>


メタタグを小文字に変換するには、`utag.cfg.lowermeta`フラグを`true`に構成します。これは、そのメタタグの名前と値のペアのうち、名前にのみ適用されます。


<blockquote>
大文字と小文字が混在するクエリ文字列パラメータがある場合は、「データソース」タブでデータソース名を更新し、正確に一致させる必要があります。このクエリ文字列タイプのデータソースを参照するコードも更新する必要があります。
</blockquote>


## 新しいCookie値

`utag_main` Cookieに、新しいCookieの名前と値のペアが追加されました。

* **`utag_main_vid`**  
`013efdc67183001adeec0eef13010a051001b00f0093c`のような、訪問を一意に識別する長い文字列
* **`utag_main__ss`**  
「セッション開始」フラグ。新しいセッションの最初のページビューでは`"1"`に構成されます。デフォルトでは、30分間操作がないとセッションが終了します。
* `utag_main_ses_id` Cookie内のセッションID値
* `utag_main_v_id` Cookie内の訪問ID値
* `utag_main__ss` Cookie内のセッション開始フラグ（0または1）

（以前のCookie値である`utag_main__st`と`utag_main_ses_id`も引き続き構成されます。）

## セッショントラッキング

訪問セッションの開始時に、空のファイル`utag.v.js`へのリクエストが1回行われます。これは、Tealiumがセッション数を記録するために内部的に使用します。HTTPリクエストURLは次のようになります。

```bash
http://tags.tiqcdn.com/utag/tiqapp/utag.v.js?a=tealium/main/201306012057&cb=1370276499302
```

新しいCookie値`utag_main__ss`は、いつ配信するかを判断するために使用されます。これは、セッションの最初のイベントでのみ送信されます。このリクエストは、すべてのタグが配信された後、最後に送信されます。

## URLフラグメント

`#`記号の後にあるキーと値のペアが、`qp.`変数として追加されます。これはAJAXサイトにとって重要です。

URLの例：`http://www.example.com?param1=value1&param2=value2#hash1=value3)`

以前：

```javascript
utag.data = { "qp.param1" : "value1", "qp.param2" : "value2"}
```

新しい動作：

```javascript
utag.data = { "qp.param1" : "value1", "qp.param2" : "value2", "qp.hash1"  : "value3"}
```

## トラッキング呼び出しですべてのページデータを利用可能

以前、`utag.view`と`utag.link`の呼び出しで認識されるのは、呼び出しに渡されたデータだけでした。`b["qp.campaign"]`などの項目は利用できませんでした。現在は、URL、メタ、Cookie値など、すべての「組み込み」データポイントが、`utag.link`および`utag.view`呼び出し用のデータレイヤーに追加されます。

また、AJAXサイトで変更される可能性がある動的項目（`b["dom.url"]`など）は、現在の値を使用するように再構築されます。現在の値は、AJAXページに最初にアクセスした時点の値とは異なる場合があります。

## 新しいオーバーライド構成

「Pre Loader」をスコープとするJavaScriptコード拡張機能と、グローバル変数`window.utag_cfg_ovrd`を使用します。

```javascript
window.utag_cfg_ovrd = {
    "noview"          : true,
    "lowerqp"         : true,
    "load_rules_ajax" : false
};
```

## その他の構成

* `utag.cfg.load_rules_ajax`  
`utag.view`および`utag.link`を呼び出すたびにロードルールを再評価しない場合は、このフラグを`false`に構成します。`utag.view`では、最初のページビューで読み込まれなかった場合、新しい`utag.X.js`ファイルも読み込まれることがあります。
* `utag.udoname`  
データオブジェクトの名前です。`utag.js`コードは、データオブジェクトがグローバル変数であることを前提としています。たとえば、別のオブジェクト内にあるオブジェクトには対応しません。デフォルトでは`utag_data`に構成されています。
* `utag.cfg.load_rules_at_wait`  
Wait（DOM Ready）時にロードルールを再評価する場合は、このフラグを`true`に構成します。これにより、`utag.js`の読み込み後にデータが構成されている場合に、そのデータを使用してDOM Readyを待機するよう構成されたタグを配信できるレガシーサポートが有効になります。
* `utag.cfg.lowerqp`  
クエリ文字列の名前と値のペアを小文字に変換する場合は、このフラグを`true`に構成します。以前は、これがデフォルトの動作でした。
* `utag.cfg.lowermeta`  
メタタグの名前を小文字に変換する場合は、このフラグを`true`に構成します。メタタグの名前と値のペアのうち、値は小文字に変換されません。
* `utag.cfg.noview`  
最初の`utag.view`呼び出しを行うタイミングを制御する場合は、このフラグを`true`に構成します。これは、最初のページ読み込みアクションではなく、アプリケーションがページビューイベントを制御するAJAXサイトで一般的です。
## 考慮事項

* 複数の注文イベントの誤送信 - `utag.link` および `utag.view` の呼び出しでは、すべての「DOM」タイプのデータポイントを毎回利用できるようになりました。たとえば、`b["qp.order_id"]` などのクエリ文字列データはページ読み込み時に取得され、注文イベントをトリガーします。しかし、同じ注文ページで `utag.link` を呼び出すと、その呼び出しにも `b["qp.order_id"]` のデータが構成されているため、2 回目の注文イベントがトリガーされます。
* 最も直感的な動作にするには、`utag.js` ファイルを読み込む前に、すべての `utag_data` 値を構成することを推奨します。また、`utag.cfg.load_rules_at_wait` はデフォルト値の「false」のままにしてください。
* `utag.js` 4.26 に更新すると、クエリ文字列パラメータを小文字化するデフォルト動作が変更されることに注意してください。値は自動的に小文字へ変換されなくなりました。
* 「All Tags」スコープの拡張機能は、DOM Ready スコープの拡張機能より先に実行される場合もあれば、後に実行される場合もあります。実行順序は保証されません。「All Tags」スコープの拡張機能でデータレイヤー要素を操作すると、Content Modification Extension の条件に影響する可能性があります。

**ベストプラクティス：** 元のデータレイヤーオブジェクトを変更しないでください。値を変更する必要がある場合は、代わりに新しい変数を使用してください。

## 既知の問題

* `utag_data` オブジェクトは `utag.data` への参照となるため、どちらか一方を変更すると、もう一方も変更されます。
* データレイヤーが `<body>` 要素の末尾、DOM Ready の直前に定義されていて、かつ `utag.js` がすでに読み込まれている場合、Internet Explorer 8 ではタイミングの問題が発生する可能性があります。ベストプラクティスとして、必ず `utag.js` ファイルを読み込む前に `utag_data` オブジェクトを宣言してください。
