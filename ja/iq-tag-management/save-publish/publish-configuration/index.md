次の手順でパブリッシュ構成を構成します。

1. 管理メニューで、**パブリッシュ構成を構成**をクリックします。**パブリッシュ構成**ダイアログが表示されます。
1. **一般パブリッシュ**または**モバイルライブラリのパブリッシュ**構成タブを選択します。  
    ![](https://docs.tealium.com/images/iq-tag-management/whiteui-publishconfiguratin-select-publish-tab.png)
1. 必要に応じて構成を調整します。
1. **保存**をクリックして変更を適用します。  

<blockquote>
一部の構成では、機能を有効にするためにパブリッシュを実行する必要があります。各パブリッシュ構成の詳細については、以下のセクションを参照してください。
</blockquote>


## 一般パブリッシュ

**一般パブリッシュ**の構成は、実装のどの側面に影響するかに応じてグループ化されています。以下のセクションでは、各パブリッシュ構成の機能について説明します。

### バージョンのワークフロー

これらの構成を使用すると、このプロファイルの実装を保存およびパブリッシュする方法を細かく調整できます。

* **パブリッシュ通知メール**  
バージョンがパブリッシュされるたびにメールを受信するには、パブリッシュ通知メールフィールドにメールアドレスを入力します。複数のメールアドレスを追加する場合は、各メールアドレスをカンマで区切ります。
* **カスタムバージョン名**  
デフォルトのタイムスタンプIDの代わりに、ユーザーがカスタムバージョン名を入力できるようにします。デフォルト値は**オン**です。
* **ワークフロー管理**  
この構成では、DevおよびQAへのパブリッシュ権限を持つユーザーが、Prodへのパブリッシュ許可をリクエストできるワークフロー管理を構成できます。ワークフロー管理を有効にすると、Prodへのすべてのパブリッシュで承認が必要になります。デフォルト値は**オフ**です。
* **プロファイルをロック**  
複数のユーザーが同じプロファイルを同時に変更できないようにします。デフォルト値は**オフ**です。
* **アラート通知メール（非推奨）**  
Webサイトでエラーが発生したときに通知を受け取るには、アカウントマネージャーに連絡してこの機能を有効にした後、このフィールドにメールアドレスを追加します。空白のままにすると、アラートは作成されません。複数のメールアドレスを追加する場合は、カンマ区切りのリストとして入力します。  

<blockquote>
この構成はサポートされなくなりました。プロファイルで有効になっていた場合でも、アラートメールは送信されません。
</blockquote>


### パフォーマンスの最適化

これらのパブリッシュ構成は、サイト上のUniversal Tag（`utag.js`）の全体的なパフォーマンスに影響します。

* **Ready Waitフラグ**  
Ready Waitフラグを有効にすると、ブラウザーからDOM Readyシグナルを受信するまで、すべての`utag.js`処理が停止します。Pre Loaderをスコープとする拡張機能は、DOM Readyの前でも引き続き実行されます。デフォルト値は**オフ**です。
* **バンドル済みタグ**  
デフォルトの**すべてのページ**読み込みルールを使用していないバンドル済みタグのリストを表示します。  
[バンドルとページパフォーマンス](https://docs.tealium.com/page-performance/)の詳細をご覧ください。
* **すべてのページで読み込むタグをバンドル**  
**すべてのページ**読み込みルールを使用するタグを`utag.js`にバンドルします。これにより、ブラウザーが実行するネットワーク呼び出しの回数が減り、パフォーマンスとページ読み込み時間が改善される可能性があります。デフォルト値は**オフ**です。  
バンドル済みタグの読み込み順序は、UIDではなく、タグ画面に表示される順序によって決まります。   
[バンドルとページパフォーマンス](https://docs.tealium.com/page-performance/)の詳細をご覧ください。
* **タグテンプレートを圧縮**  
`utag.js`およびパブリッシュされたすべてのタグのコードを圧縮します。デフォルト値は**オン**です。圧縮とは、空白やコメントなどの不要な文字をコードから削除する処理です。コードの機能は変わりません。コードの総量が削減されるため、転送とダウンロードが容易になり、速度も向上します。ただし、コードは理解しにくくなります。

### 実装

これらの構成は、Universal Tag（`utag.js`）の実装方法に影響します。

* **distro.zipファイルを生成**  
生成されたすべてのタグファイルを含む配布用アーカイブを生成します。詳細については、[セルフホスティング](https://docs.tealium.com/self-hosting/#enable-the-zip-archive)を参照してください。
* **Cookieドメイン**  
`utag_main` Cookieに構成するドメインを入力します。デフォルトでは、Tealiumがページのドメインを自動的に検出するため、このフィールドは空のままにすることをお勧めします。空のままにすると、Tealiumがドメインを自動的に検出します。ただし、この値をサイトのドメインに構成することもできます。複数のサブドメインを使用している場合は、ルートドメインを構成してください（たとえば、`www.tealium.com`ではなく`tealium.com`）。
* **Tealium CDNにファイルを配信**  
パブリッシュされたファイルをTealiumのグローバルCDNに配信するかどうかを制御します。パブリッシュされたファイルをセルフホスティングしており、アセットをCDNバケットに送信しない場合にのみ、この構成をオフにしてください。オフにした場合は、ファイルを自身で配信する必要があります。デフォルト値は**オン**です。  
セルフホスティングの詳細については、[utag.jsのセルフホスティング](https://docs.tealium.com/self-hosting/)を参照してください。
* **ページデータオブジェクト**  
Tealiumの`utag_data`以外のデータオブジェクトを使用するには、使用するデータオブジェクト名をここに入力します。
* **基本変数**  
すべてのトラッキング呼び出しで送信する`utag_data`変数を、カンマ区切りのリストで入力します。  
例：`page_name,site_language,site_currency,is_logged_in`
* **訪問セッションのタイムアウト**  
デフォルトのセッションタイムアウトである30分を上書きするには、この値をミリ秒単位で構成します（1800000ミリ秒 = 30分）。
* **カスタムパブリッシュ環境**  
デフォルトのDev、QA、Prodに加えて、カスタムパブリッシュ環境を作成できます。デフォルト値はオフです。
* **utag.sync.jsファイルを生成**  
この構成を**オン**にすると、utag.sync.jsファイルを生成してパブリッシュできます。デフォルト値は**オフ**です。この構成を初めて有効にする場合、`utag.sync.js`ファイルを生成するには、このプロファイルのすべてのパブリッシュ環境に再パブリッシュする必要があります。`utag.sync.js`ファイルを使用するには、サイト内に別のファイル参照を記述する必要もあります。できれば、ページのhead要素内に記述してください。サイト内にファイル参照を記述したものの、この構成を有効にした後ですべてのパブリッシュ環境にパブリッシュしなかった場合、まだ存在しないファイルに対して同期呼び出しが行われるため、サイトの読み込みに失敗します。  


<blockquote>
この構成は、TealiumのFlicker Free Adobe Test &amp; Targetソリューションにも必要です。
</blockquote>


* **UTF-8エンコーディングを使用**  
utag.jsファイルをデフォルトのISO 8859-1ではなくUTF-8でエンコードするには、このトグルをオンにします。デフォルト値は**オン**です。  
    
<blockquote>
2015年11月10日より前に作成されたプロファイルでは、デフォルトは**オフ**です。
</blockquote>


* **タグの読み込みを防止**  
Tealium iQで管理されているすべてのタグをすばやく無効にします。この構成をオンにした後、プロファイルを再パブリッシュする必要があります。デフォルト値は**オフ**です。
* **Web Companion**  
Web Companionのターゲット環境スイッチャーのサポートを有効または無効にします。  

<blockquote>
この機能を有効にすると、Webサイトが任意の値を持つCookieを構成できるようになるため、システムがコードインジェクションにさらされる可能性があります。この機能は、Google Chromeブラウザーを使用できない場合の便宜のために提供されています。Chromeを使用できる場合は、ベストプラクティスとして[Tealium Tools環境スイッチャー](https://docs.tealium.com/ja/iq-tag-management/tealium-tools/environment-switcher/)を使用することをお勧めします。
</blockquote>


* **データレイヤーエンリッチメントプロファイル**  
訪問データの取得元となるAudienceStreamプロファイルを指定します。ページ上のデータレイヤーが、この訪問データによってエンリッチされます。詳細については、[Tealium iQでデータレイヤーエンリッチメントを構成する](https://docs.tealium.com/configure-data-layer-enrichment-iq/)を参照してください。
### 公開 URL

これらの構成では、Tealium のデフォルトサーバー以外の公開先を指定できます。プロファイルを標準以外の場所に公開する場合（本番環境が「prod」として指定されていない場合）は、該当するフィールドに URL を入力します。Dev、QA、Prod の 3 つの環境ごとに構成できます。

* **Dev 公開 URL**  
Tealium JavaScript ファイルをセルフホスティングしている場合、またはファーストパーティドメインを使用している場合は、この構成を使用します。詳細については、[utag.js のセルフホスティング]()および[ファーストパーティドメイン]()を参照してください。
* **QA 公開 URL**  
Tealium JavaScript ファイルをセルフホスティングしている場合、またはファーストパーティドメインを使用している場合は、この構成を使用します。詳細については、[utag.js のセルフホスティング]()および[ファーストパーティドメイン]()を参照してください。
* **Prod 公開 URL**  
Tealium JavaScript ファイルをセルフホスティングしている場合、またはファーストパーティドメインを使用している場合は、この構成を使用します。詳細については、[utag.js のセルフホスティング]()および[ファーストパーティドメイン]()を参照してください。


<blockquote>
`utag.js` ファイルの配信をヨーロッパ地域に限定するには、URL フィールドに `//tags-eu.tiqcdn.com/utag/ACCOUNT/PROFILE/ENVIRONMENT` を入力する必要があります。この方法で配信場所をヨーロッパに限定すると、EU 内に物理的に配置されたサーバーのみを使用して `utag.js` ファイルを配信することになります。
</blockquote>


### レガシー構成

これらの構成は非推奨ですが、レガシーデプロイメントをサポートするために残されています。新しい実装（`utag.js` バージョン 4.26 以降）では使用しないでください。

* **プロファイルのサブロードを許可**  
別のプロファイルが Profile Loader タグを使用してこのプロファイルを読み込む場合に必要です。この機能は非推奨となり、代わりに[プロファイルライブラリ]()を使用することが推奨されています。
* **強制タイムアウト**  
読み込みに時間がかかっているタグをキャンセルするまでの時間をミリ秒単位で構成します。読み込み時間がこの値を超えたタグのみがキャンセルされます。この構成は、バージョン 4.26 より前の utag.js を使用しているプロファイルでのみ機能します。より新しいバージョンの utag.js を使用しているプロファイルには影響しません。  
Tealium は、強制タイムアウト値が経過した時点で読み込みが完了していないタグライブラリを読み込みキューから削除します。強制タイムアウトのカウントダウンは、後続のタグライブラリ呼び出し（`utag.1.js`、`utag.2.js` など）が行われた時点ではなく、最初の `utag.js` 呼び出しが行われた時点で開始されます。訪問のブラウザーの動作が遅い場合、`utag.js` またはタグライブラリのリクエスト自体が遅くなくても、強制タイムアウト機能によってタグがキャンセルされる可能性があることに注意してください。不要なタイムアウトを防ぐには、**強制タイムアウト**に大きな値を入力してください。
* **フッターをスコープとする拡張機能**  
このプロファイルが `utag.footer.js` ファイルを使用して拡張機能を読み込む場合、この値を構成するにはオンまたはオフに切り替えます。
