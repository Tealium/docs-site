## 概要



コンバージョン API を使用すると、クライアント側とサーバー側のシグナルを組み合わせることで、コンバージョントラッキングデータの正確性、信頼性、セキュリティを確保できます。

コンバージョン API は、コンバージョンイベントデータを広告プラットフォームに送信します。広告プラットフォームは、そのデータを使用して広告のパフォーマンスと広告費用対効果（ROAS）を向上させます。Tealium は、Meta（Facebook）、Google、Amazon、Snap、Pinterest、LinkedIn、Microsoft など、さまざまなベンダーのコンバージョン API を提供しています。

コンバージョン API は、Web サイト、モバイルアプリ、実店舗のオフラインデータなど、カスタマージャーニーのあらゆる段階からイベントデータを受信し、Web ブラウザに依存せずにサーバーから直接データを送信できます。

## 仕組み

コンバージョンイベントは、購入、サインイン、サイトへの登録、申し込みの完了など、顧客に関するファーストパーティデータを提供するアクションを顧客が完了したときに発生します。

Tealium は、ファーストパーティデータを広告プラットフォームに安全に送信します。広告プラットフォームでは、クライアント側タグとサーバー側コンバージョン API コネクタを組み合わせて使用します。広告プラットフォームは、そのデータをプラットフォーム上の広告に対するユーザーのインタラクションと照合し、次の目的に使用します。

* 入札、最適化、クリエイティブ配信のために、広告プラットフォームの AI および機械学習モデルへ高品質なシグナルを提供する。
* 広告のターゲティングと配信を最適化し、ROAS を向上させる。
* 広告のパフォーマンスを示すコンバージョンレポートを作成する。
* オーディエンスの構築と除外を改善し、購入意向の高い顧客をリターゲティングするとともに、無駄な広告費を削減する。

### ハイブリッドソリューション

Tealium のコンバージョン API ソリューションは通常、重複排除機能を備えたタグとコネクタをサポートしています。クライアント側タグとサーバー側コンバージョン API コネクタを併用するハイブリッドアプローチを推奨します。これにより、次のことが可能になります。

* ブラウザ構成によってタグがブロックされたり、その機能が低下したりした場合でもコンバージョンを取得する。
* タグとコンバージョン API の間でイベントを検証して重複を排除し、プラットフォームが高品質なコンバージョンシグナルを受信できるようにする。
* オンラインとオフラインのコンバージョンを取り入れ、カスタマージャーニーをより包括的に把握する。
* 広告プラットフォームの AI および最適化アルゴリズムに、より豊富で一貫性のあるトレーニングデータを提供する。


<blockquote>
ハイブリッドアプローチを 90 日間使用することを推奨します。最初の 90 日間が経過した後、広告主は広告パートナーと協力して、レジリエンシーの状態、イベント照合品質スコア、およびシグナル全体の健全性を評価する必要があります。データが高い信頼性と正確性を示している場合、広告主はクライアント側タグのシグナルを停止する判断を確信を持って行えます。
</blockquote>


## クライアント側タグと重複排除

ベンダーがクライアント側タグとサーバー側コンバージョン API の両方をサポートしている場合、Tealium では、サードパーティタグがブラウザによってブロックされたり、その機能が低下したりした際に欠落するシグナルも含め、可能な限り多くのコンバージョンイベントを取得するために、両方を実装することを推奨します。

タグとコンバージョン API を使用して同じコンバージョンを送信すると、重複したイベントが広告プラットフォームに送信される可能性があります。これを防ぐため、多くのコンバージョン API 実装では重複排除がサポートされています。重複排除とは、共有イベント識別子を使用して、2 つのシグナルが同じコンバージョンを表していることを認識し、1 回だけカウントする仕組みです。

一般的なハイブリッド構成では、次のように処理されます。

1. ブラウザ上でタグが発火し、クライアント側コンバージョンイベントが送信されます。iQ Tag Management では、多くの場合、タグ構成の Generate Event ID フラグを使用して、広告ベンダーの仕様に従ったイベントごとの一意の識別子を作成します。
1. コンバージョン API コネクタが、同じイベント識別子を持つ対応イベントを送信します。Automatic Deduplication を使用するか識別子をマッピングすることで、一意の識別子がイベントで送信されるようにします。
1. 広告プラットフォームは、共有イベント識別子を使用して重複を排除し、高品質なコンバージョンレコードを 1 件だけ保持します。

ハイブリッドパターンにより、クリーンで正確なレポートを維持しながら、シグナル損失に対するレジリエンシーが向上します。その後、Tealium Connector Insights を使用して配信を監視し、エラーを診断するとともに、サポート対象ベンダー全体で重複排除が想定どおりに機能していることを検証できます。


<blockquote>
イベント ID が正しく構成されていない、または欠落している場合、広告プラットフォームでコンバージョンが重複してカウントされる可能性があります。クライアント側タグとサーバー側コンバージョン API コネクタのイベント ID が一致していることを確認してください。
</blockquote>

## 個人を特定できる情報（PII）

顧客識別子の優先順位は広告プラットフォームごとに多少異なりますが、いずれも同じ基本原則に従っています。識別子の強度と安定性が高いほど、照合および測定の品質が向上します。以下の一般的な優先順位は、主要なコンバージョン API パートナーに共通する傾向を示しています。

#### 最も強力

* **メールアドレス** - 通常は正規化してハッシュ化
* **電話番号** - E.164 形式、通常はハッシュ化
* **プラットフォーム ID またはアカウント ID** - ログイン ID、サブスクリプション ID、広告プラットフォームまたは自社システムによって発行された安定したユーザー ID
* **安定したファーストパーティ顧客 ID** - CRM ID またはロイヤルティ ID。多くの場合、外部 ID としてマッピング

#### 中程度

* **ブラウザ識別子およびクリック識別子** - プラットフォームのクリック ID、ブラウザ ID、または同様の Cookie
* **クライアント IP アドレス**
* **クライアントのユーザーエージェント**
* **デバイス識別子**
* **ハッシュ化された氏名および住所の構成要素** - 名、姓、番地、郵便番号、市区町村、都道府県、国

#### 低い

* **構造化されていない氏名フィールド** - 氏名のみ
* **デモグラフィック属性** - 性別、年齢層、他の識別子を伴わない大まかな所在地
* **不安定な行動識別子またはセッション限定識別子** - 訪問をまたいで安定しない識別子

より強力な識別子の組み合わせにより、イベント照合品質スコアなど、プラットフォームレベルのシグナル健全性指標が向上します。これらの指標は、広告プラットフォームによるコンバージョンのアトリビューションや AI を使用した最適化の精度に直接影響します。単一のフィールドよりも、シグナルの組み合わせが重要です。ハッシュ化されたメールアドレスに電話番号と安定した外部 ID を組み合わせると、ほぼ常に、単一の IP アドレスまたは氏名フィールドよりも高い効果が得られます。

具体的にどの識別子がサポートされ、どのように優先順位付けされているかについては、各ベンダーのコンバージョン API ドキュメントを参照してください。

## 構成のベストプラクティス

コンバージョン API が正しく構成されていることを確認するには、次の手順を実行します。

1. Tealium Collect タグが構成され、コンバージョンタグより後の[読み込み順序]()の最後に読み込まれることを確認します。
1. データレイヤーで、必要な PII データを定義します（広告プラットフォームは照合に PII を使用します）。
1. コンバージョン API ベンダーがタグも提供している場合は、両方を使用することを推奨します。タグを構成し、高度な照合機能が利用可能な場合はそれを使用します。すべてのページでタグを読み込むことを推奨します。タグを構成した後、コンバージョン API コネクタを構成します。
1. コンバージョン API コネクタ用のデータソースがまだ存在しない場合は、データソースを構成します。
1. 必要なイベント ID が定義されており、クライアント側（タグ）とサーバー側（コンバージョン API）で ID が同一であることを確認します。重複排除を機能させるには、イベント ID が同一である必要があります。クライアント側タグでは Generate Event ID フラグを使用し、サーバー側コネクタでは Automatic Deduplication 機能を使用することを推奨します。
1. クライアント側コンバージョンイベントのトリガーが正しいことを確認します。必要なすべてのデータが入力された後にのみイベントをトリガーしてください。データが欠落している場合、広告プラットフォーム上の広告レポートおよび ROAS レポートが不正確になる可能性があります。クライアント側で生成されたイベント ID に基づいてサーバー側イベントフィードを構成するか、イベントフィードの条件をクライアント側タグの読み込みルールと完全に一致させることを推奨します。
## Connector Insights

Tealium Connector Insightsを使用すると、コンバージョンAPI連携のパフォーマンスを可視化できます。サポート対象ベンダーについて、Insightsではイベント配信数、エラー率、マッチ品質の指標、重複排除のステータスなどの主要な指標を確認できます。

Connector Insightsは、次の目的で使用することをお勧めします。

* タグおよびコンバージョンAPIのイベントが想定どおりに配信され、重複排除されていることを確認する。
* シグナルの健全性とマッチ品質を継続的に監視する。
* ROASやレポートに影響が生じる前に、構成上の問題をトラブルシューティングする。


<blockquote>
初期構成後はConnector Insightsを定期的に確認し、シグナルの健全性を監視して、構成上の問題を早期に検出してください。
</blockquote>

## ユースケース

![](https://docs.tealium.com/images/icons/icon-globe.svg) **Webコンバージョンのアトリビューション**



1. 買い物客が季節セールを宣伝する広告をクリックし、Webチェックアウトを通じて購入を完了します。
1. 広告タグとコンバージョンAPIはTealiumに実装されているため、購入はクライアント側で取得され、サーバー側で確認されます。この二重配信方式により、Cookieが一部失われたり広告ブロッカーが使用されたりしても、高精度なトラッキングが可能になります。
1. 広告では売上が元のクリックに紐付けられるため、広告主は予算配分を最適化し、キャンペーンのパフォーマンスをより正確に測定し、リマーケティング用の価値の高いオーディエンスセグメントを構築できます。


1. 見込み顧客が個人向けローンの広告をクリックし、事前審査フォームに入力します。
1. 広告タグがフォーム完了イベントを取得し、コンバージョンAPIがフォームデータをサーバー側から送信します。これにより、ブラウザーの制限によってクライアント側のタグが機能しない場合でも、コンバージョンが確実に記録されます。
1. 広告ベンダーは、その広告をリード獲得に貢献したものとして評価し、データを活用して入札効率を向上させ、同様の意図を持つユーザーをより適切にターゲティングできます。


1. 旅行者がバケーションパッケージの広告をクリックし、旅行先を閲覧して、複数ステップのWebチェックアウトを通じて予約を完了します。
1. タグが各ステップを追跡し、予約の確定後にコンバージョンAPIを通じてサーバー側イベントが送信されます。各ステップを追跡することで、特に途中離脱によってタグ配信が中断される可能性がある長いチェックアウトフローにおいて、アトリビューションの精度が向上します。
1. コンバージョンが元のクリックに紐付けられるため、旅行ブランドはオンラインでコンバージョンにつながる可能性が最も高いオファーを分析し、広告費用対効果（ROAS）を最大化するとともに、キャンペーンメッセージをきめ細かく調整できます。




![](https://docs.tealium.com/images/icons/icon-cash-register.svg) **オフラインコンバージョンのアトリビューション**



1. 買い物客が広告をクリックしてWebサイトを閲覧したものの、その週の後半に実店舗で購入します。
1. 会計時にメールアドレスまたはロイヤルティ番号が収集され、元の広告エンゲージメントに紐付けられます。
1. 取引がPOSシステムに記録された後、オフラインコンバージョンデータがTealiumにインポートされ、コンバージョンAPIを使用して広告プラットフォームに送信されます。


1. 顧客が住宅ローン借り換えオファーの広告をクリックしてローンの選択肢を閲覧したものの、オンラインではフォームへの入力を完了しません。
1. 顧客がコンタクトセンターに電話をかけ、担当者が電話番号またはメールアドレスを収集して申し込みを完了します。
1. コールセンターがコンバージョンを記録すると、そのデータがTealiumにインポートされ、コンバージョンAPIを使用して広告プラットフォームに送信されます。
1. これにより、広告ベンダーは借り換えの申し込みを元の広告エンゲージメントに紐付け、キャンペーンパフォーマンスをより正確にレポートし、より高度な入札最適化戦略を実施できます。このサーバー側配信により、クライアント側トラッキングの欠落やデジタル上の行動の遅延が原因で、価値の高いオフラインリードや購入意向の強いコンバージョンが失われるのを防ぎます。


1. 旅行者がバケーションパッケージの広告をクリックしてオンラインで選択肢を閲覧した後、旅行代理店に電話して予約します。通話中に、氏名、電話番号、メールアドレスを伝えます。
1. この情報が予約システムで取得され、Tealiumにインポートされた後、サーバー側のコンバージョンイベントがコンバージョンAPIを通じて広告プラットフォームに送信されます。
1. ベンダーはクリックIDまたはユーザー識別子を使用して、オフライン予約イベントを元の広告クリックと照合します。
1. 広告ベンダーはオフライン予約を元の広告クリックに紐付けられるため、予約がデジタル接点以外で完了した場合でも、マーケターはキャンペーンパフォーマンスの全体像を把握できます。



![](https://docs.tealium.com/images/icons/icon-shield.svg) **シグナル損失からの復旧**



1. 買い物客がモバイルブラウザーで広告をクリックしてチェックアウトに進みますが、ブラウザーのトラッキング構成によってタグがブロックされます。
1. 取引自体は行われますが、クライアント側ではコンバージョンが記録されません。
1. コンバージョンAPIがクリックIDと個人識別情報（PII）を復元し、注文の確定時にコンバージョンデータが広告ベンダーへ送信されます。このサーバー側配信によってアトリビューションが復元され、小売業者は過少報告を回避できるほか、価値の高い購入者に向けた入札の最適化が可能になります。


1. 借り換えの選択肢を調べている訪問が広告をクリックし、金融機関のサイトにアクセスします。
1. 訪問は事前承認フォームへの入力を開始しますが、広告ブロッカーが有効になっているため、タグが読み込まれません。
1. Tealiumがフォーム送信を取得し、データをサーバー側からコンバージョンAPIコネクタに送信します。このサーバー側での復旧により、クライアント側のシグナルが劣化または完全にブロックされる制限の厳しい環境でも、リードが正しく紐付けられ、正確なレポートとキャンペーンROIが維持されます。


1. 旅行者がモバイルデバイスで閲覧中に、割引旅行パッケージ予約に関するベンダー広告をタップします。
1. 旅行先を確認してパッケージを選択し、チェックアウトプロセスを開始しますが、完了前にネットワーク接続が切断されます。
1. 幸い、Tealiumはすでにタグを使用してクリックIDとセッションコンテキストを取得しており、シグナルが途切れる前にデータがコンバージョンAPIへ送信されていました。
1. その後、旅行者は同じメールアドレスで本人を識別し、ノートパソコンで予約を再開しますが、その端末には広告ブロッカーがインストールされています。
1. 今回はタグが抑制され、クライアント側でコンバージョンを取得できません。
1. それでも、最終的な予約確認はTealium Collectタグを通じて送信され、完了した取引が取得された後、コンバージョンAPIに送られます。シグナルが複数の段階で劣化したにもかかわらず、広告ベンダーはクリックIDとユーザーが提供したPIIを使用して予約を元のモバイル広告クリックに紐付け、正確なレポートと入札の最適化を実現できます。
