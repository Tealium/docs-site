Tealium の各APIバージョンは、3つのライフサイクルフェーズを経ます。フェーズは、受けるサポートのレベルと、必要に応じて取るべきアクションを決定します。

## プレビューAPI

一部のAPIは、安定したバージョンを受ける前にプレビューでリリースされます。プレビューAPIはカレンダーバージョンのサポートポリシーの対象外です。エンドポイント、ペイロード、およびスコープは予告なしに変更される可能性があります。

プレビューAPIを購読するには、組織がTealiumと早期アクセス契約を締結している必要があります。購読ウィザードのレビューステップで、この契約を確認し、購読が作成される前にアクセスを許可するアカウントプロファイルを認める必要があります。

## ライフサイクルフェーズ

| フェーズ | ウィンドウ (バージョンリリース後) | サポートレベル | 必要なアクション |
| --- | --- | --- | --- |
| アクティブ | 0–24ヶ月 | バグ修正、セキュリティパッチ、および非破壊的なエンリッチメントが適用されます。 | アクション不要。 |
| サポート終了 | 24–36ヶ月 | APIは機能しますが、新機能や非重要な修正は受けません。レスポンスには `Sunset` と `Deprecation` のヘッダーが含まれます。バージョンがサポート終了に入ると、後継バージョンが自動的に特定されます。 | 移行計画を立てる。 |
| サポート終了 (EOL) | 36ヶ月以上 | 利用不可。HTTP 410が返されますが、承認された契約延長がある場合は除きます。 | この日付前に移行するか、正式な延長のために契約を更新する。 |

毎四半期にアップグレードする必要はありません。中間バージョンを安全にスキップし、準備ができたときに最新バージョンに直接アップグレードできます。各バージョンは独立して全36ヶ月のライフサイクルでサポートされます。詳細については、[APIバージョニング](https://docs.tealium.com/dev-portal-api-versioning/)を参照してください。

開発者ポータルAPIカタログは、各APIのバージョンとサポート終了日をカタログカードに表示します。

## 廃止のシグナル

バージョンがサポート終了に入ると、各APIレスポンスには以下のヘッダーが含まれます：

* **`Sunset`**: バージョンがサポート終了に達する日付。
* **`Deprecation`**: 廃止バージョンのすべてのレスポンスに `true` が構成されます。
* **`Link`**: 後継バージョンのURLを指します。

次の例は、サポート終了に入るバージョンからのレスポンスで、サンセット日が2029年6月、後継バージョンが `v2026-10` であることを示す3つのヘッダーを示しています：

```none
HTTP/1.1 200 OK
Sunset: Mon, 01 Jun 2029 00:00:00 GMT
Deprecation: true
Link: </2026-10/cdp/audiences>; rel="successor-version"
```
