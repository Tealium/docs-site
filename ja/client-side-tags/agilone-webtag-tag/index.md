## 前提条件

* 認証キー（AgilOneへのAPI呼び出しの認証に必要）
* Tealium Event拡張機能（任意ですが、使用を強く推奨）

## タグの構成

最初に、タグマーケットプレイスへ移動し、AgilOne Web Tagタグをプロファイルに追加します（[タグの追加](https://docs.tealium.com/manage-tags/#add-a-tag)を参照）。

タグを追加したら、以下の構成を構成します。

* テナントID：（必須）AgilOneから提供されたテナントID。このフィールドにIDを指定するか、[データマッピング](#data-mappings)を使用して動的に構成できます。

## ロードルール

[ロードルール](https://docs.tealium.com/about-load-rules/)では、このタグのインスタンスをサイト上のいつ、どこで読み込むかを決定します。

推奨ロードルール：**すべてのページで読み込む**

## データマッピング

データマッピングは、データレイヤー変数の値をベンダータグ内の対応する変数に送信します。詳細については、[データマッピングについて](https://docs.tealium.com/about-data-mappings/)を参照してください。

AgilOne Web Tagタグの宛先変数は、その「データマッピング」タブに組み込まれています。使用可能なカテゴリは次のとおりです。

### 標準

|**宛先名**| **説明**|
|---| ---|
|テナントID|（必須）テナントID|
|認証キー|（必須）認証キーの値|
|検索語句|サイトの検索に使用されたキーワード|
|イベント名|トリガーするイベントの名前。Tealium Event拡張機能で提供されていないイベントをトリガーする場合に推奨されます。|
|イベントエンティティURL|イベントが発生しているページのURL|
|イベントエンティティ時刻|（任意）イベントがトリガーされた時刻のタイムスタンプ。タイムスタンプがイベントの送信時刻と異なる場合に**のみ**、この値を送信することをAgilOneは推奨しています。|
|イベントエンティティのカスタムデータ*|イベントエンティティとともに送信する追加データ|


<blockquote>
イベントエンティティのカスタムデータは、「イベントカスタムデータ」カテゴリとは異なります。
</blockquote>

## 標準イベントのトリガー

AgilOneでサポートされている標準イベントは、[Tealium Events拡張機能](https://docs.tealium.com/tealium-events-extension/)を通じてトリガーされます。つまり、この拡張機能でサポートされているイベントについては、イベント名やトリガー値をマッピングする必要はありません。この拡張機能により、標準化されたイベント名と、`tealium_event`という新しいデータレイヤー変数がソリューションに導入されます。各イベントには、データレイヤーの実装に一致するカスタム条件が割り当てられます。イベント条件が`true`と評価されると、`tealium_event`には事前定義されたイベント値が構成されます。TealiumのAgilOne Webtagテンプレートは、この事前定義値を読み取り、それに応じてイベントを発生させます。たとえば、「カートに追加」の条件が`true`と評価されると、`tealium_event`は`cart_add`に構成され、カートページでカートイベントが発生します。

Tealium Events拡張機能を通じてAgilOneでサポートされるイベントの完全なリストは次のとおりです。

|**イベント名**| **tealium_event変数の値**| **対応する拡張機能**|
|---| ---| ---|
|ユーザーログイン| `user_login`| Tealium Events|
|ユーザーログアウト| `user_logout`| Tealium Events|
|検索ページ表示| `search`| Tealium Events|
|商品詳細ページ表示| `product_view`| Tealium Events|
|カテゴリページ表示| `category_view`| Tealium Events|
|ブランド表示| `brand_view`| --|
|カートに追加| `cart_add`| Tealium Events|
|カートから削除| `cart_remove`| Tealium Events|
|カートを空にする| `cart_empty`| Tealium Events|
|チェックアウト| `checkout`| Tealium Events|


<blockquote>
標準イベントとともに追加のカスタムデータを送信するには、[標準カテゴリにあるイベントカスタムデータのマッピング](#event-custom-data)を構成します。
</blockquote>


### 非標準イベントのトリガー

トリガーするイベントがTealium Events拡張機能で提供されていない場合は、別の方法を使用できます。代わりにSet Data Value拡張機能を使用して、イベントトリガーとイベント条件を構成できます。その後、トリガー変数をイベント名の宛先（標準カテゴリ内）にマッピングします。

ブランド表示イベントは、非標準イベントの一例です。イベントをトリガーするには、次の手順に従います。

1. 拡張機能マーケットプレイスから、[新しいSet Data Values拡張機能を追加して構成します](https://docs.tealium.com/set-data-values-extension/)。

1. スコープをAgilOne Webtagに構成します。

1. `event_name`データ変数をテキスト`brand_view`に構成します。注意：`brand_view`の値はテンプレートで事前定義されているため、変更できません。

1. 顧客のブランド表示アクションを評価するイベント条件を追加します。たとえば、`event_type`が`brand_view`に等しい、という条件です。

<blockquote>
目的の変数が見つからない場合は、その場で追加できます。
</blockquote>


1. タグの「データマッピング」タブに移動し、`event_name`変数をイベント名の宛先（標準カテゴリ）にマッピングします。
### カート更新の送信

カートへの商品の追加およびカートからの商品の削除は標準イベントとして扱われるため、Tealium Events Extension から簡単にトリガーできます。最終的なカートのデータ（追加または削除された商品を含む）を送信する手順は、次の3つです。

1. カートへの追加／カートからの削除イベントをトリガーするように、Tealium Events Extension を構成します。
1. タグの Current Cart マッピングに移動し、任意の送信先にマッピングします。
1. E-Commerce Extension に移動し、新しく追加または削除されたカート商品を `_cprod` にマッピングします。これにより、更新されたカート商品が個別に取得されます。

ページ上でカートへの追加／カートからの削除イベントが発生すると、タグテンプレートによって追加または削除された商品と現在のカートデータが自動的にまとめられ、完全なカートリストが送信されます。


<blockquote>
削除されたカート商品を正しく識別するには、その商品を E-Commerce の `cprod` と Current Cart の両方にマッピングする必要があります。
</blockquote>
