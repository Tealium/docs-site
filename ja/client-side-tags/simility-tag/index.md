## 前提条件

* Similityアカウント

## タグの構成

まず、タグマーケットプレイスに移動し、Similityタグをプロファイルに追加します（[タグの追加](https://docs.tealium.com/manage-tags/#add-a-tag)を参照）。

タグを追加する際は、以下の構成を行います。

1. **顧客ID**：サインアップ時にSimilityからお客様（またはお客様の会社）に提供された一意の識別子です。顧客IDは必須です。このフィールドで指定するか、データマッピングを使用して動的に構成できます。
1. **ゾーン**：データをホストするデータセンターの所在地です。選択可能なオプションは、`US`（デフォルト）と`EU`です。
1. **Simility Lite**：デフォルトでオンになっています。`OFF`にすると、位置情報やマウスの動きなど、追加のユーザー情報を送信する必要があります。
1. **Simility Liteレベル**：Similityサポートチームから提供された数値（小数）です。


<blockquote>
**Simility Lite**および**Simility Lite**レベルの構成は、高度な構成です。詳細については、Similityサポートチームにお問い合わせください。
</blockquote>


## ロードルール

[ロードルール](https://docs.tealium.com/about-load-rules/)では、サイト上のどの場所で、いつこのタグのインスタンスを読み込むかを決定します。

## データマッピング

データマッピングは、データレイヤー変数の値をベンダータグ内の対応する変数に送信します。詳細については、[データマッピングについて](https://docs.tealium.com/about-data-mappings/)を参照してください。

Similityタグの宛先変数は、［データマッピング］タブに組み込まれています。使用可能なカテゴリーは次のとおりです。

### 標準

| 宛先名 | 説明 |
|:---------------------|:-----------------------------------------------------------------------------------------------------------------------|
| Simility顧客ID | （必須）サインアップ時にSimilityから提供された顧客／アカウントID |
| Simility Lite | Simility Liteを有効にするかどうかを指定するブール値（`true`/`false`） |
| Simility Liteレベル | Similityサポートチームから提供された小数値 |
| ゾーン | データをホストするデータセンターの所在地。マッピングする変数に`us`または`eu`が含まれていることを確認してください。 |
| セッションID | （必須）ユーザーセッションの一意のID |
| イベントタイプ | （必須）追跡対象のユーザーアクティビティに関連付けられたイベントをカンマで区切った文字列 |


<blockquote>
標準の宛先へのマッピングは、対応するタグ構成を上書きします。
</blockquote>


#### トランザクション情報

トランザクションデータ（ユーザー、注文、トランザクション、申し込み、プロファイルなど）を送信できます。データは、ペイロード内の`transaction_info`オブジェクトを介して送信されます。

| 宛先名 | 説明 |
|:--------------------|:---------------------------------------------------------------------------------------------------------------------------------------|
| エンティティ | ペイロードのエンティティタイプ。`transaction_info`オブジェクトを使用する場合は必須 |
| トランザクションID | トランザクションの一意のID。`transaction_info`オブジェクトを使用する場合は必須 |
| 名 | ユーザーの名 |
| 姓 | ユーザーの姓 |
| ユーザーID | ユーザーのユーザー名 |
| メール | ユーザーのメールID |
| 初回注文かどうか | ユーザーの初回注文かどうかを指定するブール値（`true`/`false`） |
| 再試行回数 | 注文を確定しようとした回数 |
| カスタムフィールド | ユーザーのトランザクションに関連するカスタムデータ。`custom`をカスタムパラメーター名に置き換えます。例：`field.order_categories` |
| カスタムネストフィールド | トランザクションデータをネスト形式で送信します。例：`field.order_details.is_first_order` |

**ペイロードの例**

トランザクション情報のマッピングは`transaction_info`オブジェクト内にラップされ、それ以外のすべてのマッピングはオブジェクトの外にあることに注目してください。

```javascript
var similityContext = {
    "customer_id": "acme",
    "session_id": "1234",
    "user_id" : "user1234",
    "simility_lite": true,
    "transaction_info": [{
      "entity": "orders",
      "id": "xyz101",
      "fields": {
          "first_name": "John",
          "last_name": "Doe",
          "user_id": "user1234",
          "email": "johndoe@example.com",
          "order_categories": ["123", "456", "789"],
          "order_details": { "is_first_order": true, "num_retries": 1 },
       }
   }]
  };
```

### Eコマース

SimilityタグはEコマースに対応しているため、デフォルトのEコマース拡張機能のマッピングを自動的に使用します。次の場合を除き、通常、このカテゴリーで手動マッピングを行う必要はありません。

* 拡張機能のマッピングを上書きする場合
* 使用したいEコマース変数が拡張機能に用意されていない場合

| 宛先名 | 説明 | Eコマース拡張機能の変数 |
|:--------------------|:-------------------------------|:------------------------------|
| 注文ID | 一意の注文ID | `_corder` |
| 注文合計 | 注文の合計金額 | `_ctotal` |
| 顧客ID | （必須）一意の顧客ID。 | `_ccustid` |
| 商品IDのリスト | 商品IDの配列 | `_cprod` |
| 名前のリスト | 商品名の配列 | `_cprodname` |
| カテゴリーのリスト | 商品カテゴリーの配列 | `_ccat` |
| 数量のリスト | 商品数量の配列 | `_cquan` |
| 価格のリスト | 商品価格の配列 | `_cprice` |
