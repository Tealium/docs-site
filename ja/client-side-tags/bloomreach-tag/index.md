## タグの構成

まず、タグマーケットプレイスに移動し、BloomReachタグをプロファイルに追加します（[タグの追加](https://docs.tealium.com/manage-tags/#add-a-tag)を参照）。

タグを追加する際に、以下の構成を構成します。

* アカウントID：BloomReachのアカウントID。
* ビューID：BloomReachから提供されるこのIDは、同じアカウントIDを使用し、商品カタログの特性が異なるサイトが複数ある場合にのみ必要です。
* ドメインキー：BloomReachから提供されるこのIDは、複数の言語バージョンがあるサイトにのみ必要です。
* TMSの追跡：タグ管理システム（TMS）としてTealiumを追跡するかどうかを切り替えます。BloomReachの実装を別のプラットフォームからTealiumへ移行しており、両方のプラットフォームでBloomReachを引き続き読み込んでいる場合にのみ、`Yes`に切り替えてください。デフォルトは`No`です。これにより、BloomReachは各プラットフォームからのトラッキング呼び出しを区別できます。
* ページビュー時に`br_data`をクリア：ページビューごとに`br_data`オブジェクトをクリアするか、保持されている値を残すかを切り替えます。シングルページアプリケーションやAJAXアプリケーションでは、多くの場合`Yes`に構成します。デフォルトは`No`です。

## ロードルール

[ロードルール](https://docs.tealium.com/about-load-rules/)は、サイト上でこのタグのインスタンスをいつ、どこに読み込むかを決定します。

推奨ロードルール：**すべてのページ**

## データマッピング

データマッピングは、データレイヤー変数の値をベンダータグ内の対応する変数に送信します。詳細については、[データマッピングについて](https://docs.tealium.com/about-data-mappings/)を参照してください。

BloomReachタグの宛先変数は、タグの**データマッピング**タブに組み込まれています。利用可能なカテゴリは以下のとおりです。

### 標準／グローバル

| **宛先名** | **説明** |
|:---------------------|:--------------------------------------------------------------------------------------------------------------------------|
| アカウントID | 構成済みの**アカウントID**を上書きします。 |
| ビューID | 構成済みの**ビューID**を上書きします。 |
| ドメインキー | 構成済みの**ドメインキー**を上書きします。 |
| タイトル | ページタイトルを現在のページのタイトルで上書きします。 |
| 通貨 | 取引の通貨コードを上書きします。 |
| ユーザーID | Eコマース拡張機能の`_ccustid`値を上書きします。 |
| TMS追跡フラグ | 構成済みの「TMSの追跡」構成を上書きします。有効にするには、値が文字列`yes`である必要があります。 |
| br_dataクリアフラグ | 構成済みの「ページビュー時に`br_data`をクリア」構成を上書きします。有効にするには、値が文字列`yes`である必要があります。 |
| イベントグループ | デフォルトのイベントグループを上書きするためにマッピングします。BloomReachの担当者に相談した後にのみ上書きしてください。 |
| イベントタイプ | デフォルトのイベントタイプを上書きするためにマッピングします。BloomReachの担当者に相談した後にのみ上書きしてください。 |

### ページタイプ（`ptype`）

| **宛先名** | **説明** |
|:---------------------|:-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| ptype | （すべてのページビューで必須）BloomReachには、`homepage`、`product`、`category`、`search`、`content`、`thematic`、`other`の7つのページタイプ分類があります。マッピングされた変数の値を入力し、ドロップダウンから適切な`ptype`を選択して、`ptype`を動的に構成します。<br><br>ページタイプがBloomReachでサポートされているページタイプのいずれにも該当しない場合は、`other`を使用します。カスタムptypeは、BloomReachの担当者に相談した後にのみ構成してください。 |

### カテゴリページ

| **宛先名** | **説明** |
|:---------------------|:--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| カテゴリID | BloomReachのデータベース／カタログで参照される一意のカテゴリIDです。カテゴリIDは、フィード内の`crumb_id`と一致する必要があります。通常、これは数値IDまたは一意のパンくずパスです。<br><br>パンくずパスを渡す場合、個々のパンくず値を区切らないでください。 |
| カテゴリ名 | ページのパンくずリストです。各パンくずはパイプ（&#124;）で区切る必要があります。 |

### コンバージョンページ

| **宛先名** | **説明** |
|:---------------------|:----------------------------------------------------------------------------------------------------------------|
| 注文ID | コンバージョンの注文IDまたは取引ID。 |
| 注文合計 | 税金と送料を含む注文の合計金額。 |
| 商品IDのリスト | 商品IDの配列。 |
| 名前のリスト | 商品名の配列。 |
| SKUのリスト | 商品SKUの配列。 |
| カテゴリのリスト | 商品カテゴリの配列。 |
| 価格のリスト | 商品価格の配列。 |
| 数量のリスト | 注文内の各商品の数量を格納する配列。 |
| コンバージョンフラグ | コンバージョンページまたはサンキューページでは、これを`1`に構成します。注文IDに値が構成されると、自動的に`1`に構成されます。 |

### 商品ページ

| **宛先名** | **説明** |
|:---------------------|:---------------------------|
| 商品IDのリスト | 商品IDの配列。 |
| 名前のリスト | 商品名の配列。 |
| SKUのリスト | 商品SKUの配列。 |
### 検索ページ

| **宛先名** | **説明** |
|:-----------|:---------|
| 検索語句 | ページを表す検索クエリの値。 |

### 仮想ページビュー

| **宛先名** | **説明** |
|:-----------|:---------|
| 元の参照元URL | 仮想ページビューイベントを発生させる際に、最初に読み込まれたページのURLを指定します。仮想ページビューが発生すると自動的に取得されますが、ここでマッピングすることによって上書きできます。 |

### イベント

ページ上で特定のイベントをトリガーするには、以下の宛先にマッピングします。イベントをトリガーするには、次の手順を実行します。

1. ドロップダウンリストからイベントを選択します。定義済みのリストから選択するか、カスタムイベントを作成できます。カスタムイベントの場合は、イベントを識別するための名前を入力します。カスタムパラメーターまたはイベントを構成する前に、BloomReachの担当者にご相談ください。
1. **Trigger**フィールドに、マッピングする変数の値を入力します。
1. さらにイベントをマッピングするには、**+**ボタンをクリックし、手順1と2を繰り返します。
1. **Apply**をクリックします。

指定した値がデータレイヤー内で見つかると、イベントがトリガーされます。

| **宛先名** | **説明** |
|:-----------|:---------|
| カートに追加 | 訪問が商品をカートに追加したときにトリガーします。デフォルトのイベントグループ：`cart`。デフォルトのイベントタイプ：`click-add`。 |
| コンテンツページビュー | 訪問が、別のページに特化した商品以外のページ（レシピ、ブログ、記事ページなど）を開いたときにトリガーします。 |
| コンテンツ検索 | 訪問が検索を実行したときにトリガーします。 |
| クイックビュー | 訪問が商品の詳細を表示するためにクイックビューを開いたときにトリガーします。通常、一覧ページまたはカテゴリーページで発生します。デフォルトのイベントグループ：`product`。デフォルトのイベントタイプ：`quickview`。 |
| 検索候補 | 訪問が検索語句を入力して送信をクリックしたとき、または自動提案された語句が表示され、訪問がその語句をクリックしたときにトリガーします。デフォルトのイベントグループ：`suggest`。デフォルトのイベントタイプ：`submit`、`click`。 |
| 仮想ページビュー | 現在のページが、新しいページビューとして追跡するのが最適な方法で更新されたときにトリガーします。これはAJAXサイトやシングルページアプリで一般的です。 |
| ウィジェットからカートに追加 | 訪問がおすすめから商品をカートに追加したときにトリガーします。 |
| ウィジェットのクリック | 訪問がおすすめの商品をクリックしたときにトリガーします。 |
| ウィジェットの表示 | 訪問がおすすめの商品を表示したときにトリガーします。 |
| カスタム | カスタムイベントをトリガーします。これを構成する前に、BloomReachの担当者にご相談ください。 |

### イベントパラメーター

特定のイベントのパラメーターにマッピングできます。

| **宛先名** | **説明** |
|:-----------|:---------|
| 商品ID（`prod_id`） | 「カートに追加」または「クイックビュー」イベントの商品ID。 |
| 商品名（`prod_name`） | 「クイックビュー」イベントの商品名。 |
| 商品SKU（`sku`） | 「カートに追加」または「クイックビュー」イベントの商品SKU。 |
| 検索クエリ（`q`） | 「検索候補」イベントで訪問が入力した検索語句。 |
| 表示クエリ（`aq`） | 「検索候補」イベントで訪問に表示された、自動提案された検索語句。 |


<blockquote>
「検索候補」イベントに「表示クエリ」パラメーターを渡すと、イベントタイプは自動的に`click`に構成されます。それ以外の場合、イベントタイプは`submit`になります。
</blockquote>


#### セグメントパラメーター

宛先名`br_data.SEGMENT_NAME`を使用して、カスタムセグメントパラメーターを追加できます。ここで、`SEGMENT_NAME`はセグメント名を表します。

例：`br_data.customer_tier = "vip"`
