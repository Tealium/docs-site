## 仕組み

* 注文IDが構成されると、購入トラッキングが自動的に実行されます。
* 「Pixel ID」フィールドには、ピクセルIDをカンマ区切りのリストで入力できます。
* **イベントIDを生成**：Facebookピクセルで`event_id`パラメータを生成し、これらのイベントIDをサーバーサイド属性として利用できるようにするには、`true`に構成します。
  * 最新バージョンのTealium Collectタグが必要です。
  * カスタム変数を`event_id`にマッピングする場合は、`true`に構成する必要があります。
  * 詳細については、[Web向けConversions API](#conversions-api-for-web)を参照してください。
* 商品数量の配列が存在する場合、テンプレートは`num_items`の値を自動的に計算しようとします。
* マッピングを使用して、以下を実行できます。
  * `trackSingle`を切り替える（デフォルトは`false`）— 有効にすると、`fbq('trackSingle')`を使用して、明示的にマッピングされたピクセルIDにのみイベントを送信します。無効にすると、`fbq('track')`を使用して、初期化されたすべてのピクセルIDにイベントを配信します
  * `disablePushState`を切り替える（デフォルトは`false`）
  * タグ構成を動的に構成する
  * Eコマース拡張機能の値を上書きする
* 以下のEコマース拡張機能パラメータをサポートしています。
  * 注文ID
  * 小計
  * 通貨
  * 商品IDのリスト
  * 商品カテゴリのリスト
  * 商品価格のリスト
  * 商品数量のリスト
  * 商品名のリスト

  
<blockquote>
Facebookピクセルタグは、ユーザーデータを自動的にハッシュ化します。この機能は変更できません。
</blockquote>


### Web向けConversions API


<blockquote>
この機能を使用するには、有効な[Tealium Collectタグ](https://docs.tealium.com/tealium-collect-tag/)が必要です。
</blockquote>


Facebook Conversions API for Webをサポートするには、**イベントIDを生成**を`true`に構成します。**イベントIDを生成**を有効にすると、このタグはトラッキングされるイベントごとに一意のイベントIDを生成し、Facebook Conversionsコネクタで使用できるように属性としてEventStreamに送信するとともに、`event_id`パラメータでFacebookピクセルに渡します。このイベントID属性をコネクタでマッピングすることで、Webベースのタグとサーバーサイド統合を同期できます。

タグは、以下の命名規則に従って生成されたイベント属性を使用して、イベントIDを送信します。

```nohl
fb_event_id_{FACEBOOK_EVENT}_{TAG_UID}
```

たとえば、タグ#32の購入イベントでは、次の属性と値が送信されます。

```json
{
  "fb_event_id_Purchase_32": "028b2ade7478..."
}
```

同じタグのページビューイベントでは、次の属性と値が送信されます。

```json
{
  "fb_event_id_PageView_32": "084b1cda7461..."
}
```

#### 重複排除

イベントを適切に重複排除するには、FacebookピクセルタグのイベントIDを、Tealium Collectタグから送信されるペイロードに含める必要があります。そのためには、次の手順を実行します。

* **タグタイミング**ドロップダウンから、**優先**を選択します。
* **バンドルフラグ**トグルを`On`に構成します。
* [読み込み順序マネージャー画面](https://docs.tealium.com/load-order-manager/)を使用して、FacebookピクセルタグをTealium Collectタグより先に発火させます。Tealium Collectタグを最後に発火させることをお勧めします。

これらのイベントID属性の使用方法については、[Facebook Conversionsコネクタ：Webイベントの重複排除](https://docs.tealium.com/facebook-conversions-connector/#deduplication-for-web-events)を参照してください。

#### 従来のイベントID

以前のバージョンのFacebookピクセルタグでは、イベントID属性は`fb_event_id_Purchase`など、`fb_event_id_{FACEBOOK_EVENT}`という形式で生成されていました。これらの古い属性名は引き続きタグによって生成されますが、同じページ上の複数のFacebookタグをサポートしていないため、従来形式と見なされます。

最新バージョンのFacebookピクセルタグでは、生成される属性名にタグUIDを含めることで、ページ上で複数のFacebookタグを発火できます。イベントID属性に従来形式を引き続き使用している場合は、タグを最新バージョンに更新し、新しいイベントID属性を参照することをお勧めします。

## タグの構成

新しいタグを追加するには、タグマーケットプレイスに移動します。詳細については、[タグについて](https://docs.tealium.com/about-tags/)を参照してください。

タグを追加するときは、以下の構成を構成します。

* **ピクセルID**
  * FacebookピクセルID。
  * ピクセルIDは、コードスニペット内に長い数字列として表示されます。
  * 複数のピクセルIDを、スペースを入れずにカンマ区切りのリストで入力できます。
  * 例：`fbq("init", "12345678901234");`
* **詳細マッチング**
  * Facebookの詳細マッチングサービスを有効にし、データを渡します。
  * 例：`fbq("init", "12345678901234", {em:"6dd8b7d7..."});`
  * **詳細マッチング**を有効にしてから、個人を特定できる情報（PII）を含むパラメータをマッピングする場合は、**Metaイベントマネージャ**で**自動詳細マッチング**を無効にし、パラメータを手動でのみマッピングすることを強くお勧めします。**自動詳細マッチング**では、ニーズや範囲を超えたPIIパラメータが追加でマッピングされ、セキュリティおよびプライバシー上の問題が発生する可能性があります。詳細については、Facebookの[Webサイトまたはモバイルアプリで自動詳細マッチングを構成する](https://www.facebook.com/business/help/1993001664341800?id=1205376682832142)を参照してください。
* **イベントIDを生成**
  * イベントIDをサーバーサイドに送信するには、Tealium Collectタグが必要です。
  * Facebookの各トラッキングイベントに対してイベントIDを自動的に生成します。
  * イベントID属性は、次の命名規則に従います：`fb_event_id_{FACEBOOK_EVENT}_{TAG_UID}`
  * 例：`"fb_event_id_Purchase_32" : "028b2ade7478..."`
* **自動ページビューイベント**：ページビューイベントを自動的にトラッキングするには、`True`に構成します。

## イベントマッピング

Facebookピクセルイベントは、イベントにマッピングする変数を選択し、トリガーを入力することで、データマッピングを通じて構成します。次のユースケースに示すように、変数が特定の値と一致すると、トリガーによってイベントが開始されます。

### ユースケース：購入イベント

購入イベントを構成するには、次の手順を実行します。

1. 変数ドロップダウンリストから`tealium_event`を選択し、**宛先を選択**をクリックします。
1. **カテゴリ**セクションで、**イベント**を選択します。
1. **マッピングされた変数が次と等しい場合**フィールドを`Purchase`に構成します。これは、購入をトリガーするために`tealium_event`が一致する必要がある値です。
1. **イベントをトリガー**ドロップダウンリストで`Purchase`を選択します。これは、`tealium_event`が購入と等しい場合にトリガーされるイベントです。![](https://docs.tealium.com/images/client-side-tags/a.png)購入イベントとともに送信する必要がある追加データが、組み込みのEコマース拡張機能のマッピングでまだカバーされていない場合は、**カスタムパラメータ**を使用して追加の購入データをマッピングします。

次の例では、購入イベントとともに商品ブランドを渡します。

1. 変数ドロップダウンリストから`product_brand`を選択し、**宛先を選択**をクリックします。
1. **カテゴリ**セクションで、**イベント固有のパラメータ**を選択します。
1. カスタムパラメータの**宛先**フィールドを`brand`という名前に構成します。
1. **対象イベント**ドロップダウンリストで、カスタムパラメータを収集するイベント`Purchase`を選択します。  
![](https://docs.tealium.com/images/client-side-tags/c.png)

[Facebook Pixel Helper](https://developers.facebook.com/docs/facebook-pixel/support/pixel-helper/)またはブラウザが提供する開発者ツールを使用して、マッピングをテストします。

1. **ネットワークパネル**を使用し、Facebookでフィルタリングして、Facebookをキーワードとして含むすべてのネットワークリクエストを表示します。
1. リクエスト名を確認して、購入イベントが成功したことを確認します。
1. リクエストを開き、**クエリ文字列パラメータ**まで下にスクロールして、構成したデータマッピングの値（`purchase`、`product_id`、`product_brand`）を確認します。  
![](https://docs.tealium.com/images/client-side-tags/d.png)
## データマッピング

データマッピングは階層構造に従い、イベント固有パラメータなどの具体的なマッピングが、より一般的なマッピングより優先されます。たとえば、**標準トラッキングパラメータ**タブで変数を**通貨**の宛先にマッピングし、さらに **ViewContent** イベントでも**通貨**の宛先にマッピングした場合、**ViewContent** のマッピングが一般的なマッピングより優先されます。ただし、これは **ViewContent** イベントにのみ適用されます。その他のすべてのイベントでは、標準トラッキングのマッピングが使用されます。

データマッピングは、データレイヤー変数の値をベンダータグ内の対応する変数に送信します。詳細については、[データマッピングについて](https://docs.tealium.com/about-data-mappings/)を参照してください。

使用可能なカテゴリは次のとおりです。

#### コンテンツタイプ

**標準トラッキングパラメータ**タブまたは**イベント固有パラメータ**のマッピングで、`content_type` パラメータに直接マッピングして構成します。

**コンテンツタイプ**タブでは、`content_type` パラメータを条件に応じて、サポートされている以下のいずれかの値に構成できます。

* `destination`
* `flight`
* `home_listing`
* `hotel`
* `product`
* `product_group`
* `vehicle`

マッピングされた変数がフィールドに入力した値と等しい場合、ドロップダウンリストから選択したタイプが値として構成されます。ほとんどの場合は `product` または `product_group` が使用されます。この値は、Facebookにアップロードした商品フィード内の商品に指定した `content_type` と一致する必要があります。その他の値は、主にダイナミック広告で使用されます。

|変数| 型 | 説明|
|---| ---| ---|
|`destination`|  文字列 | 目的地。 |
|`flight`|  文字列 | フライト。 |
|`home_listing`|  文字列 | 住宅リスティング。 |
|`hotel`| 文字列 | ホテル。 |
|`product`|  文字列 | 商品。 |
|`product_group`|  文字列 | 商品グループ。 |
|`vehicle`| 文字列 | 車両。 |
